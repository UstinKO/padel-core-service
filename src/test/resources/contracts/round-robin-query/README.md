# Исходные wire-эталоны круговой таблицы

Эталоны получены и проверены в LFPT-1375 на неизменённом приложении после PR #1372. RoundRobinRankingBaselineTest сравнивает полный JSON, включая набор полей, null и порядок массивов. При отсутствующем файле тест завершается ошибкой; автоматической перезаписи эталона нет. Фактический нормализованный ответ сохраняется только в игнорируемый target/round-robin-query-baseline/ для разбора различий.

Одиннадцать состояний: пустой турнир, POINTS/SETS до счёта, полный круг, pending-финал, сыгранный финал, ничья POINTS и гость с неуказанным уровнем. Команда finish дополнительно сравнивается со сыгранным финалом: ответ уже имеет finished=true до изменения статуса турнира, а сам JSON finish/GET остаётся тем же.

Fixture создаётся из синтетических игроков/регистраций. Номера команд после initialize закрепляются по порядку fixture, чтобы внутренний порядок HashMap регистрации не менял посторонние имена между прогонами. Это подготовка тестовых данных, не изменение правил нумерации продукта. Существующие интеграционные проверки исходной инициализации сохраняются отдельно.

Нормализация заменяет только динамические значения: tournamentId на 1; реальные team ID на 100+номер пары; player ID на 200+индекс fixture; ID дополнительных матчей на 300+порядок создания; UUID email на fixture. Значения полей/статистика/порядок не нормализуются. Неизвестный ID остаётся исходным и не получает замену по предположению о номере строки.

Наблюдаемые особенности:

- Корневой boolean называется finished, а не isFinished. После полного круга он true при статусе турнира CERRADO; новый pending round делает его false.
- POINTS начинает с позиций 1/2, SETS — 1/1. Круговой ranking не переставляется дополнительным финалом; finalRanking меняется.
- В DTO присутствуют null setDifference, регистрационные и плей-офф-поля, которые этот сервис не заполняет. Их нельзя начать копировать из entity при смене маппера.
- PlayerPlayingSide доступен Java-потребителю DTO, но отсутствует в JSON. SIN_ESPECIFICAR и уровень гостя дают null.
- JSON ranking требует авторизации. Anonymous Accept JSON получает 401, Accept HTML — redirect на login; публичная MVC-страница остаётся доступной без сессии.
- Отсутствующий турнир даёт ResourceNotFoundException, не обработанный данным MVC-контроллером; конечный jar отвечает 500. Обработка этого класса ошибок уже поставлена в #453, родственная ошибка публичной страницы — в #445. Canonical fix требует отдельного явного обновления baseline, новая норма 404 в миграции не вводится.

Помимо эталонов новый набор проверяет частичный круг/null mode, прочие места/встречу без места, права/redirect, реальную read-only транзакцию без сохранения позиций и joined write-read/rollback состояния и истории. RoundRobinIntegrationTest сохраняет исходную регрессию финала/бронзы/исправления/restore; adapter/engine-тесты — подробные критерии равенств. Тесты не подменяют маппинг или сервисную реализацию.
