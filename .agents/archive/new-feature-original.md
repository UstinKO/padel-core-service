Ты — Senior Fullstack разработчик. Твоя задача — реализовать систему управления турниром по паделу.

Пожалуйста, выполни строго по шагам:

Проанализируй текущую кодовую базу и найди похожие реализации (турнирные сетки, системы расписаний, админ-панели).

Создай необходимые файлы компонентов, утилит и тестов.

Добавь маршрутизацию и подключи к API, если нужно.

Убедись, что все существующие тесты проходят.

Зафиксируй изменения.

Используй только паттерны и библиотеки, которые уже есть в проекте.

ТЕХНИЧЕСКОЕ ЗАДАНИЕ: Система управления турниром по паделу
1. ОБЩАЯ КОНЦЕПЦИЯ
   Тип: парный турнир

Формат: квалификация (2 матча на команду) → плей-офф (на вылет)

2. ПАРАМЕТРЫ СИСТЕМЫ
   Команды: от 2 (мин.), рекомендуемо 16, без верхнего ограничения

Корты: 2–10, динамическое назначение, без простоя

3. ФОРМАТ МАТЧА
   1 сет до 6 геймов

При 5–5 — тай-брейк до 7 очков

Возможные результаты: 6–0, 6–1, 6–2, 6–3, 6–4, 6–5

4. РЕГИСТРАЦИЯ КОМАНД
   Два способа:

Самостоятельная (через сайт)

Ручная администратором (указать игроков, отметить оплату, подтвердить участие, добавить комментарий)

Источники: website, whatsapp, walk-in, admin_manual

5–6. КВАЛИФИКАЦИОННЫЕ МАТЧИ
1-й матч: по порядку регистрации (1 vs 2, 3 vs 4…)

2-й матч: предпочтительно winner vs winner, loser vs loser, но не обязательно

7–9. КЛЮЧЕВЫЕ ПРАВИЛА
Каждая команда играет ровно 2 матча

Повторные матчи запрещены

Корты не простаивают

При нечётном количестве: последняя команда играет с победителем первого матча

При <16 команд: система динамически перемешивает команды, чтобы избежать нехватки соперников

Приоритет подбора: 1) сыграла <2 матчей, 2) не играли ранее, 3) одинаковый результат, 4) любой доступный

10. ДОПУСТИМОЕ НАРУШЕНИЕ
    При <16 команд разрешено winner vs loser, если это необходимо для выполнения главного правила (2 матча на команду)

11. СТАТИСТИКА КОМАНДЫ
    matches_played, wins, losses

sets_won, sets_lost, set_difference (формула: sets_won − sets_lost)

games_won, games_lost, game_difference (формула: games_won − games_lost)

12. РЕЙТИНГ ПОСЛЕ КВАЛИФИКАЦИИ
    Сортировка по:

Количество побед

Разница сетов

Разница геймов

Количество выигранных геймов

Случайный выбор / ручная корректировка

13–15. ПЛЕЙ-ОФФ
Стадии: 1/8, 1/4, 1/2, финал

При <16 команд: лучшие проходят напрямую в 1/4 (15→1, 14→2, 13→3, 12→4)

Пары: лучшая vs худшая, повторные матчи запрещены (кроме финала)

16. УПРАВЛЕНИЕ КОРТАМИ
    При освобождении корта — назначение следующего матча. Приоритет: матч следующей стадии > матч квалификации > матч ожидания

17. АДМИНИСТРАТИВНЫЕ ФУНКЦИИ
    CRUD команд, отметка оплаты, подтверждение прихода, назначение/изменение матча/корта/соперника, ввод/исправление результата, принудительное назначение

18. ПУБЛИЧНАЯ СТРАНИЦА ТУРНИРА
    Отображать: название, дата, стадия, количество команд, список команд, таблица квалификации, текущие/следующие матчи, корты, результаты, сетка плей-офф. Автообновление: каждые 10–30 секунд.

19. ГЛАВНАЯ ЛОГИКА СИСТЕМЫ
    Четыре ключевые цели:

Каждая команда играет 2 квалификационных матча

Корты не простаивают

Повторные матчи исключаются

Сильные команды не встречаются слишком рано
