Прочитай корневой `AGENTS.md`, затем [полный протокол](../../workflows/develop-feature.md).
Контекст: `specs/MASTER.md`, соответствующая спека, `.agents/PROJECT.md`, `docs/Home.md`.

Выполни стадии по ролям [Analyst](../../roles/analyst.md), [Developer](../../roles/developer.md),
[Tester](../../roles/tester.md), затем финальную сверку Architect. Если делегирование поддерживается,
передавай путь рабочей директории и дожидайся результата; иначе последовательно выполни роли сам
с отдельными отчётами. Файлы ролей не регистрируют подагентов автоматически.

Сохраняй протокол GitHub, гейты на бизнес-вопросах и защиту от дублей. Каждый прогон без изменений,
включая продолжение, оставляет новый `🤖 pipeline-reply <N>`. Движок различает ответы по id комментария.
Push и PR разрешены в рамках явно запущенного конвейера; сообщения в Telegram отправляет движок.
`pipeline:ready` ставь после финального ревью и зелёных проверок последнего коммита: дальше действует автомерж.
Не обещай успешный деплой до его завершения. В итоговом отчёте укажи issue/PR, проверки и ограничения.
