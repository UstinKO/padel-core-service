Прочитай `AGENTS.md`, `specs/MASTER.md`, [роль Analyst](../../roles/analyst.md) и релевантные разделы `docs/`.
Проверь существующие issue, спеки и код на дубли и готовые реализации.
Для клиентского запроса используй `specs/requests/_template.md`; для технической постановки из issue
промежуточный запрос не нужен. Заполни `specs/features/LFPT-XXXX-<slug>.md` по шаблону:
проверяемые критерии приёмки, зависимости, edge cases и документы для обновления.
LFPT берётся только из настоящего issue. При недоступном GitHub не выдумывай номер.

Неразрешённые бизнес-вопросы означают `draft`. После согласования — `approved`.
Не меняй приложение и не публикуй изменения в рамках этого навыка. Правило Analyst о коммите
применяется только при явно порученном коммите или внутри `$develop-feature`.
Для полного цикла по отдельному поручению используй `$develop-feature` с подготовленной спекой.
