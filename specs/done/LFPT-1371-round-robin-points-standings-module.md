# LFPT-1371: Feature многомодульный монолит — выделить расчёт мест кругового турнира POINTS

## Статус
done

## Источник

[Issue #1371](https://github.com/UstinKO/padel-core-service/issues/1371), родитель #1041, предшественник #1350 / PR #1352. Техническая постановка напрямую из поручения продолжить переход после мержа.

## Контекст / зачем

После SETS оставшаяся ветка RoundRobinStandings вычисляет места POINTS через JPA-компаратор RoundRobinRules. Чистый расчёт получает нейтральные входы в engines. Оба прежних Java API используют одного владельца формулы; адаптер сохраняет исходные сущности.

## Связь с MASTER.md

Сохраняются правила кругового парного турнира: POINTS использует сумму игровых очков, дополнительные встречи не меняют круговую статистику. Действующий порядок из кода: totalScore DESC, matchesWon DESC, pointDifference DESC, matchesLost ASC, teamNumber ASC, id ASC. Места POINTS последовательные, даже при полном равенстве. Бизнес-инварианты и #1243/#1244 не меняются.

## Требования

### Функциональные

- До замены выполнить characterization обоих legacy API; ожидания после выделения не менять.
- RoundRobinPointsStandingsEngine зависит только от JDK: record Team с индексом исходной строки, ID, номером, totalScore, победами, набранными/пропущенными очками и поражениями; record Ranked с индексом и местом. Сортировка и rank используют единый компаратор.
- Разница очков вычисляется при достижении соответствующего критерия. Boxed-поля не нормализуются: одиночная строка может содержать null; более поздние критерии не читаются при различии ранних. Пустой список, одинаковые ID/номера и стабильность равных строк сохраняются.
- MapStruct в bootstrap переводит entity в record, результат — в прежний Ranked с исходным объектом по индексу. Контекст списка не сохраняется. Default-маппер с фабрикой — адресный мост для сохранения статических API, без нового bean.
- RoundRobinStandings.rank POINTS и RoundRobinRules.order POINTS делегируют engine. order(null) сохраняет POINTS, rank(null mode) сохраняет SETS; сервисный fallback отсутствующего scoringMode прежний. POINTS не читает matches.
- SETS engine/mapper и фильтрация, остальные методы RoundRobinRules, TeamAmericanoService, currentPosition/saveAll, транзакции, история, права, HTTP/JSON/WS/UI и JPA сохраняются.
- Artifact guard требует девять вычислительных классов и 21 вложенный тип; ограничения зависимостей и ArchUnit не ослабляются.

### Нефункциональные

Java release 17, типизированные данные, автономные engine unit-тесты. Полный clean verify с frontend на отдельной PostgreSQL; итоговый jar в собственном preview. Проверка прежнего jar/возврата на той же синтетической БД. Новых строк интерфейса и переводов нет.

## Вне скоупа

Начисление/валидация счёта, finalOrder и дополнительные встречи, изменение правил/контрактов, перенос application-сценариев, persistence/web/integrations, физическая БД и Swarm. #1051 остаётся поздним этапом.

## Изменения в системе

### API

Прежние rank/Ranked/order сохраняются. Новый внутренний engine API содержит только нейтральные данные и компаратор.

### БД

Без миграций/схемы и пользовательских данных; используются отдельные синтетические fixtures.

### UI

Production UI не меняется. Прежний браузерный сценарий SETS/POINTS проверяет ввод/исправление счёта, дополнительные встречи, завершение, историю и страницы организатора/зрителя.

### Документация

.agents/PROJECT.md, docs/architecture.md, навигация/план модульного монолита, отдельные решения и безопасная сводка проверок.

## Edge cases

Все критерии равны, повторяющиеся ID/номера, отрицательная разница, крайние Integer, nullable-поля поздних критериев, одиночная null-строка. Дубликаты не сворачиваются в Map по ID. Входные объекты/списки не меняются. Многорепличная конкурентность не затрагивается чистой функцией; взаимодействие JPA остаётся в прежней транзакции.
