- Подготовить схему application→engines и точный allowlist типов для ArchUnit/artifact guard; существующий запрет всего legacy package не заменять разрешением пакета целиком.

## Критерии приёмки

- [x] Карта всех callers/входов/DTO и транзакций проверена по актуальному master; указаны текущие запросы, границы и временные мосты.
- [x] Новые characterization-проверки проходят на исходном коде, эталоны/хеши/команды и синтетические данные воспроизводимы; прежние проверки переиспользованы.
- [x] Семантики инициализации/завершения/GET/rollback описаны и проверены; никакого изменения поведения для будущей реализации не замаскировано в baseline.
- [x] Спецификация application-среза уточнена конкретными моделями/портом/маппингом и точками wiring; бизнес-неопределённости отсутствуют либо вынесены владельцу.
- [x] Полная сборка и общий runtime smoke/возврат проходят; безопасный отчёт отличает backend/автоматическую приёмку от ручной.

## Edge cases

Пустой/неинициализированный/несуществующий турнир, null scoringMode и fallback config, гостевой партнёр/уровень/сторона, частичный круг, равенства/общие места, pending и дополнительные встречи без места, исправление/restore. Чтение из write-транзакции видит её изменения; не вводятся новый isolation/lock/REQUIRES_NEW и новый commit. Отсутствие повторной ручной/физической приёмки отмечается явно. Некорректные legacy-входы не превращаются в новые бизнес-правила.
