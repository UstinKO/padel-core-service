# Экран ручного объединения профилей

Статус: approved. Задача #1384, зависимость сервер #1383 / PR #1386.

Предварительная проверка показывает тип/активность обоих профилей, направление, различия, сохраняемый основной аккаунт и переносимые группы данных. Готовность отображается отдельно от статуса пользовательской заявки. В ручном сценарии «Ожидает проверки» заменяется конкретным следующим шагом.

Кнопка видна и при запрете, но отключена с причиной рядом. Для контактов доступны KEEP_ACCOUNT и корректный USE_GUEST_PHONE; некорректный, отсутствующий либо неоднозначный телефон не переносится. Для отсутствующего/некорректного телефона недоступна проверка WHATSAPP; пользователь явно выбирает IN_PERSON/OTHER и подтверждает принадлежность профилей одному человеку. Разные стороны требуют выбора. Уровень основного аккаунта и вход сохраняются.

Отправка требует заполненных решений. Двойное нажатие не отправляет второй POST. После неизвестного результата допускается только чтение актуального состояния; подтверждённый MERGED показывается как успех без повтора. Пересекающаяся история объясняется номером события. Все новые тексты RU/ES/EN.

Браузерный тест с настоящим Spring-сервером, одноразовыми аккаунтами и отдельной PostgreSQL проверяет шесть успешных сочетаний RU/ES/EN × 1440/390, конфликт события на трёх языках, контакт и сторону, видимость кнопки, отсутствие переполнения, повтор submit и потерю ответа. Проверяется сохранение C7, Telegram, доступа и перенесённой регистрации; выполнен вход в основной аккаунт после переноса. Отправка писем/уведомлений и внешние запросы отключены. Тест включён в существующий browser job GitHub; результаты и снимки сохраняются в target/guest-merge-browser-qa.

Рабочие профили автоматически не объединяются. Выпуск требует отдельного поручения.
