# Совместимость среза рейтинга после C3

Продолжение разрешённого выпуска #1290 → #1291. Первый серверный автодеплой отклонил readiness и восстановил предыдущий полный выпуск. Отдельный регрессионный тест воспроизводит отказ конструктора PilotEloRefresh на неизменённом срезе C5 со старым списком прогресса.

Проверка сохранённого среза должна принимать точное воспроизведение одной из двух известных шкал: прежняя C5–C10 и новая C3–C10. Все поля, очки, матчи, прогресс, aliases, дата и веса формата по-прежнему сравниваются строго. Исходные файлы не перезаписываются; непохожий на допустимую версию срез отклоняется до чтения БД. После проверки текущий рейтинг рассчитывается новой шкалой с C3/C4.

Проверки: замороженные прежние C5 и C4; новые C3/C4; испорченные параметры среза; полный Maven verify, GitHub и штатный автодеплой. Только после успешного серверного выпуска продолжается интерфейс #1291.

Результат локальной проверки: ошибка на прежнем срезе C5 воспроизведена до исправления. После исправления прошли 38 профильных проверок, в том числе полноценный Spring Boot запуск и readiness с включённым пилотом и замороженным старым C5-срезом. Maven verify: 1245 тестов, 0 ошибок, 2 штатных пропуска. docs-drift, agent-migration, 48 тестов relay и git diff --check успешны. История и срез в тестах не изменяются; C3/C4 новой шкалы и отказ при неверном формате проверены отдельно.

GitHub выявил независимую коллизию тестовой фикстуры remember-me: постоянный ID 61 мог принадлежать строке другого интеграционного теста. Проверка переведена на собственную сохранённую запись с автоматически выданным ID и уникальным email, с откатом транзакции. Контракт сессии и рабочая логика входа не меняются.
