# LFPT-1358: классификация посещений для аналитики

Статус: implementation. Источник: #1358; продолжение разделения окружений #521.

## Цель

Отделять внешнюю аудиторию 1-Padel от служебной работы и проверок без удаления истории GA4 и без IP-фильтра общей сети клуба. Существующие права, мероприятия и регистрации не меняются.

## Контракт

После работы MVC-контроллера, до рендера HTML, analyticsTraffic содержит только group и reason. Приоритет: non-prod/preview/test path → test/test_environment; существующий флаг testTournament → test/test_event; административный маршрут → internal/admin_page; авторизованный OwnerRole (SUPER_ADMIN, ADMIN, ORGANIZER, CLUB_ADMIN) → internal/staff_account; иначе visitor/public. ROLE_PLAYER и анонимный посетитель остаются visitor. Классификация не предоставляет доступ.

Тестовый статус берётся из уже загруженных TournamentDto/Tournament. Имя, видимость и заполненность события не доказывают тестовый характер. King of Court передаёт флаг родительского Tournament; kingId не считается tournamentId. Дополнительных SQL-запросов нет. REST, redirect и forward не модифицируются.

Non-prod по-прежнему не получает production Measurement ID автоматически. Если ID задан явно, посещение всё равно test. Не передаются ФИО, email, телефоны, IP, ID аккаунта.

## Зависимость и приёмка

Подключение к gtag, ручной режим тестового браузера и настройка GA4 — #1359, отдельный frontend PR. До его выпуска backend совместим с текущими шаблонами. Проверки: роли, анонимный/обычный игрок, DTO/entity тестового события, оба URL King с различными ID, non-prod, REST и перенаправления. Исторические 794 пользователя не переклассифицируются.
