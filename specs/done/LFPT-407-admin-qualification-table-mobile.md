## Контекст / зачем
Админ-страница `admin/americano/tournament-playoff.html` (`/tournaments/team-playoff/admin/{id}`, раздел "Квалификация") рендерит таблицу рейтинга квалификации с 12 колонками (`#`, Статус, Пара, M1, M2, Sets G, Sets P, Games G, Games P, Dif.Sets, Dif.Games, PJ) без какой-либо мобильной адаптации — только `overflow-x:auto`-обёртка и фиксированный десктопный `font-size`/`padding`. На телефоне (591px, скриншот с реального турнира) видно только первые 3-4 колонки, администратору приходится постоянно скроллить таблицу горизонтально во время турнира, чтобы увидеть счёт (M1/M2).

Аналогичная проблема для **публичных** страниц турниров (в т.ч. `tournaments/team-playoff/view.html` — та же по структуре таблица, тот же класс `.table`) уже была решена в issue #364 (закрыт 2026-09-13, PR смержен): добавлены `@media (max-width: 768px)` и `@media (max-width: 480px)`, уменьшающие `font-size`/`padding` ячеек `.table th`/`.table td`. Issue #364 явно ограничивал скоуп только публичными страницами — админские таблицы (в т.ч. эта) остались без адаптации, что и создало текущий разрыв в UX между публичной и админской версией одной и той же таблицы.

## Связь с MASTER.md
Чисто техническая правка вёрстки/CSS существующей страницы, бизнес-инварианты и роли не затрагивает. `specs/MASTER.md` не меняется.

## Анализ (что реально происходит)

- `admin/americano/tournament-playoff.html:26-29` — блок `.table{...}`, `.table th{...}`, `.table td{...}` в `<style>` страницы: `font-size:.875rem` (таблица), `.8rem` (th), `padding:.65rem 1rem` — без единого `@media`-переопределения. Это ровно тот же набор правил, что был в `tournaments/team-playoff/view.html` **до** фикса #364 (см. диф того PR) — с тех пор публичная страница получила `@media`-блок (`view.html:24-33`), админская — нет.
- Таблица квалификации — `admin/americano/tournament-playoff.html:364-410` (`<table class="table">` внутри `<div style="overflow-x:auto;...">`, строка 364). Колонка "Пара" (строки 389-393) рендерит **одну** строку `team.displayName` (уже отформатированную сервисом как `"Игрок1 / Игрок2"`), в отличие от публичной версии, где имена — два отдельных `<span>` (`team.player1Name`/`team.player2Name`). Для переноса имён внутри ячейки на узком экране важно не запрещать перенос строки в этой колонке (сейчас нет `white-space:nowrap` конкретно на `td`, только на `th` — сама ячейка уже технически может переноситься, но колонка не имеет ограничения по ширине, поэтому длинное имя просто раздвигает таблицу, а не переносится).
- Прецедент точечной мобильной адаптации именно админской таблицы уже есть в проекте — `admin.css:435-459` (`#playersTableView`, LFPT-218): id-scoped `overflow-x:auto` + уменьшенные `padding`/`font-size` только для одной конкретной таблицы, не глобально для класса `.admin-table`. Тот же принцип (не трогать остальные админские таблицы, скоуп — только эта) применим здесь: страница `tournament-playoff.html` определяет свой собственный `<style>` с классом `.table` (не `.admin-table` из `admin.css`), поэтому изменение локально для этого файла и не задевает другие страницы с классом `.table` (`tournament.html`, `tournament-double.html` — см. "Вне скоупа").

## Требования

### Функциональные
1. На экране шириной ≤768px и ≤480px (реальные брейкпоинты мобильных устройств) таблица квалификации на `admin/americano/tournament-playoff.html` уменьшает `font-size` и `padding` ячеек `.table th`/`.table td` — по образцу уже принятых в проекте значений для той же таблицы на публичной странице (`tournaments/team-playoff/view.html:24-33`):
   - `≤768px`: `.table{font-size:.78rem}`, `.table th{padding:.5rem .6rem;font-size:.7rem}`, `.table td{padding:.5rem .6rem}`.
   - `≤480px`: `.table{font-size:.7rem}`, `.table th{padding:.4rem .45rem;font-size:.62rem}`, `.table td{padding:.4rem .45rem}`.
2. Колонка "Пара" получает ограничение по ширине (`max-width`) на этих же брейкпоинтах и `white-space:normal`/`word-break` там, где нужно, чтобы длинное значение `team.displayName` ("Игрок 1 / Игрок 2") переносилось на несколько строк внутри ячейки, а не раздвигало таблицу.
3. Приоритетные 5 колонок (`#`, Статус, Пара, M1, M2) должны помещаться на экране 375px (iPhone SE/стандартный узкий вьюпорт) без горизонтальной прокрутки — остальные 7 колонок (Sets G/P, Games G/P, Dif.S/G, PJ) могут уходить в горизонтальный скролл того же `overflow-x:auto`-контейнера, который уже есть (строка 364).
4. Обёртка `overflow-x:auto` (уже существующая, строка 364) не убирается — остаётся как страховка для полного набора колонок на очень узких экранах.
5. Структура таблицы (набор, порядок, названия колонок), сама разметка `th:each`/`th:text`/бизнес-данные — не меняются, правится только CSS/вёрстка.

### Нефункциональные
- i18n: не применимо — новых пользовательских строк не добавляется, только CSS.
- Безопасность: не применимо — правка не затрагивает пользовательский ввод.
- Производительность: не применимо — чистый CSS, не влияет на серверную нагрузку.

## Вне скоупа
- **`tournaments/team-playoff/view.html`** (публичная версия) — уже адаптирована в #364, не трогается.
- **`admin/americano/tournament.html`** (Americano, таблица рейтинга) и **`admin/americano/tournament-double.html`** (Team Americano, таблица рейтинга) — та же самая проблема (широкая таблица `.table`/`ranking-table` без мобильной адаптации в админке), подтверждено при анализе (`grep` находит `class="table"`/`overflow-x:auto` в обоих файлах), но не входит в скоуп issue #407 (который называет конкретно Team Playoff, по скриншоту с реального турнира). Заведён отдельный issue #408 как побочная находка — см. итоговый отчёт.
- **Доска кортов, форма нового матча, вкладки раундов** (`admin/americano/tournament-playoff.html`, ниже квалификационной таблицы) — не таблицы, не относятся к этой доработке.
- Изменение состава/порядка колонок таблицы — явное ограничение из клиентского запроса ("не менять структуру таблицы").

### UI
- `src/main/resources/templates/admin/americano/tournament-playoff.html` — в блоке `<style>` (строки 26-29) добавляются `@media (max-width: 768px)` и `@media (max-width: 480px)` для `.table`/`.table th`/`.table td`, плюс ограничение ширины и перенос текста для колонки "Пара" в таблице квалификации (строки 364-410). Другие таблицы этой же страницы (команды — строки 231-315; доска кортов — не таблица) этим селектором не затрагиваются, если только явно не используют тот же класс `.table` для той же колонки "Пара" — в этом случае им ok получить тот же файл-scoped media-фикс как побочный эффект (тот же файл, тот же класс, тот же визуальный контекст админ-страницы).

## Критерии приёмки
- [ ] На вьюпорте 375px (iPhone SE) страница `/tournaments/team-playoff/admin/{id}` с начатой квалификацией: колонки `#`, Статус, Пара, M1, M2 видны на экране без горизонтальной прокрутки контейнера.
- [ ] На вьюпорте 375px оставшиеся колонки (Sets G/P, Games G/P, Dif.S/G, PJ) доступны через горизонтальный скролл того же `overflow-x:auto`-блока (не исчезли, не наложились друг на друга).
- [ ] Длинное значение колонки "Пара" (`team.displayName`, например "Danila Gorbanev / Nikita Gorbanev") переносится на несколько строк внутри ячейки на узком экране, не раздвигая таблицу за пределы вьюпорта.
- [ ] На десктопном вьюпорте (>1024px) внешний вид таблицы не изменился (те же значения `font-size`/`padding`, что и до правки).
- [ ] Публичная страница `tournaments/team-playoff/view.html` не изменилась (визуально и по содержимому файла, кроме случаев совпадения с уже задействованными общими статическими ресурсами — в данном случае правка целиком в собственном `<style>` `tournament-playoff.html`, общих файлов нет).
- [ ] `./mvnw compile -DskipTests` проходит (чистая вёрстка, но проверяем, что Thymeleaf-шаблон не сломан синтаксически).
- [ ] Побочная находка (аналогичная проблема в `admin/americano/tournament.html` и `admin/americano/tournament-double.html`) зафиксирована отдельным GitHub issue.

## Edge cases
- Пустой рейтинг (`ranking == null` или `#lists.empty()`) — таблица рендерит только `<thead>` без строк, адаптация CSS применяется одинаково (шапка таблицы — та часть, что должна помещаться в первую очередь).
- Очень длинное имя одного из игроков (превышающее ширину колонки даже после `word-break`) — допустимо перенести на много строк, лишь бы не расширяло саму колонку/таблицу за пределы контейнера.
- Планшетный вьюпорт (768-1024px, между брейкпоинтами) — не в критериях приёмки явно, но не должен визуально ломаться (переход между `@media`-блоками — стандартный CSS-каскад, как на уже принятой публичной странице).
