# LFPT-0903: Feature backend API UI v2 — публичные состояния King of Court, Americano и Team Playoff

## Статус
done

## Источник
Напрямую из [issue #903](https://github.com/UstinKO/padel-core-service/issues/903). Основа #826/#827 уже влита, зависимый фронтенд — #911. Исходная версия master: `83617f4`.

## Контекст / зачем
React live-экранам нужны публичные данные первого отображения и надёжное обновление после событий, перезагрузки и восстановления связи. Сейчас часть данных собирается в Thymeleaf-контроллерах; старые DTO могут включать контакты и административные поля. Новый контракт только читает текущее проведение и сохраняет действующие расчёты и порядок.

## Связь с MASTER.md
- Сервер остаётся источником счёта, бонусов за корт, ручных корректировок, рейтинга, расписания, квалификации и плей-офф.
- King of Court, индивидуальный Americano, круговой Team Americano и Team Playoff не подменяют друг друга.
- История публичных матчей не является административной историей восстановлений проведения; внутренние снимки, акторы и комментарии аудита не публикуются.
- Контакты участников не раскрываются; `mostrarNivel` управляет публичным уровнем. Участие, резерв, подтверждение, отмена, оплата и guest claim не меняются.
- MASTER не требует изменения бизнес-инвариантов.

## Проверка существующего кода
- `PublicEventService` допускает только существующий активный не-BORRADOR турнир. `PublicEventStateService` уже различает формат/фазу, включая TEAM_AMERICANO, TEAM_PAIRS и TEAM_PLAYOFF; новый resolver обязан согласоваться с карточкой события.
- `kingId` отличается от `tournamentId`. `KingOfCourtService.getCurrentState/getRanking/getPlayerMatchHistory` уже читают состояние и результаты; ручные очки входят в существующий серверный расчёт.
- `AmericanoViewController` собирает first render через `isInitialized`, `getRankingWithDetails` и `getRounds`.
- `TeamPlayoffViewController` содержит сборку раундов, порядковых номеров квалификационных матчей и разделение волн; её следует вынести в общий read-service, которым продолжат пользоваться старые страницы.
- `AmericanoTeamDto` содержит email/телефоны. Его нельзя публиковать напрямую или прятать контакты только CSS/клиентским mapper.
- Реальные старые топики: `/topic/tournament/{kingId}` и `/topic/team-playoff/{tournamentId}`. В MASTER/PROJECT есть устаревшее имя KoC-топика; контракт и ADR-0010 уже отмечают расхождение.
- `WebSocketService` отправляет разные payload после commit, иногда полные DTO. У Americano нет собственного WS. ADR-0010 предусматривает один STOMP-клиент, invalidate/refetch и polling Americano; для публичного безопасного уведомления понадобится уточнить предложенный ADR.

## Требования

### Функциональные
- `GET /api/public/events/{eventId}/live` возвращает типизированный snapshot с явным discriminator формата и отдельными record DTO King of Court, индивидуального Americano и Team Playoff. OpenAPI использует oneOf; произвольные Map и JPA entities не являются контрактом.
- Общая часть: eventId, фактический format/phase/status, имя мероприятия, canonicalLiveUrl, актуальный instance id (kingId для KoC), идентификатор/версия текущего проведения из существующего источника, generatedAt и параметры безопасного обновления.
- Snapshot содержит публичные rounds/courts/matches, расписание, серверный ranking и историю сыгранных матчей. История конкретного игрока может быть выделена в документированный read endpoint, если это нужно для размера ответа; нельзя делать запрос на каждого игрока/матч.
- KoC отдельно отдаёт очки матчей, бонусы за корт, итог ручных корректировок и итоговый рейтинг; внутренние причины/авторы корректировок не раскрываются.
- Americano использует существующий порядок, счёт и раскладку раундов. Team Playoff возвращает квалификацию, волны, номера матчей для команд, стадии, связи сетки, серверные результаты и текущую очередь кортов в публичном объёме.
- До инициализации — 200 NOT_STARTED с пустыми коллекциями, без создания проведения/раундов. Неоднозначный TEAM_PAIRS не объявлять готовым Team Playoff до фактической инициализации. Завершение и отмена отражаются по данным сервера, не по наличию кнопки/дате.
- Resolver по родительскому eventId возвращает действительный kingId и тот же формат, что карточка события. Для старого входа по kingId предусмотреть безопасный read alias `/api/public/king-of-court/{kingId}/live`: проверить родительский турнир и принадлежность актуальному проведению, не подменять инстанс молча. Устаревший инстанс имеет явный 409 и безопасную ссылку продолжения; существующий legacy URL не меняется.
- Круговой Team Americano и нетурнирные live-форматы не притворяются Team Playoff: 409 LIVE_FORMAT_UNSUPPORTED с допустимой legacy-ссылкой, сохранение прежнего просмотра. Сам круговой формат не переносится этой задачей.
- Новые snapshot/alias допускают только GET/HEAD, имеют no-store и не возвращают персональные session-поля. Владельцы и CLUB_ADMIN получают тот же публичный read contract; административные действия остаются на прежних защищённых endpoint.

### Ошибки, видимость и realtime
- Единая проверка публичной видимости: отсутствующий/неактивный/BORRADOR event — 404; SOLO_POR_ENLACE доступен по прямой ссылке, без добавления в публичные списки.
- Типизированные ProblemDetail ES/RU/EN: 404 LIVE_EVENT_NOT_FOUND, 409 LIVE_FORMAT_UNSUPPORTED/LIVE_INSTANCE_CHANGED, 422 LIVE_INVALID_ID/LIVE_INVALID_FILTER; недоступная БД — 503 LIVE_DATA_UNAVAILABLE. Ошибка не раскрывает скрытый турнир, SQL или исключение.
- Новые публичные уведомления `/topic/public/live/{eventId}` содержат только eventId/тип изменения и допустимую версию, без результатов, контактов, actor/comment или старого DTO. Старые топики и payload сохраняются для действующих клиентов.
- Публиковать уведомление после успешного commit; rollback не создаёт событие. Проверить score/round/finish, ручные очки и восстановление проведения. Если старый путь изменения не публикует событие, bounded polling гарантирует перечитывание, это явно документируется.
- SUBSCRIBE на новый публичный топик проходит ту же проверку видимости, SEND от клиента не выполняет доменные действия. Не расширять доступ к существующим admin endpoint и не менять мобильный контракт.
- Americano обновляется GET polling, без внедрения нового WS для него. stale/reconnecting — состояние транспорта клиента, не новая доменная фаза турнира.

### Нефункциональные
- Java release 17, record DTO, MapStruct, read-only сервисы; расчёты остаются в существующих доменных сервисах.
- Проверить и устранить N+1 в затронутом snapshot read path, включая вложенные команды и квалификационный ranking. Запросы пакетные; объём обращений к БД не растёт на каждый матч/игрока. Большие ответы не отрезать молча, при необходимости документировать пагинацию истории.
- Согласовать частоту refetch/polling с rate limit; не отключать защиту и не ослаблять login/register-квоты ради live.

## Вне скоупа
Изменение алгоритмов, посева, сетки и победителя; live-пульты/мутации; новый WS для Americano; кабинет/booking/резерв/guest claim; раскрытие архивов conduct audit; публичное включение React; отдельный контур #904 и deploy/rollback #905.

## Изменения в системе
### API
Новый public snapshot, resolver/alias по kingId, при необходимости ограниченный endpoint истории; отдельный public invalidation topic и его проверка подписки. Старые API/STOMP-потребители сохраняются.
### БД
Новые бизнес-поля и миграция не планируются. Read-model использует существующие таблицы/версии проведения; текущие миграции не редактируются.
### UI
В этой задаче не меняется. Общий read-service переиспользуется старым view-controller без изменения его публичного поведения.
### Документация
Обновить `docs/endpoints/king-of-court.md`, `americano.md`, описание Team Playoff, новый public-live endpoint doc/OpenAPI, `docs/frontend-react/contract/{api,cross-cutting,screens}.md`, ADR-0010 и `.agents/PROJECT.md`. Уточнить фактический KoC-топик в MASTER/PROJECT как исправление технической ссылки, не изменение бизнес-правила.

## Критерии приёмки
- [ ] Анонимный клиент получает полные безопасные snapshot всех трёх форматов в not-started/live/qualification/playoff/finished/cancelled состояниях.
- [ ] Рейтинг, счёт, бонусы, ручные очки, порядок и сетка совпадают с доменными сервисами; DTO/controller не пересчитывают итоги.
- [ ] Guest/Player/Owner/CLUB_ADMIN не получают контакты игроков, внутренние заметки и admin actions в REST и новом WS.
- [ ] ID, несовпадение формата/инстанса и скрытые события имеют документированные 404/409/422 без HTML, неизвестный источник данных — безопасный 503.
- [ ] Чтение не пишет в БД, не инициализирует турнир и не отправляет уведомления; источник актуального проведения совпадает с карточкой.
- [ ] Новые события после commit не содержат legacy payload; reconnect допускает повторное чтение без применения клиентских дельт.
- [ ] Contract/authorization/integration и проверки числа SQL-запросов покрывают три формата, длинные турниры и старые API; полный verify на отдельной PostgreSQL проходит.
- [ ] Один итоговый коммит и отдельный PR #903; frontend #911 имеет явную зависимость.

## Edge cases
Несуществующий/нулевой/переполненный ID, скрытый или отменённый event, нет instance/раундов, завершённый последний KoC без активного instance, устаревший kingId, повторная инициализация/restore, неполный счёт и несостоявшийся матч, bye/play-in, ручное продвижение, длинная сетка/19 раундов, отсутствие контактов/уровня, rollback транзакции, шторм событий, БД недоступна.

## Открытые вопросы
Изменений бизнес-инвариантов не требуется. Технический план подтверждён пользователем 2026-11-11, включая безопасные public notifications наряду с legacy STOMP и polling Americano.
