# LFPT-1459: Короткая привязка Telegram с сайта

Владелец согласовал основной путь приглашения: общая ссылка сайта `/telegram/join` → вход при необходимости → одна явная кнопка подключения → персональный Start в боте → готово. Используется действующий `PlayerTelegramLinks`: серверная сессия удостоверяет профиль, приватный update Start удостоверяет Telegram. Дополнительный callback подтверждения профиля не нужен. Старый путь `/telegram/connect` с общим Start остаётся совместимым.

GET не создаёт токенов и не меняет предпочтения. Гость возвращается на тот же маршрут после обычного или Google-входа; destination не содержит персональных данных. Авторизованный активный обычный игрок видит своё имя. Явный POST требует PLAYER и CSRF, создаёт прежний одноразовый секрет на 10 минут и отвечает 303 непосредственно на t.me. Секрет не рендерится в общей странице или адресе входа. Для уже подключённого профиля новый секрет не выдаётся и дата связи не меняется. При недоступности/ошибке — возврат на страницу без автоматического повтора. Предпочтение WhatsApp меняется только явным подключением, как в текущем кабинете.

Общий доступ использует существующий флаг onboarding и прежние проверки пилота/активности. Автоматика, ежедневная сводка, ручные кампании и независимый пилот чеков не меняются. GET `/api/admin/telegram/site-invitation` возвращает каноническую общую ссылку из app.base-url; старый endpoint приглашения сохраняет прежний формат. До выпуска зависимого шаблона `/telegram/join` показывает существующую локализованную страницу недоступности. Общую ссылку публиковать после последовательного выпуска сервера и интерфейса #1460.

Приёмка: чистые destination и сохранение обычного/Google-входа, отсутствие мутаций на GET, CSRF/роль, переход 303, один Start завершает связь, чужой/истёкший/повторный токен не подменяет профиль, существующая связь сохраняется. Полный verify и отдельная БД. Реальный браузер и тексты ES/RU/EN — во frontend #1460. Cloudflare и черновик #1456 не затрагиваются; мерж/production отдельно.
