# LFPT-0653: Карточки мероприятий в личном кабинете игрока — главным заголовком формат

## Статус
done

## Источник
Клиентский запрос: [specs/requests/LFPT-0653-dashboard-card-format-heading.md](requests/LFPT-0653-dashboard-card-format-heading.md). Issue: [#653](https://github.com/UstinKO/padel-core-service/issues/653).

## Контекст / зачем
На главной странице (`/`, `HomeController`) карточки мероприятий уже переработаны в LFPT-0435/LFPT-0495: главный заголовок карточки — формат мероприятия (`TournamentType`), под ним — модальность участия, а пол/категория — только в верхней цветной части. В личном кабинете игрока (`/players/dashboard`, `PlayerDashboardController`) карточки формируются отдельной функцией в `static/js/dashboard.js` (`createTournamentCardElement`) и сохранили старую структуру: заголовком выступает `tournament.nombre` — автогенерированное название турнира (LFPT-374, "Стандартизация карточки турнира"), которое в большинстве случаев текстуально совпадает с «Пол · Категория» (например «Masculino · C7_C6»), т.е. дублирует верхнюю цветную часть, а формат мероприятия (`tournament.tipo`) показан ниже, одной строкой среди прочей информации.

Задача — привести иерархию карточки в личном кабинете к уже реализованной на главной: формат — главным заголовком, без повторения пола/категории, короткая строка модальности участия под заголовком.

## Связь с MASTER.md
Не затрагивает бизнес-инварианты `specs/MASTER.md` (статусы регистрации, флоу парной регистрации, ограничение по уровню и т.д.) — чисто отображение уже существующих полей `TournamentDto` (`tipo`, `modalidad`, `generoFormato`, `categoriaNivel`), без изменения бизнес-логики регистрации/отмены.

## Требования

### Функциональные
- В `createTournamentCardElement` (`static/js/dashboard.js`) заменить заголовок карточки (`<h3 class="torneo-title">`) с `tournament.nombre` на отображаемое название формата (`tipoDisplay`, через существующий `displayMaps.tipo`) — по аналогии с `createTournamentCard` в `static/js/home.js`.
- Добавить под заголовком строку модальности участия — переиспользовать существующие i18n-ключи `card.modalidad.individual` / `card.modalidad.doubles` (уже используются в `home.js`, присутствуют в `messages-{es,ru,en}.js`), с тем же CSS-классом `tournament-modalidad`, что и на главной (стиль уже определён в `style.css`, подключённом и на странице дашборда).
- Верхняя цветная часть карточки (`torneo-badge` с полом, `torneo-badge torneo-badge-level` с категорией) — не менять.
- Бейдж «Записан» (`my-tournament-badge`), блок даты/времени, клуба/адреса, счётчика участников/мест, стоимости, кнопки отмены/регистрации и «Подробнее» (`torneo-footer`) — не менять по содержанию и логике, только порядок размещения относительно нового заголовка/строки модальности при необходимости аккуратной вёрстки.
- Поле `tournament.nombre` больше не выводится визуально на карточке (как и на главной странице — по тому же принципу LFPT-0435/0495), но остаётся доступным в данных карты (`data-tournament-name`, модальные окна регистрации/отмены используют его для текста диалогов — не трогать).
- Изменение затрагивает все три вкладки личного кабинета («Мои турниры», «Все», «История») и обе исторические/активные выборки, так как все они рендерятся через одну и ту же функцию `createTournamentCardElement` на одном и том же наборе полей `TournamentDto` (подтверждено: `PlayerDashboardController.dashboard()` отдаёт `upcomingTournaments` и `historicalTournaments` как `List<TournamentDto>` с одинаковым набором полей).

### Нефункциональные
- i18n: новых строк не требуется — используются существующие ключи `card.modalidad.individual`/`card.modalidad.doubles` (уже переведены на es/ru/en, тексты совпадают с примерами клиента).
- Производительность: не затрагивается (чисто клиентский рендеринг, без новых запросов).
- Безопасность: новых точек входа данных нет.

## Вне скоупа
- Полный редизайн карточек (скругления, градиент, цвета, кнопки, компоновка личного кабинета) — не трогаем.
- Вынесение общей функции рендеринга карточки в отдельный переиспользуемый модуль между `home.js` и `dashboard.js` — в этой задаче ограничиваемся переносом уже проверенного паттерна (переиспользование тех же i18n-ключей/CSS-класса), без архитектурного рефакторинга на общий JS-модуль: `home.js` работает на анонимной главной странице без кнопок регистрации/отмены, `dashboard.js` — на авторизованной странице с другой логикой кнопок и вкладок; полное объединение — отдельная техническая задача, если понадобится.
- Детальный статус регистрации (`CONFIRMED`/`WAITLIST` и т.п.) как отдельный бейдж — в карточке личного кабинета такого бейджа не было и до этой задачи (есть только общий бейдж «Записан» для любой активной регистрации); эта задача ничего не меняет в этой части, расширение статусной информации — вне скоупа.

## Критерии приёмки
- [x] На вкладке «Мои турниры» каждая карточка показывает форматом мероприятия главный заголовок (например, «Король корта», «Американо», «Cancha Abierta», «Тренировка + игра»), а не автогенерированное название турнира. Проверено Playwright: карточка King of Court — заголовок «Король Корта».
- [x] То же самое — на вкладках «Все» и «История». Проверено Playwright: вкладка «Все» — «Cancha Abierta»/«Americano equipos», вкладка «История» — «Padel Clinic».
- [x] Пол и категория показаны один раз — только в верхней цветной части карточки (`torneo-badge`/`torneo-badge-level`); в заголовке карточки они не повторяются. Подтверждено на скриншотах (мобиль/десктоп) и DOM-дампе карточек.
- [x] Под главным заголовком показана строка «Индивидуальное участие» для `modalidad == INDIVIDUAL` и «Парное участие» для `modalidad == DOBLES`. Подтверждено на тестовых турнирах обеих модальностей.
- [x] Бейдж «Записан», дата/время, название и адрес клуба, счётчик участников/мест, стоимость, кнопки отмены/регистрации и «Подробнее» отображаются и работают так же, как до изменения — markup и обработчики не менялись, только порядок/заголовок.
- [x] Переключение языка интерфейса (locale ru/es/en в браузере) показывает заголовок формата и строку участия на соответствующем языке без вставок на другом языке — проверено Playwright для ru-RU/es-AR/en-US.
- [x] Карточка не выглядит визуально разваленной на мобильной ширине (390px) и на десктопе (1280px) — скриншоты приложены к отчёту тестировщика, устранён лишний отступ от `min-height` под старое двустрочное название.

## Edge cases
- Турнир без указанной модальности (`modalidad == null`) — не ожидается в реальных данных (поле обязательно при создании турнира), но на случай некорректных старых данных: трактовать как `INDIVIDUAL` (тот же дефолт, что уже неявно используется на главной странице через тройной оператор `tournament.modalidad === 'DOBLES' ? ... : ...`).
- Турнир без `tipo` (не ожидается, обязательное поле) — `displayMaps.tipo[tournament.tipo] || tournament.tipo || 'N/A'`, как уже сделано и для `home.js`, и для текущего кода `dashboard.js` (переиспользуем существующий паттерн).
- Пустой список турниров на вкладке — существующее поведение `empty-state` не меняется.
