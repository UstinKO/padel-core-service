# LFPT-0435: Feature карточки турниров на главной — переработка по макету (статус мест вместо цены/лимита)

## Статус
done (PR #436, деплой подтверждён)

## Источник
`specs/requests/LFPT-0435-home-tournament-cards-redesign.md` (Telegram, отправитель — customer). Issue: https://github.com/UstinKO/padel-core-service/issues/435

Telegram-сообщение (для reply): 4659

## Контекст / зачем

Карточка турнира на главной (`/`) в текущем виде отдаёт приоритет собственному названию турнира, цене и числу мест — а тип формата (Americano/Rey de Cancha/Cancha Abierta) виден мелкой строкой в середине, и нет визуального индикатора "остались ли места". Заказчик прислал макет с новой структурой карточки, ставящей во главу угла тип турнира, модальность участия, дату/место и автоматический статус заполненности — чтобы при беглом просмотре сразу было понятно, что это за турнир, когда/где и есть ли смысл смотреть дальше.

## Связь с MASTER.md

Не затрагивает бизнес-инварианты MASTER.md (статусы регистрации, флоу парной регистрации и т.д.) — чисто витринное изменение состава полей карточки на главной. `inscritosActuales`/`cupoMax`, на которых считается статус заполненности, уже существуют и заполняются в `TournamentService.mapToDtoWithBatchedData(...)` (см. `TournamentDto.java`), новых полей/инвариантов не вводится.

## Требования

### Функциональные

1. **Верхняя часть карточки (шапка)** — без изменений: бейдж пола (`generoFormato`) + бейдж категории (`categoriaNivel`), градиентный фон.
2. **Заголовок карточки** — тип турнира (`tournament.tipo`, через существующий `displayMaps.tipo` в `home.js`, т.е. `t('enum.tipo.koc')` и т.д.) вместо `tournament.nombre`. Собственное название турнира с карточки главной убирается полностью (бейджи пола/категории уже дают эту информацию — дублирование вида "Masculino · C9" в тексте не нужно).
3. **Подзаголовок — модальность.** Под заголовком: "Participación individual" при `modalidad === 'INDIVIDUAL'`, "Participación en pareja" при `modalidad === 'DOBLES'`. Новые i18n-ключи (см. "Изменения в системе → UI"), не путать с уже существующими `enum.modalidad.individual`/`enum.modalidad.doubles` ("Individual"/"Dobles") — та пара для фильтров, эта — полная фраза для карточки.
4. **Дата и время** — без изменений (существующая логика форматирования `fecha`/`hora`, включая fallback на `card.date.unknown`/`card.time.unknown`).
5. **Клуб и адрес** — без изменений (`club-name` + `club-address`, включая fallback `card.club.unknown`; названия клубов/адреса не переводятся — выводятся как есть из данных).
6. **Статус наличия мест — новый элемент.** Считается на клиенте в `home.js` от заполненности:
   - `fillRatio = cupoMax > 0 ? inscritosActuales / cupoMax : 0`
   - `fillRatio >= 1` → статус `full` → 🟢/🟠/⚪ см. ниже — "Cupos completos"
   - `0.7 <= fillRatio < 1` → статус `limited` — "Últimos cupos"
   - `fillRatio < 0.7` (включая `cupoMax` отсутствует/0 — считаем как "есть места", а не как ошибку) → статус `available` — "Hay cupos"
   - Пороги (70%/100%) — точные значения из макета, в отличие от абсолютных порогов `getSpotsStatus()` в `torneos.js` (10 пар/15 игроков, LFPT-374) — это осознанно другая, более точная формула именно для этой карточки; `torneos.js` не трогаем (см. "Вне скоупа").
   - Отображается как бейдж с цветным индикатором (зелёный/оранжевый/серый — переиспользовать `--color-success`/`--color-warning`/`--color-dark-gray` уже определённые в `style.css`).
7. **Кнопки.**
   - "Más información" — как сейчас, ссылка на `/torneo/{id}`, `btn btn-outline btn-small`. Текст меняется с текущего "Ver detalles" на "Más información"/"Подробнее"/"More info" (новый ключ, см. UI).
   - Основная кнопка регистрации — сохраняется существующая логика ветвления `started` / `estado === 'REGISTRO_ABIERTO'` / иначе бейдж статуса турнира (см. "Вне скоупа" — эту логику не трогаем, только текст и доп. условие внутри ветки `REGISTRO_ABIERTO`):
     - Если турнир уже начался (`isTournamentStarted`) — как сейчас, без изменений ("Iniciado", locked).
     - Если `estado === 'REGISTRO_ABIERTO'` и **не** `started`:
       - статус мест `full` → кнопка "Inscribirse en reserva"/"Записаться в резерв" (новый ключ), визуально менее акцентная (см. UI/CSS), но кликабельная — ведёт туда же, на `/torneo/{id}` (логика записи в резерв уже существует на странице турнира, здесь только текст/цвет кнопки).
       - иначе → "Inscribirse"/"Записаться" (новый ключ) вместо текущего "Registrarse".
     - Иначе (турнир не в `REGISTRO_ABIERTO`, например `PUBLICADO`) — как сейчас, бейдж `tournament-status` с текстом статуса турнира. Не пересекается по месту с новым бейджем статуса мест — они не показываются одновременно с этой веткой кнопки (бейдж статуса мест — отдельный элемент над футером, показывается всегда, независимо от кнопки).
8. **Убрано с карточки:** строка цены (`precio`/`moneda`, иконка `fa-tag`) и строка количества мест как число (`cupoMax` + "cupos"/"jugadores", иконка `fa-users`) — обе секции `tournament-info-item` удаляются из `createTournamentCard`.

### Нефункциональные

- i18n: все новые строки — только в `static/js/i18n/messages-{es,ru,en}.js` (карточка рендерится в `home.js` через `t()`, не через Thymeleaf `#{...}` — `messages_{es,ru,en}.properties` не используются этим кодом и не трогаются).
- Не переводить: `clubNombre`, `clubDireccion` и любые другие данные конкретной сущности (уже так в текущем коде — `escapeHtml`, без прогона через `t()`).
- Производительность — не применимо (чистый клиентский рендеринг существующих данных, без новых запросов).

## Вне скоупа

- `/torneos` (`torneos.html` + `torneos.js`) — отдельная страница с независимым рендерингом карточек (`torneo-*` CSS-классы, свой `getSpotsStatus()` с другой формулой/порогами). Не меняется в этой задаче.
- Логика самой записи в резерв/лист ожидания на странице турнира (`/torneo/{id}`) — не меняется, кнопка "Inscribirse en reserva" ведёт на существующий флоу.
- Ветка кнопки для `estado !== 'REGISTRO_ABIERTO'` (бейдж статуса турнира) и ветка `started` (locked) — логика не меняется, только новый бейдж статуса мест добавляется как отдельный, независимый от них элемент.
- Backend/DTO — `inscritosActuales`/`cupoMax` уже есть и заполняются, новых полей не вводится.

## Изменения в системе

### API
Нет изменений — используются уже существующие поля `TournamentDto.inscritosActuales`/`cupoMax` в `tournamentsJson`.

### БД
Нет изменений.

### UI

- `src/main/resources/static/js/home.js` — метод `createTournamentCard(tournament)`:
  - заголовок карточки: `tipoDisplay` вместо `tournament.nombre`;
  - новая строка-подзаголовок модальности;
  - удалить `tournament-info-item` для цены и для количества мест;
  - удалить отдельную строку `tournament-info-item` с `fa-trophy`/`tipoDisplay` (тип теперь в заголовке, дублировать не нужно);
  - новый метод расчёта статуса мест (`fillRatio`/пороги 70%/100%, как в "Требования" п.6) и рендер бейджа;
  - в ветке `estado === 'REGISTRO_ABIERTO' && !started` — текст/класс кнопки в зависимости от статуса мест.
- `src/main/resources/static/css/style.css` — новые классы для подзаголовка модальности и бейджа статуса мест (варианты `available`/`limited`/`full`, цвета `--color-success`/`--color-warning`/`--color-dark-gray` + `--color-light-gray` фон по аналогии с уже существующими `.tournament-status.status-*`), новый модификатор кнопки для "Inscribirse en reserva" (менее акцентный вариант `.btn-primary`, например бледный фон + текст `--color-primary`, по аналогии с макетом). `templates/index.html` — изменений разметки не требует (вся карточка строится в JS).
- `src/main/resources/static/js/i18n/messages-{es,ru,en}.js` — новые ключи (раздел `── home.js (LFPT-0435 tournament card) ──`):
  - `card.modalidad.individual` = "Participación individual" / "Индивидуальное участие" / "Individual participation"
  - `card.modalidad.doubles` = "Participación en pareja" / "Парное участие" / "Doubles participation"
  - `card.spots.completos` = "Cupos completos" / "Мест нет" / "Fully booked" (отдельно от уже существующего `card.spots.full` = "Sin cupos"/"Мест нет"/"Sold out", используемого `torneos.js` — тексты ES/EN отличаются по формулировке от того, что попросил заказчик для этой карточки, трогать общий ключ нельзя, чтобы не изменить текст на `/torneos`)
  - `card.btn.more_info` = "Más información" / "Подробнее" / "More info"
  - `card.btn.register_now` = "Inscribirse" / "Записаться" / "Register" (отдельно от `dashboard.card.btn.register` = "Registrarse"/другой контекст — дашборд игрока, не трогаем)
  - `card.btn.register_waitlist` = "Inscribirse en reserva" / "Записаться в резерв" / "Register (waitlist)"
  - Переиспользуются без изменений: `enum.genero.*`, `enum.tipo.*`, `card.date.unknown`, `card.time.unknown`, `card.club.unknown`, `card.status.started`, `card.spots.available` (= "Hay cupos"/"Есть места"/… — текст уже совпадает с макетом), `card.spots.limited` (= "Últimos cupos"/"Последние места"/… — уже совпадает).

  Точное именование ключей (`card.modalidad.*`, `card.spots.completos`, `card.btn.*`) — на усмотрение Developer при реализации, лишь бы не переопределялись уже используемые где-то ещё ключи (проверить `grep` перед добавлением) и текст на всех трёх языках соответствовал списку выше.

## Критерии приёмки

- [ ] На `/` карточка турнира показывает (в этом порядке): пол+категория (шапка), тип турнира (заголовок), модальность, дату/время, клуб+адрес, статус мест, кнопки "Más información" + "Inscribirse"/"Inscribirse en reserva" — проверено на всех трёх языках сайта (es/ru/en, через `Accept-Language` или `?lang=`).
- [ ] Цена (`precio`/`moneda`) и число мест (`cupoMax` как число) с карточки убраны — визуально отсутствуют.
- [ ] Строка типа с иконкой `fa-trophy` (дублировавшая заголовок) убрана.
- [ ] Название турнира (`tournament.nombre`) на карточке не отображается.
- [ ] Статус мест: турнир с `inscritosActuales/cupoMax < 0.7` → "Hay cupos"/"Есть места" (зелёный); `0.7–0.99` → "Últimos cupos"/"Последние места" (оранжевый); `= 1` (или `>=`) → "Cupos completos"/"Мест нет" (серый) — проверено на турнирах во всех трёх состояниях.
- [ ] При статусе "мест нет" кнопка регистрации — "Inscribirse en reserva"/"Записаться в резерв" (не "Inscribirse"/"Записаться"), ведёт на `/torneo/{id}` как и обычная кнопка.
- [ ] Ветки `started` (турнир уже начался) и `estado !== 'REGISTRO_ABIERTO'` (например `PUBLICADO`) визуально не сломаны — прежнее поведение кнопки/бейджа сохранено, бейдж статуса мест показывается независимо и не конфликтует по месту.
- [ ] Визуальный стиль карточки (форма, скругления, градиентная шапка, цвета, общий стиль кнопок `btn-outline`/`btn-primary`) не изменился относительно текущего — новые элементы (подзаголовок модальности, бейдж мест) вписаны в существующий стиль, не ломают его.
- [ ] `/torneos` (`torneos.html`/`torneos.js`) не затронут — карточки там выглядят и ведут себя как до этой задачи.
- [ ] Фильтры и пагинация ("показать ещё") на `/` продолжают работать без регрессий после изменения `createTournamentCard`.
- [ ] `./mvnw verify` проходит.

## Edge cases

- `cupoMax` отсутствует/равен `0`/`null` — не должно приводить к делению на ноль или к статусу "мест нет"; трактуется как "Hay cupos" (см. "Требования" п.6).
- `inscritosActuales` больше `cupoMax` (гипотетически, например при гонке регистраций) — `fillRatio` может быть `> 1`, всё равно должен маппиться в статус `full`, не ломать бейдж/не показывать отрицательные числа (числа и не показываются — только категориальный статус).
- Турнир без `clubDireccion` — как и сейчас, адрес просто не рендерится (без изменений).
- Тип турнира, для которого нет ключа в `displayMaps.tipo` (гипотетический будущий формат вроде "Entrenamiento + juego" из примера заказчика, которого пока нет в `TournamentType`) — как и сейчас в существующем коде, `displayMaps.tipo[tournament.tipo] || tournament.tipo` — покажет сырое значение enum, не сломает рендер. Добавление новых типов турнира — вне скоупа этой задачи.

## Открытые вопросы

Нет — макет и текст заказчика описывают состав карточки, пороги статуса мест и правило переключения кнопки однозначно; технические детали (точные имена i18n-ключей, конкретные CSS-классы) оставлены на усмотрение Developer как техническая, не бизнес-неоднозначность (см. `GIT_WORKFLOW.md` §3).
