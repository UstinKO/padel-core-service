# LFPT-1195: Fix восстановление истории Team Playoff — обновлять открытое legacy-табло

## Статус
done
in-progress

## Источник

[Issue #1195](https://github.com/UstinKO/padel-core-service/issues/1195), M08 приёмки #1045. Владелец утвердил исправление 18.11.2026; техническая постановка без отдельного клиентского запроса.

## Контекст / зачем

Сервер восстанавливает снимок истории, React получает invalidation, но legacy-зритель остаётся со старым результатом. Причина — восстановление уведомляет только public topic. Уже работающий legacy realtime перечитывает страницу по сообщению своей темы.

## Связь с MASTER.md

Правила результатов, посева, истории, состава и прав клуба сохраняются. Уведомление о восстановлении отправляется после commit; rollback не сообщает об успешном изменении.

## Требования

### Функциональные

- После успешного restore Team Playoff вызвать существующую after-commit доставку `WebSocketService` с `STATE_UPDATED` и пустым payload в `/topic/team-playoff/{tournamentId}`.
- Сохранить invalidation `/topic/public/live/{tournamentId}`, объединение уведомлений в транзакции, серверное восстановление ID/пар/счёта/связей и проверку доступа.
- Другие форматы не получают сообщений в Team Playoff topic.

### Нефункциональные

Java 17, прежние транзакции и клиенты. Пользовательских строк нет; ES/RU/EN не меняются. Браузерная проверка выполняется в отдельном синтетическом контуре без сброса ручного стенда #1045.

## Вне скоупа

UI-изменения, новые бизнес-правила и миграции; перенос Maven-модулей, production-переключение и изменение других форматов.

## Изменения в системе

### API

HTTP прежний; добавлено событие актуализации существующей legacy-темы после restore. Публичный DTO не расширяется.

### БД

Миграций нет; snapshot и журнал сохраняются прежним путём.

### UI

Прежний слушатель автоматически обновляет legacy-табло. React продолжает snapshot-refetch.

### Документация

[Доставка после восстановления](../../docs/endpoints/conduct-history-realtime.md), `.agents/PROJECT.md` и журнал #1045 с отдельным результатом повторной проверки агента.

## Критерии приёмки

- [ ] Уведомления обеих тем отсутствуют до commit; успешная фиксация доставляет legacy STATE_UPDATED и public invalidation.
- [ ] Rollback после восстановления не отправляет сообщения обеих тем.
- [ ] Реальные legacy/React-зрители после restore убирают отменённый счёт без ручного refresh, остальные результаты/ID/связи сохранены.
- [ ] Целевые интеграционные тесты, полный verify, общий smoke и проверки документации проходят.

## Edge cases

Stale-версия, изменившийся состав, чужой клуб, неподдерживаемый снимок, rollback и недоступный брокер не создают ложного успешного обновления. Сбой доставки после commit не откатывает уже сохранённую историю; действует существующий AfterCommit.
