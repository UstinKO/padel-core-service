## Итог

Механика полностью подтверждена end-to-end: **spec → код → живое QA → PR** в одной облачной сессии `claude.ai/code/routines`, без Telegram, без единого ручного вмешательства внутри самих прогонов раундов 2-3. Три поправки к плану, найденные и закрытые по ходу:

1. **`Agent tool`-делегирование недоступно в роутине.** Асинхронный вызов без возможности синхронно дождаться результата (`ScheduleWakeup` внутри роутины не работает). Фикс — раздел "Режим `cloud`" в `develop-feature.md`: одна сессия играет все роли инлайн, следуя чек-листам `.claude/agents/*.md` напрямую, не делегируя.
2. **Права GitHub App — не то же самое, что OAuth-авторизация.** "Authorized GitHub Apps" (просто вход) ≠ "Installed GitHub Apps" (реальный доступ на запись к конкретному репозиторию). Без явной установки с правами Read+Write и `git push`, и `mcp__github__create_branch` падают в `403`, при этом ничего не подсказывает создателю роутины, что дело именно в этом — тратится раунд на диагностику.
3. **Мелкие трения окружения решаются тестировщиком-роутиной самостоятельно, без участия архитектора**: несовпадение пути к закешированному бинарнику Chromium (`find /opt/pw-browsers -iname chrome*` вместо угадывания версии в пути) и обход задизейбленной JS-кнопки через `form.submit()` при уже готовых тестовых данных — оба случая произошли независимо в раундах 2 и 3 и оба раза самостоятельно устранены тестировщиком. Не потребовало правок в `tester.md`, но стоит иметь в виду как стандартный класс трения облачного QA.
