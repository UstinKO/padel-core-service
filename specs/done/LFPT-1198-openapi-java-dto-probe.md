# LFPT-1198: Feature контракт API — проверить генерацию Java DTO из OpenAPI

## Статус
done
approved

## Источник

[Issue #1198](https://github.com/UstinKO/padel-core-service/issues/1198), родитель [#1197](https://github.com/UstinKO/padel-core-service/issues/1197); утверждённая владельцем подготовка второй фазы. Техническая постановка без отдельного клиентского запроса.

## Контекст / зачем

Первый после движка небольшой срез — публичное чтение клубов. Последовательность отделяет проверку генерации, границу application, wire-контракт и независимую приёмку.

## Связь с MASTER.md

Бизнес-правила, роли и публичные данные сохраняются. Новых пользовательских строк, внутреннего HTTP и изменения БД нет.

## Требования

## Цель и исходные факты
По ADR-0002 направление OpenAPI JSON → Java принято; генератор и его совместимость ещё не доказаны. В root pom.xml Java 17, Jackson 3.2.4, общий jackson-annotations 2.22.4, MapStruct 1.6.3. Нельзя добавлять Jackson 2 databind/core ради генератора. OpenAPI-контракты находятся в docs/frontend-react/contract/.

## Что сделать
На локальном изолированном наборе примеров из существующих Club, Tournament, Problem и account/player-events схем проверить кандидата генератора. Зафиксировать версии OAS/генератора/шаблоны/параметры и воспроизводимую команду Maven. Если кандидат несовместим, записать воспроизводимый отказ и выбрать совместимый способ либо явный ограниченный адаптер; не скрывать отказ подключением второго JSON-стека.

## Критерии приёмки
- [x] Две чистые генерации в target дают одинаковые Java-исходники; generated Java не коммитится и не правится вручную.
- [x] Модели компилируются с release 17, Jakarta validation и Jackson 3; нет javax, jackson-databind/core 2, JPA/Spring Data/MVC и HTTP-клиентских зависимостей.
- [x] JSON round-trip и MapStruct проверены для BigDecimal, дат/времени/зоны, wire-enum, отсутствующего поля/null, readOnly/writeOnly, коллекций, oneOf/allOf/$ref, ProblemDetail/fieldErrors на представительных существующих схемах. Неподдерживаемая конструкция обозначена явно; фиктивный PASS запрещён.
- [x] Отчёт содержит фактический dependency tree, команды/версии и подход для первого клубного DTO; сборка/запуск действующего приложения не изменены.

Результат 20.11.2026: [воспроизводимая проба и ограничения](../../docs/modular-monolith/phase-2/generator-probe.md), два ожидаемых отказа upstream, две положительные чистые генерации и 12 тестов. Nullable-валидация исправлена небольшим входным шаблоном; presence/readOnly/writeOnly/live oneOf не объявлены поддержанными. Ограниченный способ подходит только для следующего Club response. Корневой verify — 1105 тестов без ошибок, общий browser/JWT smoke и репетиция выпуска/отката на собственном preview пройдены; приёмка #1045 остаётся отдельной.

## Границы и зависимости
Только техническая проба и её проверяемые материалы; production endpoints, DTO и Maven-владение приложения не переключаются. Проба может выполняться до закрытия #1045, так как не расширяет перенос; подключение нового runtime-модуля — только после #1045.

## Документы
ADR-0002 и docs/modular-monolith/phase-2/generator-probe.md; результат не подменять документацией инструмента.

## Порядок выполнения
Родитель #1197. Без runtime-переноса; прямая подготовительная задача.

## Общие гарантии
Java release 17; бизнес-правила MASTER, HTTP/JSON/WS, ES/RU/EN, права и данные сохраняются. Изменений БД/Liquibase и production-переключения UI нет. Один слой и отдельный PR. Каждый реализационный PR самостоятельно сохраняет работоспособность приложения: корневой ./mvnw verify на отдельном PostgreSQL, smoke конечного jar/образа, legacy/API/React/Expo, проверка возврата на предыдущий артефакт. Runtime и доступы не публикуются; pipeline:ready, мерж и деплой подготовкой не разрешаются.

## Изменения в системе

### API
Существующие GET /api/public/clubs и /api/public/clubs/{id}; контракт сохраняется. В задаче технической пробы endpoints не переключаются.

### БД
Без миграций/переноса данных. PostgreSQL и Liquibase принадлежат поздней #1051.

### UI
Без изменения пользовательского интерфейса; потребители — React ClubPages/Catalogue/EventPage и API discovery.ts. Проверки в отдельной #1201.

## Edge cases

Пустой список, неизвестный/неактивный ID, нечисловой ID, nullable поля, порядок nombre/id, отказ БД, base URL с завершающим /, внешние OpenAPI $ref, неподдерживаемый тип генератора, старая вкладка клиента и возврат прежнего jar.

## Открытые вопросы

Бизнес-вопросов нет. Технические решения принимаются по результатам кода/пробы и фиксируются в ADR; совместимость не объявляется заранее.
