# Ручное объединение профилей по выбранным ID

Статус: approved. Задача #1383, интерфейс #1384. Продолжение #1125.

## Причина
Ручная проверка переиспользовала телефонные блокировки заявки. Отсутствующий или некорректный телефон давал общий CONTACT_CONFLICT, а интерфейс скрывал форму. Самостоятельная заявка не требуется, однако фактически без нормализуемого телефона ручной перенос был невозможен.

## Контракт
Ручная проверка ID сохраняет действующие роли SUPER_ADMIN/ORGANIZER и проверяет активный гостевой источник, активный основной аккаунт, разные ID и пересечения истории. Контакт не удостоверяет принадлежность выбранных профилей автоматически. Перед POST требуется verified и явный способ проверки личности.

Review дополнен readiness AVAILABLE/NEEDS_RESOLUTION/FORBIDDEN/COMPLETED; Profile — guest/active. conflicts запрещают перенос; differences показывают разрешимые различия. Отсутствующий, некорректный и неоднозначный телефон различаются. Поиск и подтверждение телефонной заявки сохраняют требование однозначного телефонного совпадения, причины отсутствия гостя, не-гостя и неоднозначности разделены.

ManualMerge.contactChoice: KEEP_ACCOUNT сохраняет телефон основного аккаунта (в том числе отсутствие), Telegram и вход; USE_GUEST_PHONE переносит только корректный однозначный телефон с прежним replacePhone при замене. При отсутствии contactChoice старые корректные запросы сохраняют совместимость, некорректный телефон требует явного KEEP_ACCOUNT. Для гостя без корректного телефона WHATSAPP недоступен: нужна личная либо другая согласованная проверка. Telegram из телефонного поля не извлекается. Уровень основного аккаунта остаётся прежним; конфликт стороны разрешается существующим sideChoice.

## Целостность
Сохраняется транзакционный перенос идентификаторов регистраций, оплат, явки, партнёрств, матчей, результатов и истории. Пересечения событий и рейтинга блокируют операцию с указанием причины. При ошибке аудита весь перенос откатывается. Блокировки профилей и уникальный аудит обеспечивают безопасный повтор, в том числе без телефона. Аудит содержит источник, получателя, автора, время, способ проверки и contact_resolution. Чужое уже завершённое объединение не переназначается.

## Миграция и откат
v1.90 разрешает NULL phone_key только у завершённого ADMIN-объединения с IN_PERSON/OTHER; добавляет contact_resolution. Старые записи не изменяются. Старый сервер читает завершённые записи, но не создаёт ручное объединение без телефона. Обратная миграция с NULL phone_key намеренно блокируется SET NOT NULL: сначала нужен отдельный план сохранения новых аудиторских записей, удалять их ради отката нельзя.

## Проверки
Синтетические гостевой C6 с Telegram-подобной строкой в телефоне и основной C7 с Telegram; отсутствие заявки; явный выбор контакта; разные проверки личности; сохранение основного аккаунта, регистрации, оплаты и явки; пересечения; права/CSRF; обычные телефонные заявки; повтор/конкуренция и ошибка записи аудита. Реальные профили не меняются.
