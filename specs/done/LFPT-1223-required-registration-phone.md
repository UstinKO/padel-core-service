# LFPT-1223 — Обязательный телефон перед записью

Статус: approved. Пользователь подтвердил 19.11.2026.

Телефон игрока обязателен, Telegram дополнительный. Новые контакты принимают местный номер с ISO-страной или международный, нормализуются E.164. Проверяется возможная длина номера, не владение. Telegram принимает ввод без @. Ошибка возвращает отдельный код и поле, не сохраняет часть контакта. Старые профили с телефоном остаются совместимы, Telegram-only требует телефон. Гостевые/администраторские сценарии и контакт партнёра не изменяются. Клиентская форма — отдельная задача LFPT-1224.

Проверки: нормализация AR/RU/международного номера, короткий/длинный/недопустимый ввод, телефон обязателен при Telegram, отсутствие частичного обновления, локализация ES/RU/EN.

## Создание аккаунта, согласовано 19.11.2026

Сверка с актуальным master 25.11.2026: нормализация телефона и возврат к турниру сохраняют выбранную сторону корта LEFT/RIGHT/EITHER. При ошибке контакта сторона остаётся в непарольных данных формы. Серверные тесты регистрации проверяют сочетание местного/международного телефона, стороны и безопасного возврата. Категория C3 и её поддерживаемый вариант ввода сохраняются.

POST /players/registro использует ту же нормализацию контактов до проверки ограничений DTO. Страна phoneCountry необязательна, начальная AR. Поле telefono сохраняется E.164, Telegram необязателен. Уровень обязателен, sentinel SIN_ESPECIFICAR не принимается веб-формой. Ошибки сохраняют непарольные поля и выбранный положительный tournamentId, очищают пароль и CAPTCHA. После создания аккаунта действует обычный автоматический вход, затем возврат на /torneo/ID#tournament-registration. Без корректного ID сохраняется /?welcome=true. URL возврата собирается из проверенного числа, внешний адрес не используется. Остальные JSON API и создание через Google сохраняют существующие правила.

## Совместимость с актуальной архитектурой

Сверка 27.11.2026: используется `PlayerPrincipal` для ID вошедшего игрока и `padel-persistence` для профиля. Проверка обязательного телефона находится в `PlayerContacts` модуля `padel-application`, поэтому одинаково действует для профиля, сессии и регистрации. После сохранения контактов статус и допуск к записи читают свежий профиль из базы. Совместимость старых сериализованных сессий сохраняется.
