# LFPT-0911: Feature frontend UI v2 — live-экраны King of Court, Americano и Team Playoff

## Статус
done

## Источник
Напрямую из [issue #911](https://github.com/UstinKO/padel-core-service/issues/911). Фундамент #827 и системные страницы #912 влиты. Интеграцию блокирует только backend #903; он реализуется первым.

## Контекст / зачем
Перенести пользовательские live-экраны UI 0.7 на реальные серверные данные, сохранив результаты и публичные URL действующего сайта. Макет содержит вымышленные раунды/формулы; они не являются источником правил.

## Связь с MASTER.md
Сервер рассчитывает счёт, очки матчей/кортов/ручные корректировки, ranking, посев, победителя и связи сетки. King of Court, индивидуальный Americano и Team Playoff имеют отдельные views. Круговой Team Americano не подменяется плей-офф. Контакты, запись, очередь участия и оплаты не изменяются; административных действий у зрителя нет.

## Требования
### Функциональные
- Подключить закрытые React-маршруты на основе исходных URL: `/preview/torneo/:eventId/king-of-court`, `/preview/tournaments/americano/:eventId`, `/preview/tournaments/team-playoff/:eventId`, нужные ranking/history deep links. Старый вход по kingId использует безопасный alias #903, без путаницы instance id и event id.
- Вход из существующей React-карточки открывает соответствующий preview live route; каноническая/share-ссылка остаётся публичной серверной ссылкой, без preview/admin пути. Публичные ссылки старых страниц продолжают работать.
- Первое отображение из типизированного public snapshot #903 через TanStack Query. Отдельные views отображают только фактический формат; неподдерживаемый round-robin предлагает действующий legacy-просмотр.
- Вкладки корты/расписание/рейтинг/история, выбор раунда/истории и диалог матчей игрока работают с данными сервера. Порядок, места, итоги и bracket connections не вычисляются в браузере.
- KoC: явно разделить очки матчей, бонусы кортов и ручные корректировки. Americano не показывает бонус KoC. Team Playoff различает квалификационные матчи, волны и стадии плей-офф, номера команд и номера матчей команды.
- Тексты правил из demo не копируются, если они расходятся с действующим сервисом. Равные очки не означают вымышленное общее место, а частично сыгранный турнир не выдаётся за официально завершённый.
- Guest получает spectator view без контролов внесения счёта/генерации/продвижения. Player может выделить себя по серверной session identity; это не меняет публичный contract и не раскрывает контакты.
- Общие share/QR переиспользуются. PNG сетки доступен зрителю там, где отображается сетка: экспортировать серверную готовую раскладку, не вычислять посев/победителя на клиенте; исключить controls и приватные данные из картинки.

### Обновления и состояния
- Один жизненный цикл STOMP-клиента на приложение (`@stomp/stompjs` + SockJS), совместимый с StrictMode. Подписка на безопасный public invalidation topic #903, не на чувствительный legacy payload.
- Событие только инвалидирует запрос. Coalescing/bounded refetch не создаёт запрос на каждое дублирующее событие; новый snapshot заменяет старый целиком, не добавляет дубликаты матчей.
- Reconnect, возвращение фокуса/видимости и смена актуального instance требуют повторного чтения. Игнорировать устаревшие ответы и отменять ненужные GET при смене мероприятия; не оставлять подписки на прошлое событие.
- Для Americano — polling 20 секунд при видимой вкладке, без новой серверной технологии; для KoC/Playoff — WS и ограниченный fallback для пропущенных событий. 429 учитывает реальный Retry-After, защита не обходится.
- Loading/not-started/live/finished/cancelled не смешиваются с состояниями транспорта stale/reconnecting/offline/error. При временном сбое сохранять последний успешный публичный snapshot с отметкой устаревания, без вымышленных нулевых результатов; после 403/404 убрать недоступные данные.
- Пользователь видит время последнего успешного чтения. Восстановленная связь не считается актуальностью, пока не загружен новый snapshot. Рейтинг/история обновляются вместе с кортами.
- Ссылки на вкладку/раунд/игрока переживают reload/back и корректируются при исчезновении объекта после restore. GET/refresh не выполняют мутации и не создают проведение.

### Нефункциональные
- ES/RU/EN сразу, единая cookie lang; токены/компоненты текущего React, адаптация UI 0.7 без fixture/domain demo service и demo user.
- Клавиатура, native dialogs/focus return, reduced motion, длинные имена, 320/390/1440 px, mobile landscape и крупное табло. Не скрывать существенные итоги при уменьшении экрана.
- Не ослаблять SUPER_ADMIN-защиту `/preview/**`. Guest/player браузерные проверки — в изолированной loopback-сборке с реальным API и отдельной БД/отключёнными уведомлениями, как в предыдущем блоке. Развёртываемый контур остаётся #904.
- Добавить только нужные закреплённые зависимости; проверить основной bundle и lazy live chunks, не увеличивать молча бюджет основного JS.

## Вне скоупа
Админские live-пульты, изменение счёта/раундов/посева/сеток, круговой Team Americano, новая модель участия/резерва, кабинет, новый WS для Americano, публичное включение маршрутов и итоговый гейт #913.

## Изменения в системе
### API
Только потребление snapshot/alias и public invalidation #903; сервер — источник всех доменных данных.
### БД
Без изменений.
### UI
Отдельные live views, typed client/hooks, общий realtime lifecycle, история/раунды/игрок, состояния соединения, безопасные public links/экспорт и переход из карточки события.
### Документация
`frontend/README.md`, `docs/frontend-react/{plan,design-0.7-coverage}.md`, contract API/screens/cross-cutting, ADR-0010 и `.agents/PROJECT.md`.

## Критерии приёмки
- [ ] Три формата отображают реальные snapshot; результаты/ранжирование/расписание совпадают с API после reload и reconnect.
- [ ] Повторные WS события не дублируют матчи/строки, StrictMode не создаёт второй клиент, уход со страницы снимает подписку.
- [ ] Пропущенный результат/restore отражается после refetch; stale не скрывается ложным признаком connected и не заменяет данные нулями.
- [ ] Guest не получает контактов/admin controls; round-robin не выдаётся за Team Playoff.
- [ ] История, player dialog, выбор раунда, deep links, share/QR и PNG текущей сетки работают без demo расчётов.
- [ ] Playwright покрывает три формата, 19 раундов/длинные имена/большую сетку, reconnect/stale, 404/409/429/503 и mobile/desktop; есть browser pass с реальным backend.
- [ ] Все три языка, format/lint/typecheck/unit/build/size, docs-drift и упаковка Maven проходят; Expo `/app/**` и legacy сохранены.
- [ ] Один собственный коммит и отдельный PR с Depends-On на backend #903; production live route не переключается.

## Edge cases
Нет раундов/счёта, неизвестные player/round/instance, завершённое или отменённое событие, play-in/bye/ожидающий матч, одинаковые очки, ручная коррекция/restore, два открытых live-экрана, повторная подписка, шторм WS, потерянное событие, поздний HTTP-ответ, скрытая вкладка, разрыв связи при диалоге, недоступный PNG export, ошибочный URL/filter, исчезнувшая строка после refetch.

## Открытые вопросы
Бизнес-правила не меняются. Технический план блока подтверждён пользователем 2026-11-11. Публичное переключение и тестирование на реальных iPhone/Android не подразумеваются без доступных устройств/отдельного решения; браузерная эмуляция не объявляется проверкой физического телефона.
