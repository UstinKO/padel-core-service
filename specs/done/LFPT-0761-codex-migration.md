# LFPT-0761: Feature среда разработки — переносим правила и конвейер на Codex

## Статус
done

## Источник
https://github.com/UstinKO/padel-core-service/issues/761
Прямое поручение владельца проекта: адаптировать накопленные правила и автоматизацию под Codex.

## Контекст / зачем
Правила проекта, роли и Telegram-запуск зависели от Claude Code. Нужны читаемая Codex точка входа,
проектные навыки и исполняемый адаптер с сохранением GitHub-протокола автомержа и деплоя.

## Связь с MASTER.md
Бизнес-инварианты, форматы турниров, регистрации, оплаты и роли пользователей не меняются.
В MASTER обновляются только пути к техническим правилам.

## Требования

### Функциональные
- Перенести действующие правила в `.agents/`, создать корневой `AGENTS.md` и навыки `new-feature`/`develop-feature`.
- Сохранить роли Analyst/Developer/Tester/Architect, спецификации и GitHub-маркеры.
- Обновить ссылки, исключения деплоя и классификацию изменений в оркестраторе и движке.
- Подготовить отслеживаемый Git адаптер relay → Codex CLI с отдельным checkout, приватным состоянием и обработкой сбоев.
- Сохранить старую SQLite-очередь и зарегистрированные worktree; исходники сервера сверить до выкатки.

### Нефункциональные
- Приватные документы и настройки остаются исключёнными из Git.
- Воркер не использует боевую БД, не отключает sandbox, не передаёт Telegram-токен дочернему процессу.
- Проверки автоматики не вызывают модели и не пишут в Telegram/GitHub.
- Один CLI-воркер с общей тестовой БД выполняет одну задачу одновременно.

## Вне скоупа
Изменение продукта, API и схемы PostgreSQL. Публикация, боевое переключение relay,
установка зависимостей на сервер, миграция существующих worktree и оплата API.

## Изменения в системе

### API
Публичные API приложения не меняются. Используется существующий внутренний выключатель конвейера.

### БД
Liquibase не меняется. В локальной SQLite движка добавляются nullable `execution_id` и `launch_key` без потери задач.

### UI
UI продукта не меняется. В карточке задачи отображается ошибка воркера.
Документы: `docs/codex-migration.md`, Home, pipeline-autonomy, журнал движка и технические ссылки.

## Критерии приёмки
- [ ] Codex получает правила через AGENTS.md и находит оба проектных навыка.
- [ ] Действующие инструкции не требуют Claude routine или Claude browser tools.
- [ ] Классификация AGENTS.md/.agents не требует деплоя приложения, изменения automation требуют.
- [ ] Старая SQLite-очередь сохраняет задачи после добавления execution_id.
- [ ] Сбой CLI отражается без ожидания GitHub-следов; код 0 не считается успешным деплоем.
- [ ] Повторное исполнение не начинается, пока предыдущий процесс задачи активен.
- [ ] Проверки приватности, ссылок, документации и тесты автоматики проходят.
- [ ] Описаны фактические границы проверки и шаги активации/отката.

## Edge cases
Недоступный CLI, ошибка clone/авторизации, отсутствующие правила в master, старые записи очереди,
тайм-аут процесса, повторный запуск, отставание индекса GitHub и приватные временные ссылки.

## Открытые вопросы
Не блокируют подготовку кода: место размещения выделенного воркера и конкретная дата переключения
согласуются перед выкаткой. Альтернативный GitHub Actions executor не входит в эту реализацию.
