# LFPT-1332: Feature многомодульный монолит — выделить движок и валидатор расписания Americano

## Статус
done
implemented

## Источник

[Issue #1332](https://github.com/UstinKO/padel-core-service/issues/1332), родитель #1041. Техническая постановка из согласованного плана King of Court → Americano; владелец подтвердил продолжение после мержа PR #1281. Промежуточный клиентский запрос не нужен.

## Контекст / зачем

AmericanoScheduleEngine оценивает расписание через AmericanoScheduleValidator, а валидатор использует MatchSlot движка. Их совместный перенос завершает очередной чистый вычислительный срез без цикла между Maven-модулями. Оба класса уже используют только JDK.

## Связь с MASTER.md

Сохраняются правила индивидуального Americano, очередность раундов, счёт, история, дополнительные очки, права и транзакции. Бизнес-инварианты не меняются.

## Требования

### Функциональные

- Переместить AmericanoScheduleEngine, AmericanoScheduleValidator и два одноимённых Test из корневого src в padel-tournament-engines. Все четыре файла сохраняются байтово: package, методы, MatchSlot, ScheduleReport, Random, DP/fallback, число попыток, bye и критерии проверки расписания не меняются.
- AmericanoService и сервисные тесты остаются в bootstrap. Вызовы, MapStruct, JPA, транзакции, @ConductChange и внешние контракты сохраняются; Spring bean для статических утилит не создаётся.
- Проверка jar требует четыре выделенных вычислительных класса и девять публичных вложенных типов в одной библиотеке engines, без shadow-классов, Spring/JPA или bytecode новее Java 17.
- ArchUnit допускает примитивные массивы после разбора типа элемента. Массив legacy-объектов остаётся запрещённым; весь service-пакет не разрешается.

### Нефункциональные

Каждый PR самостоятельно сохраняет работоспособность приложения. Корневой verify с frontend выполняется на отдельной PostgreSQL; конечный jar проверяется в собственном preview. Новых строк и переводов, миграций и внешних интеграций нет. Мерж и production-деплой остаются отдельным решением владельца.

## Вне скоупа

Оптимизация алгоритма/тестов, изменение случайности или качества расписания, массовый рефакторинг AmericanoService, новые application/persistence/web/integrations модули, PostgreSQL/Swarm и самостоятельное исправление прежних дефектов.

## Изменения в системе

### API

Java API и существующие HTTP/JSON/WS сохраняются.

### БД

Без схемы, Liquibase и данных пользователей. Только синтетические fixtures своего preview.

### UI

Production UI не меняется; действующие экраны проведения проверяются браузером.

### Документация

.agents/PROJECT.md, docs/architecture.md, навигация/план модульного монолита и отдельный отчёт переноса с безопасной сводкой.

## Критерии приёмки

- [x] Четыре файла совпадают с исходным master; 12 engine- и 8 validator-тестов выполняются в engines без Spring/БД.
- [x] Границы и jar отклоняют отсутствие класса, shadow основного/вложенного типа, legacy-массив, framework и неверный bytecode; примитивные массивы разрешены.
- [x] Полный clean verify с frontend и сервисными сценариями успешен на отдельной PostgreSQL.
- [x] Реальные API и браузер проверяют полный цикл, сохранённые раунды, счёт, следующий раунд, историю и desktop/mobile RU/ES/EN на конечном jar.
- [x] Общий smoke и репетиция выпуска/отката прошли; прежний jar читает то же проведение, возврат сохраняет расписание/счёт и отпечаток схемы/Liquibase.
- [x] Документация, автоматика, docs-drift, приватность и локальное ревью пройдены; результаты привязаны к артефакту, ограничения перечислены.

## Edge cases

Полные циклы 8/12/16/20/24 игроков, разное число кортов, 21 игрок с bye, граница полного цикла, повторы партнёров, баланс соперников/кортов и все отрицательные примеры валидатора сохраняются по исходным тестам. Равные результаты двух случайных генераций не требуются: сравниваются сохранённое расписание и инварианты. Для сборки — вложенные record, примитивные массивы и единственный владелец классов; для runtime — права/CSRF, история и обратимый откат.
