# LFPT-0904: Feature backend UI v2 — закрытый тестовый контур без доступа к production-данным

## Статус
done
testing — технический план подтверждён пользователем 2026-11-11; реализация и локальная проверка завершены, ожидается CI итогового коммита.

## Источник

Напрямую из [issue #904](https://github.com/UstinKO/padel-core-service/issues/904). Зависимости #826/#827 завершены. Следующая задача — #905; итоговая frontend-приёмка #913 дополнительно ждёт #909/#910.

## Контекст / зачем

Действующий `/preview/**` уже ограничен SUPER_ADMIN, но работает в том же приложении, что и production API. Это защита маршрута, а не независимая среда данных и внешних эффектов. Нужен воспроизводимый закрытый контур на настоящем backend и React с синтетическими данными, который можно проверить локально и затем отдельно разместить для приёмки.

В коде уже есть сборка React в jar, SPA allowlist, session/CSRF и ограничения preview. Их требуется переиспользовать. `@EnableScheduling` включён на главном классе, а scheduled-обработчики распределены по нескольким сервисам: одного свойства размера пула недостаточно для отключения. SMTP, Telegram, Meta, OAuth и логирование проверяются вместе с сетевой изоляцией, а не только отдельными флагами.

## Связь с MASTER.md

Бизнес-инварианты регистрации, оплаты, резерва, отмены и форматов сохраняются. Production allowlist SPA остаётся пустым; `/app/**` остаётся существующей Expo-сборкой. По ADR-0013 `/preview/**` доступен SUPER_ADMIN даже после прохождения внешнего барьера контура. Seed не реализует неподтверждённые правила #759/#760/#901.

## Требования

### Функциональные

1. Добавить отдельный профиль интеграционного preview и самостоятельный Compose-проект: приложение, собственная PostgreSQL, локальный SMTP-приёмник и входной reverse proxy. Не переиспользовать production compose, env, БД, volumes и учётные записи.
2. По умолчанию публиковать только входной порт на loopback. Перед всеми UI/API/assets/health должен действовать отдельный серверный барьер доступа; выбранный вариант — Basic Auth на reverse proxy с локально генерируемым файлом паролей. Одна скрытая ссылка не является защитой. Session/CSRF и роли приложения сохраняются после прохождения барьера.
3. Приложение, PostgreSQL и SMTP находятся в изолированной runtime-сети без выхода во внешний интернет. Порты приложения, БД и SMTP не публикуются на хост. Внешний reverse proxy контура не проксирует произвольные адреса. Загрузка зависимостей во время сборки отделяется от runtime.
4. Профиль допускает только выделенный локальный сервис PostgreSQL с отдельным именем БД. Небезопасные настройки, совмещение с production-профилем и отсутствие обязательных настроек приводят к отказу старта, а не к fallback на обычную БД.
5. SMTP направлен только в локальный приёмник. Telegram, Meta/CAPI, analytics, внешний OAuth, внешнее логирование и другие интеграции выключены либо заменены безопасным приёмником. Профиль не использует production секреты. Недоступность внешних эффектов подтверждается также сетевым тестом.
6. Для этого профиля отключить регистрацию всех прикладных scheduled jobs. В обычных профилях scheduling по умолчанию остаётся включённым. Ручные действия API и after-commit уведомления на локальный SMTP продолжают проверяться.
7. Команды подготовки/запуска/остановки и seed/reset воспроизводимы. Seed создаёт синтетические SUPER_ADMIN/player/guest и сценарии основных форматов, пары/solo/резерв/отмена, используя существующие правила. Пароли генерируются локально, не публикуются. Чужие аккаунты не меняются.
8. Reset проверяет идентичность Compose-проекта, выделенную БД и маркер созданного контура; удаляет только принадлежащие seed данные с известными идентификаторами. Ошибочный target, отсутствие маркера или внешняя БД означают отказ до записи. Не использовать массовое удаление пользовательских баз или volumes.
9. Все ответы контура имеют noindex/robots-маркировку. Добавить безопасную идентификацию среды и версии сборки в защищённый диагностический ответ; явная маркировка также нужна в закрытой точке входа. Не раскрывать hostname БД, приватные адреса, токены и credentials.
10. Добавить отдельные liveness/readiness проверки и документированную команду полного отключения контура. Health не раскрывает подробности постороннему запросу.
11. Проверить `/preview/**`, `/web/**`, API, CSRF, session и неизменность `/app/**`/legacy в пределах выделенного контура. Изменение production маршрутов не требуется.

### Нефункциональные

Java source/release 17, типизированная конфигурация и DTO. Настройки по умолчанию действующего приложения сохраняются. Новые видимые строки — ES/RU/EN. Эксплуатационная документация содержит только безопасные примеры и имена переменных; локальные пароли, env и runtime-состояние игнорируются Git.

## Вне скоупа

Публичная публикация окружения, удалённая настройка сервера/DNS/TLS/VPN, копирование production данных и секретов, переключение боевых SPA URL, переопределение правил #759/#760/#901, разработка экранов #909/#910. Проверка атомарного deploy/rollback — #905, полная пользовательская приёмка — #913. Закрытый контур не означает завершение этих задач.

Удалённое размещение не входит в согласование этой реализации: после локальной проверки будет отдельное конкретное предложение с адресом и способом доступа без публикации секретов.

## Изменения в системе

### API

Бизнес-маршруты сохраняются. Диагностический контракт среды/версии и liveness/readiness доступны только внутри закрытого контура. Глобальная внешняя защита покрывает и ранее публичные API/статику; ограничения `/preview/**` внутри приложения не ослабляются.

### БД

Бизнес-миграция не планируется. Выделенная БД получает действующие Liquibase-миграции. Данные seed и маркер безопасности принадлежат только окружению; schema/данные production не меняются.

### UI

Существующие React/legacy/Expo ресурсы используются как есть. Добавляется маркированная закрытая точка входа; новая продуктовая вёрстка не входит. Если потребуется изменение React-исходников, сначала уточнить границу отдельной frontend-задачи.

### Код и документация

Отдельные Compose-конфигурация, профиль, входной reverse proxy, команды управления/seed, проверка конфигурации, управление scheduling, тесты безопасности и интеграционные сценарии. Обновить `.agents/PROJECT.md`, `docs/architecture.md`, `docs/auth-flow.md`, `docs/frontend-react/contract/cross-cutting.md`, безопасный runbook закрытого контура и ссылку в `docs/Home.md`. Приватные инфраструктурные документы не включать в PR.

## Критерии приёмки

- [ ] Чистый запуск с отдельным именем проекта создаёт только выделенные ресурсы; повторный запуск не затрагивает чужую БД или процессы.
- [ ] Без внешней авторизации запросы к UI, API, assets, login и health отклоняются; с ней `/preview/**` всё ещё требует SUPER_ADMIN приложения.
- [ ] Авторизованный player получает свой session/CSRF, а SUPER_ADMIN открывает preview deep link и refresh. POST без CSRF отклоняется.
- [ ] Runtime не соединяется с внешними SMTP/Telegram/Meta/OAuth/БД; письмо попадает только в локальный приёмник. Проверен отрицательный сетевой сценарий.
- [ ] Scheduled jobs не зарегистрированы в preview; в обычном профиле они остаются включёнными.
- [ ] Production-профиль или небезопасный DB target приводит к отказу старта до миграций/подключения к пользовательской БД.
- [ ] Повторный seed идемпотентен; reset очищает только синтетические записи после проверки маркера. Неправильный target/маркер запрещает запись.
- [ ] Ответы содержат noindex, диагностика показывает preview и проверяемую ревизию без секретов. Readiness отражает доступность тестовой БД.
- [ ] Реальный браузер подтверждает session/CSRF, preview deep link, `/web/**`, legacy и `/app/**`. Результаты относятся к последнему коммиту.
- [ ] `./mvnw verify`, проверки документации/конвейера и конфигурации Compose проходят; собственные тестовые процессы останавливаются штатной командой, синтетические данные остаются только в выделенном volume/runtime для повторного запуска.
- [ ] Один backend-коммит и PR с `Closes #904`; удалённый deploy и production routing не выполняются.

## Edge cases

Занятый локальный порт, повторный запуск, существующий чужой Compose-проект, неверные credentials/маркер, недоступный SMTP или БД, подмена переменных подключения, совмещение профилей, попытка обойти proxy через внутренний порт, запрос WS/deep link, cookie/CSRF после входа, рестарт приложения, старый образ, guest со служебным email, случайный production токен в окружении, ошибка seed посередине транзакции, остановка только собственного проекта.

## Открытые вопросы

Бизнес-решения не требуются. На согласование вынесен технический вариант: локальный отдельный Compose с внешним Basic Auth, внутренней сетью без исходящего интернета, безопасным профилем и синтетическим seed. Вопросы размещения для удалённого заказчика решаются отдельным шагом после готовой локальной реализации.

## Реализация и проверки

- Профиль `preview`, отдельный Compose, Basic Auth gateway, SQL-маркер UUID до Liquibase, синтетический seed/reset по сохранённым ID. Runtime-сеть приложения использует `internal` и gateway mode `isolated`; только gateway подключён к входной сети и публикует loopback-порт.
- Планировщик вынесен в условную конфигурацию: по умолчанию включён, в preview выключен. Для preview отдельный console-only logback с маскированием.
- Управление использует локальный Docker socket, Docker 28+, проверенный runtime и не даёт переменным хоста подменять путь/порт/ревизию. Внешние редиректы запрещены. Доступы и состояние игнорируются Git; Docker build получает только jar.
- Полный `./mvnw verify`: 943 теста, 0 ошибок, 1 пропуск на отдельной тестовой PostgreSQL. Дополнительно 4 теста утилиты preview, 6 тестов служебных проверок, 48 тестов relay и 5 тестов worker (1 пропуск), docs-drift, check-agent-migration, actionlint и diff-check.
- Реальный Compose и Chromium: внешний барьер на UI/API/assets/health, SUPER_ADMIN/player, session/CSRF, preview deep link/refresh, React/legacy/Expo, noindex/маркировка и отключение OAuth. Письмо перехвачено Mailpit; внешнее соединение и контрольный сервис хоста недоступны при работающем соединении с внутренней БД.
- Проверены отрицательные старты с внешним datasource/Liquibase URL, совмещением с prod и чужим UUID-маркером. Reset сохранил постороннюю контрольную запись; неверный маркер остановил запись, повторный GET не изменил seed.
- Проверка включена в PR Check с обязательной остановкой собственного контура. Исходники mobile-app, её сборка, React-экраны и production allowlist не менялись.
- Граница выпуска: готов локальный контур. Удалённый адрес/TLS/VPN, выдача доступа заказчику, deploy/rollback #905 и итоговая приёмка #913 остаются отдельными шагами.
