# Запрос на доработку

## Что нужно сделать
Проверить и исправить полный сценарий восстановления пароля, а также улучшить логирование ошибок.

Сейчас пользователь нажимает «Забыли пароль», указывает email, получает письмо для восстановления пароля, однако ссылка/кнопка из письма не работает. Пользователь не может перейти к установке нового пароля и, соответственно, не может войти в аккаунт.

Нужно протестировать весь сценарий от начала до конца, а не только отправку email:
1. Пользователь нажимает «Забыли пароль».
2. Вводит зарегистрированный email.
3. Backend создаёт token для восстановления.
4. Пользователю приходит письмо.
5. Проверить фактический URL, который находится в кнопке письма.
6. При переходе по ссылке должна открываться страница создания нового пароля.
7. Token должен корректно передаваться на backend.
8. Пользователь вводит новый пароль.
9. Пароль успешно изменяется.
10. Старый пароль больше не работает.
11. Новый пароль работает.
12. Использованный token повторно использовать нельзя.
13. Просроченный token должен показывать понятное сообщение и предлагать запросить новое письмо.

Проверить сценарий как минимум на мобильном телефоне и компьютере, а также при открытии ссылки напрямую из Gmail/другого почтового клиента.

Отдельно проверить именно формирование ссылки — это первое подозрительное место. Например, письмо может содержать `localhost/reset-password?...`, старый домен, неправильный `http` вместо `https`, неправильный frontend-роут, некорректно вставленный token, либо URL, который frontend не умеет открывать напрямую. Отдельный вариант: страница вида `1-padel.com/reset-password?token=...` работает при переходе внутри сайта, но при прямом открытии URL из письма сервер не знает маршрут и отдаёт ошибку (типичная проблема у SPA-приложений) — поэтому тестировать обязательно именно кликом из реального письма.

## Где это происходит
Страница входа (`/login`, кнопка «Забыли пароль») → письмо восстановления пароля → страница установки нового пароля.

## Зачем это нужно
Пользователи, забывшие пароль, не могут восстановить доступ к аккаунту — это блокирует вход в сервис.
