# Запрос на доработку

> Источник: Telegram, тема "AI Разработка", отправитель: customer (переслано от Evgeny_754), telegram_launch_message_id: 4784.

## Что нужно сделать
В разделе оплат турнира сейчас наверху показывается только общая сумма по валюте, например:

```
ARS — 330 000
```

Нужно расширить этот блок и дополнительно показывать разбивку суммы по способу получения денег. Например:

```
ARS — всего 330 000
— Банковский перевод: 150 000 ARS
— Наличные: 120 000 ARS
— Карта: 60 000 ARS
```

Для криптовалюты аналогично:

```
USDT — всего 180
— Bybit: 120 USDT
— Binance: 60 USDT
```

Суммы должны рассчитываться автоматически на основании данных, внесённых по каждому игроку. Учитывать только оплаты со статусом «Оплачено». Если по какому-то способу оплаты сумма равна нулю, его можно не показывать, чтобы не перегружать интерфейс. Общую сумму по валюте оставить, но ниже или рядом показывать её детализацию.

Важно: если сейчас для крипты система хранит только способ «Крипто», но не хранит, куда именно пришла оплата — Bybit / Binance / другое, нужно добавить отдельное поле/селектор счёта или платформы, чтобы эти суммы можно было корректно разделять.

Цель — чтобы после турнира можно было сразу увидеть, сколько денег должно находиться наличными, сколько пришло банковским переводом, сколько на карте и сколько на каждом криптокошельке, без ручного подсчёта строк.

## Где это происходит
Админ-панель, страница управления платежами турнира: `/admin/tournaments/{id}/payments`. Приложен скриншот этой страницы (блок `TOTAL / ОПЛАТИЛИ / НЕ ОПЛАТИЛИ / ПОСЕТИЛИ / ARS $330 000` и таблица игроков со столбцом «Способ»).

## Зачем это нужно
После турнира организатору нужно сразу видеть разбивку по способу получения денег (наличные/перевод/карта/крипто-площадка), чтобы сверить физические наличные и остатки на разных счетах, не пересчитывая строки таблицы вручную.

## Примеры / референсы
Приложен скриншот текущего блока сумм и таблицы платежей (легенда внизу уже показывает 4 цветовые категории метода: Наличные / Перевод / Крипто / Карта).

## Есть ли ограничения
Общая сумма по валюте должна остаться как есть — детализация добавляется дополнительно, не взамен.

Побочная находка при анализе (не входит ни в одну из задач выше, заведена отдельно как технический долг): issue #477 — существующий блок общей суммы по валюте не фильтрует по статусу «Оплачено» и не исключает партнёрские строки пары, теоретически может завышать сумму.
