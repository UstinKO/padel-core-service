# Запрос на доработку

## Что нужно сделать

Во время тестирования парного турнира (Team Playoff — квалификация + плей-офф) обнаружено несколько связанных проблем в работе резервных команд и команд, которые не пришли на турнир. Нужно привести всю логику к единому статусу команды.

Тестовый сценарий: турнир создан на 8 команд, зарегистрировано 9 команд — первые 8 должны быть в основном составе, 9-я — в резерве.

Сейчас резерв корректно отображается только в разделе регистраций турнира, но в других разделах система воспринимает резервную команду как обычного участника.

1. **Отображение резервной команды в административной панели.** В разделе регистраций 9-я команда уже определяется как резервная — эту логику сохранить. Но в разделе «Оплаты и посещаемость» резервная команда сейчас не выделяется отдельно — её нужно визуально отделять (например, блок «Основной состав» / блок «Резерв»), оставив доступной для просмотра/работы администратору.

2. **Отображение резерва на публичной странице турнира.** Сейчас обычный пользователь видит только счётчик мест в листе ожидания, но не видит, кто туда входит. Нужно разделить участников: «Участники 8/8» + список основных команд, отдельно «Список ожидания / Резерв» + сами резервные команды. Резервная команда не должна визуально выглядеть как полноценный участник турнира. Тексты — RU/ES/EN.

3. **Резервные команды нельзя импортировать в квалификацию.** При нажатии «Импортировать регистрации» в квалификацию должны попадать только команды основного состава. Резервные команды не должны попадать в квалификационную таблицу, не появляться среди доступных команд для матча, не участвовать в жеребьёвке, не учитываться в количестве участников квалификации и при формировании плей-офф.

4. **Автоматический перевод из резерва при увеличении вместимости.** Если администратор увеличивает максимальное количество команд (например, с 8 на 16), резервная команда (или несколько — по очередности регистрации) должна автоматически перейти в основной состав, пока есть свободные места. После этого она должна вести себя как обычный участник (импорт в квалификацию, отображение в оплатах/участниках).

5. **Добавить статус «Не пришла».** В день турнира админу нужна возможность в разделе «Оплаты и посещаемость» отметить зарегистрированную команду как «Не пришла» (или аналогичный статус), без удаления из базы/истории регистрации — команда должна остаться в регистрациях, оплатах и истории турнира с понятной отметкой.

6. **Команда «Не пришла» должна исключаться из квалификации.** Если команда уже была импортирована в квалификацию, но до начала её матчей администратор отметил «Не пришла» — система должна автоматически исключить её из активной квалификации (не отображаться в квалификационной таблице/списке доступных команд, не участвовать в создании матчей, не учитываться в количестве участников).

7. **Неявка не должна блокировать запуск плей-офф.** Сейчас возможна ситуация: реально играют 7 команд (все сыграли по 2 квалификационных матча), но в таблице остаётся 8-я команда без единого матча — система считает квалификацию незавершённой, и кнопка запуска плей-офф не появляется. При проверке готовности квалификации нужно учитывать только реально участвующие команды — отметка «Не пришла» не должна блокировать завершение квалификации/запуск плей-офф.

8. **Пересчёт после исключения команды.** После перевода команды в статус «Не пришла» количество активных команд, квалификационная таблица, требования по числу сыгранных матчей и логика bye/первого этапа плей-офф должны пересчитываться исходя из фактического числа участвующих команд (пример: было 8, 1 не пришла → активных 7, плей-офф строится как для турнира из 7 команд, а не 8).

9. **Важный edge case: команда уже сыграла матч.** Если команда уже сыграла хотя бы один квалификационный матч, простая отметка «Не пришла» не должна тихо исключать её из квалификации автоматически (это может повлиять на результаты других команд) — такой сценарий либо блокируется явной ошибкой, либо требует отдельного подтверждённого действия. Основной сценарий этой задачи — команда, которая не пришла и не сыграла ни одного матча.

10. **Единый источник статуса.** Статус команды должен быть единым для всех разделов системы (админ-панель, публичная страница, оплаты, квалификация, плей-офф), а не определяться независимо в каждом месте. Ориентировочная модель: `MAIN` (основной состав) / `WAITLIST`/`RESERVE` (резерв) / `NO_SHOW` (не пришла) / `CANCELLED` (отменена).

## Где это происходит

Формат турнира — Team Playoff (парный Americano с квалификацией + плей-офф, `TournamentType.AMERICANO_TEAMS`): страница регистраций турнира в админке, `/admin/tournaments/{id}/payments` («Оплаты и посещаемость»), `/tournaments/team-playoff/admin/{tournamentId}` (управление квалификацией/плей-офф), публичная страница турнира `/torneo/{id}`.

## Зачем это нужно

Без единого статуса администратор не может доверять данным турнира — резерв пересчитывается неверно, плей-офф может не стартовать из-за формально "незавершённой" квалификации, а неявка команды в день турнира никак не фиксируется в системе.

## Примеры / референсы

Критерий готовности — сценарий проверки:
1. Создать турнир на 8 команд, зарегистрировать 9. Первые 8 — основные, 9-я — резерв (регистрации, оплаты, публичная страница).
2. «Импортировать регистрации» → в квалификацию попадают только 8 основных команд.
3. Увеличить вместимость до 16 → 9-я команда автоматически становится основной.
4. В другом тесте — 8 основных команд, одну отметить «Не пришла» → она исчезает из активной квалификации, оставшиеся 7 играют по 2 матча, после этого квалификация считается завершённой и доступен запуск плей-офф. Не пришедшая команда остаётся в истории регистрации с отметкой «Не пришла».

## Есть ли ограничения

Не затрагивать уже сыгранные результаты матчей — исключение команды из квалификации задним числом (после того как она сыграла матч) не должно происходить тихо/автоматически.
