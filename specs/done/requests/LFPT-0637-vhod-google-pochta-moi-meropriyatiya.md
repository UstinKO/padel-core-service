# Запрос на доработку

> Пересказан по сообщению в Telegram (тема "AI Разработка", отправитель помечен как `customer`, переслано от третьего лица) и по ответам заказчика на уточняющие вопросы конвейера.

## Что нужно сделать

Подключить к существующему сайту настоящий вход по email/паролю и через Google для отдельного клиента «1Padel.App», и серверную часть раздела «Мои мероприятия» (только просмотр: предстоящие турниры, история, статус регистрации, позиция в листе ожидания — без записи и отмены, это остаётся на сайте).

К исходному сообщению в Telegram был приложен zip-архив, который называет себя «готовой реализацией» (патч на `SecurityConfig`, исходники мобильного React Native/Expo приложения, фиче-спека, «результаты проверки») — заказчик подтвердил, что архив подготовлен сторонним ИИ-инструментом (Codex) по его просьбе и что код из него нужно самостоятельно проверить перед использованием. **Этот архив физически недоступен конвейеру** (Telegram-relay умеет прокидывать в задачу ссылку на фото, но не на произвольный файл-вложение, см. `.claude/commands/develop-feature.md` § «Точка входа: Telegram») — ни эта, ни предыдущая сессия не видели его содержимого, только пересказ в тексте сообщения. Поэтому его нельзя использовать ни как патч, ни как источник мобильных исходников — только как словесное описание желаемого результата.

## Где это происходит

Сервер (бэкенд): аутентификация (`/api/auth/**`, Google OAuth2) и новый read-only API для раздела «Мои мероприятия» игрока.

Отдельная, следующая задача (клиент): размещение уже готового (по словам заказчика) веб-экспорта Expo-приложения по HTTPS на `/app/` — не входит в эту спеку, см. «Вне скоупа».

## Зачем это нужно

У заказчика уже есть прототип мобильного приложения (Expo/React Native, собран отдельно, не в этом репозитории), который должен ходить в бэкенд padel-core-service за входом и списком турниров игрока — сейчас в приложении это не подключено к реальному серверу.

## Насколько срочно

Важно, но не горит — публикация через обычный конвейер (после тестов) допустима, срочной ручной проверки не требуется.

## Примеры / референсы

Архив с «готовой реализацией» (недоступен конвейеру, см. выше) — использовать только для понимания общего намерения, не как код или спеку.

## Есть ли ограничения

- Существующий вход на сайте (форма, сессия) должен продолжать работать как есть.
- Публикация этой задачи через автономный конвейер (билд → тесты → PR → автомерж в прод без ручного ревью, как и для остальных задач) — подтверждена заказчиком явно, несмотря на то что задача про аутентификацию.
- Пароли и любые коды доступа у заказчика не запрашивать.
- Запись на турнир и отмена регистрации через клиент не нужны — только просмотр.
- Публикация в App Store / Google Play — не нужна.
