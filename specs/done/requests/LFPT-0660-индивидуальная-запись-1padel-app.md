# Запрос на доработку

## Что нужно сделать
Подключить индивидуальную запись на мероприятие прямо внутри веб-клиента 1Padel.App (не переход на сайт) для Короля корта, индивидуального Americano, «Тренировки + игры» (Padel Clinic) и Cancha Abierta. Парную регистрацию в эту задачу не включаем — для парных турниров запись остаётся на сайте.

Подготовлены изменения, тесты и инструкция по применению: https://github.com/eugenegwork-coder/1padel-app/tree/main/updates/individual-registration — проверить код, адаптировать к актуальному master, проверить состояние PR #652 (попап после регистрации на Padel Clinic) и согласованность показываемых в приложении условий (штрафы/отмена) с тем, что сейчас реально показывает сайт.

## Где это происходит
Веб-версия 1Padel.App (`/app/`) — экран деталей мероприятия (карточка события), после выбора мероприятия из списка.

## Зачем это нужно
Сейчас в приложении можно только посмотреть расписание и «Мои мероприятия» — сама запись требует перехода на сайт. Это лишний шаг для игрока, который уже открыл приложение.

## Примеры / референсы
Готовый патч заказчика (клиентский код, без изменений сервера): https://github.com/eugenegwork-coder/1padel-app/tree/main/updates/individual-registration/individual-registration.patch, подготовлен на основе master `padel-core-service` после LFPT-0646 (коммит `04ab54d3`). README патча описывает сценарий: вход при необходимости → проверка актуальных данных мероприятия, своей записи и контакта → показ стоимости и условий → явное подтверждение чекбоксом → реальный POST на существующий API регистрации → показ CONFIRMED/WAITLIST из ответа сервера → переход в «Мои мероприятия».

## Есть ли ограничения
- Парная регистрация и отмена участия через приложение — не в этой задаче.
- Серверных изменений не требуется — патч использует только существующие эндпоинты (`/api/public/tournaments/{id}`, `/api/players/me/tournaments`, `/api/players/me/contact-status`, `PATCH /api/players/me/contact`, `POST /players/tournaments/{id}/register`).
- Перед публикацией — проверить регистрацию на специально созданном тестовом мероприятии, не на реальном турнире с живыми игроками.
- Веб-клиент нужно пересобрать (`pnpm build:site`) и закоммитить обновлённую сборку в `src/main/resources/static/app/`.
