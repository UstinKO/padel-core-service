# Запрос на доработку

> Собрано из сообщения заказчика в Telegram (3 сообщения, пересланы от Evgeny_754). Сохранено как есть, с минимальной структуризацией под шаблон — техническую проработку делает фиче-спека LFPT-0749.

## Что нужно сделать

Исправить алгоритм формирования расписания индивидуального турнира Americano. На турнире №127 (20 участников, 5 кортов, 19 раундов, 95 матчей) обнаружены проблемы с распределением партнёров, соперников и использования кортов. Нужно исправить сам алгоритм (математически корректное формирование расписания), а не расписание конкретного турнира.

Обязательные требования к алгоритму:

1. **Уникальность партнёров.** Для полного цикла (N игроков → N-1 раундов) каждый участник получает каждого другого участника партнёром ровно один раз. Для 20 участников: 19 матчей на игрока, 19 разных партнёров, 190 уникальных партнёрских комбинаций, повторы недопустимы.
2. **Равномерность соперников.** Каждый участник должен встречаться с остальными в качестве соперника максимально равномерно — идеал для 20 участников: ровно 2 раза с каждым, без пар, которые не встретились ни разу или встретились 3+ раза. Если идеал недостижим математически — минимизировать отклонения, не нарушая уникальность партнёров.
3. **Равномерное распределение по кортам.** Для 20 участников/5 кортов/19 раундов — 3-4 матча на корт на игрока, без длинных серий на одном корте (не более 2 подряд, где возможно), каждый игрок должен посетить все корты. Рекомендуется отдельный этап оптимизации кортов после формирования матчей.
4. **Корректность каждого раунда**: каждый участник в раунде ровно один раз, 4 уникальных игрока на матч, 2 команды по 2, корректное число матчей (для 20/5 — ровно 5 матчей в раунде).
5. **Автоматическая проверка расписания** после генерации — партнёры, соперники, корты, раунды. Нарушение обязательных условий — расписание не подтверждается.
6. **Поддержка разных конфигураций**, минимум: 8/2/7, 12/3/11, 16/4/15, 20/5/19, 24/6/23 (участники/корты/раунды). Для каждой — проверить математическую достижимость идеала; если недостижим для части конфигураций — обрабатывать корректно (не падать, не выдавать мусор).
7. **Автоматизированное тестирование**: минимум 100 генераций на каждую основную конфигурацию, валидатор на каждом сгенерированном расписании, 100% успешных генераций без нарушения обязательных условий, без зависаний/чрезмерно долгой генерации. Если алгоритм не может сформировать корректное расписание — понятная ошибка, а не некорректный результат.
8. **Приоритеты алгоритма**: обязательные (раунд корректен → 4 уникальных игрока в матче → уникальные партнёры) выше оптимизационных (равномерность соперников → равномерность кортов → разнообразие последовательности кортов).
9. Рассмотреть известные математические методы формирования сбалансированных расписаний (комбинаторные схемы, round-robin/circle method и т.п.) вместо случайной генерации с последующими исправлениями, но не предполагать, что идеальное распределение соперников/кортов возможно для любого N — это нужно математически проверять, а не постулировать.

Дополнительное требование заказчика (важно, т.к. 1-Padel уже используется для реальных турниров):
- Перед изменением алгоритма — сохранить текущую рабочую версию (то есть фикс не должен ломать существующий флоу, пока не проверен).
- Фикс не должен автоматически менять расписания уже существующих/проводимых турниров — только генерацию новых.
- Проверить сначала на тестовом турнире, не трогая реальные/проводимые соревнования.

## Где это происходит

Раздел «Турниры → Индивидуальный Americano». Генерация раундов при инициализации турнира (`AmericanoService`, админка `/tournaments/americano/admin/{tournamentId}`, preview — `POST /tournaments/americano/{tournamentId}/preview-rounds`).

## Зачем это нужно

Расписания реальных турниров получаются несправедливыми: неравномерные соперники и корты — жалобы от организатора/игроков после турнира №127.
