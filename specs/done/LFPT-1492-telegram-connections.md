# Статистика подключения Telegram и необязательное приглашение

Статус: approved. Запрос владельца 27.11.2026, #1492; интерфейс #1493.

## Поведение

Отказ «Не пользуюсь Telegram» хранится в аккаунте отдельно от предпочтения канала. Он скрывает приглашение в кабинете и после записи, но не назначает WhatsApp, не меняет регистрацию и не отключает существующую связь. Игрок может отменить отказ в профиле или явно подключить Telegram независимо от отказа. Сохранённый отказ действует на всех устройствах; подключённые и выбравшие WhatsApp не видят приглашения. Нет обязательного диалога при входе. Интерфейс доступен ES/RU/EN.

GET статуса дополнен invitationDismissed. PUT /api/players/me/telegram/invitation принимает dismissed boolean: только активный обычный PLAYER в допустимой области пилота, CSRF; отсутствие бота не препятствует отказу. GET ничего не меняет. Изменение идемпотентно, не принимает чужой playerId.

GET /api/admin/telegram/connections — только SUPER_ADMIN, no-store. Единый агрегат активных профилей: registered (без гостей), connected, notConnected, whatsapp, declined, guests. Категории исключают пересечения: гость → WhatsApp → действующая личная связь (enabled, положительный user_id, chat_id=user_id) → отказ → без подключения. registered равен сумме четырёх обычных категорий. Неактивные исключены. Подключение независимо от enabled/pilot/automatic бота: это статистика сохранённых связей, не обещание доставки. Нет контактов, Telegram ID и токенов.

Добавляется только boolean telegram_invitation_dismissed NOT NULL DEFAULT false в player_contact_preferences; прежние значения канала сохраняются. Добавочная миграция v1.94-telegram-invitation-dismissal не зависит от отложенного автоперевода.

## Приёмка

Проверить агрегат и отсутствие пересечений, нули, disabled-связь, гостей и неактивных; права/CSRF/валидацию; отказ и возврат после повторного GET; сохранение WhatsApp и личной связи; отсутствие запросов Telegram. Полный verify на отдельной PostgreSQL. Интерфейс и браузерная приёмка отдельным PR #1493. Планировщики, production и платные API не меняются.

## Результат проверки

Полный verify на отдельной чистой PostgreSQL: 1776 тестов, 0 ошибок и падений, 14 штатных пропусков. Четыре новых интеграционных сценария прошли: агрегаты, устойчивый отказ/возврат, CSRF/валидация и закрытая статистика. 48 relay прошли; docs-drift и agent-migration без расхождений. Четыре проверки собранного JAR прошли, один Liquibase и 100 ресурсов. Проверки не обращались к production и не отправляли сообщения.
