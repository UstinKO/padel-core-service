## О продукте

Платформа для организации падель-турниров. Целевой рынок — Аргентина (валюта ARS, телефон +54). Есть публичный сайт для игроков (регистрация на турниры, рейтинг, профиль) и админ-панель для владельцев клубов/организаторов (создание турниров, управление участниками, платежи вручную, генерация сеток).

## Роли пользователей

Два независимых типа пользователей, разные таблицы, оба реализуют `UserDetails`:

| Роль | Кто это | Возможности |
|------|---------|-------------|
| `ROLE_PLAYER` | Игрок | Регистрация на турниры, профиль, дашборд, рейтинг |
| `ROLE_OWNER` | Владелец клуба | Управление своими турнирами и клубом |
| `ROLE_SUPER_ADMIN` | Суперадмин платформы | Полный доступ ко всем клубам/турнирам |
| `ROLE_ORGANIZER` | Организатор | Управление турнирами (без владения клубом) |
| `ROLE_CLUB_ADMIN` | Клубный администратор | Привязан к конкретному клубу (`Owner.clubId`, LFPT-375); видит и администрирует только турниры, регистрации, оплаты и матчи/раунды/результаты (все форматы) своего клуба — прямой доступ по ID к ресурсу чужого клуба отклоняется (LFPT-376). Публичный сайт не затронут |

Вход: форма (сессия) для веба, JWT (access 24h / refresh 7d) для API, Google OAuth2 (только для игроков, создаёт `PlayerPadel` при первом входе).

**Создание аккаунта через форму сайта по email:** телефон обязателен, Telegram заполняется по желанию. Вход через Google и существующие аккаунты используют действующий порядок.

**Обязательное условие для регистрации на турнир:** `PlayerPadel.hasValidContact()` — валидный телефон `+54` **или** Telegram username. Без этого регистрация на турнир невозможна.

**Ограничение по уровню (LFPT-0303, LFPT-0744):** самостоятельная регистрация на турнир с "простой" категорией уровня (`C9..C4` для мужской шкалы, `D9..D6` для женской) допускается только если расчётный уровень игрока отличается от расчётного уровня категории турнира не более чем на одну ступень (своя категория либо соседняя сильнее/слабее). Расчётный уровень переводит обозначения в единую числовую шкалу соответствия мужских и женских категорий: `Cn → n`, `Dn → n + 1` (например, `D6` ≈ `C7`) — пол категории сам по себе не блокирует регистрацию, женщина может зарегистрироваться на мужской турнир и наоборот, если расчётные уровни близки. Правило не применяется к открытым форматам (Cancha Abierta, Padel Clinic), категориям `TODOS`/`PRINCIPIANTES`/диапазонам, формату SUMA и категориям `D5`/`D4` (там отдельная логика, вне этого правила). Игрок без указанного уровня не может зарегистрироваться на турнир с такой категорией. Администратор/координатор не ограничен этим правилом.

## Форматы турниров

Один турнир — один формат, задаётся при создании и не меняется:

| Формат | Что это | Ключевые сущности |
|--------|---------|--------------------|
| Одиночный/парный bracket | Классическая сетка на выбывание | `Match` |
| King of Court | Ротация по кортам раунд за раундом, real-time табло | `TournamentKingOfCourt`, раунды/корты/статистика |
| Americano | Все играют со всеми в течение турнира, индивидуальный рейтинг | раунды/матчи/игроки Americano |
| Team Americano | Как Americano, но парами/командами; может включать плей-офф-стадию (Team Playoff) | команды/раунды Americano |

King of Court транслирует состояние в реальном времени через WebSocket (`/topic/tournament/{kingId}`) — используется для табло на экране во время турнира.

### История проведения

Для King of Court, Americano, Team Americano и Team Playoff сервер фиксирует историю проведения вместе с подтверждёнными изменениями. Координатор с правами управления может продолжить существующее проведение из карточки события или восстановить версию из истории. Восстановление создаёт новую актуальную версию, сохраняя более поздние записи и текущие регистрации и оплаты. Сброс текущего раунда King of Court очищает его результаты, сохраняя пары, корты и предыдущие раунды.

### Дополнительные очки

После стартового распределения координатор «Короля корта» или индивидуального Americano может начислять и списывать очки по игроку и этапу. Итог включает ручную сумму с сохранением действующего порядка критериев мест. В «Короле корта» автоматический бонус за корт показывается отдельно. Исправление счёта и обычный сброс раунда сохраняют ручные корректировки. При восстановлении истории корректировки возвращаются вместе с игровым состоянием. Правки завершённого турнира доступны через административное редактирование результатов без перезапуска.

## Статусы регистрации на турнир

```
CONFIRMED         — основной состав, участвует в матчах
WAITLIST          — лист ожидания, ждёт освобождения места
SOLO_ADD_LATER    — неполная заявка в резерве, партнёра добавят позже
SOLO_SEARCH       — неполная заявка в резерве, игрок ищет партнёра
CANCELLED         — отменена
PARTNER_INVITED   — легаси (до LFPT-0687): партнёр ещё не принял приглашение по email.
                    Новые регистрации в этот статус не попадают — пара (с партнёром как с
                    аккаунтом, так и без) сразу получает CONFIRMED/WAITLIST, см. «Флоу
                    парной регистрации» ниже
```

**Бизнес-правило листа ожидания:** освобождённое место закрепляется автоматически. В индивидуальном турнире его получает следующий игрок, в парном — первая готовая пара по времени очереди. Приглашения с таймером больше не создаются.

## Флоу парной регистрации

Игрок, регистрирующий пару, уже сам договорился с партнёром заранее — регистрация завершается
немедленно, без ожидания email-подтверждения от партнёра или действия координатора (LFPT-0687).

1. Первый игрок указывает данные партнёра — существующий аккаунт (по email/телефону/ID) или
   контакт нового партнёра (имя, телефон и/или Telegram; email у партнёра не обязателен).
2. Если партнёр без аккаунта — он создаётся сразу же (уровень `SIN_ESPECIFICAR`, т.к. его
   реальный уровень пока не известен).
3. Оба игрока сразу получают один и тот же статус по занятости турнира: `CONFIRMED`, если есть
   свободное место, иначе `WAITLIST`. Отдельного промежуточного статуса ожидания нет.

Координатор может вручную связаться с партнёром по телефону/Telegram после регистрации — это
не условие участия пары, а последующая организационная связь.

**Легаси:** регистрации, созданные до LFPT-0687, могли застыть в статусе `PARTNER_INVITED` —
для них всё ещё работает email-подтверждение по ссылке (`POST /api/tournaments/double/confirm`);
после подтверждения пара встаёт в конец очереди резерва (`WAITLIST`), как и раньше (LFPT-0668).

«Ищу партнёра» и «Добавлю партнёра позже» создают неполную заявку в резерве даже при заполненной основе. Пока пара не собрана, место не занято. Заявка остаётся доступна в соответствующем режиме поиска или добавления партнёра.

При добавлении заранее согласованного партнёра сохраняется исходное время очереди. Если оба уже записались по отдельности, используется более раннее время. Предложение через поиск требует принятия. Готовая пара получает ближайшее доступное место с учётом очереди и не вытесняет подтверждённых участников. Ручной перевод в основу разрешён для готовой пары при свободном месте. Ручной возврат в резерв переносит обоих участников за уже ожидающие пары.

**Отмена участника пары:** если из основного состава выходит один игрок, второй сохраняет место и видит состояние «Нужна замена партнёра». Автоматическое продвижение резерва не запускается. Оставшийся участник может добавить замену; срока автоматического исключения нет. Если один игрок выходит из пары в резерве, заявка становится неполной и сохраняет исходную позицию очереди. При отмене всей пары место освобождается, после чего продвигается следующая готовая пара. История отмены и платежей сохраняется.

### Ответ на запрос участия

После автоматического перевода парной заявки из резерва место закрепляется сразу, а игроки получают запрос подтвердить участие или отказаться. Отсутствие ответа не меняет состав. При прямой записи готовой пары достаточно уведомления о записи. За гостевого партнёра может ответить игрок, оформивший пару. Ответ участника хранится отдельно от отметок организатора.

Переведённый из резерва игрок может отказаться до старта, даже если обычный дедлайн отмены прошёл. Правила расчёта оплаты сохраняются. Новый партнёр при замене в основе получает запрос подтвердить участие. Отказ от предложения сыграть вместе сохраняет исходные одиночные заявки.

### Сохранение факта отмены

Отмена сохраняет регистрационную строку, платежи и маркетинговую историю. Факт каждого перехода в отмену хранится отдельно с областью операции, кодом причины и известным инициатором. Повторная запись может переиспользовать регистрационный ID, но не стирает прежние события отмены. Повтор уже выполненной отмены не создаёт нового события или уведомления. Владелец токена ссылки резерва не считается проверенным владельцем аккаунта. Историческим данным без достоверного инициатора и времени эти сведения не приписываются.

Комментарий организатора доступен затронутому участнику и организатору с правом управления мероприятием; публичные карточки, live-табло и посторонние игроки его не получают. Денежные условия и допуски к отмене сохраняются.

## Уведомления игрокам

Email (Thymeleaf-шаблоны) на ключевые события: регистрация, подтверждение email, регистрация на турнир, приглашение партнёра, приглашение из листа ожидания, отсутствие мест, сброс пароля. Дополнительно — Telegram-бот для DM-напоминаний игрокам и алертов организаторам.

## Защита от абьюза при регистрации

Слои (по порядку): reCAPTCHA v3 → honeypot-поле → блок disposable-email доменов → IP rate limit. На уровне сети — Cloudflare + Nginx rate limiting + CrowdSec. Технические детали — [.agents/SECURITY.md](../.agents/SECURITY.md), карта угроз — [.agents/THREATS.md](../.agents/THREATS.md).

## Платежи

Нет реального платёжного шлюза — платежи фиксируются организатором вручную в админ-панели (`/admin/tournaments/{id}/payments`). Это осознанное текущее ограничение продукта, не баг.

## Добавление мероприятия в календарь

Разовый экспорт активного мероприятия в Google TEMPLATE / Apple / .ics — только чтение. Не регистрирует, не подтверждает участие, не меняет резерв и оплату. Единые данные RU/ES/EN, формат и категория вместо одного гендера, стабильный UID без обещания устранения дублей. Точная длительность в минутах и IANA-зона хранятся в настройках; при пустом значении в минутах длительность берётся из duracion. Если задан диапазон, используется большая граница. Ручное значение имеет приоритет. Изменения не синхронизируются: календарь содержит публичную ссылку на актуальную страницу. У SOLO_POR_ENLACE сохраняется доступ по прямой ссылке без попадания в списки. Спека: LFPT-0808/LFPT-0809.

## Границы доменов (важно при написании фиче-спек)

Проект готовится к разделению на микросервисы: Payments → Notifications → Bracket → Identity → King of Court → Americano → Tournament-core. Фиче-спеки не должны создавать новые скрытые связи между этими будущими границами без явного упоминания — см. [docs/microservices-migration-plan.md](../docs/microservices-migration-plan.md) на предмет уже известных архитектурных ловушек.

## i18n

Публичный UI, админка и email — `es`/`ru`/`en`. Любая новая пользовательская строка обязана попасть во все три файла локализации. Детали — [docs/i18n/README.md](../docs/i18n/README.md).
