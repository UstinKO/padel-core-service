Единый источник истины о том, **как работает продукт** с точки зрения бизнес-логики, ролей и пользовательских сценариев. Это не техническая документация — за архитектурой кода, package layout, URL-картой и командами идти в [.claude/CLAUDE.md](../.claude/CLAUDE.md).

## О продукте

Платформа для организации падель-турниров. Целевой рынок — Аргентина (валюта ARS, телефон +54). Есть публичный сайт для игроков (регистрация на турниры, рейтинг, профиль) и админ-панель для владельцев клубов/организаторов (создание турниров, управление участниками, платежи вручную, генерация сеток).

## Роли пользователей

Два независимых типа пользователей, разные таблицы, оба реализуют `UserDetails`:

| Роль | Кто это | Возможности |
|------|---------|-------------|
| `ROLE_PLAYER` | Игрок | Регистрация на турниры, профиль, дашборд, рейтинг |
| `ROLE_OWNER` | Владелец клуба | Управление своими турнирами и клубом |
| `ROLE_SUPER_ADMIN` | Суперадмин платформы | Полный доступ ко всем клубам/турнирам |
| `ROLE_ORGANIZER` | Организатор | Управление турнирами (без владения клубом) |

Вход: форма (сессия) для веба, JWT (access 24h / refresh 7d) для API, Google OAuth2 (только для игроков, создаёт `PlayerPadel` при первом входе).

**Обязательное условие для регистрации на турнир:** `PlayerPadel.hasValidContact()` — валидный телефон `+54` **или** Telegram username. Без этого регистрация на турнир невозможна.

## Форматы турниров

Один турнир — один формат, задаётся при создании и не меняется:

| Формат | Что это | Ключевые сущности |
|--------|---------|--------------------|
| Одиночный/парный bracket | Классическая сетка на выбывание | `Match` |
| King of Court | Ротация по кортам раунд за раундом, real-time табло | `TournamentKingOfCourt`, раунды/корты/статистика |
| Americano | Все играют со всеми в течение турнира, индивидуальный рейтинг | раунды/матчи/игроки Americano |
| Team Americano | Как Americano, но парами/командами; может включать плей-офф-стадию (Team Playoff) | команды/раунды Americano |

King of Court транслирует состояние в реальном времени через WebSocket (`/topic/king-of-court/{tournamentId}`) — используется для табло на экране во время турнира.

## Статусы регистрации на турнир

```
CONFIRMED         — основной состав, участвует в матчах
WAITLIST          — лист ожидания, ждёт освобождения места
WAITLIST_INVITED  — получил приглашение, есть 5 минут на подтверждение
CANCELLED         — отменена (сам игрок, либо после 2 неответов на приглашение)
PAIR_REGISTERED   — парная регистрация: первый игрок подтверждён, ждёт партнёра
PARTNER_INVITED   — парная регистрация: партнёр ещё не принял приглашение
```

**Бизнес-правило листа ожидания:** когда место освобождается, следующий игрок из `WAITLIST` автоматически получает `WAITLIST_INVITED` и email с дедлайном (проверяется каждые 10 минут). Игрок теряет место после 2 неотвеченных приглашений — переходит в `CANCELLED`.

## Флоу парной регистрации

1. Первый игрок регистрируется на двоих → его статус `PAIR_REGISTERED`, партнёру уходит email-приглашение.
2. Партнёр переходит по ссылке из письма и подтверждает участие.
3. Оба переходят в `CONFIRMED`.

Альтернативный путь — "ищу пару на месте": игрок регистрируется соло с намерением найти партнёра, система показывает список таких игроков и позволяет им объединиться в пару (либо вручную, либо через плановое автосведение).

## Уведомления игрокам

Email (Thymeleaf-шаблоны) на ключевые события: регистрация, подтверждение email, регистрация на турнир, приглашение партнёра, приглашение из листа ожидания, отсутствие мест, сброс пароля. Дополнительно — Telegram-бот для DM-напоминаний игрокам и алертов организаторам.

## Защита от абьюза при регистрации

Слои (по порядку): reCAPTCHA v3 → honeypot-поле → блок disposable-email доменов → IP rate limit. На уровне сети — Cloudflare + Nginx rate limiting + CrowdSec. Технические детали — [.claude/SECURITY.md](../.claude/SECURITY.md), карта угроз — [.claude/THREATS.md](../.claude/THREATS.md).

## Платежи

Нет реального платёжного шлюза — платежи фиксируются организатором вручную в админ-панели (`/admin/tournaments/{id}/payments`). Это осознанное текущее ограничение продукта, не баг.

## Границы доменов (важно при написании фиче-спек)

Проект готовится к разделению на микросервисы: Payments → Notifications → Bracket → Identity → King of Court → Americano → Tournament-core. Фиче-спеки не должны создавать новые скрытые связи между этими будущими границами без явного упоминания — см. [docs/microservices-migration-plan.md](../docs/microservices-migration-plan.md) на предмет уже известных архитектурных ловушек.

## i18n

Публичный UI, админка и email — `es`/`ru`/`en`. Любая новая пользовательская строка обязана попасть во все три файла локализации. Детали — [docs/i18n/README.md](../docs/i18n/README.md).
