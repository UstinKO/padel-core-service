# LFPT-316: Устранение падения на мёртвом роуте GET /tournaments/americano/{id}/initialize

## Статус
approved

## Источник
GitHub issue напрямую (без клиентского запроса в `specs/requests/`, задача техническая, от архитектора): https://github.com/UstinKO/padel-core-service/issues/316. Найдено при анализе спеки [LFPT-314](../done/LFPT-314-americano-preview-dead-route.md) (тот же контроллер, тот же паттерн бага — несуществующий Thymeleaf-шаблон вместо рабочей страницы), которая уже смержена в master (PR #315).

## Контекст / зачем

`AmericanoViewController.showInitializeForm` (`GET /tournaments/americano/{tournamentId}/initialize`, `src/main/java/.../controller/view/americano/AmericanoViewController.java`, строки 166-194) для существующего AMERICANO-турнира, который ещё **не инициализирован**, возвращает имя view `tournaments/americano/initialize`. Такого файла нет — в `templates/tournaments/americano/` лежат только `view.html` и `ranking.html` (подтверждено `ls`). Thymeleaf бросает `TemplateInputException`, пользователь видит 500.

**Важное отличие от LFPT-314:** тот роут (`/tournaments/americano/admin/{id}/preview`) был проверен как полностью мёртвый — ни одна ссылка в UI на него не вела. Этот роут (`/tournaments/americano/{id}/initialize`) технически публичный (namespace без `/admin/`), но **реально достижим не только прямым набором URL в адресной строке**: в том же контроллере, в методе `previewRounds` (`POST /tournaments/americano/{tournamentId}/preview-rounds`, строки 221-257), catch-блок при любом исключении от `americanoService.previewRounds(...)` делает `return "redirect:/tournaments/americano/" + tournamentId + "/initialize";` (строка 255). Форма, которая шлёт этот POST, реально существует и используется в проде — `admin/tournaments/details.html` строит `form.action = '/tournaments/americano/' + TOURNAMENT_ID + '/preview-rounds'` (JS, строка ~1712) и сабмитит её из инлайн-формы конфигурации Americano-турнира. То есть **сегодня, до фикса**, организатор/супер-админ, который на странице `/admin/tournaments/{id}` заполняет форму предпросмотра раундов с некорректными параметрами (например, недостаточно активных игроков для выбранного числа кортов), получает не текст ошибки, а падение с `TemplateInputException` на редиректе. Это не косметическая уборка мёртвого кода, а реальный, воспроизводимый в проде краш на error-path легитимного рабочего флоу.

Кроме прямого набора URL и redirect из `previewRounds`, других ссылок на этот GET нигде нет — подтверждено `grep` по `src/main/resources/templates` и `src/main/resources/static/js` (никаких `href`/`action`/`form.action`, ведущих на `.../{id}/initialize` без `/admin/`, кроме самого редиректа из `previewRounds`, найденного выше).

Рабочий флоу настройки/предпросмотра/инициализации Americano-турнира, как и в LFPT-314, живёт на `admin/tournaments/details.html` (`GET /admin/tournaments/{id}`): та же инлайн-форма конфигурации, тот же POST `/tournaments/americano/{id}/preview-rounds`, и рабочий POST-обработчик инициализации `/tournaments/americano/admin/{id}/initialize`. Создавать новый шаблон `tournaments/americano/initialize.html` избыточно — он дублировал бы уже существующий, поддерживаемый UI. **Технический выбор:** редирект на существующую рабочую страницу, без нового шаблона — тот же подход, что и в LFPT-314.

## Связь с MASTER.md
Фича не меняет ни одного инварианта `specs/MASTER.md`. Затрагивает раздел "Форматы турниров" (Americano) только на уровне навигации — бизнес-логика инициализации (`AmericanoService.initializeAmericanoTournament`, `AmericanoService.isInitialized`, `AmericanoService.previewRounds`) не меняется, переиспользуются существующие проверки. Изменений в MASTER.md не требуется.

## Требования

### Функциональные

1. `GET /tournaments/americano/{tournamentId}/initialize` для существующего турнира типа `AMERICANO`, который ещё **не инициализирован**, должен вернуть HTTP 302 редирект на `/admin/tournaments/{tournamentId}` (страница деталей турнира с формой конфигурации/предпросмотра/инициализации) — без рендеринга какого-либо `tournaments/americano/*` шаблона и без нового flash-сообщения. Целевая страница — та же, что выбрана в LFPT-314 для аналогичной "неинициализированной" ветки соседнего метода, и та же страница, откуда реально приходит форма `preview-rounds`, чей error-path заводит сюда (см. "Контекст") — так организатор после ошибки предпросмотра попадает обратно на страницу с формой, а не на постороннюю страницу.
   - Без нового flash-сообщения по той же причине, что и в LFPT-314: не создавать новую пользовательскую строку, требующую перевода на `es/ru/en`, ради ветки, у которой и так нет специфичного содержательного сообщения (текущий код на этой ветке никакого flash не выставляет).
   - Ранее выставляемый в модель дефолтный `AmericanoConfigDto` (points/courts/rounds/shuffle) для рендеринга несуществующего шаблона удаляется — он не нужен для редиректа, страница `/admin/tournaments/{id}` строит собственные дефолты конфигурации независимо.
2. Ветка для турнира с типом, отличным от `AMERICANO`, не меняется: редирект на `/tournaments/{tournamentId}` с flash `error` = `"Este torneo no es de tipo Americano"` (существующая строка и целевой URL, поведение регрессионно фиксируется тестом). **Не трогается в этой фиче**, несмотря на отдельно найденную проблему — см. "Вне скоупа".
3. Ветка "уже инициализирован" не меняется: редирект на `/tournaments/americano/{tournamentId}` (рабочий `viewTournament`) с flash `info` = `"El torneo ya está inicializado"`.
4. Косвенный эффект фикса: `POST /tournaments/americano/{tournamentId}/preview-rounds` при исключении внутри `americanoService.previewRounds(...)` продолжает редиректить на `/tournaments/americano/{tournamentId}/initialize` (строка 255, код метода `previewRounds` не меняется в этой фиче — см. "Вне скоупа"), но теперь этот редирект больше не падает, а долетает до рабочей страницы `/admin/tournaments/{tournamentId}` через два последовательных 302 вместо крэша.

### Нефункциональные
- i18n: новых пользовательских строк нет (см. п.1 — решение спроектировано так, чтобы их избежать).
- Производительность/нагрузка: не применимо — чистая навигационная правка, GET без новых запросов к БД (используются уже существующие `getActiveTournamentById` и `isInitialized`).
- Безопасность: новая точка входа данных от пользователя не создаётся. Метод как и раньше не имеет специфичного `@PreAuthorize` — защищён только общим правилом `.anyRequest().authenticated()` из `SecurityConfig` (путь `/tournaments/americano/{id}/initialize` НЕ входит в whitelist `permitAll()`, который покрывает только однословный `/tournaments/americano/*`, т.е. без вложенных сегментов — подтверждено чтением `SecurityConfig`, строки 87-88, 128). Это значит, что маршрут технически доступен любому аутентифицированному пользователю (включая `ROLE_PLAYER`), но реальный воспроизводимый путь попадания сюда — через `previewRounds`, который сам защищён `@PreAuthorize("hasAnyRole('SUPER_ADMIN', 'ORGANIZER')")`. См. Edge cases.

## Вне скоупа
- Создание нового Thymeleaf-шаблона `tournaments/americano/initialize.html` — осознанно отклонённый вариант (см. "Контекст"), по аналогии с LFPT-314.
- Добавление `@PreAuthorize` на `showInitializeForm` — метод и так не имеет отдельной ролевой проверки, как и большинство соседних `GET`-методов этого контроллера (`viewTournament`, `viewRounds`, `viewMatch` и др.); ужесточение авторизации не запрошено и не относится к причине падения.
- Обработка `IllegalArgumentException` для несуществующего/удалённого `tournamentId` — существующее общее поведение контроллера (как и в LFPT-314), не связано с этим багом.
- **Изменение `previewRounds` (строка 255)** — редирект-таргет `/tournaments/americano/{tournamentId}/initialize` в catch-блоке не переписывается напрямую на `/admin/tournaments/{tournamentId}`, хотя это устранило бы двойной 302-редирект и точнее донесло бы флеш-сообщение об ошибке предпросмотра (сейчас это сообщение фактически теряется при двойном редиректе — см. Edge cases). Решение — минимизировать диф этой фичи строго до причины бага, описанной в issue (падение в `showInitializeForm`); оптимизация цепочки редиректов в `previewRounds` — отдельная, самостоятельная UX-доработка, не баг-фикс. Рекомендуется отдельный тикет, если владельцу продукта важно сохранять текст ошибки предпросмотра при её возникновении.
- **Отдельная находка вне скоупа, обнаруженная в процессе анализа:** ветка "неверный тип турнира" в этом же методе (`showInitializeForm`, п.2 функциональных требований) редиректит на `/tournaments/{tournamentId}` — такого маршрута не существует ни в одном контроллере (подтверждено `grep` по `src/main/java`; реальный маршрут деталей турнира — `GET /torneo/{id}`, единственное число, испанский, `TournamentViewController`). Переход по этой ветке приводит к обычной HTTP 404 (Spring "No handler found"), а не к падению приложения — потому не подпадает под формулировку issue про `TemplateInputException`, и не является предметом этого тикета. **Тот же самый паттерн (`redirect:/tournaments/" + tournamentId`) присутствует и в соседнем методе `showRegisterForm`** (строка 100, "неверный тип турнира"), который вообще не упомянут в issue #316. Оба случая — самостоятельный баг с иной причиной (сломанная ссылка на несуществующий роут, не мёртвый шаблон), затрагивающий два разных метода. Рекомендуется завести отдельный тикет (например, LFPT-317) на исправление обоих на `/torneo/{tournamentId}` — не включаем в этот PR, чтобы не расширять скоуп сверх того, что описано в issue.

## Изменения в системе

### API
- `GET /tournaments/americano/{tournamentId}/initialize` — поведение ветки "не инициализирован" меняется (см. Функциональные требования, п.1). URL, HTTP-метод, path-параметр не меняются. Остальные две ветки метода не меняются.

### БД
Нет изменений. Новая Liquibase-миграция не требуется.

### UI
Новых шаблонов нет. Целевая страница редиректа (`admin/tournaments/details.html` через `GET /admin/tournaments/{id}`) уже существует и не изменяется в рамках этой фичи.

### Документация

- [ ] `GET /tournaments/americano/{tournamentId}/initialize` для уже инициализированного AMERICANO-турнира по-прежнему возвращает HTTP 302 на `/tournaments/americano/{tournamentId}` с flash `info` = `"El torneo ya está inicializado"` (регресс не сломан).
- [ ] MVC/юнит-тест на `AmericanoViewController.showInitializeForm`, покрывающий все три ветки выше (структура аналогична существующему `AmericanoViewControllerTest`, покрывающему `showAdminPreviewForm` для LFPT-314).
- [ ] Отдельный тест (или явный комментарий/assert в существующем тесте на `previewRounds`), подтверждающий, что catch-блок `previewRounds` по-прежнему редиректит на `/tournaments/americano/{tournamentId}/initialize` (регресс не сломан) — и что этот редирект теперь не приводит к падению при последующем переходе (косвенно покрывается тестом на `showInitializeForm` из предыдущего пункта, так как это тот же самый обработчик).

- [ ] `.claude/CLAUDE.md`, раздел "Americano Admin Pages" — добавлена запись о фиксе (аналогично записи про LFPT-314). `.claude/` целиком в `.gitignore` — правка не попадёт в git-diff PR, обновляется на диске worktree и синхронизируется архитектором в основной репозиторий отдельно (см. `develop-feature.md`), не блокирует PR.

## Edge cases
- Несуществующий `tournamentId` — поведение не меняется (`IllegalArgumentException`, как и раньше), не покрывается тестом в рамках этой фичи (аналогично LFPT-314).
- Турнир существует, но неактивен/удалён (`getActiveTournamentById` не находит) — то же самое, не меняется.
- Конкурентный доступ — не применимо, метод не пишет в БД (только `GET`, только чтение `isInitialized`/`getActiveTournamentById`), 2 реплики за Docker Swarm ничего не меняют для этого чтения.
- Пользователь без прав ORGANIZER/SUPER_ADMIN, но аутентифицированный (например, `ROLE_PLAYER`), заходит на `GET /tournaments/americano/{id}/initialize` напрямую (нет `@PreAuthorize`, только `.anyRequest().authenticated()`) — после фикса, если турнир не инициализирован, его перекинет на `/admin/tournaments/{id}`, где сработает уже существующая (не меняемая этой фичей) ролевая проверка `/admin/**` (`hasAnyRole("OWNER","SUPER_ADMIN","ORGANIZER","ADMIN")`) и сработает уже существующий `CustomAccessDeniedHandler` (issue #278) — на практике не голый 403, а мягкий редирект на публичную страницу турнира `/torneo/{id}` (200). Это отличается от LFPT-314 (там целевой роут был `/admin/tournaments/americano/admin/...`, тоже без явной ролевой проверки на самом методе, но по факту недостижим для игрока не через админку) — в любом случае после фикса поведение объективно лучше, чем `TemplateInputException`/500 до фикса, регресса нет.
- Флеш-сообщение об ошибке из `previewRounds` (текст конкретной причины сбоя предпросмотра, например "número insuficiente de jugadores") при цепочке `previewRounds` → `showInitializeForm` → редирект на `/admin/tournaments/{id}` технически теряется, так как `showInitializeForm` не переносит флеш дальше (Spring `RedirectAttributes`-флеш привязан к следующему запросу, а не ко всей цепочке редиректов). Это не регресс — до фикса сообщение тоже фактически не доходило до пользователя (браузер получал страницу ошибки вместо сообщения), но явно фиксируем как известное ограничение, не устраняемое в этой фиче (см. "Вне скоупа").

## Открытые вопросы
Нет открытых вопросов, требующих бизнес-решения. Технический выбор (редирект на `/admin/tournaments/{id}` вместо нового шаблона) обоснован кодом: это единственная страница с реальной, поддерживаемой формой конфигурации/инициализации Americano, и именно туда фактически ведёт форма `preview-rounds`, чей error-path — единственный реально воспроизводимый путь попадания на этот роут помимо ручного набора URL. Две находки, выходящие за рамки этого тикета (сломанный редирект `/tournaments/{id}` в ветке "неверный тип" — присутствует в этом методе и в соседнем `showRegisterForm`; неоптимальная потеря флеш-сообщения при двойном редиректе из `previewRounds`), явно вынесены в "Вне скоупа" с рекомендацией завести отдельные тикеты — не блокируют статус `approved` этой спеки.
