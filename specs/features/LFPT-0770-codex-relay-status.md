## Контекст / зачем
В руководстве миграции описан аварийный монитор, но отсутствуют команды текущей диагностики. Оператору нужно проверить контейнер relay, расписание таймера и результат последней проверки без запуска уведомлений.

## Связь с MASTER.md
Бизнес-инварианты MASTER.md не затрагиваются. Меняется только эксплуатационная документация.

## Требования

### Функциональные
- Добавить в `docs/codex-migration.md` отдельный раздел проверки состояния relay и аварийного таймера.
- Привести команды чтения состояния контейнера `codex-worker-worker-1`, счётчика перезапусков и ограниченного журнала.
- Привести команды чтения состояния, включения при загрузке и расписания `padel-codex-monitor.timer`, результата последнего запуска `padel-codex-monitor.service` и его журнала.
- Объяснить ожидаемые результаты: работающий контейнер, активный таймер, минутный интервал, допустимый `inactive (dead)` для завершившегося oneshot. Успешное завершение монитора само по себе не доказывает исправность relay и доставку уведомления.

### Нефункциональные
Документация на русском; новые строки UI и i18n отсутствуют. Команды выполняются оператором на сервере с необходимыми правами. Не выводить окружение, секреты или приватное состояние; диагностические журналы просматривать локально и очищать перед публикацией. Команды не должны запускать монитор вручную, менять службы или отправлять сообщения.

## Вне скоупа
Изменение приложения, relay, монитора, unit-файлов и конфигурации; активация или перезапуск служб; диагностика реального сервера.

## Критерии приёмки
- [ ] В новом разделе есть команды состояния, счётчика перезапусков и ограниченного журнала контейнера, совпадающего с `monitor.py`.
- [ ] Есть команды `is-active`, `is-enabled`, `list-timers` для таймера и чтения результата/журнала oneshot-службы; имена совпадают с unit-файлами.
- [ ] Объяснены минутное расписание, нормальное завершение oneshot и ограничения успешного exit status монитора.
- [ ] Все диагностические команды только читают состояние; нет вывода окружения/секретов, ручного запуска мониторинга и отправки сообщений.
- [ ] Diff содержит только документацию и спецификацию; `docs-drift.py`, `check-agent-migration.py` и существующие тесты relay проходят, `git diff --check` без замечаний.

## Edge cases
Отсутствующий контейнер или unit трактуются как повод сверить установку и имя проекта, а не запускать второй polling. Нет доступа к Docker/systemd — оператор использует предусмотренные права на хосте. Отсутствие записей журнала или успешный exit status не доказывают сквозную работоспособность конвейера. Конкурентный доступ и миграции данных неприменимы.
