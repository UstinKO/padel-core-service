# LFPT-364: Компактные таблицы рейтинга/квалификации на мобильных экранах

approved

## Источник
GitHub issue [#364](https://github.com/UstinKO/padel-core-service/issues/364), заведён конвейером `/develop-feature` (режим cloud) по прямой технической задаче архитектора, пришедшей через Telegram (скриншот + короткое описание). Прямой вход, `specs/requests/` не создавался.

Telegram-сообщение (для reply): 4262

## Контекст / зачем

На узких мобильных экранах публичные страницы турниров с широкими таблицами (рейтинг Americano/Team Americano, квалификационный рейтинг Team Playoff — до 13 колонок: `#`, Статус, Пара, Ситуация, P1, P2, SG, SP, GG, GP, Dif.S, Dif.G, PJ) не сжимаются под ширину экрана: шрифт и внутренние отступы ячеек остаются такими же, как на десктопе. В результате на экране видно 2-3 первые колонки, остальное скрыто за горизонтальным скроллом (`overflow-x:auto` на обёртке уже есть и остаётся рабочим фолбэком). Архитектор прислал скриншот `/tournaments/team-playoff/{id}` (591px ширина) в подтверждение.

## Связь с MASTER.md

Чисто визуальное/CSS изменение публичных страниц просмотра турниров, бизнес-логику и инварианты `MASTER.md` не затрагивает.

## Требования

### Функциональные
- На трёх публичных страницах турниров с идентичным паттерном таблицы (`class="table"` внутри обёртки `overflow-x:auto`/`.ranking-table`) уменьшить font-size и padding ячеек таблицы через `@media`-запросы, чтобы на мобильном экране (≤768px, дополнительно ужесточить на ≤480px) помещалось заметно больше данных без потери читаемости:
  - `templates/tournaments/team-playoff/view.html` — квалификационная таблица (секция "Квалификационная таблица" / `team_playoff.qual.ranking`), пример со скриншота.
  - `templates/tournaments/americano/view.html` — таблица рейтинга (`.ranking-table`).
  - `templates/tournaments/team-americano/view.html` — таблица рейтинга (`.ranking-table`).
- Подход — тот же, что уже применён в проекте для карточек кортов в `americano.css` (комментарий "Responsive - просто сжимаем, не ломая структуру"): только уменьшение размеров, без скрытия колонок и без смены табличной структуры на карточки. Колонки остаются те же, полный набор данных доступен без прокрутки экрана вниз или дополнительных кликов — только уменьшенным шрифтом.
- Горизонтальный скролл (`overflow-x:auto`) остаётся как фолбэк на случай экранов уже 480px, где даже сжатая таблица не помещается целиком — не убирать.

### Нефункциональные
- Не затрагивает бэкенд, API, БД — чисто CSS/HTML правка трёх существующих Thymeleaf-шаблонов.
- i18n не требуется — новых пользовательских строк нет.
- Не ломает существующую desktop-вёрстку (изменения только внутри `@media (max-width: 768px)`).

## Вне скоупа
- Не переделываем таблицы в карточки/адаптивный список на мобильном (сохраняем табличную структуру, как в остальном проекте).
- Не трогаем другие таблицы проекта вне трёх перечисленных страниц (например, admin-панель — не публичная, не мобильный сценарий по назначению).
- Не меняем брейкпоинты/подход в `americano.css` для уже существующих mobile-блоков (карточки кортов) — только добавляем новые правила для `.table`/`.ranking-table`.

## Критерии приёмки
- [ ] На `/tournaments/team-playoff/{id}` (турнир с непустым `qualStarted`/рейтингом) при ширине вьюпорта 480px и 375px таблица квалификации отображается с уменьшенным шрифтом/отступами по сравнению с desktop-версией (проверяется вычисленным `font-size`/`padding` через Playwright, не на глаз).
- [ ] На тех же ширинах видно больше строк/колонок таблицы в одном экране без скролла, чем до изменения (сравнение computed CSS до/после, не скриншот на глаз).
- [ ] Аналогичное сжатие подтверждено для `.ranking-table` на `/tournaments/americano/{id}` и `/tournaments/team-americano/{id}`.
- [ ] Desktop-вёрстка (≥769px) визуально не изменилась — `font-size`/`padding` `.table th`/`.table td` совпадают со значениями до правки.
- [ ] `overflow-x:auto` на обёртке таблицы сохранён на всех трёх страницах (фолбэк-скролл не убран).
- [ ] Существующий функционал страниц не сломан: переключение раундов квалификации (`team-playoff`), realtime-обновление через WebSocket, отображение статусов команд/матчей — работает как раньше (ручная проверка в браузере).

## Edge cases
- Пустой рейтинг (`ranking == null` / `qualStarted == false`) — блок таблицы не рендерится вовсе (`th:if="${qualStarted}"`), медиа-правки на этот случай не влияют.
- Очень длинные имена игроков в колонке "Пара"/"Team" — не в скоупе этой правки (не регрессия, поведение не меняется, `overflow-x:auto` по-прежнему доступен).
