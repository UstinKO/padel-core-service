# LFPT-1254. Одиночные заявки в оплатах — сервер

Статус: approved. Интерфейс — #1255. Основание: согласованный план от 22.11.2026.

## Границы

Обычная страница оплат, парная регистрация. SUPER_ADMIN/ADMIN используют действующий глобальный доступ; ORGANIZER/CLUB_ADMIN — действующее право управления конкретным турниром. Клуб не получает чужие мероприятия на своей площадке. Новые роли и назначения координаторов не вводятся по решению пользователя.

## Действия

- Чтение всех активных неполных заявок, включая SOLO_SEARCH, SOLO_ADD_LATER, WAITLIST и сохранённое место после выхода партнёра. Отдельно доступны отменённые одиночные заявки с платежами.
- Добавление существующего игрока или гостя штатным механизмом без обязательного email. Поиск по имени/фамилии/телефону/Telegram. Найденная действующая заявка открывается вместо повторной записи.
- Добавление партнёра из общей базы/гостя либо объединение двух существующих неполных заявок. Превью показывает участников, исходные/итоговый статусы, отдельные оплаты, предупреждения и влияние на проведение.
- Снятие с турнира через отмену с известным инициатором; профиль, платежи и история сохраняются. Возврат денег не выполняется.

## Инварианты

1. Существующие ID заявок и профилей сохраняются. Одна пара — две связанные регистрационные строки, одно парное место, единый booking ID.
2. Оплаты остаются на исходных регистрационных ID. Текущие платежи переводятся на общий booking ID без копирования; исторические платежи других booking ID не переносятся. Оплата, валюта, комментарии, подтверждения и присутствие каждого независимы.
3. Неполный резерв места не занимает. Сохранённое основное место используется при дополнении/объединении. Два резерва сначала образуют одну резервную пару; продвижение только штатной очередью #759. Освобождение и продвижение происходят после сохранения всей пары. Более раннее время очереди сохраняется.
4. Изменения сериализуются блокировкой турнира. Повтор UUID возвращает прежний результат; другой состав с тем же UUID отклоняется. Превью имеет контроль состояния; конкурентное изменение требует нового превью.
5. Начатая квалификация не блокирует незадействованных игроков. Матчи, где затронутые игроки/команды уже назначены, в очереди или сыграли, защищены: ответ содержит конкретные матчи и переход к существующей корректировке. Круговое расписание/посев плей-офф не пересоздаются.
6. После ранее выполненного импорта незадействованная команда обновляется без дубля; неполная команда не готова к матчу. Повторный импорт не создаёт дополнительные команды. При отсутствии прежнего импорта сохраняется штатный запуск проведения.
7. Уведомления о снятии/продвижении — после commit. Объединение не рассылает ложную отмену; напоминания об отсутствующем партнёре прекращаются. Служебный журнал фиксирует автора, время, заявки и действие.
8. Правила допуска сохраняются; уже существующее право ручного добавления вне уровня используется только с явным подтверждением предупреждения. Уровни профилей не редактируются.

## Проверка

Изолированный PostgreSQL: две валюты и две оплаты после объединения, присутствие каждого; основа+основа, основа+резерв, резерв+резерв, полный турнир; снятие и история; гость и повтор; два конкурирующих сотрудника; доступ всех четырёх ролей и отказ к чужим объектам; импорт/повторный импорт/начатая квалификация; защищённые матчи; отсутствие ложной отмены. Полный verify и обязательные проверки репозитория. Production не изменяется.
