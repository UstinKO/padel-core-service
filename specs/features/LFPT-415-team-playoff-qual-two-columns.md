## Контекст / зачем

Админ-страница `admin/americano/tournament-playoff.html` (`/tournaments/team-playoff/admin/{id}`, раздел "Квалификация") показывает матчи квалификации как один раунд за раз: кнопки-вкладки "Раунд 1"/"Раунд 2" переключают видимость (`switchQualRound()`, JS), каждая карточка матча растянута на всю ширину контейнера. Во время турнира координатору приходится постоянно переключаться между вкладками, чтобы сопоставить первый и второй матч одной и той же команды — на десктопе при этом остаётся неиспользуемое свободное пространство по бокам.

Технически "Раунд 1"/"Раунд 2" — не отдельные сущности `AmericanoRound` (квалификация всей фазы турнира — один round-контейнер, `TeamPlayoffService.getOrCreateQualificationRound`), а визуальные "волны" матчей, полученные на бэкенде через `TeamPlayoffViewController.splitQualificationWaves()`: матчи группируются по `max(team1MatchOrdinal, team2MatchOrdinal)` — первый матч команды (M1) попадает в волну 1, второй (M2) — в волну 2. Это уже готовые, разделённые по вкладкам-волнам данные ровно в нужной структуре — доработка нужна только в шаблоне (HTML/CSS), без изменений в контроллере/сервисе.

## Связь с MASTER.md

Чисто фронтенд-доработка отображения существующего экрана администратора. Не затрагивает роли, статусы регистрации, форматы турниров или другие инварианты `specs/MASTER.md` — файл не меняется.

## Требования

### Функциональные

1. **Десктоп (viewport ≥ 1025px)** — обе волны квалификации (`qualRounds[0]` = Раунд 1/M1, `qualRounds[1]` = Раунд 2/M2, если уже существует) отображаются одновременно, без переключения: левая колонка — Раунд 1, правая — Раунд 2. Кнопки-вкладки "Раунд 1"/"Раунд 2" (`#qualTabs`) на этой ширине скрываются — они не нужны, когда обе волны видны одновременно.
   - Брейкпоинт `1025px` выбран по уже принятому в проекте разделению tablet/desktop (`admin.css`: `@media (min-width: 769px) and (max-width: 1024px)` для планшета, `> 1024px` — десктоп) — двухколоночная раскладка активируется только на "настоящем" десктопе, не на планшете, чтобы не сжимать карточки матчей до нечитаемой ширины на промежуточных экранах. Техническое решение, не бизнес-вопрос.
   - Если существует только волна 1 (волна 2 ещё не создана — ни одна команда не сыграла второй матч) — под колонкой "Раунд 1" пустого места для "Раунда 2" нет, единственная волна занимает всю ширину блока (`grid-template-columns: repeat(auto-fit, minmax(...))` естественно даёт 1 колонку на 1 элемент).
   - Над каждой колонкой — заголовок с номером раунда (переиспользуется существующий ключ `americano.round.prefix` + `round.roundNumber`, тот же текст, что сейчас показывают кнопки-вкладки).
   - Карточки матчей (`.match-card`) в двухколоночном режиме уже физически вдвое уже (колонка ≈ половина ширины блока) — дополнительно уменьшаются внутренние отступы/размер шрифта (`.match-header`, `.match-body`, `.team-name`, `.team-sub`) для компактности, аналогично точечным admin-only уменьшениям, уже принятым в проекте (LFPT-407).
2. **Мобильная/планшетная версия (viewport ≤ 1024px)** — поведение не меняется: кнопки-вкладки "Раунд 1"/"Раунд 2" видимы, активна ровно одна волна за раз, переключение по клику (`switchQualRound()`, без изменений в JS).
3. **Заметность M1/M2.** Существующий бейдж возле имени команды (`admin.playoff.col.m1`/`admin.playoff.col.m2`, уже выводится в карточке матча — `match.team1MatchOrdinal`/`match.team2MatchOrdinal`) получает различающуюся заливку вместо нейтрального серого `.info-pill`: M1 — один акцентный цвет, M2 — другой, жирным. Эффект: в паре с двухколоночной раскладкой из п.1 координатор видит сразу — команда с бейджем M1 только в левой колонке ещё не играла второй матч (ждёт), с бейджами и в левой, и в правой — уже сыграла оба. Текст бейджей (`M1`/`M2`/`P1`/`P2` по локали) не меняется — только визуальное усиление.
4. Область "Nuevo partido" (форма создания нового матча) и раздел "Playoff" (`.round-content` там же класс, что и у блока волн квалификации) — их вёрстка и раскладка не должны измениться этой доработкой, так как это два **разных** назначения одного и того же класса `.round-content` на странице. Правки CSS должны быть заскоуплены отдельным id/классом, специфичным для блока волн квалификации, а не глобально по `.round-content`.

### Нефункциональные
- i18n: новых пользовательских строк нет — переиспользуются уже существующие ключи (`americano.round.prefix`, `admin.playoff.col.m1`, `admin.playoff.col.m2`) для всех трёх локалей (es/ru/en, уже присутствуют).
- Безопасность: не применимо — чистая вёрстка существующей admin-only страницы, новых точек ввода данных нет.
- Производительность: не применимо — чистый CSS/HTML, без новых запросов к серверу.

## Вне скоупа

- Любые изменения в `TeamPlayoffService`/`TeamPlayoffViewController` — данные волн (`splitQualificationWaves`) уже в нужной форме, бэкенд не трогается.
- Публичная страница турнира (`tournaments/team-playoff/view.html`) — запрос касается только админки; на публичной странице нет раундов-вкладок квалификации в этом виде (там таблица рейтинга, уже адаптирована в #364/#407).
- Секция "Playoff" (сетка плей-офф ниже квалификации на той же странице) — не двухколоночная, остаётся как есть.
- Таблица рейтинга квалификации (`.table` со счётом/сетами/etc, строки 376-422 шаблона) — уже адаптирована отдельно (#407), этой доработкой не затрагивается.
- Блок "Partidos en cola" (очередь без корта, LFPT-367) — отдельный блок выше волн раундов, не входит в двухколоночную раскладку.
- Автоматическая визуальная подсветка "одна и та же команда в обеих колонках" (например, линия-коннектор между карточками) — не запрошено явно, усложнение сверх ТЗ; заметность M1/M2-бейджа из п.3 уже даёт нужный эффект сопоставления без этого.

## Критерии приёмки

- [ ] На viewport ≥ 1025px, квалификация с уже созданными матчами в обеих волнах (M1 и M2): обе колонки "Раунд 1"/"Раунд 2" видны одновременно на одном экране без клика по вкладкам, кнопки-вкладки `#qualTabs` не видны.
- [ ] На viewport ≥ 1025px, квалификация только начата (сыграны/создаются только матчи M1, волна 2 ещё не существует): видна только одна колонка "Раунд 1" на всю ширину блока, ничего не падает и не рендерит пустую вторую колонку.
- [ ] На viewport ≤ 1024px (мобильный/планшетный) поведение не изменилось: видна ровно одна волна, кнопки-вкладки "Раунд 1"/"Раунд 2" видны и переключают активную волну по клику, как до доработки.
- [ ] Бейдж M1 и бейдж M2 у команды в карточке матча визуально различаются цветом (не одинаковый нейтральный `.info-pill`-серый, как до доработки) на всех вьюпортах.
- [ ] Секция "Nuevo partido" (форма создания нового матча) и секция "Playoff" (сетка плей-офф) визуально не изменились — их раскладка не задета новым CSS, заскоупленным по `#qualRoundContent`.
- [ ] Ввод счёта, изменение корта/команды у ещё не завершённого матча (`toggleCourtEdit`/`toggleTeamEdit`/`submitQualScore` и т.п.) продолжают работать без изменений в обеих колонках десктопной раскладки — JS не менялся, но нужно убедиться, что двухколоночная раскладка не ломает клики/раскрытие инлайн-форм редактирования.
- [ ] `./mvnw compile -DskipTests` проходит.
- [ ] Реальный проход в браузере (Playwright, `cloud`-режим) на десктопном и мобильном вьюпорте с турниром, у которого квалификация начата — подтверждает пп. выше визуально (скриншот/DOM-проверка), не только чтение кода шаблона.

## Edge cases

- Только одна волна существует (см. выше, п.2 критериев) — не должно быть пустой второй колонки/лишнего пустого пространства с рамкой.
- Волн больше двух теоретически не бывает — `splitQualificationWaves` группирует по `max(ordinal1, ordinal2)`, а ordinal команды не может быть больше 2 (M1/M2, по одному матчу каждого типа на команду в этом формате) — на верстку это не влияет: `grid-template-columns: repeat(auto-fit, minmax(...))` корректно отрисует любое фактическое количество волн, если оно вдруг окажется больше 2.
- Квалификация не начата вообще (`qualStarted == false`) — блок волн (`th:if="${not #lists.isEmpty(qualRounds)}"`) не рендерится совсем, как и сейчас — доработка не затрагивает этот путь.
- Ресайз окна браузера в реальном времени с десктопной ширины на мобильную (или наоборот) без перезагрузки страницы — переход между режимами чисто на CSS (`min-width` медиа-запрос), должен происходить сразу, без некорректно застрявшего состояния (при переходе на мобильную ширину видна ровно та волна, что была активна последней по JS-состоянию — как правило первая, если пользователь не переключал вкладки на десктопе).
