# LFPT-1350: Feature многомодульный монолит — выделить расчёт мест кругового турнира SETS

## Статус

done

## Источник

[Issue #1350](https://github.com/UstinKO/padel-core-service/issues/1350), родитель #1041, предшественник #1343 / PR #1347. Техническая постановка напрямую из поручения продолжить переход после мержа.

## Контекст / зачем

RoundRobinStandings вычисляет места по JPA-сущностям. Прямой перенос в engines нарушил бы принятую границу. Выделяется только SETS и мини-таблица личных встреч с минимальными нейтральными входами; legacy-адаптер сохраняет статический Java API, исходные entity и действующий режим POINTS.

## Связь с MASTER.md

Сохраняются правила кругового парного турнира: победы, общая разница геймов, победы/разница внутри группы с равными общими показателями; общие места SETS и номера команд только для порядка строк. Дополнительные встречи не меняют круговую статистику. Бизнес-инварианты и #1243/#1244 не меняются.

## Требования

### Функциональные

- До замены выполнить расширенный characterization-набор исходного RoundRobinStandings. Ожидаемые результаты после замены не менять.
- Создать RoundRobinSetStandingsEngine в существующем engines: только JDK, собственные record Team/Match/Ranked и private Meetings. Входы не содержат entity/DTO/legacy enum, display name, principal или ссылки на БД.
- Номер исходной строки связывает результат с исходным объектом команды; id команды используется для личных встреч. Возвращаемые из RoundRobinStandings.Ranked объекты сохраняют идентичность, входные списки и поля не меняются.
- MapStruct в bootstrap преобразует entity в нейтральный вход и результат в legacy Ranked с исходной entity по индексу. Статическая фабрика default-маппера — адресный переходный мост для сохранения существующего static API, без нового Spring bean/изменения сервисных конструкторов.
- POINTS-ветка RoundRobinStandings и весь RoundRobinRules сохраняются. SETS-адаптер передаёт только завершённые круговые встречи с обоими счетами; порядок прежней фильтрации сохраняется. Для пустого списка команд матчи не читаются. null mode сохраняет существующий путь SETS этого Java API; сервисный fallback null scoringMode→POINTS не меняется.
- TeamAmericanoService, управление currentPosition/saveAll, транзакции, права, история, HTTP/JSON/UI, начисление и дополнительные матчи сохраняются.
- Artifact guard требует восемь вычислительных классов и девятнадцать вложенных типов; Java 17, без shadow/framework. ArchUnit не ослаблять.

### Нефункциональные

Новый engine тестируется без Spring/БД. Полный clean verify с frontend выполняется на отдельной PostgreSQL; итоговый jar — в своём preview, с прежним jar/возвратом и отпечатком схемы/Liquibase. Переводы, миграции и новые интеграции не требуются.

## Вне скоупа

Перенос POINTS/начисления/дополнительных встреч, изменение формулы/правил/внешнего API, новые application/persistence/web/integrations-модули, физическая БД и Swarm. #1051 остаётся поздним этапом.

## Изменения в системе

### API

Существующий RoundRobinStandings.rank/Ranked и HTTP/JSON/WS сохраняются. Внутренний engine API содержит только нейтральные вычислительные данные.

### БД

Без схемы/Liquibase и пользовательских данных; используются синтетические fixtures собственного контура.

### UI

Production UI не меняется. Настоящий браузер проверяет SETS/POINTS, результаты, дополнительные встречи/завершение и историю на итоговом jar.

### Документация

.agents/PROJECT.md, docs/architecture.md, план/навигация модульного монолита, отдельный отчёт с моделью адаптера, результатами до/после и безопасной сводкой.

## Критерии приёмки

- [x] Расширенные тесты проходят до/после на legacy API с теми же ожиданиями; исходные тесты RoundRobinRules/Standings сохраняются.
- [x] Автономные engine-тесты проверяют все критерии SETS, состав мини-таблицы, общие места и порядок строк; адаптер сохраняет ссылки/поля/порядок входов, POINTS не читает матчи.
- [x] MapStruct генерирует преобразования; JPA/DTO не проникают в engines; artifact/ArchUnit-проверки проходят.
- [x] Полный clean verify с frontend на отдельной PostgreSQL проходит, включая RoundRobinIntegration/Elo и Team Playoff.
- [x] Итоговый jar проходит Round Robin SETS/POINTS через реальные API/браузер, общий smoke, репетицию выпуска/отката; прежний jar и возврат сохраняют результаты/позиции и схему/Liquibase.
- [x] Документация, автоматика, ссылки, приватность и локальное ревью пройдены, ограничения отражены.

## Edge cases

Пустой/одиночный состав, полное равенство/цикл, разные номера при одинаковом спортивном месте, одинаковый номер при разных id, чужие/placement/pending матчи и неполный счёт; POINTS с одинаковыми id и нечитаемым списком матчей. Для SETS существующий отказ при дублирующемся id не превращается в новое правило. Взаимодействие с JPA остаётся в прежней сервисной транзакции; engine только вычисляет результат.
