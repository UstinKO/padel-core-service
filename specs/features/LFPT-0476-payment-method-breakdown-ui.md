# LFPT-0476: Feature вывод разбивки суммы оплат по способу оплаты на странице платежей турнира (фронтенд)

## Контекст / зачем

Зависимая бэкенд-задача [LFPT-0475](https://github.com/UstinKO/padel-core-service/issues/475) (PR [#478](https://github.com/UstinKO/padel-core-service/pull/478), смержен) уже передаёт в шаблон `admin/tournaments/payments.html` новый атрибут модели `paymentBreakdown` (`List<CurrencyPaymentBreakdownDto>`), но ни один шаблон его не использует. Эта задача — только разметка: вывести эту уже готовую агрегированную разбивку под существующим блоком общей суммы по валюте (`.summary-stats`), чтобы организатор видел не только "ARS — $330 000", но и сколько из этой суммы пришло наличными/переводом/картой/по какой крипто-площадке.

## Связь с MASTER.md

Раздел "Платежи" `specs/MASTER.md` — платежи фиксируются организатором вручную в админ-панели, без платёжного шлюза. Эта фича не меняет механизм фиксации оплаты, только добавляет отображение уже агрегированных на бэкенде данных. Инварианты не меняются, обновление `MASTER.md` не требуется.

## Требования

### Функциональные
- Под (или рядом с) существующим блоком `.summary-stats` (суммы по валюте) вывести новый блок: для каждого элемента `paymentBreakdown` — валюта, общая сумма (`total`) и список `byMethod` (способ → сумма).
- Подпись способа оплаты — через существующие ключи `enum.paymentMethod.*` (`method.method.name()`), без дублирования текста из `PaymentMethod.getDisplayName()`/`getDescription()`.
- `method.method == null` ("способ не указан", `PAID` без выбранного способа) — отдельная строка с текстом из нового ключа `admin.payments.breakdown.no_method`, не пропускается молча.
- Бэкенд уже не передаёт способы с нулевой суммой по валюте и валюты без единого подходящего платежа — шаблон не должен сам повторно фильтровать (`byMethod`/`paymentBreakdown` рендерятся как есть, без дополнительных `th:if` по сумме).
- Если `paymentBreakdown` пуст (турнир без единого `PAID`-платежа) — весь блок разбивки не выводится (`th:if` на уровне обёртки), остальная страница (таблица, форма) рендерится как обычно.

### Нефункциональные
- i18n: новые пользовательские строки — заголовок блока (`admin.payments.breakdown.title`), подпись "всего" (`admin.payments.breakdown.total`) и подпись группы "способ не указан" (`admin.payments.breakdown.no_method`) — во все три файла (`messages_es.properties`, `messages_ru.properties`, `messages_en.properties`), рядом с существующими `admin.payments.*` ключами. Подписи самих способов — существующие `enum.paymentMethod.*`, новых не заводится.
- Безопасность — новой точки входа данных от пользователя нет, страница и её доступ (`tournamentAccessService.assertCanManageTournament`) не меняются, блок read-only.
- Стиль — компактный, в духе существующего `.summary-stats`/`.payment-legend` (см. `payment-management.css`), не вводить новый визуальный язык без необходимости.

## Вне скоупа
- Логика агрегации (валюта/способ/фильтр `PAID`/обработка `partnerRow`) — сделана в LFPT-0475, здесь не трогается и не проверяется повторно юнит-тестами (уже покрыта `PaymentServiceBreakdownTest`).
- Изменение существующего блока общей суммы по валюте (`.summary-stats`, `#aggregates.sum(...)`) — остаётся как есть (известная отдельная проблема — issue [#477](https://github.com/UstinKO/padel-core-service/issues/477), технический долг, не эта задача).
- Отдельное поле/селектор площадки для крипты — не требуется, `BY_BIT`/`BINANCE` — обычные элементы `PaymentMethod`, различаются автоматически через существующие `enum.paymentMethod.*` подписи.
- Числовое форматирование суммы (разделители тысяч) — не вводится: существующий блок `.summary-stats` выше тоже выводит `BigDecimal` без форматирования (`#aggregates.sum(...)` без `#numbers.formatDecimal`); новый блок держит тот же стиль ради консистентности, это не регрессия и не в скоупе issue.

## Изменения в системе

### API
Без изменений — `GET /admin/tournaments/{tournamentId}/payments` уже отдаёт `paymentBreakdown` в модель (LFPT-0475).

### БД
Не требуется.

### UI
- `src/main/resources/templates/admin/tournaments/payments.html` — новый блок `<div class="payment-breakdown" th:if="${paymentBreakdown != null and not #lists.isEmpty(paymentBreakdown)}">` сразу после закрывающего `</div>` блока `.summary-stats` (строка 93 в текущей версии), перед блоком `.payment-legend`. Внутри — `th:each` по `paymentBreakdown`, и вложенный `th:each` по `byMethod` для каждой валюты.
- `src/main/resources/static/css/payment-management.css` — новые правила для `.payment-breakdown`/вложенных классов, в стиле уже существующих `.summary-stats`/`.stat-item`/`.payment-legend` (компактные блоки, та же цветовая палитра `#f1f5f9`/`#64748b`/`#0f172a`).
- Новые i18n-ключи `admin.payments.breakdown.title`, `admin.payments.breakdown.total`, `admin.payments.breakdown.no_method` — в `messages_{es,ru,en}.properties`.

## Критерии приёмки
- [ ] На странице `/admin/tournaments/{id}/payments` под блоком суммы по каждой валюте виден блок разбивки по способу оплаты (валюта + способ + сумма), для турнира с несколькими валютами и способами оплаты
- [ ] Для валюты без ни одного `PAID`-платежа в блоке разбивки эта валюта не отображается (бэкенд её не передаёт — проверяется, что шаблон не ломается и не домысливает нулевые строки)
- [ ] Для турнира вообще без оплаченных платежей (`paymentBreakdown` пуст) страница рендерится без ошибок, блок разбивки просто не выводится
- [ ] Платёж `PAID` без выбранного способа (`method == null`) отображается отдельной строкой с текстом `admin.payments.breakdown.no_method`, а не пропускается
- [ ] Подписи способов оплаты (включая `BY_BIT`/`BINANCE`) взяты из существующих `enum.paymentMethod.*`, отдельных новых ключей под способы не заведено
- [ ] Заголовок блока и подпись "способ не указан" переведены на `es`/`ru`/`en` (новые ключи присутствуют во всех трёх файлах)
- [ ] Визуально проверено в браузере (Playwright) на турнире с несколькими валютами/способами оплаты, включая `BY_BIT`/`BINANCE` и платёж без способа — не только чтение кода шаблона
- [ ] `./mvnw compile -DskipTests` проходит (чисто фронтенд-задача, но шаблон/i18n должны оставаться валидными)

## Edge cases
- Турнир без единого платежа или без единого `PAID`-платежа — `paymentBreakdown` пуст, блок не выводится, остальная страница (пустая таблица/заглушка) не затрагивается.
- Один и тот же способ в нескольких валютах (например `CASH` и в ARS, и в USD) — рендерится как две независимые строки в двух разных группах валют (бэкенд уже группирует по валюте отдельно).
- Способ `null` ("не указан") — рендерится, не пропускается (см. критерии приёмки).
- Валюта `USDT` — в существующем блоке `.summary-stats` выводится без символа валюты (`$`/`€`); новый блок разбивки выводит код валюты текстом (`ARS`/`USD`/`EUR`/`USDT`) без привязки к символам — единообразно для всех валют, не ломается на `USDT`.
