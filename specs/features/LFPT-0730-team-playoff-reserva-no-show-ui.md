# LFPT-0730: Feature отображение резерва и статуса «не пришла» в админке и на публичной странице Team Playoff (frontend)

## Статус
approved

## Источник
[specs/requests/LFPT-0729-reserva-no-show-team-playoff.md](../requests/LFPT-0729-reserva-no-show-team-playoff.md), issue [#730](https://github.com/UstinKO/padel-core-service/issues/730). Зависит от бэкенд-задачи [LFPT-0729](LFPT-0729-team-playoff-status-unificado.md) (PR #732): `AmericanoPlayerStatus.NO_SHOW`, `markNoShow`/`cancelNoShow`, `PaymentManagementViewDto.isReserve`.

## Контекст / зачем

LFPT-0729 сделал резерв (`WAITLIST`) видимым в данных страницы оплат (`isReserve`) и дал backend-механизм отметки «не пришла» (`AmericanoPlayerStatus.NO_SHOW`), но ни один шаблон ещё не использует эти данные. Администратор продолжает не видеть резерв на странице «Оплаты и посещаемость» и не имеет кнопки «Не пришла» в интерфейсе Team Playoff; обычный пользователь на публичной странице турнира видит только агрегированный счётчик листа ожидания, без самих резервных пар.

## Связь с MASTER.md

Не меняет инварианты `specs/MASTER.md` — чисто отображение уже существующих (после LFPT-0729) статусов.

## Требования

### Функциональные

1. **Публичная страница турнира** (`tournament-details.html`, формат Team Playoff/`AMERICANO_TEAMS`) — отдельная секция «Список ожидания / Резерв» со списком резервных пар по именам, визуально приглушённая (не выглядит как полноценный участник), под основной таблицей участников. Счётчик (`tournament.waitlist.double`) не трогается — список дополняет его, не заменяет.
2. **`admin/tournaments/payments.html`** — резервные строки (`player.reserve == true`) визуально отделяются от основного состава: приглушённый стиль строки + текстовая плашка «Резерв» в колонке игрока. Форма сохранения (`payments[i].*`) продолжает работать для резервных строк как и для любых других — админ может редактировать оплату/заметки резервной пары, не теряя данных при сохранении.
3. **`admin/americano/tournament-playoff.html`** — у каждой `ACTIVE`-команды в списке команд квалификации (где уже есть кнопки управления командой) — кнопка «Не пришла» (вызывает `POST /tournaments/team-playoff/admin/teams/{teamId}/no-show`); у команды в статусе `NO_SHOW` — бейдж «Не пришла» вместо обычных кнопок и кнопка «Отменить отметку» (`POST .../no-show/cancel`). Ошибка backend (команда уже сыграла матч) приходит как flash-сообщение (`error`) — отображается тем же механизмом, что и другие ошибки на этой странице.
4. **i18n** — все новые строки в `messages_{es,ru,en}.properties` (+ `messages.properties`): секция резерва на публичной странице, плашка «Резерв» на оплатах, кнопка/бейдж «Не пришла», подтверждение действия.

### Нефункциональные
- i18n — обязательно (новый пользовательский текст), проверка `Accept-Language: ru`/`es`/`en` вживую — нет смешения языков.
- Безопасность — новых точек входа данных нет, кнопки вызывают уже защищённые (`@PreAuthorize`) эндпоинты LFPT-0729.

## Вне скоупа
- Любые изменения backend-логики (сделаны в LFPT-0729, этот PR не их трогает).
- Отображение `NO_SHOW` в публичной квалификационной таблице (`team_playoff/view.html`) — не запрошено явно, публичная таблица квалификации и так не показывает команды без единого матча иначе, чем остальные (не задевает реальных пользователей сценария).

## Критерии приёмки
- [ ] Турнир 8 основных + 1 резерв: на `/torneo/{id}` видна секция со списком резервной пары по именам (не только счётчик).
- [ ] На `/admin/tournaments/{id}/payments` резервная пара видна с плашкой «Резерв», её данные оплаты/посещения можно сохранить через обычную форму.
- [ ] На странице Team Playoff админки у `ACTIVE`-команды есть кнопка «Не пришла»; после клика — бейдж «Не пришла» и кнопка отмены; команда не предлагается как доступная для квалификационного матча (backend-поведение LFPT-0729, здесь только отображение).
- [ ] Попытка отметить «Не пришла» для команды, уже сыгравшей матч — flash-сообщение с понятным текстом, не технический stacktrace.
- [ ] Все новые строки — под `ru`/`es`/`en`, без смешения языков.
- [ ] `./mvnw verify` зелёный, `docs-drift.py` — 0 расхождений.

## Edge cases
- Турнир без резерва (`reserveDoubleRegistrations` пуст) — секция на публичной странице не рендерится вообще (`th:if`).
- Не-Team-Playoff DOBLES турнир — секция резерва по именам не показывается (остаётся только существующий счётчик) — осознанно вне скоупа (см. «Вне скоупа» в бэкенд-спеке).
