# LFPT-0542: Feature компактный переключатель языка ES/EN/RU в шапке админ-панели (frontend)

## Статус
approved

## Источник
Клиентский запрос [specs/requests/LFPT-0541-admin-lang-switcher.md](../requests/LFPT-0541-admin-lang-switcher.md) (Telegram, пересланное сообщение от Evgeny_754, `telegram_launch_message_id: 4984`). GitHub issue [#542](https://github.com/UstinKO/padel-core-service/issues/542). Зависит от бэкенд-задачи [#541](https://github.com/UstinKO/padel-core-service/issues/541) (cookie-резолвер, `?lang=` override) — спека [LFPT-0541-admin-lang-switcher-backend.md](LFPT-0541-admin-lang-switcher-backend.md).

## Контекст / зачем
Бэкенд (#541) добавляет механизм, который принимает `?lang=es|ru|en`, сохраняет выбор в cookie и отдаёт ему приоритет над `Accept-Language`. Но без UI-элемента в админ-панели этим механизмом физически неоткуда воспользоваться — нужен компактный переключатель в шапке, рядом с приветствием администратора и кнопкой выхода.

## Связь с MASTER.md
Не затрагивает инвариантов `specs/MASTER.md` — чисто UI-слой над механизмом резолвинга локали из #541. Роли/доступ не меняются: переключатель виден всем, у кого есть доступ к `/admin/**` (`OWNER`, `SUPER_ADMIN`, `ORGANIZER`, `ADMIN`, `CLUB_ADMIN` — `SecurityConfig`).

## Требования

### Функциональные

1. **Единая точка изменения — `fragments/admin-header.html`.** Фрагмент `header(pageTitle)` уже используется всеми страницами `/admin/**` (подключается `th:replace`/`th:insert` во всех admin-шаблонах, см. `CLAUDE.md § Package Layout`/грep по `fragments/admin-header`). Добавить переключатель один раз в этот фрагмент — не дублировать по страницам.
2. **Разметка.** В блоке `.navbar-menu` с приветствием/кнопкой выхода (`admin-header.html`, рядом со `span.user-greeting` и формой `/logout`, перед или после них) — компактный блок из трёх вариантов: `ES` / `EN` / `RU` (коды языка, не полные названия — компактность, п.1 критериев запроса). Каждый вариант — элемент с `data-lang="es|en|ru"` (кнопка/ссылка, не `<select>` — быстрее кликать, нет лишнего шага открытия списка для всего трёх опций). Текущий активный язык — визуально выделен (класс `active`/`btn-primary` по аналогии с остальными `btn`-стилями проекта, см. `static/css/admin.css`), остальные два — обычный/приглушённый стиль.
3. **Поведение клика — JS, не перезагрузка на дефолтный URL.** Новый файл `static/js/lang-switcher.js` (подключается в `admin-header.html` рядом с `admin-menu.js`), слушает клики на переключателе и переходит на `location.pathname + '?' + <текущие query-параметры без старого lang> + 'lang=' + code` — то есть сохраняет остальные параметры текущей страницы (например `?clubId=5`, `?nivel=PRO` в списках `/admin/tournaments`, `/admin/players`), не просто `href="?lang=es"` (который стирал бы остальные параметры — проверено, у `/admin/tournaments` и `/admin/players` есть фильтры через query-параметры, терять их при переключении языка — плохой UX и не то, что просил клиент: "не перегружать", но и не ломать текущий контекст страницы). Серверная часть (`LocaleChangeInterceptor` из #541) сама применит `?lang=` и выставит cookie — на фронтенде никакого отдельного вызова API не нужно, обычная навигация браузера.
4. **Подсветка активного языка.** Текущий язык известен на сервере (`#locale.language`, уже используется в `admin-header.html` для `html lang`/подключения `messages-{lang}.js`) — передать его в разметку (например, `th:classappend` на элементе переключателя, сравнивая `data-lang` с `${#locale.language}` через `th:each`/`th:if` в разметке, без доп. JS-определения языка на клиенте).
5. **Компактность.** Три коротких элемента (`ES`/`EN`/`RU`, не полные названия языков) в одну строку, без выпадающего списка — минимальная ширина в шапке, не требует доп. breakpoint-правил в мобильном бургер-меню сверх уже существующих (`.navbar-menu` и так адаптивен, см. `admin.css`).
6. **Собственные данные не переводить** — не относится к этой задаче напрямую (эта задача не трогает отображение имён/названий клубов), зафиксировано как явное ограничение, не требующее кода: убедиться, что новый переключатель не добавляет никакой логики перевода динамических данных (названий, имён) — только статический UI-текст самого переключателя (если есть, например `aria-label`).

### Нефункциональные
- i18n: если добавляется `aria-label`/`title` для доступности (например "Idioma" / "Язык" / "Language") — новый ключ `admin.nav.language` во все три `messages_{es,ru,en}.properties`, по аналогии с существующими `admin.nav.*` (`messages_ru.properties:1834-1839`). Сами подписи вариантов (`ES`/`EN`/`RU`) — коды языков, не переводятся ни в одной локали (это не пользовательский текст, а идентификаторы языка, как и в клиентском запросе).
- Безопасность: новой точки входа данных от пользователя нет — клик формирует обычную GET-навигацию с уже валидируемым на бэкенде (#541) параметром `lang`.

## Вне скоупа
- Сам механизм резолвинга/приоритета/cookie — реализован в [#541].
- Применение переключателя к публичному сайту (`fragments/public-header.html`) и личному кабинету игрока — явно вне скоупа клиентского запроса (п.5 запроса), не реализуется в этой задаче.
- Перевод названий клубов/имён игроков/адресов — явно не делается (п.6 запроса).

## Изменения в системе

### API
Нет. Использует существующий (после #541) query-параметр `?lang=` — без изменений в контроллерах.

### БД
Нет.

### UI
- `src/main/resources/templates/fragments/admin-header.html` — новый блок переключателя в `.navbar-menu` рядом с приветствием/кнопкой выхода, подключение `lang-switcher.js`.
- `src/main/resources/static/js/lang-switcher.js` — новый файл, обработчик клика (строит URL с сохранением текущих query-параметров, заменяя/добавляя `lang`).
- `src/main/resources/i18n/messages_es.properties`, `messages_ru.properties`, `messages_en.properties` — новый ключ `admin.nav.language` (если используется `aria-label`).
- `src/main/resources/static/css/admin.css` — стили компактного переключателя (переиспользовать существующие `btn`/`btn-outline`/`btn-sm` классы, где возможно, минимум нового CSS).

## Критерии приёмки
- [ ] На любой странице `/admin/**` (проверить минимум на 3 разных: `/admin`, `/admin/tournaments`, `/admin/players`) в шапке справа, рядом с приветствием/кнопкой выхода, виден компактный переключатель ES/EN/RU.
- [ ] Клик по варианту — текущая страница перерисовывается на выбранном языке (видимый текст меню/заголовков меняется).
- [ ] На странице с query-параметрами (например `/admin/players?nivel=PRO`) клик по варианту языка сохраняет `nivel=PRO` в URL после переключения (фильтр не сбрасывается).
- [ ] Активный язык в переключателе визуально отличим от двух остальных вариантов.
- [ ] Переход на другую admin-страницу после переключения — язык остаётся выбранным (cookie из #541 передаётся).
- [ ] Обновление страницы (F5) после переключения — язык остаётся выбранным.
- [ ] На мобильной ширине (бургер-меню) переключатель не ломает существующую вёрстку шапки/бургер-меню (регрессия `admin-menu.js`/`.navbar-collapse`).
- [ ] Если добавлен `admin.nav.language` — ключ присутствует и не пустой во всех трёх `messages_{es,ru,en}.properties`.
- [ ] `./mvnw verify` зелёный, регрессии на header/burger-menu нет.

## Edge cases
- Переключение языка на странице с формой (например `/admin/tournaments/new`) — навигация по GET на тот же `pathname + query` сбрасывает несохранённый ввод формы (ожидаемо для смены языка через переход, как и в большинстве подобных переключателей; явно не требуется сохранять состояние незаполненной формы — не упомянуто в запросе).
- `#542` смержен раньше `#541` (бэкенд не готов) — переключатель рендерится и кликабелен, но язык не меняется и не сохраняется (query-параметр `lang` просто игнорируется текущим `AcceptHeaderLocaleResolver`, cookie не пишется). Не является багом этой задачи — ожидаемое промежуточное состояние при раздельном мерже, устраняется мержем #541 (см. раздел «Зависимости» в #541).
- Два реплики в Docker Swarm — чисто статический фрагмент + клиентский JS, не обращается к серверному состоянию сверх обычной навигации — дополнительного риска нет.
