# LFPT-0912: Feature frontend UI v2 — юридические и системные страницы

## Статус
implemented — блок подтверждён пользователем, реализация выполнена 2026-11-11.

## Источник
[Issue #912](https://github.com/UstinKO/padel-core-service/issues/912), напрямую из issue. Зависит от #899 и влитых #826/#827; используется auth/session foundation #908.

## Контекст / зачем
Подготовить реальные юридические страницы и общие системные состояния React до переключения публичных маршрутов. Тексты и cookie-consent сохраняют утверждённое поведение действующего сайта.

## Связь с MASTER.md
Бизнес-правила и юридические формулировки не меняются. Нет новых требований к участию/контактам/согласиям. Аналитика и маркетинг не включаются до соответствующего действующего согласия.

## Проверка существующего кода
- Источники утверждённых текстов: `templates/legal/terminos.html`, `privacidad.html`, `cookies.html` с ES/RU/EN. Они содержат реальные тексты, не следует брать disclaimer/demo content из макета.
- CookieController уже поддерживает POST `/api/cookies/accept`, `/reject`, `/customize?analytics=...&marketing=...`; cookieConsent=accepted/rejected/customized, отдельные analyticsConsent/marketingConsent и существующий revoke.
- Общие 404 и локальные error состояния уже есть в React, но полноценные error boundary, offline/429/503 и session-expired ещё не реализованы.

## Требования
- Подготовить React-страницы действующих доменных `/terminos`, `/privacidad`, `/cookies` под preview-prefix; production URL остаются legacy.
- Перенести утверждённый текст всех трёх языков без изменения формулировок, дат и реквизитов. Зафиксировать проверки эквивалентности содержимого с текущими источниками. Не получать Thymeleaf DOM во время работы React и не использовать demo legal copy.
- Сохранить серверный cookie-consent contract через существующие POST + CSRF. Воспроизводить состояние cookies, персонализацию и отказ; не запускать аналитику до согласия. Ошибка сохранения согласия не изображает успех.
- Добавить root error boundary и страницы session expired, forbidden, offline, rate limit с фактическим Retry-After/blockedUntil, unavailable и not found.
- 401 ведёт к входу с безопасным возвратом; 403 не запускает бесконечный повтор login. Offline/retry повторяет только чтение, не мутации. Неизвестный исход мутации не объявляется неуспехом/успехом без reconcile.
- Не маскировать неизвестный ресурс и недоступный backend пустым успешным SPA shell. Сохранить серверные 404/503 на прямых entity URL и не расширять production allowlist.
- ES/RU/EN, keyboard/focus/scroll, screen-reader labels, reduced motion, responsive 320/390/1440 px, canonical/noindex по назначению.

## Изменения в системе
### API
Использовать существующий CookieController и error/session contracts #899, без нового серверного legal API и изменения юридической модели.
### БД
Без изменений.
### UI
Legal pages/content, consent UI, root boundary, системные страницы/роуты и обработчики ошибок. Переиспользовать session/destination основу #908; юридические тексты — статическая миграция текущего утверждённого содержимого, не fixtures.
### Документация
`frontend/README.md`, screen/API contracts, React plan, документация cookie/аналитики и `.agents/PROJECT.md`.

## Вне скоупа
Юридическая экспертиза и правка текстов/реквизитов, новые consent purposes, переключение production URL, кабинет/booking/live и итоговая приёмка #913.

## Критерии приёмки
- [ ] Тексты трёх legal страниц ES/RU/EN соответствуют текущим утверждённым источникам; входящие публичные URL сохраняются.
- [ ] Consent accept/reject/customize совпадает с серверными cookies; до согласия нет внешней аналитики/маркетинга, revoke сохраняется.
- [ ] Все системные состояния воспроизводятся тестами без stack trace, технического тела и белого экрана.
- [ ] 401 сохраняет безопасный возврат; 403 не цикличен; 429 показывает реальное время, offline/retry не повторяет POST/PUT/DELETE.
- [ ] Deep link 404/503 не становится фиктивным 200; preview закрыт/noindex, production allowlist не изменён.
- [ ] pnpm check, Playwright, docs-drift, Maven package проходят; ES/RU/EN, доступность и размеры экранов проверены.
- [ ] Один собственный коммит и отдельный PR с явными зависимостями.

## Edge cases
Отказ clipboard здесь не относится к consent, cookies disabled, ответ CSRF 403, недоступность backend при сохранении выбора, испорченные consent cookies, session expired при открытом диалоге, Retry-After в секундах/дате, неизвестный route и исключение в React-компоненте.

## Открытые вопросы
Технический план подтверждён пользователем. Новых юридических/бизнес-решений не предлагается; любые найденные противоречия утверждённого текста передаются владельцу отдельно.

## Результаты проверки
`pnpm check`: форматирование, линтер, типизация, 37 unit-тестов, production build и бюджеты размеров проходят. Playwright: 36 сценариев desktop/mobile. Девять проверок legal copy подтверждают полный текст и ссылки ES/RU/EN. Полный clean verify на отдельной PostgreSQL: 892 теста, ошибок нет, один пропущен; итоговый JAR пересобран.
Отдельный браузер с реальным cookie API и собранным JAR проверил accept/customize/reload/revoke, все девять legal page/locale сочетаний, canonical/noindex, реальные HTTP 404/503 и ширины 1440/390/320 без переполнения. Скриншоты просмотрены, ошибок JavaScript нет. Внешние SDK в закрытом preview не загружаются. Проверки 401/403/offline/429 и границы ошибок воспроизводятся в unit/Playwright. Production URL, allowlist и SUPER_ADMIN-защита preview сохранены.

Ошибки форм переведены по устойчивым кодам и меняют язык вместе с интерфейсом. Ссылки резюме ведут к реальным контролам CAPTCHA/контакта/пароля, доступное имя поля отделено от сообщения ошибки; это проверено unit- и браузерными тестами. Во время изменения аккаунта параллельная отправка второй формы блокируется.
