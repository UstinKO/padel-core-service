# LFPT-1125. Заявки на объединение профилей

## Статус
testing

[Задача #1125](https://github.com/UstinKO/padel-core-service/issues/1125) развивает [#901](https://github.com/UstinKO/padel-core-service/issues/901). Интерфейс поставляется по [#1126](https://github.com/UstinKO/padel-core-service/issues/1126).

Игрок с самостоятельным аккаунтом создаёт заявку на сайте даже при недоступности WhatsApp. Сайт показывает постоянный номер, дату и статус. Номер позволяет найти обращение, а решение принимает уполномоченный администратор.

Администратор может начать сверку из очереди или выбрать гостя и основной аккаунт из раздела игроков. Сервер повторно проверяет оба профиля, нормализованный телефон и конфликты участия перед переносом. Подтверждение по WhatsApp требует указать номер фактического отправителя. Для другого способа проверки администратор явно подтверждает принадлежность обоих профилей и указывает способ.

При различии телефонов основного и гостевого профилей требуется отдельное подтверждение замены. Категория и Telegram основного аккаунта сохраняются. Действующие регистрации и результаты переходят на ID основного аккаунта. Исходные записи оплат, отмен и маркетинговой атрибуции сохраняются по своим идентификаторам. Повторное объединение возвращает прежний результат.

Если пересекаются турниры, матчи или готовые рейтинговые записи, заявку можно отправить на уточнение. Перенос выполняется одной транзакцией. Устаревшие ссылки подтверждения от имени гостя и его учётные данные отзываются.

В проверке используются синтетические профили и отдельная PostgreSQL. Сервер и интерфейс должны попасть в один выпуск, поскольку новая отметка о ручной проверке обязательна для подтверждения заявки.
