# LFPT-0489: Feature короткая ссылка для Instagram-профиля — /ig-bio с редиректом 302 и UTM-метками

## Статус
approved

## Источник
Клиентский запрос [specs/requests/LFPT-0489-ig-bio-short-link.md](../requests/LFPT-0489-ig-bio-short-link.md), issue [#489](https://github.com/UstinKO/padel-core-service/issues/489).

Telegram-сообщение (для reply): 4845

## Контекст / зачем

Маркетинг хочет короткую, легко набираемую ссылку для раздела "ссылка в био" профиля Instagram, ведущую на главную страницу `1-padel.com` с собственной UTM-меткой источника (`instagram_profile`) — отдельной от уже существующей метки `calendar_october` для ссылки `/oct-ig` (LFPT-0472), т.к. это постоянная ссылка профиля, а не ссылка под конкретную кампанию.

## Связь с MASTER.md

Фича не касается бизнес-логики продукта (роли, турниры, регистрации) — чисто техническая маршрутизация на публичном сайте. `MASTER.md` не затрагивается и не требует изменений.

## Требования

### Функциональные
- `GET /ig-bio` → HTTP-редирект на `https://1-padel.com/?utm_source=instagram&utm_medium=social&utm_campaign=instagram_profile`
- Редирект — настоящий HTTP-редирект (`Location`-заголовок на полный целевой URL с query-string), не JS/meta-refresh — чтобы UTM-параметры были в адресной строке браузера сразу после перехода.
- Доступ анонимный (без логина) — путь должен быть явно добавлен в `permitAll()` в `SecurityConfig`, иначе анонимный переход упрётся в `/login` (та же ловушка, что была закрыта для `/oct-tg`/`/oct-wa`/`/oct-ig` в LFPT-0472).

### Нефункциональные
- Код статуса редиректа: **302 (Found / временный)**, не 301 — явно запрошено заказчиком. Совпадает с техническим решением LFPT-0472 (ссылка-профиль может быть переразмечена в будущем, постоянный 301 рискует быть закэширован навсегда). Spring MVC `"redirect:..."` отдаёт 302 по умолчанию.
- i18n: не применимо — редирект не рендерит пользовательский текст.
- Безопасность: нет новой точки входа данных от пользователя (нет параметров, нет записи в БД) — только статическая маршрутизация на предопределённый захардкоженный URL. CSRF/rate-limit не затрагиваются (простой `GET` без побочных эффектов).

## Вне скоупа

- Общий механизм управления короткими ссылками (админка, БД-таблица, произвольные алиасы) — не делаем, ссылка захардкожена в коде, как и предыдущие три.
- Изменения в `nginx`/Cloudflare — не требуются: редирект реализован на уровне приложения (Spring MVC controller), проходит через обычный git-flow и деплой `deploy.yml`.
- Отслеживание кликов/статистика по переходам (кроме того, что увидит GA по UTM) — не делаем.

## Изменения в системе

### API

Добавить `/ig-bio` в существующую таблицу `SHORT_LINK_TARGETS` и в `@GetMapping` того же `MarketingRedirectController.java` (LFPT-0472) — не создавать параллельный контроллер/механизм (DRY, `CODE_REVIEW.md` §2).

| Method | URL | Ответ |
|---|---|---|
| GET | `/ig-bio` | 302 → `https://1-padel.com/?utm_source=instagram&utm_medium=social&utm_campaign=instagram_profile` |

### БД

Не требуется.

### UI

Не требуется (чистый редирект, ни один шаблон не затронут). Задача — backend-only (`GIT_WORKFLOW.md` §1.4: только `src/main/java/**` + `SecurityConfig`).

### Конфигурация безопасности

`SecurityConfig.securityFilterChain` — добавить `/ig-bio` в список `permitAll()` рядом с `/oct-tg`, `/oct-wa`, `/oct-ig`.

### Документация

`.claude/CLAUDE.md`, раздел "Public Pages" — добавить строку про `/ig-bio` в навигационную карту (обновляется на диске рабочей директории; `.claude/` в `.gitignore`, в git-diff PR не попадёт — синхронизация вне этого PR).

## Критерии приёмки

- [ ] `GET /ig-bio` без авторизации возвращает `302` с заголовком `Location: https://1-padel.com/?utm_source=instagram&utm_medium=social&utm_campaign=instagram_profile`
- [ ] Путь `/ig-bio` не конфликтует с существующим маппингом (проверено `grep` по контроллерам — свободен)
- [ ] После перехода по ссылке в браузере открывается главная страница `1-padel.com` со всеми UTM-метками в адресной строке
- [ ] Существующие публичные и защищённые маршруты не затронуты (регрессия по соседним `permitAll()`-путям не ожидается — чисто аддитивное изменение)
- [ ] Проверено после деплоя на проде (см. требование заказчика "проверь ссылку после деплоя")

## Edge cases

- Запрос с дополнительным query-string (`/ig-bio?foo=bar`) — лишние параметры из входящего запроса не переносятся на целевой URL; `foo=bar` игнорируется (как и в LFPT-0472).
- `POST`/другие методы на `/ig-bio` — не поддерживаются (только `GET`).
- Конкурентный доступ / несколько реплик (Docker Swarm) — не релевантно, обработчик stateless, без записи в БД.

## Открытые вопросы

Нет открытых вопросов, требующих решения заказчика — задача полностью технически однозначна (один фиксированный URL из запроса, стандартный HTTP-редирект, прямой аналог уже сделанной и принятой LFPT-0472).
