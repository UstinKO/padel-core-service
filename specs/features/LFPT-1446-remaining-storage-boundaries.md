# LFPT-1446: Feature многомодульный монолит, фаза 6 — закрыть оставшиеся границы JDBC и JPA

## Статус
approved

## Источник
[Issue #1446](https://github.com/UstinKO/padel-core-service/issues/1446). Техническая постановка по утверждённой фазе 6. Родитель [#1051](https://github.com/UstinKO/padel-core-service/issues/1051).

## Контекст / зачем
Завершить владение хранением по фактическому остаточному реестру, в том числе отчёты, чеки, рейтинг, Telegram, служебные сценарии.

## Связь с MASTER.md
[MASTER](../MASTER.md) определяет роли, границы клубного доступа, регистрацию, турнирные состояния и хранение истории вместе с подтверждённым изменением. Сценарии сохраняют текущие инварианты. Зависимости [#1443](https://github.com/UstinKO/padel-core-service/issues/1443), [#1444](https://github.com/UstinKO/padel-core-service/issues/1444), [#1445](https://github.com/UstinKO/padel-core-service/issues/1445).

## Требования

### Функциональные

- Определить рабочие срезы остатка по результатам предыдущих задач. Разделить SQL persistence и вызывающие сценарии, сохраняя действующие проверки доступа, права и preview-предохранители.
- Включить полные проверки границ application/controller и обратных зависимостей модуля. Сверить их с целевым графом.

### Нефункциональные
- Java release 17, JDK 21 в CI, одна транзакционная граница и один Boot JAR.
- Каждый PR проходит полный verify на отдельной PostgreSQL, артефактные и архитектурные guards, runtime/релевантный браузер и проверку совместимости предыдущего релиза.
- Сохраняются действующие права, i18n ES/RU/EN и внешние контракты. Новых пользовательских строк нет.

## Вне скоупа
Ручной релиз остаётся обычным. Физическая миграция PostgreSQL, Swarm и изменения бизнес-правил вне задачи.

## Изменения в системе

### API
Прежние MVC/HTTP/WS входы, поля, статусы и права.

### БД
Прежняя PostgreSQL и schema. Отдельная тестовая БД для интеграции.

### UI
Действующие клиенты используют прежние данные. Приёмочные сценарии запускаются через штатные входы.

### Документация
[План фазы 6](../../docs/modular-monolith/phase-6/README.md), документация фактических границ, затронутые endpoints и техническая карта при необходимости.

## Критерии приёмки

- [ ] Runtime JPA/JDBC и Liquibase принадлежат padel-persistence, а зависимости на bootstrap/web/integrations и внешние DTO отсутствуют.
- [ ] Все зависимые SQL-сценарии стартуют с одной схемой, проверены откат и совместимость клиента.

## Edge cases
Активные, выключенные и отсутствующие данные, пустой результат, прежние права, повтор запроса и rollback. Границы проверяются на актуальной схеме.

## Открытые вопросы
Бизнес-вопросов нет. Технические подзадачи выделяются по фактическим связям JPA и потребителям. Реальные пользовательские данные и production-сервер не используются для QA.
