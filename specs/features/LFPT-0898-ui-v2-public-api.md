# LFPT-0898: Feature backend API UI v2 — публичный каталог, карточка события и клубы

## Статус
done

## Источник
[GitHub issue #898](https://github.com/UstinKO/padel-core-service/issues/898). Спецификация составлена напрямую из issue.

## Контекст / зачем
React-страницам нужны публичные типизированные данные без Thymeleaf Model и демонстрационных fixtures. Действующий мобильный клиент уже получает массив из `/api/public/tournaments`; замена массива на страницу нарушит совместимость.

## Связь с MASTER.md
Каталог не публикует черновики. Сохраняются действующие правила регистрации, вместимости, резерва, контактов и различия турнирных форматов. `SOLO_POR_ENLACE` исключается из списков, но доступен по прямой ссылке. Бизнес-инварианты и схема БД не меняются.

## Требования

### Функциональные
- Сохранить `/api/public/tournaments` и `/{id}`: текущую структуру DTO, значения вместимости, публичный состав и прежние коды ошибок для мобильного клиента.
- Добавить отдельный каталог с пагинацией в БД. Использовать действующие правила публичной видимости и доступности мероприятий, не вычислять их заново на клиенте.
- Повторно использовать `PublicTournamentDto`, MapStruct и пакетную загрузку клубов/счётчиков регистраций из `TournamentService`; не выполнять запросы на каждую карточку.
- Главная получает ограниченную подборку предстоящих мероприятий и реальные агрегированные счётчики. Не переносить захардкоженное значение `totalClubs = 50` из текущего `HomeController`.
- Список клубов содержит активные клубы, карточка — только разрешённые публичные сведения. Не сериализовать `createdBy`, служебные даты и административные поля `ClubDto`.
- Новые API используют типизированные DTO и ProblemDetail с устойчивым `code` для ошибок.

### Нефункциональные
- Пагинация: `page >= 0`, `1 <= size <= 50`, `page × size <= 2147483647` (предел смещения JPA), по умолчанию `page=0&size=12`; стабильная сортировка по дате, времени и id.
- Фильтры применяются до пагинации. Страница за последней в допустимом диапазоне смещения возвращает пустой `items`, сохраняя корректные `totalElements` и `totalPages`.
- Новые пользовательские ошибки локализуются на ES/RU/EN. API не раскрывает персональные контакты, токены, исключения или JPA entity.
- Публичные данные доступны анонимно, мутации и существующие ограничения авторизации не меняются.

## Вне скоупа
Новые правила участия, оплаты и вместимости; React-экраны; переключение production URL; миграции БД; полная унификация ошибок существующих мобильных API.

## Изменения в системе

### API
- `GET /api/public/catalog`: `{items, page, size, totalElements, totalPages}`; фильтры `clubId`, `type`, `modality`, `gender`, `level`, `status`, `from`, `to`. Значения enum — действующие доменные значения; даты — ISO local date, некорректный диапазон — 400 ProblemDetail.
- `GET /api/public/home`: реальные счётчики активных клубов/игроков и доступных предстоящих мероприятий, ограниченная подборка `PublicTournamentDto`.
- `GET /api/public/clubs`: безопасные DTO активных клубов, стабильная сортировка по имени и id.
- `GET /api/public/clubs/{id}`: публичная карточка клуба; неизвестный/неактивный id — 404 ProblemDetail.
- Существующий `GET /api/public/tournaments/{id}` используется для карточки мероприятия без изменения формата ответа: формат, модальность, уровень, ISO-время/зона, клуб, цена/валюта, статус, `registrationOpen`, PLAYERS/PAIRS, вместимость, основной состав/резерв и описание.
- OpenAPI документирует новые контракты, границы пагинации, фильтры и ошибки.

## Edge cases
Неизвестный enum, отрицательная страница, слишком большой размер, смещение `page × size > 2147483647` и обратный диапазон дат дают 400 `INVALID_CATALOG_FILTER`. Пустая БД даёт нулевые счётчики и пустые списки. Заполненный состав и закрытая регистрация отображают серверные состояния, не ошибку транспорта. Запросы только читают данные и не отправляют уведомлений.
