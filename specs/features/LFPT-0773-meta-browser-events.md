# LFPT-0773: События Meta в браузере и маркетинговое согласие

## Статус
testing

## Источник
https://github.com/UstinKO/padel-core-service/issues/773. Прямое задание пользователя в Codex. Зависит от backend #772.

## Контекст / зачем
Доставлять Pixel-события подтверждённых действий, не считать клики, ошибки, резерв и регистрацию аккаунта успешной записью на мероприятие.

## Связь с MASTER.md
Статусы не меняются. Сопоставление статусов и финансовые ограничения описаны в [контракте](../../docs/endpoints/meta-marketing.md).

## Требования
- Один общий скрипт через fragments/analytics::cookie-consent; подключение SDK после маркетингового согласия и включённой конфигурации.
- PageView только публичных контентных страниц; ViewContent только /torneo/{id}. Личный кабинет может выдавать серверные конверсии, но не PageView/ViewContent приватного раздела. Логин, регистрация аккаунта, токеновые/служебные страницы не инициализируют Pixel.
- Конверсии только из серверного журнала: EventRegistration / EventWaitlist / EventRegistrationPending с сохранённым eventID. Purchase в браузере отсутствует.
- Первый контекст сохраняется до запроса записи; сбой аналитики не отменяет запрос записи. UTM из исходного перехода сохраняются до очистки URL и при входе не теряются.
- Отказ/отзыв немедленно прекращает события. После отзыва уже загруженного SDK повторное согласие сохраняет новый контекст, но Pixel возобновляется только на следующей безопасной странице, чтобы не смешать старую идентичность.
- Нет noscript-пикселя, обходящего согласие. Отключена autoConfig; единственный advanced-matching параметр — согласованный хеш случайного external_id. Токены и контакты не передаются.
- SDK не загружается на страницах с неизвестными/чувствительными query или referrer. Валидные рекламные параметры сохраняются локально сервером, затем убираются из URL до загрузки Pixel.

## Критерии приёмки
- [x] Отсутствие согласия / только analytics / отключённая конфигурация — без SDK и сохранения контекста.
- [x] Согласие в cookie-баннере запускает ровно один PageView; событие имеет ViewContent с ID.
- [x] Успех получает серверный ID, ошибка/резерв/ожидание/аккаунт не становятся EventRegistration.
- [x] Повторный запрос/перезагрузка не создают новую конверсию; UTM не стираются прямой страницей.
- [x] Отзыв и сетевой отказ не ломают регистрацию.
- [x] Контакты/токены в URL/referrer блокируют SDK; в произвольные параметры уходят только проверенные ID/enum.
- [x] 11 браузерных тестов Chromium прошли с подменённым SDK; приём Meta отдельно не заявляется.

## Сквозная проверка приложения
На окончательном JAR с отдельной локальной PostgreSQL и одноразовыми аккаунтами проверены: UTM → вход → подтверждённая запись → ручная оплата 400 ARS → итог 1000 ARS → повтор сохранения. Получены два денежные события 400/600 и один полностью оплаченный участник. Русская ссылка в админке скачивает защищённый CSV с UTM без контактов. SDK подменён, CAPI-токен пуст: реальный приём Meta не проверен. Полный Maven verify: 547 тестов, 0 failures/errors/skipped; Chromium: 11/11.
