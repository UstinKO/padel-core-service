# Telegram: отправка и история кампаний

Согласовано владельцем 25.11.2026 после приёмки предпросмотра #1389/#1390. Сервер #1394, интерфейс #1395. Реальный выпуск и сообщения игрокам не разрешены.

Подготовка сохраняет неизменяемые текст, автора, область, точные выбранные ID и состояние личной связи. UUID клиента делает повтор создания безопасным; тот же UUID с другим содержимым отклоняется. Новый участник группы после предпросмотра не добавляется. Черновик действует 15 минут. Подтверждение — явный POST с confirmed=true, только автором с актуальными правами. Повтор не создаёт новый запуск.

Единая подписка и /stop сохраняются. Перед каждым сообщением проверяются актуальные права отправителя, активность мероприятия, участие для адресатов из мероприятия, активность/тип профиля, WhatsApp, пилот и поколение подключения. Удаление связи и повторное подключение не возобновляют старую очередь. Дополнительные адресаты вне события допустимы только SUPER_ADMIN. Для теста адресат — только текущий связанный активный профиль из существующих organizer-owner-id/organizer-chat-id; клиент не передаёт Telegram ID. Пока личная привязка других административных аккаунтов не реализована, проба для них недоступна.

Отправка отделена от HTTP-подтверждения долговечной очередью PostgreSQL. Захват одной записи фиксируется до внешнего вызова и исключает одновременную обработку. Подключение защищено существующей общей блокировкой на время проверки и отправки одного сообщения: /stop ждёт уже начатую операцию и запрещает последующие. Используется существующий транспорт, pacing и ledger. После сбоя сохранённый SENT восстанавливается из ledger; неопределённый исход остаётся UNKNOWN без автоматического повтора. Exactly-once провайдер не обещается. Общая координация всех jobs/распределённых квот остаётся #1213.

Результаты: PENDING, IN_FLIGHT, SENT, FAILED, BLOCKED, UNKNOWN, SKIPPED. SENT означает принятие Telegram API, не прочтение. Только FAILED можно заново поставить в очередь явным подтверждением; действие имеет свой UUID и повторно проверяет права/связь. BLOCKED/UNKNOWN/SENT не повторяются. История сохраняет автора, текст, время и результат каждого адресата. Исторические ID не получают каскадное удаление вместе с профилем/событием. Телефоны, email, chat ID, токены и fingerprint клиенту не выдаются.

Новый флаг telegram.players.campaigns.enabled по умолчанию false. Подготовка и история доступны без отправки; подтверждение/проба/повтор и worker требуют включённого флага и доступного бота. Автоматические подтверждения и чеки не меняются. Проверки только на отдельной QA-БД с подменой внешнего API.
