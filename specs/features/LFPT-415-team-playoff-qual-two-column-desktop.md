# LFPT-415: Team Playoff admin — квалификация в две колонки на десктопе + заметнее M1/M2

## Статус
approved

## Источник
GitHub issue [#415](https://github.com/UstinKO/padel-core-service/issues/415) (прямой технический вход от архитектора, оформлен из пересланного в Telegram клиентского запроса организатора). `specs/requests/` не создавался — вход через готовый issue, см. `develop-feature.md` "Вход 3".

Telegram-сообщение (для reply): 4622

## Контекст / зачем

На странице `/tournaments/team-playoff/admin/{id}` (раздел "Calificación" / "Квалификация") матчи текущего раунда квалификации растянуты почти на всю ширину десктопного экрана, а между Раундом 1 и Раундом 2 нужно переключаться кнопками-вкладками (`.round-tab`). Во время живого турнира это мешает координатору быстро увидеть общую картину: какие пары уже сыграли первый матч, какие — второй, кто ждёт второго матча. На десктопе достаточно свободного места, чтобы показывать оба раунда одновременно в две колонки, не переключаясь.

## Связь с MASTER.md

Не затрагивает бизнес-инварианты `MASTER.md` — чисто визуальная перекомпоновка уже отображаемых данных. Формат турнира Team Playoff и её раунды квалификации (`specs/MASTER.md` строка про Team Americano/Team Playoff) не меняются.

## Требования

### Функциональные

- На **десктопе** (ширина viewport ≥ 769px, тот же брейкпоинт, что уже используется в файле для мобильной адаптации, `max-width: 768px`) раздел "Раунды квалификации" показывает **все имеющиеся раунды (волны) одновременно, в колонках** (обычно 2: Раунд 1 слева, Раунд 2 справа), без необходимости кликать по вкладкам.
  - Если реально существует только 1 волна (второй матч ещё никто не начал) — показывается одна колонка на всю доступную ширину, второй пустой колонки не рисуем.
  - Табы-переключатели (`#qualTabs` / `.round-tab`) на десктопе скрываются — они больше не нужны, раунды видны сразу.
  - У каждой колонки — свой заголовок с номером раунда (переиспользовать `#{americano.round.prefix}` + номер, тот же текст, что сейчас в табе), чтобы после скрытия табов не потерялась подпись "Раунд 1" / "Раунд 2".
  - Карточки матчей (`.match-card`) внутри колонки — компактнее (примерно вдвое уже, чем сейчас на всю ширину): уменьшенные паддинги/шрифты в `.match-header`/`.match-body`/`.team-name`/`.score-display` **только в этом десктопном двухколоночном режиме**, чтобы обе колонки помещались без горизонтального скролла на типичных десктопных ширинах (≥1280px).
- На **мобильной версии** (≤768px, как сейчас) поведение не меняется: одна колонка на всю ширину, переключение между Раундом 1 и Раундом 2 кнопками-вкладками — существующая логика `switchQualRound()`/`qTabs`/`qRounds` в `<script>` не трогается.
- Обозначение M1/M2 (badge `.info-pill` рядом с командой — какой по счёту матч квалификации у неё в этой карточке) визуально усиливается, чтобы отличие "команда играет свой 1-й матч" vs "команда играет свой 2-й матч" было заметно с одного взгляда, а не только по мелкому серому тексту:
  - M1 — нейтральный (текущий серый `.info-pill`) стиль остаётся как индикатор "ещё не завершила квалификацию".
  - M2 — отдельный, более контрастный акцентный стиль (окрашенный бейдж, тот же акцентный оттенок, что уже используется в проекте для "ожидающих"/приоритетных элементов на этой же странице, например `#fef3c7`/`#b45309` или `#dbeafe`/`#1e3a8a`, см. существующие `.info-pill` с инлайн `style` на этой же странице), чтобы сразу визуально выделялась команда, которая уже доигрывает свой второй (решающий) матч квалификации.
  - Правило "кто уже сыграл оба матча" по-прежнему read-only видно из таблицы рейтинга выше (столбцы P1/P2 со счётом, `qualStatus` 🟢/🔴/🟡/⏳) — эта таблица не меняется, задача не про неё.

### Нефункциональные
- Производительность: не затрагивается, изменение чисто в CSS/HTML разметке одного Thymeleaf-шаблона, без новых запросов к серверу.
- i18n: новых пользовательских строк нет — переиспользуется существующий ключ `americano.round.prefix` (уже во всех `messages_{es,ru,en}.properties`). Правок в `messages_*.properties` не требуется.
- Безопасность: новых точек входа данных от пользователя нет.

## Вне скоупа
- Не трогаем раздел "Playoff" (плей-офф после квалификации, `<div th:if="${playoffStarted}">`) — там своя двухуровневая (полуфинал/финал) структура, задача явно про квалификацию.
- Не трогаем таблицу рейтинга квалификации (`#qualRankingTbody`) и "Доску кортов" (`#courtBoardGrid`) — уже существующие и не упомянутые в задаче блоки.
- Не трогаем backend (`TeamPlayoffViewController.splitQualificationWaves`, `TeamPlayoffService`) — данные уже приходят предразбитыми на волны/раунды, меняется только их отображение.
- Не переносим этот же паттерн на другую похожую страницу — `admin/americano/tournament-double.html` (Team Americano round-robin, issue #413 упоминает то же дублирование в шапке карточки, но это отдельная, не заявленная в этом issue задача).
- Двухколоночный режим не адаптируем под планшетную ширину отдельным брейкпоинтом — используем ровно существующую границу 768/769px (мобильный/десктоп), как в остальном файле.

## Изменения в системе

### API
Нет изменений — используются существующие данные, уже передаваемые в модель (`qualRounds`).

### БД
Нет изменений.

### UI
- `src/main/resources/templates/admin/americano/tournament-playoff.html`:
  - CSS: новый `@media (min-width: 769px)` блок, скоупленный на обёртку секции "Раунды квалификации" (понадобится присвоить этой обёртке `id`, например `qualRoundsSection`, сейчас у неё класса/id нет) — не должен затрагивать одноимённый общий класс `.round-content`, который также используется в разделе "Playoff" (там раскладка должна остаться как есть).
  - HTML: добавить заголовок раунда внутри каждого `qround-N` блока (скрыт на мобильном через CSS, виден на десктопе); присвоить `id="qualRoundsSection"` обёртке.
  - CSS: усиленный акцентный стиль для M2-бейджа рядом с командой в `match-card` (сейчас — общий `.info-pill` без различия M1/M2), новый класс, например `.info-pill.m2-badge`, применяется рядом с существующим условием `match.team1MatchOrdinal == 1 ? M1 : M2` (и симметрично для team2) — только меняется `class`/добавляется класс по условию, сам текст бейджа не меняется.

## Критерии приёмки
- [ ] На desktop viewport (≥1280px) страница `/tournaments/team-playoff/admin/{id}` с активной квалификацией и обоими раундами (волнами) начатыми показывает Раунд 1 и Раунд 2 **одновременно**, каждый в своей колонке, без клика по вкладкам — оба видны на экране без горизонтального скролла.
- [ ] На том же desktop viewport вкладки `.round-tab` ("Раунд 1"/"Раунд 2") не отображаются (или визуально скрыты) — они избыточны, раунды и так видны.
- [ ] Каждая из двух колонок имеет видимый заголовок с номером раунда (тот же текст, что раньше был в табе).
- [ ] Если на момент проверки существует только 1 волна (никто ещё не начал второй матч) — отображается одна колонка на всю ширину, вторая пустая колонка не рисуется и не оставляет "дыру" в раскладке.
- [ ] Карточки матчей в двухколоночном режиме заметно компактнее, чем в текущем одноколоночном виде (уменьшены паддинги/шрифты), обе колонки помещаются без горизонтального скролла.
- [ ] На mobile viewport (≤768px, например 375×812) поведение не изменилось: видна одна колонка на всю ширину, кнопки "Раунд 1"/"Раунд 2" переключают видимый раунд, как раньше (регрессионная проверка).
- [ ] Бейдж M2 у команды в карточке матча визуально отличается от бейджа M1 (другой цвет/фон), не только текстом.
- [ ] Раздел "Playoff" (плей-офф-сетка после квалификации) визуально не изменился — раскладка `.round-content` там осталась прежней (регрессионная проверка, т.к. этот класс общий).
- [ ] `./mvnw compile -DskipTests` проходит без ошибок (шаблон валиден для Thymeleaf).
- [ ] Ручной проход в браузере (Playwright, `cloud`-режим) подтверждает все пункты выше на живом турнире с квалификацией в процессе.

## Edge cases
- Квалификация ещё не начата (`qualStarted == false`) — блок с раундами вообще не рендерится (`th:if="${not #lists.isEmpty(qualRounds)}"`), это ветвление не меняется, поведение то же, что сейчас.
- Только 1 команда/матч сыграла — 1 волна с 1 карточкой — должна красиво лечь в одну колонку, не растягиваться на всю ширину экрана гигантской пустой карточкой (компактный размер карточки применяется независимо от их количества).
- Очень широкий десктопный экран (>1920px) — две колонки не должны растягиваться до неразумной ширины карточек; допустимо ограничить `max-width` колонки или центрировать — не критично, не блокирует критерии приёмки, но не должно выглядеть сломанным.
