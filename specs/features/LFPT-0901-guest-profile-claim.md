# LFPT-0901: Подтверждение гостевого профиля через WhatsApp

## Статус
testing

## Источник
[GitHub #901](https://github.com/UstinKO/padel-core-service/issues/901) и решение владельца продукта от 12.11.2026.

## Сценарий

- При создании аккаунта и добавлении номера в существующий аккаунт сервер проверяет нормализованный телефон. Совпадение блокирует создание второго профиля или запись чужого номера. Публичный ответ предлагает связаться с 1Padel в WhatsApp и не содержит чужих данных.
- Игрок пишет в официальный WhatsApp 1Padel. Организатор сравнивает номер отправителя с уже сохранённым номером гостя. Имя, произвольный введённый номер или Telegram сами по себе ничего не подтверждают.
- Если аккаунта ещё нет, организатор активирует исходный профиль на указанный игроком реальный email после сверки телефона. Доступ к нему игрок получает через существующее восстановление пароля, которое он запускает сам. ID гостя и ссылки на него сохраняются.
- Если аккаунт уже есть, заявка из авторизованного профиля указывает целевой аккаунт. Организатор после переписки подтверждает её. Если у обоих профилей есть записи на один турнир, привязка останавливается и сохраняет обе записи для отдельной ручной проверки.
- Несколько совпадающих профилей, отсутствующий или ошибочный номер требуют ручного разбора. По непроверенному контакту привязка невозможна.
- При активации и привязке сохраняются регистрации, партнёры, статусы, платежи, результаты и история. Состояние резерва и согласие на предложение пары не меняются.
- Обязательные уведомления недоступному гостю передаются оформившему пару с указанием, кому адресовано уведомление. Персональные ссылки на подтверждение от имени гостя второму игроку не передаются. В синтетические домены письма не отправляются.

## Реализация

- Общая проверка номера для HTML-регистрации, API регистрации и обновления контактов. Точный нормализованный номер и блокировка по этому контакту используются внутри транзакции.
- Серверные операции активации и привязки доступны координаторам с правом управления глобальными профилями. Обязательны CSRF для браузерных сессий, повторная проверка номера и аудит ID профилей, оператора и времени. В логах нет полных контактов, паролей или секретов.
- Для существующего аккаунта целевой ID берётся из авторизованной заявки. Повторная обработка возвращает тот же результат. Конкурентные заявки и конфликты возвращают типизированные ошибки без частичного обновления.
- Живые ссылки на профиль обновляются в транзакции. Исторические записи сохраняют исходные факты. Привязка должна учитываться при показе истории и восстановлении старых снимков проведения.
- Пользовательские и административные экраны поставляются [фронтенд-задачей #994](https://github.com/UstinKO/padel-core-service/issues/994) после бэкенда. Новые сообщения доступны на ES, RU и EN.
- [MASTER.md](../MASTER.md) и технические документы обновляются в PR. Правила резерва #759 и подтверждения участия #760 не меняются.

Перед выпуском задать переменную GitHub `GUEST_CLAIM_WHATSAPP_URL` со ссылкой официального WhatsApp. Конвейер переносит её в окружение приложения и проверяет значение в контейнере перед принятием выпуска. Без неё регистрация по занятому номеру остаётся заблокированной, а отправка заявки временно недоступна.

## Проверки

Локальный Maven verify на отдельной PostgreSQL: 952 теста, один пропущен, ошибок нет. Интеграционные сценарии проверяют блокировку дубля, доступ, CSRF, повтор, конкурентное подтверждение, оплату, резерв и перенос старых снимков на целевой ID. Письма проверены на локальном тестовом отправителе.

## Критерии приёмки

- [ ] Гость найден при вводе номера в поддерживаемых аргентинских форматах. Регистрация и добавление контакта не создают дубль.
- [ ] Угадывание номера не даёт доступ к профилю, истории, данным контакта или заявке другого игрока.
- [ ] После активации на исходном ID видны прежние регистрации, включая резерв, и сохраняются партнёры, платежи и результаты.
- [ ] После привязки к существующему аккаунту история доступна его владельцу. Две записи на один турнир блокируют операцию, обе остаются на месте.
- [ ] Повтор, параллельные подтверждения, отсутствие прав, изменение номера после подачи заявки и неоднозначное совпадение покрыты тестами.
- [ ] Письма не уходят на синтетический адрес. Оформитель получает адресованное партнёру уведомление без ссылки, позволяющей ответить от его имени.
- [ ] Автоматические SMS и WhatsApp-коды отсутствуют. Полный Maven verify и проверки документации проходят.
