# LFPT-0456: Feature новый тип турнира «Тренировка + игра» (Clínica de pádel) — добавить TournamentType.PADEL_CLINIC

## Статус
approved

## Источник
`specs/requests/LFPT-0456-padel-clinic-event-type.md` (клиентский запрос через Telegram, тема "AI Разработка"), issue [#456](https://github.com/UstinKO/padel-core-service/issues/456).

Telegram-сообщение (для reply): 4724

## Контекст / зачем
Заказчику нужен новый, узнаваемый тип мероприятия «Тренировка + игра» (групповая тренировка с игрой) — отдельный от уже существующих `KING_OF_COURT`, `AMERICANO`, `AMERICANO_TEAMS`, `CANCHA_ABIERTA`. Эта задача — техническая основа (сам `TournamentType`), без которой зависимая фронтенд-задача (LFPT-0457: выпадающий список, карточки, страница турнира, i18n) не сможет создавать турниры нового типа.

## Связь с MASTER.md
`specs/MASTER.md § Форматы турниров` перечисляет 4 формата. Добавление пятого (`PADEL_CLINIC`) расширяет таблицу форматов, но не меняет существующие инварианты статусов регистрации/ролей. MASTER.md обновляется отдельно после полного завершения обеих задач (456+457) — см. "Вне скоупа".

## Требования

### Функциональные
- Новая константа `TournamentType.PADEL_CLINIC` в `src/main/java/com/padle/core/padelcoreservice/model/enums/TournamentType.java`, с `value = "Clínica de Pádel"` (испанский домен-термин, по аналогии с `KING_OF_COURT("Rey de Cancha")`, `CANCHA_ABIERTA("Cancha Abierta")`; поле `value` нигде в runtime не читается — `getValue()` не используется ни в одном `.java`/шаблоне на момент написания спеки, проверено `grep`, но заполняется для внутренней консистентности enum).
- Поведение по умолчанию (аналогично `CANCHA_ABIERTA`, именно так сформулировал заказчик — "аналогично ... Открытый корт"): никакой специальной серверной логики (сеток/раундов/напоминаний) не требуется — турнир этого типа работает как регистрация без привязанного формата соревнования, так же как уже работает для `CANCHA_ABIERTA`.

### Нефункциональные
- i18n — не в этой задаче (см. "Вне скоупа", зависимая задача LFPT-0457).
- Безопасность — новая точка входа данных отсутствует: `tipo` как и раньше принимает значения `TournamentType`, Spring биндит enum по имени константы, `@Enumerated(EnumType.STRING)` не требует доп. валидации.

## Вне скоупа
- Любое отображение в UI (форма создания, фильтры, карточки, страница турнира) — задача [LFPT-0457](https://github.com/UstinKO/padel-core-service/issues/457), отдельный PR.
- i18n-ключи (properties/JS) для названия типа — там же, LFPT-0457.
- Email-напоминания за 5 часов до начала (`IndividualTournamentReminderScheduler`, `INDIVIDUAL_TYPES` = `{AMERICANO, KING_OF_COURT}` + отдельная проверка `CANCHA_ABIERTA`) — заказчик не просил такое же поведение для нового типа; `PADEL_CLINIC` НЕ добавляется в этот список. Если впоследствии понадобится — отдельная задача.
- Обновление `specs/MASTER.md` (таблица форматов) — делается одним PR после того, как обе задачи (456 и 457) смержены и задеплоены, чтобы не описывать в мастер-спеке формат, который ещё не виден пользователю целиком.
- Обновление `.claude/CLAUDE.md` (если потребуется) — вне `git diff` этого PR (`.claude/` в `.gitignore`), синхронизируется архитектором отдельно при необходимости.

## Изменения в системе

### API
Без изменений сигнатур. `POST /api/tournaments` / `POST /admin/tournaments` и далее — как и раньше принимают любое значение `TournamentType` по имени константы; `PADEL_CLINIC` становится валидным значением наравне с остальными четырьмя.

### БД
Без миграции. `tournaments_db.tipo` — `VARCHAR(20)`, `@Enumerated(EnumType.STRING)`, без `CHECK`-ограничения на конкретный список значений (проверено — ни одна Liquibase-миграция в `db/changelog/versions/` не содержит `CHECK` на колонку `tipo`). `PADEL_CLINIC` (12 символов) помещается в отведённую длину.

### UI
Нет изменений в этой задаче.

## Критерии приёмки
- [ ] `TournamentType.java` содержит константу `PADEL_CLINIC("Clínica de Pádel")`
- [ ] `TournamentType.values()` возвращает 5 констант (было 4)
- [ ] `./mvnw compile -DskipTests` — успешно
- [ ] `./mvnw verify` — успешно (все существующие тесты проходят без изменений — новая константа не ломает switch/exhaustive-проверки, т.к. в кодовой базе нет `switch` по `TournamentType`, проверено `grep`)
- [ ] Прямой запрос `POST /api/tournaments` с `"tipo": "PADEL_CLINIC"` (валидные остальные поля) создаёт турнир без ошибки 400/500, значение сохраняется и читается обратно как `PADEL_CLINIC`

## Edge cases
- Пустой/некорректный `tipo` — поведение не меняется, `TournamentType.valueOf(...)` по-прежнему бросает исключение для неизвестных строк (как и для любого другого несуществующего имени константы) — обрабатывается существующим `GlobalExceptionHandler`, без изменений.
- Существующие турниры (других типов) — не затрагиваются, миграции данных нет.
