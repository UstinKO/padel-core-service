# LFPT-0905: Feature backend deploy UI v2 — сборка, smoke-check и атомарный rollback React assets

## Статус

review — пользователь подтвердил реализацию 2026-11-12. Проверка выпуска/отката проводится в закрытом контуре; production самостоятельно не изменяется.

## Источник

Напрямую из [issue #905](https://github.com/UstinKO/padel-core-service/issues/905). Зависимости #826/#827/#904 закрыты; закрытый контур реализован в PR #974. Исправление публичной главной #975/PR #976 также влито. Итоговая приёмка #913 зависит от этой задачи, но дополнительно ждёт #909/#910.

## Контекст / зачем

React уже собирается в jar вместе с backend. В pom закреплены Node/pnpm и frozen lockfile, а серверная раздача задаёт no-cache для index и immutable для hashed assets. Повторять эти реализации не требуется.

Текущий deploy проверяет readiness и доступность `/web/index.html`, но не весь граф JS/CSS и не авторизованный deep link preview. Откат восстанавливает jar и резервную копию `.env`, затем пересобирает образ; информация о версии и точная конфигурация запуска не оформлены единым проверяемым выпуском. Последняя рабочая копия удаляется сразу после успешных проверок. Нужны воспроизводимая единица выпуска, полноценный smoke и проверенный откат согласованной версии.

## Связь с MASTER.md

Бизнес-правила и MASTER не меняются. По ADR-0013 и исправлению #975 публичные маршруты и оформление сохраняются до отдельного акцепта. Пустой production SPA allowlist не должен автоматически расширяться. Проверка отсутствия SPA forward дополняется проверкой прежнего публичного шаблона; изменения Thymeleaf в обход закрытого preview запрещены.

## Требования

### Функциональные

1. Аудировать Maven/Dockerfile/PR Check/deploy и переиспользовать действующие pinned Node/pnpm, lockfile, jar packaging и cache policy. Чистая сборка не зависит от локальных node_modules, старого target или runtime оператора.
2. Добавить проверяемый манифест выпуска: commit ревизия, контрольные суммы jar, index и графа React-ресурсов, идентификатор runtime-образа и несекретная конфигурация маршрутов. Проверять наличие всех entry/dynamic JS/CSS и локальных ресурсов, а не одного index. Содержимое `/app/**` должно соответствовать исходной Expo-сборке этой ревизии.
3. Использовать неизменяемые версии артефакта/образа и конфигурации запуска. Предыдущий рабочий выпуск сохраняется до подтверждения нового; rollback использует сохранённый выпуск, а не повторную сборку старого jar на потенциально другой конфигурации.
4. Выпускать backend, текущий React index/assets, идентификатор версии и SPA allowlist как одну согласованную единицу. Секретная конфигурация хранится только локально/на стороне среды с закрытыми правами; токены, `.env` и приватные адреса не входят в публичный манифест, логи или CI artifacts.
5. Проверять candidate до активации; после активации — readiness с ограниченным временем и smoke графа ресурсов. Неуспех smoke/readiness либо прерывание операции восстанавливают предыдущие образ, конфигурацию запуска и метаданные. Не публиковать успешную версию до прохождения smoke. Для первоначального запуска без предыдущего выпуска выдавать явный отказ/состояние, не заявлять успешный rollback без источника.
6. В закрытом контуре #904 проверять авторизованный `/preview/torneos` и refresh/deep link, index и все необходимые JS/CSS, `/app/**`, прежнюю публичную главную и отказ preview для guest/PLAYER. Изменение allowlist на production не является частью smoke.
7. Сохранить корректный Cache-Control: index/HTML требует перепроверки, hashed assets immutable. Учесть уже открытые вкладки и отложенную загрузку chunk при смене версии; не отдавать HTML вместо отсутствующего JS. Конкретный механизм совместимости старых hashed assets выбирается при реализации, проверяется отдельным сценарием и не включает переключение публичных URL.
8. Защитить выпуск от параллельного переключения и смешения предыдущего/candidate состояния. Ошибка rollback явно отмечается как ошибка; последняя рабочая копия не удаляется преждевременно, текущие пользовательские базы и чужие процессы не пересоздаются.
9. Добавить воспроизводимую репетицию минимум двух различимых выпусков: успешный переход, отсутствующий chunk/ресурс, неуспешный readiness и восстановление прежней версии. Использовать настоящий backend/браузер и синтетические данные; проверять совпадение версии, манифеста, конфигурации и загруженных ресурсов после отката.
10. Подключить проверки сборки/манифеста/smoke и репетицию к CI. Применять тот же проверенный механизм в штатном workflow выпуска; подготовить безопасную инструкцию ручного восстановления и инвентаризацию требуемых runtime-файлов. Если фактическая конфигурация сервера отличается от версионируемой, не считать её проверенной по предположению: зафиксировать разницу и согласовать применение отдельно.

### Нефункциональные

Java source/release 17, текущие API и профили сохраняются. Новых пользовательских бизнес-строк не планируется; диагностические сообщения на русском, возможные видимые строки сразу ES/RU/EN. Ресурсы проверяются по фактическому артефакту и HTTP, не только по чтению шаблонов. Внешние эффекты и данные при репетиции изолированы средствами #904.

## Вне скоупа

Переключение production SPA routes, редизайн публичного Thymeleaf, разработка booking/cabinet, ответы на бизнес-вопросы #759/#760/#901, изменение БД или автоматический откат Liquibase/пользовательских данных. Откат кода требует совместимости схемы; эта задача не обещает безопасный downgrade произвольной будущей миграции. Zero-downtime и новые способы доступа заказчика/TLS/VPN не вводятся.

Самостоятельный merge, SSH-изменение production и запуск боевого deploy в рамках интерактивной реализации не разрешены. Проверка deploy/rollback проводится в выделенном закрытом контуре. После готового PR фактическое применение к production требует отдельного поручения владельца.

## Изменения в системе

### API

Бизнес-эндпоинты не добавляются. При необходимости уточняется существующая защищённая диагностика preview: только среда/ревизия/состояние выпуска, без секретов. Права SUPER_ADMIN и CSRF сохраняются. Поведение статических ресурсов расширяется только для подтверждённой согласованной доставки версий.

### БД

Миграций и reset production нет. Репетиция использует выделенную PostgreSQL и синтетические сценарии #904. Маркер безопасности и границы seed/reset сохраняются.

### UI

Дизайн, публичные URL, React-экраны и mobile-app исходники не меняются. Возможные изменения frontend build config относятся только к манифесту/packaging. Пользовательские изменения поведения клиента, если окажутся необходимы, оформляются отдельной frontend-задачей, а не скрываются в backend-выпуске.

### Код и документация

Планируемые области: `pom.xml`, Dockerfile и отдельные runtime-конфигурации, проверки артефакта/выпуска, `automation/ui-preview/`, `.github/workflows/pr-check.yml` и `deploy.yml`, при необходимости backend-раздача версий ресурсов. Обновить `.agents/PROJECT.md`, `docs/architecture.md`, `docs/ui-v2-preview.md`, безопасный runbook выпуска/rollback, frontend cross-cutting contract и навигацию `docs/Home.md`. Приватные инфраструктурные документы не публиковать.

## Критерии приёмки

- [x] Чистая CI-сборка создаёт jar с полным графом React-ресурсов; манифест соответствует фактическим байтам, Expo не изменена.
- [x] Неполный/повреждённый артефакт отклоняется до переключения, текущий рабочий выпуск сохраняется.
- [x] Успешный выпуск в контуре показывает согласованные backend/React/метаданные/allowlist одной версии.
- [x] Смоделированные missing chunk и readiness failure приводят к сохранению или восстановлению прежнего полного выпуска; после отката ссылки index, ресурсы и конфигурация соответствуют его манифесту.
- [x] Старый открытый клиент корректно переживает смену версии/дозагрузку chunk; отсутствующий JS не подменяется HTML.
- [x] Реальный браузер подтверждает preview deep link/refresh, роли, cache headers, legacy `/` и существующий `/app/**`.
- [x] Production SPA allowlist остаётся пустым; публичная главная сохраняет оформление после #975.
- [x] Прерывание/конкурентный выпуск не уничтожает последнюю рабочую копию; неуспешный rollback не объявляется успешным.
- [x] Полный verify, проверки документации/конвейера, сборки, release state и браузерная репетиция проходят на последнем коммите.
- [x] Один итоговый backend-коммит и PR с `Closes #905`; в отчёте отдельно указаны проверенный контур и непроводившийся production deploy.

## Edge cases

Первый выпуск без backup, невалидный манифест/контрольная сумма, устаревший index, missing dynamic import, недоступный readiness, прерывание после замены candidate, ошибка восстановления, нехватка места, два параллельных выпуска, ручная конфигурация среды, несовместимая схема БД, сохранённые пользовательские вкладки, повторный запуск и неверный UUID-маркер/проект, закрытый доступ к preview во время smoke.

## Открытые вопросы

Бизнес-вопросов нет. Перед реализацией согласуется технический план изменения процесса выпуска. Реальная конфигурация production не считается изученной по содержимому репозитория; read-only инвентаризация при необходимости и отдельное разрешение на применение остаются обязательной границей. Локальная репетиция не называется проверенным production deploy.

## Реализация и проверка

- Maven уже фиксирует Node v24.12.0/pnpm v11.25.0, frozen lockfile и устанавливает зависимости в чистом CI checkout. Docker builder копирует frontend без node_modules; кэш Maven/пакетов не является источником собранных assets. Эти механизмы сохранены.
- Добавлены Vite manifest, проверка полного графа/байтов React и неизменности Expo, закреплённый runtime-образ и автономный пакет выпуска. Общий механизм preview/production хранит приватные снимки, блокировку, журнал и предыдущую версию. Старые hashed chunks сохраняются.
- Read-only аудит реального runtime подтвердил отличие серверного Dockerfile от репозитория, отсутствие image pin и jar bind, пустую SPA allowlist, совместимость архитектуры/Python и доступа к логам. Новая доставка не пересобирает серверный Dockerfile. Самостоятельный production deploy не проводился.
- Локальный `./mvnw verify` с отдельной тестовой БД, frontend check, 52 Playwright e2e, проверки документации/конвейера и тесты механизма выпуска прошли. Браузерная проверка собственного preview подтвердила роли, сеть, deep links, React/Expo и legacy главную. Репетиция двух синтетических QA-выпусков подтвердила старый lazy chunk после переключения, ручной откат, HTTP missing chunk/readiness failure и recovery журнала.
- Последний коммит дополнительно проверяется CI PR. Приёмка #913 и разрешение публикации новых UI-маршрутов остаются отдельными задачами. Публичные шаблоны, API и миграции не меняются.
