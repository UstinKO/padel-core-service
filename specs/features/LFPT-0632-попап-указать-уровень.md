# LFPT-0632: Всплывающее окно «Указать уровень» при регистрации без указанного уровня игрока

## Статус
approved

## Источник
Прямая техническая постановка от архитектора (декомпозиция LFPT-0303 на бэкенд/фронтенд — `GIT_WORKFLOW.md` §1.4), issue [#632](https://github.com/UstinKO/padel-core-service/issues/632), зависит от #303 (бэкенд, ветка `feature/LFPT-303`, PR #631). Источник бизнес-требования — тот же customer-запрос (Telegram, `telegram_launch_message_id: 5223`), что и у LFPT-0303.

Telegram-сообщение (для reply): 5223

## Контекст / зачем

Бэкенд (LFPT-0303) уже блокирует самостоятельную регистрацию и возвращает `needLevel: true` в JSON-ответе, если `PlayerPadel.nivelJugador` не указан. Сейчас фронтенд просто показывает текст ошибки в обычном окне результата — без явного призыва к действию. Заказчик хочет отдельное окно с понятным текстом и кнопкой, ведущей в профиль, плюс (желательно) удобный возврат к регистрации после сохранения уровня.

## Связь с MASTER.md

Реализует UI-часть правила, описанного в `specs/MASTER.md` (строка о LFPT-0303, добавлена в бэкенд-PR). Не меняет инвариантов, только отображение существующего backend-флага.

## Требования

### Функциональные

1. Новый модуль `static/js/level-check.js` (`LevelCheck.show(tournamentId)`) — показывает модальное окно с текстом «Для регистрации на турнир сначала укажите свой уровень в личном кабинете» и кнопкой «Указать уровень», ведущей на `/perfil`. Перед переходом — сохраняет `tournamentId` в `sessionStorage` (ключ `pendingLevelRegistrationTournamentId`) для последующего удобного возврата (п.4).
2. Вызывается вместо обычного окна ошибки во всех точках самостоятельной регистрации, где возможен `needLevel: true`:
   - `static/js/dashboard.js`: одиночная регистрация (`/players/tournaments/{id}/register`), соло-регистрация на парный турнир (`register-solo`), регистрация пары (`register`, режим `WITH_PARTNER`).
   - `static/js/tournament-details.js`: те же три точки.
3. Обычная ошибка "уровень слишком далёк" (без `needLevel`) продолжает показываться как раньше (без изменений в этой ветке кода).
4. **Желательно, не блокирует приёмку.** На странице `/perfil` (`static/js/profile.js`) — после успешного сохранения профиля (`th:if="${successMessage}"` уже на странице) если в `sessionStorage` есть `pendingLevelRegistrationTournamentId` — показать небольшую ссылку/баннер "Вернуться к регистрации" на `/torneo/{id}`, затем очистить ключ из `sessionStorage` (независимо от того, показан баннер или нет — чтобы не всплывал на несвязанных визитах).

### Нефункциональные

- i18n: новые ключи только в `static/js/i18n/messages-{es,ru,en}.js` (не Java `messages_*.properties` — это клиентский текст, используемый через `t()`), по образцу секции `contact-check.js` в тех же файлах.
- Без новых серверных эндпоинтов — используется уже существующий флаг `needLevel` из LFPT-0303.

## Вне скоупа

- Сама backend-проверка — реализована в LFPT-0303 (#303, PR #631).
- `add-partner` (`/api/tournaments/double/{tournamentId}/add-partner`) — на сегодня не вызывается ни из одного из двух JS-файлов (нет кнопки в текущем UI, вызывается только `register`/`register-solo`/`register-solo`), поэтому обработка `needLevel` там не добавляется — нечего вызывать.
- Любая серверная логика сохранения/передачи `tournamentId` между запросами (редиректы, query-параметры, cookie) — используется только `sessionStorage` на клиенте, без изменений в `PerfilController`.

Без изменений — используется существующий флаг `needLevel`.

### UI

## Критерии приёмки

- [ ] Попытка одиночной регистрации на турнир без указанного уровня (`needLevel: true` в ответе) — показывается окно `LevelCheck`, а не обычная ошибка, и в консоли нет JS-исключений.
- [ ] То же для соло-регистрации на парный турнир и для регистрации пары (`WITH_PARTNER`), на обеих страницах (`players/dashboard`, `torneo/{id}`).
- [ ] Обычная ошибка "уровень слишком далёк" (без `needLevel`) — показывается как раньше, без изменений поведения.
- [ ] Кнопка «Указать уровень» ведёт на `/perfil`.
- [ ] Текст окна и кнопки переведён на все три локали (`es`/`ru`/`en`), проверено вживую под `Accept-Language`.
- [ ] (Желательно) После сохранения уровня на `/perfil` — виден баннер/ссылка возврата к турниру, с которого пришёл игрок; баннер не появляется, если в `sessionStorage` ничего не сохранено.

## Edge cases

- `sessionStorage` недоступен (приватный режим браузера) — обёрнуто в `try/catch`, попап всё равно показывается, просто без удобного возврата.
- Игрок открыл `/perfil` без предварительной попытки регистрации — баннер не показывается (ключ в `sessionStorage` не установлен).
- Игрок сохранил профиль, но уровень всё равно не выбран (теоретически невозможно — поле `required`, но защитно) — баннер показывается всё равно (клиент не перепроверяет сам уровень, доверяет тому, что раз форма сохранилась без ошибки — уровень указан, т.к. поле обязательно на бэкенде, issue #82).
