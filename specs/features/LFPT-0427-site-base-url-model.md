# LFPT-0427: Fix относительный URL в og:image — передать app.base-url в шаблоны страниц

## Контекст / зачем

Исходная проблема: шаблоны страниц задают `og:image` относительным путём, а общего атрибута с базовым URL в моделях страниц не было. Для превью в мессенджерах нужны абсолютные адреса. Задача подготавливает серверный контракт для #429: сами теги и изображения здесь не меняются, поэтому готовое превью не является результатом #427.

Не меняет бизнес-инварианты [MASTER.md](../MASTER.md): роли, регистрацию, турниры, оплаты и локализацию. Новых связей между бизнес-доменами нет. MASTER.md менять не требуется.

## Требования

### Функциональные

1. Добавить глобальный атрибут модели страниц `siteBaseUrl` типа `String`, доступный как `${siteBaseUrl}` в Thymeleaf. Он должен работать для публичных страниц, кабинета игрока и админки без ручного добавления в каждый контроллер.
2. Источник — существующее свойство `app.base-url` с обычным механизмом переопределения Spring. В prod оно берётся из `APP_BASE_URL`; локальные и тестовые переопределения должны сохранять приоритет. Не вводить вторую настройку или домен в Java-коде.
3. Перед добавлением в модель удалить завершающие `/`. Не менять схему, hostname, порт и префикс пути. `https://example.org///` преобразуется в `https://example.org`, `http://localhost:8080/padel/` — в `http://localhost:8080/padel`.
4. Использовать централизованный MVC-компонент с `@ControllerAdvice` и `@ModelAttribute`. Не добавлять ответственность подготовки модели в `GlobalExceptionHandler`.
5. Не добавлять атрибут для `@RestController` и обработчиков `@ResponseBody`; существующие HTTP-статусы, JSON и заголовки ответов сохраняются.
6. Не менять адреса редиректов. Новый атрибут не должен добавляться в `Location` как query-параметр или менять существующие параметры.

### Нефункциональные

- Реализация совместима с Java 17 и текущими зависимостями проекта. На момент сверки в pom.xml Spring Boot 4.1.2; понижать или обновлять зависимости для этой задачи не требуется.
- Нет новых обращений к БД, внешним сервисам и новых зависимостей.
- Пользовательских строк нет, новые ключи ES/RU/EN не нужны.
- URL берётся из конфигурации, а не из заголовков `Host`/`Forwarded`/`X-Forwarded-Host` или параметров запроса. Другие значения конфигурации в модель не передаются.

## Изменения в системе

### API

Новых endpoints и изменений JSON-контрактов нет. Добавляется только внутренний контракт модели страниц: `siteBaseUrl: String`, значение `app.base-url` без завершающих `/`.

### БД

Без изменений; Liquibase-миграция и бэкфилл не нужны.

### UI

Шаблоны и внешний вид не меняются. Атрибут становится доступен существующим страницам; использование в Open Graph тегах выполняется отдельно в #429.

### Код и технические особенности

Новый advice разместить в `config/` основного пакета `com.padle.core.padelcoreservice`. Исключение JSON-обработчиков должно учитывать аннотации класса и метода: `@RestController` сам является `@Controller`, а обычные MVC-контроллеры также содержат `@ResponseBody`-методы. Ограничение только пакетом `controller/view` не подходит — оно пропустит кабинет игрока и админку.

Учесть передачу простых атрибутов модели в query-параметры Spring MVC редиректов. Если нужна дополнительная обработка редиректной модели, она должна затрагивать только новый атрибут; глобально менять поведение существующих редиректов нельзя.

### Документация для обновления вместе с реализацией

- `docs/architecture.md`: в описании слоя Controller и конфигурации указать `siteBaseUrl`, его источник и исключения для JSON/редиректов. Сверить относящееся к задаче описание `APP_BASE_URL` с фактическим application.yml.
- `.agents/PROJECT.md`: кратко описать общий атрибут в разделе Architecture. Таблицы URL и БД не меняются.
- `docs/Home.md`, `docs/domain-overview.md` и endpoint-таблицы не требуют новых записей: маршруты не добавляются. Исторические ADR и findings не переписывать.
