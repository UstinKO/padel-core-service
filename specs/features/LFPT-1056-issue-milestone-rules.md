# LFPT-1056: Feature организация бэклога — назначать Milestone при создании задач

## Статус

done

## Источник

[Issue #1056](https://github.com/UstinKO/padel-core-service/issues/1056), прямое поручение владельца закрепить выбор раздела и создание нового при отсутствии подходящего. Техническая постановка из issue, отдельный клиентский запрос не требуется. Задача назначена в актуальный раздел «Техдолг — качество и сопровождение кода».

## Контекст / зачем

Бэклог организован в Milestones, но без правила новые задачи снова могут оставаться вне направлений. Нужно встроить маршрутизацию в существующие инструкции и навыки, чтобы она применялась к обычной работе и декомпозиции без отдельного агента.

## Связь с MASTER.md

Бизнес-инварианты, API, роли и сценарии приложения не меняются. Правило относится к метаданным GitHub и процессу постановки задач.

## Требования

### Функциональные

- Единый источник — `.agents/ISSUE_ORGANIZATION.md`, доступный из AGENTS, GIT_WORKFLOW, навыков new-feature/develop-feature и полного протокола.
- Каждая новая рабочая issue получает один открытый Milestone по цели. Числовой number и актуальное описание читаются из GitHub, а не берутся из старых примеров.
- Тематическое направление имеет приоритет над общим типом; bug/слой/форматы/служебные метки сохраняются.
- При отсутствии подходящего раздела создать новый осмысленный Milestone без придуманного срока и обновить индекс #1055. Классификация входит в порученное создание задачи и не требует отдельного подтверждения.
- Для пар backend/frontend сохраняются отдельные issues/PR и зависимости, основной Milestone обычно общий. Подходящее существующее назначение сохраняется.
- Закрытые исторические разделы автоматически не переоткрываются; дубли проверяются до создания.
- Проверка записи — перечитать issue; частичный сбой не скрывается и не вызывает дублирование issue.
- Постоянный индекс `backlog:index` может быть без Milestone; обычные задачи не получают эту метку как обход классификации.

### Нефункциональные

Обновляются только инструкции и документация. Существующие навыки остаются короткими и ссылаются на общий документ; новое приложение/агент/автоклассификатор не создаются. Секреты и runtime не публикуются; исходные полномочия пользователя/среды сохраняются.

## Вне скоупа

Массовая повторная группировка бэклога, изменение бизнес-правил и issue-статусов, новая workflow-автоматика, Python-классификатор, расписание обслуживания индекса, мерж и деплой.

## Изменения в системе

### API

API приложения без изменений. GitHub Milestone назначается в рамках порученного создания задачи; текущая задача использует существующий раздел техдолга.

### БД

Нет.

### UI

Нет новых пользовательских строк и переводов; браузерный прогон не требуется.

### Документация

Новый `.agents/ISSUE_ORGANIZATION.md`; ссылки из `AGENTS.md`, `.agents/GIT_WORKFLOW.md`, `.agents/skills/new-feature/SKILL.md`, `.agents/skills/develop-feature/SKILL.md`, `.agents/workflows/develop-feature.md`, `.agents/CODE_REVIEW.md` и `docs/Home.md`.

## Критерии приёмки

- [x] Общий документ и все ссылки доступны, инструкции не требуют отдельного агента или отсутствующего навыка.
- [x] Описаны существующий/новый раздел, баг тематической области, legacy UI, техдолг против модульности, persistence против Swarm и парные задачи.
- [x] Создание нового раздела разрешено в рамках уже порученной задачи, не расширяет полномочия создавать несогласованные issues и не обходит sandbox.
- [x] GitHub number/title берутся из актуального каталога; метки/зависимости сохраняются; после записи есть проверка.
- [x] Новая #1056 имеет корректный Milestone; остальные задачи в этой реализации не перераспределены.
- [x] Оба навыка проходят quick_validate; docs-drift, agent-migration, релевантные unit-тесты и diff проверены; результаты/ограничения отражены в PR.

## Edge cases

Несколько подходящих направлений; смысловой дубль с другим названием; закрытый исторический этап; пара backend/frontend; появившийся параллельно Milestone; issue создана, а назначение не удалось; GitHub недоступен/нет полномочий; служебный индекс; будущий самостоятельный продуктовый поток вне текущих разделов. Правило не обещает автоматической классификации без запуска агента и доступного GitHub.

## Открытые вопросы

Неразрешённых бизнес-вопросов нет. Имена/номера будущих разделов определяются по живому GitHub в момент создания задачи.

## Результаты проверки

Оба существующих навыка прошли штатный quick_validate из skill-creator; PyYAML установлен только в одноразовое окружение вне репозитория. docs-drift и check-agent-migration — 0 расхождений. Python suites: .github/bin — 8, telegram-relay — 48, codex-worker — 5, ui-preview — 6, releases — 22; всего 89 тестов успешно. Новые/изменённые ссылки и diff проверены. Проверка GitHub подтвердила Milestone текущей #1056. Новые тестовые Milestones для валидации не создавались. Полный Maven/браузерный прогон не требовался: приложение не менялось.
