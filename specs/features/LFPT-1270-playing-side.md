# Предпочтительная сторона игрока — сервер

Источник: [постановка](../requests/LFPT-1270-playing-side.md), issue #1270; интерфейс #1271.
План согласован 23.11.2026.

## Инварианты

- Nullable PlayingSide LEFT/RIGHT/EITHER: null — нет ответа, не EITHER. Никакого backfill.
- Ответ не выводится из пола, руки, уровня или матчей. Не влияет на регистрацию, пары, результаты и оплаты.
- PATCH /api/players/me/playing-side сохраняет сторону своего активного профиля; необязательный уровень позволяет завершить оба вопроса за один шаг. Изменение уровня отдельно сохраняет сторону.
- POST /api/players/me/playing-side/visit атомарно резервирует показ на 24 часа в БД; повторные страницы и устройства не повторяют опрос. POST /defer откладывает с момента закрытия ещё на 24 часа. Только интерфейс кабинета вызывает visit.
- При сохранённом ответе опрос больше не появляется. Ошибка не завершает опрос и не сбрасывает выбор в форме.
- Необязательная сторона при регистрации; Google-профиль проходит тот же шаг в кабинете. Ручное добавление гостя допускает отсутствие стороны; найденный существующий профиль не изменяется вводом организатора.
- Существующие права управления турниром не дают права редактировать чужой профиль. Административное изменение — действующий SUPER_ADMIN.
- Сторона каждого участника доступна в управлении. Публичный показ следует mostrarNivel; само значение настройки не мигрируется. Внутренние дополнительные DTO-поля не сериализуются в общие legacy API; публичный live-контракт маскирует их явно.
- Объединение профилей: перенос заполненного в пустой; сохранение заполненного при пустом госте; разные заполненные значения требуют ACCOUNT/GUEST. Без явного разрешения перенос не начинается.

## Проверки

Сохранение/смена, независимость уровня, регистрация без ответа и с ответом, Google principal, отложенный/параллельный показ, чужой профиль и CSRF, видимость, конфликт и повтор объединения. Полная серверная проверка на отдельном PostgreSQL; UI — в зависимой задаче.
