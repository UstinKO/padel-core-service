# Telegram для игроков — первая версия

Статус: объём выбран владельцем 23.11.2026; реализация #1294, интерфейс #1295.

## Границы

Для игроков используется отдельный бот 1-Padel и собственный TELEGRAM_PLAYERS_BOT_TOKEN. Технический бот инцидентов и бот разработки не переиспользуются. Без отдельного токена новая интеграция недоступна; служебные алерты сохраняют прежний канал.

Подключение профиля, подтверждение участия, напоминание и персональная сводка организатору. Оплаты, чеки, приветствия, рекламные приглашения и публикации исключены. Существующие email, финансовые условия и правила отмены сохраняются.

## Поведение

- Способ связи хранится для аккаунта: UNSPECIFIED / TELEGRAM / WHATSAPP. Выбор WhatsApp отключает текущую связь Telegram и аннулирует ещё не использованные ссылки. Автоматических WA-сообщений нет; организатор видит предпочтение и необходимость ручной связи. Явное повторное создание ссылки Telegram возвращает выбор TELEGRAM; само по себе это не означает подключения.
- Ссылка подключения сохраняет поддерживаемый текущий язык сайта в preferred_locale: ручной выбор сайта имеет приоритет перед Accept-Language, неподдерживаемый язык — ES. Изменение способа связи и отсутствие ответа не влияют на регистрацию.

- Авторизованный игрок получает одноразовый непрозрачный токен подключения на 10 минут. В базе только SHA-256. Привязка принимается только из личного чата с совпадающими Telegram user/chat ID; username не удостоверяет личность. Один Telegram связан с одним игроком. Перепривязка чужого соединения запрещена. Отключение и /stop прекращают новые DM.
- Организатор запрашивает подтверждения для активного основного состава своего мероприятия. Используется отдельный ParticipationRequest с причиной ORGANIZER; существующий актуальный запрос резерва/замены не сбрасывается. Кнопка подтверждения проверяет связанный профиль, цикл регистрации и права. Повтор безопасен. Отсутствие ответа ничего не отменяет. «Не смогу» открывает действующий сайт; новая финансовая политика не вводится.
- Настраиваемый автоматический запрос по умолчанию за 24 часа, напоминание за 3 часа. Если запрос впервые создаётся в окне напоминания, уходит одно сообщение с подтверждением. Перед фактической отправкой проверяются актуальные событие, регистрация и подключение. Отключённые и гостевые аккаунты не связываются по догадке.
- Сводка содержит количество и имена участников, ответы, неподключённый Telegram и проблемы отправки. Ручной просмотр доступен управляющему конкретным событием. Отправка владельцу доступна только настроенному SUPER_ADMIN и только в заданный личный чат; ежедневная отправка опциональна.
- Тексты игрокам ES/RU/EN по профилю; сводка владельцу RU. Данные турнира берутся из текущих записей; время — IANA-зона мероприятия.

## Надёжность

Позиция polling хранится в БД, polling сериализован арендой. Ключ уведомления включает регистрацию, её версию, получателя, вид и время старта: обычный повтор не повторяет отправку, а перенос позволяет сообщить новые данные. Долговечная отметка IN_FLIGHT создаётся до внешнего вызова. После неясного сетевого результата сохраняется UNKNOWN без автоматической повторной отправки; exactly-once Telegram не обещается. Успех — только положительный ответ API. При 403 соединение отключается. Новые задачи Telegram не заменяют общий аудит cron/Swarm #1213.

## Проверки

Привязка без username; чужая/просроченная/использованная ссылка; групповой /start; отключение; чужая/повторная/устаревшая кнопка; права клуба; отмена/повторная запись/перенос; рестарт и конкуренция отправок; ошибки и таймаут Telegram; адресат сводки; переводы. Внешний API в тестах подменяется. Выпуск и включение на реальных игроках отдельно от PR.

## Первый запуск на одном аккаунте

До общего выпуска включён pilot-enabled=true. Доступ задаётся ровно одним pilot-player-id и одним pilot-tournament-id; пустые значения никого не допускают. Проверяются выдача/погашение ссылки, предпочтение, получатель DM, запросы участия, callbacks, планировщик и события сводки. Сохранённая ранее связь другого игрока не даёт права отправки. Сводка пилота доставляется только в личный чат связанного тестового профиля; organizer-chat-id должен совпадать с ним.

В разрешённом мероприятии запрос создаётся только для самого тестового игрока. Запросы остальных участников не создаются и не изменяются; гостевые регистрации с делегированием в пилот не входят. Из остальных мероприятий запросы не создаются. Действующие старые уведомления остальных игроков сохраняются, а тестовый профиль исключается из старого бота во избежание дублей и обхода отключения.

Для проверки используют отдельное мероприятие с одним тестером, доступное по ссылке. Флаг testTournament=true по-прежнему исключает событие из уведомлений. Автоматическая отправка и ежедневная сводка остаются выключены до настройки пилота. Общий доступ требует отдельного явного pilot-enabled=false. Проверки в коде не означают запуск на сервере.
