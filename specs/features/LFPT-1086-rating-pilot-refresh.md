# LFPT-1086. Автоматический пересчёт пилота Elo

Зависит от LFPT-1083 / PR #1084. Реализация и приёмка только на тестовой версии; выпуск не разрешён.

## Поведение

Участник пилота при следующем открытии кабинета или рейтинга получает пересчитанные Elo, места, категории, медали и историю. Сохранённые результаты читаются в одной согласованной транзакции; пересчёт идёт с начала истории, поэтому исправление старого счёта влияет и на последующие турниры. Формула, подтверждение категорий и список доступа не меняются. Это обновление при загрузке страницы, не push в уже открытый браузер.

Проверенный архив соединяется с БД без двойного учёта. Новые турниры после даты среза берутся из действующих результатов: полностью сохранённые раунды индивидуальных форматов и завершённые парные матчи с четырьмя ID и счётом. Отменённые/неактивные события исключаются. Титулы индивидуальных форматов появляются после завершения турнира.

Старый турнир можно передать под автоматическое управление только явным включением его ключа в `managedEvents` после сверки всего турнира с БД. Его текущие результаты полностью заменяют исторические, а не добавляются к ним. Исчезнувшие/сброшенные результаты такого турнира перестают учитываться. Подтверждённые исторические дата и категория сохраняются. Архивные события и старые турниры вне этого списка остаются проверенной историей: несверенные старые матчи не включаются автоматически.

## Конфигурация

Обычный профиль, `app.rating.pilot.enabled=true`, прежний список игроков и срез. Дополнительно `app.rating.pilot.auto-refresh=true` и `app.rating.pilot.history` — внешний JSON с полями `history` (names/events/aliases), `liveAfter` (последний день исходного среза), `managedEvents` и `excludedEvents` (на тестовом — ключи старых искусственных сценариев). Все поля обязательны. История не может содержать события позднее liveAfter. Управляемые события должны присутствовать в истории и иметь ключ S-ID; списки управления и исключений не пересекаются.

При запуске базовая история должна воспроизвести все строки исходного среза с тем же шагом и связями ID, иначе приложение не запускает включённый пересчёт. Новые ID связываются по той же карте подтверждённых дублей. Одному матчу и событию соответствует один ключ. Выключенный auto-refresh оставляет прежний режим фиксированного среза. Сервис только читает БД, не включает профиль preview, не создаёт аккаунты/таблицы/результаты и не сохраняет вычисленные очки поверх старого рейтинга.

БД читается только после проверки доступа к пилоту. При ошибке источника новый результат не выдаётся за свежий; старый публичный кабинет остальных игроков продолжает работать независимо от пересчёта.

## Приёмка

- Базовый срез и все строки совпадают до добавления результатов; повторное чтение не меняет их.
- Новый турнир отражается в Elo, местах и истории без перезапуска.
- Исправление более раннего матча пересчитывает последующую историю; возврат счёта возвращает результат.
- Управляемый старый турнир не учитывается дважды; отмена/сброс исключают его результаты.
- Несверенные старые события, исключённые тестовые события, некорректные ID не проходят скрыто.
- В браузере проверяются разрешённый кабинет, прежний кабинет постороннего игрока и выход из аккаунта.
