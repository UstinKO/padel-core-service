# LFPT-0634: Fix модальное окно ошибки регистрации не закрывается кнопкой Aceptar

## Статус
approved

## Источник
Клиентский запрос [specs/requests/LFPT-0634-модалка-ошибки-регистрации-не-закрывается.md](../requests/LFPT-0634-модалка-ошибки-регистрации-не-закрывается.md). Issue [#634](https://github.com/UstinKO/padel-core-service/issues/634). Telegram-сообщение (для reply): 5236.

## Контекст / зачем
После внедрения `TournamentLevelPolicy` (LFPT-0303) на странице турнира (`tournament-details.html`) при самостоятельной регистрации игрока с уровнем за пределами допустимого диапазона показывается модальное окно `#resultModal` с сообщением об ограничении. Кнопка закрытия этого окна не работает: окно остаётся открытым, пользователь не может продолжить работу со страницей иначе как перезагрузкой. Баг затрагивает не только эту ошибку — любую ошибку прямой (одиночной) регистрации, отображаемую через тот же код.

## Связь с MASTER.md
Фича не меняет бизнес-инвариантов `MASTER.md` (ограничение по уровню, `specs/MASTER.md#обязательное-условие-для-регистрации-на-турнир` и соседний пункт про уровень) — чисто технический дефект на уровне JS-обработчиков модальных окон страницы турнира.

## Требования

### Функциональные
1. Обработчик кнопок `[data-dismiss="modal"]` в `tournament-details.js` должен закрывать то модальное окно, внутри которого находится нажатая кнопка (`btn.closest('.modal')`), а не всегда `#partnerModal` через `closeModal()`:
   - если это `#partnerModal` — сохранить текущее поведение (`closeModal()`: сброс формы, очистка выбранного партнёра, скрытие инфо-сообщения, сброс режима регистрации);
   - для любого другого модального окна — убрать класс `.show` и снять инлайновый `style.display`, если он был выставлен (`modal.style.removeProperty('display')`).
2. В ветке обработки ошибки прямой регистрации (строка ~451 `tournament-details.js`, `fetch('/players/tournaments/{id}/register')` → `data.success === false` и не `data.needLevel`) убрать строку `resultModal.style.display = 'block'` — показ окна обеспечивается только классом `.show` (как и везде в `showResultModal()`).

### Нефункциональные
- i18n: новых пользовательских строк нет, правило не затронуто.
- Безопасность: новой точки входа данных от пользователя нет.

## Вне скоупа
- Закрытие модальных окон по клику на фон (`window.addEventListener('click', ...)`) для окон, кроме `#partnerModal`, — заказчик не просил, текущее поведение (не закрывается по клику на фон) для `#resultModal`/`#registrationConfirmModal` не меняется.
- Логика `#cancelModal` (уже работает через собственный обходной путь с клонированием кнопок в `handleCancellation`) — не трогать.
- Логика попапа «Указать уровень» (`LevelCheck`, LFPT-0632) — отдельный компонент, не использует `data-dismiss="modal"` по тому же пути.

## Критерии приёмки
- [ ] Регистрация игрока уровня C6 на турнир категории C8 (вне диапазона ±1 ступень) — в `#resultModal` появляется сообщение об ограничении.
- [ ] Кнопка «Aceptar»/OK в `#resultModal` закрывает окно и затемнение фона (класс `.show` снят, окно визуально скрыто).
- [ ] После закрытия повторная попытка регистрации того же игрока на тот же турнир снова показывает сообщение об ограничении (окно не осталось в «залипшем» состоянии, обработчик переиспользуется корректно).
- [ ] Закрытие формы выбора партнёра (`#partnerModal`, парный турнир) по кнопке `[data-dismiss="modal"]` продолжает работать как раньше: форма сбрасывается, выбранный партнёр очищается.
- [ ] Закрытие окна отмены регистрации (`#cancelModal`) не регрессировало.
- [ ] Успешная регистрация (`showResultModal('success', ...)`) и её автозакрытие по таймеру не регрессировали.

## Edge cases
- Два последовательных вызова `showResultModal`/ветки ошибки без перезагрузки страницы — каждый раз окно корректно открывается и закрывается (нет накопления классов/инлайн-стилей из предыдущего показа).
- Пустой список модальных окон на странице (например, не парный турнир — `#partnerModal` отсутствует в DOM) — обработчик не должен падать на `btn.closest('.modal')` для существующих окон.
