# LFPT-0556: Fix страница деталей турнира в админке показывает вдвое меньший лимит пар, чем реальный (cupoMax делится на 2)

## Статус

approved — задача и спецификация согласованы пользователем, открытых бизнес-вопросов нет.

## Источник

GitHub issue: https://github.com/UstinKO/padel-core-service/issues/556.
Спецификация подготовлена напрямую по issue, без промежуточного запроса в `specs/requests/`.

## Контекст / зачем

На странице `/admin/tournaments/{id}` в заголовке таблицы подтверждённых участников для парного турнира вместимость ошибочно делится на два. При `cupoMax = 16` отображается лимит 8 пар. Для `DOBLES` значение `cupoMax` уже выражено в парах: это подтверждается реализацией `TournamentService` и [спецификацией LFPT-374](../done/LFPT-374-tarjeta-torneo-autotitulo-cupos.md).

## Связь с MASTER.md

Используются существующие правила парной регистрации и административного управления турнирами из [MASTER.md](../MASTER.md). Исправляется отображение вместимости; бизнес-инварианты и порядок регистрации не меняются. Изменения MASTER не требуются.

## Требования

### Функциональные

1. В заголовке таблицы `Inscripciones` для `modalidad == DOBLES` показывать `effectiveCupoMax` без деления на два.
2. Сохранить текущий расчёт числа подтверждённых пар и отображение индивидуальных турниров.
3. Удалить соседний устаревший комментарий, утверждающий, что вместимость нужно делить на два.

### Нефункциональные

- Новые пользовательские строки и переводы не добавляются; используется существующий ключ `admin.tournaments.details.pairs_label` для ES/RU/EN.
- Дополнительных запросов к БД и изменений производительности не требуется.
- Новые точки входа и правила доступа не добавляются.

## Вне скоупа

- Расчёт регистраций, вместимости и резерва в сервисах.
- Счётчики «Parejas inscritas» и кнопки импорта из отдельной задачи [#570](https://github.com/UstinKO/padel-core-service/issues/570).
- Дизайн страницы и рефакторинг соседних блоков.

Изменений нет.

### БД

### UI

Страница: `GET /admin/tournaments/{id}`.
Шаблон: `src/main/resources/templates/admin/tournaments/details.html`.

В блоке `reg-table-header` таблицы `Inscripciones`, в подписи вместимости для `DOBLES`, заменить:

```html
th:text="'/ ' + ${effectiveCupoMax / 2} + ' ' + #{admin.tournaments.details.pairs_label}"
```

на:

```html
th:text="'/ ' + ${effectiveCupoMax} + ' ' + #{admin.tournaments.details.pairs_label}"
```

Удалить комментарий:

```html
<!-- DOBLES: пары = confirmedRegs/2 из cupoMax/2 -->
```

Выражение `${confirmedRegs.size() / 2}` не изменять: оно относится к числу регистрационных записей, а не к вместимости.

## Критерии приёмки

- [ ] Парный турнир с `cupoMax = 16` показывает лимит `/ 16`, а не `/ 8`.
- [ ] Парный турнир с нечётным `cupoMax = 15` показывает `/ 15`.
- [ ] При отсутствии подтверждённых участников лимит продолжает отображаться полностью.
- [ ] Индивидуальный турнир показывает прежние число участников и вместимость.
- [ ] Подпись единиц сохраняет локализацию ES/RU/EN.
- [ ] Выполнена проверка реальным браузером; если среда недоступна, ограничение явно отражено в отчёте.
- [ ] `./mvnw verify` и `python .github/bin/docs-drift.py` проходят. Для интеграционных тестов используется отдельный PostgreSQL.

Для этой локальной правки шаблона отдельный автоматический тест, повторяющий выражение, не добавляется.

## Edge cases

- Нечётная вместимость и пустой список участников обрабатываются без деления лимита.
- Уже существующие турниры получают исправленное отображение без миграции.
- Конкурентная регистрация и обработка некорректных значений вместимости остаются в существующей логике.
