# LFPT-0651: Всплывающее окно после регистрации на Padel Clinic — без штрафа за опоздание

## Статус
approved

## Источник
Клиентский запрос через Telegram (`specs/requests/LFPT-0651-попап-padel-clinic-отмена.md`), issue [#651](https://github.com/UstinKO/padel-core-service/issues/651).
Telegram-сообщение (для reply): 5289

## Контекст / зачем

После успешной индивидуальной регистрации на турнир (`status == CONFIRMED`) игрок видит всплывающее окно с условиями участия — реализовано в LFPT-0448. Окно различает только `CANCHA_ABIERTA` и «всё остальное»: любой другой тип турнира, включая `PADEL_CLINIC`, получает текст индивидуального соревновательного турнира целиком, в том числе пункт «если вы приходите позже начала турнира, вы начинаете турнир со стартовым результатом −10 очков».

Padel Clinic (`TournamentType.PADEL_CLINIC`, добавлен в LFPT-0456) — тренировочное мероприятие с индивидуальной регистрацией, механически аналогичное Cancha Abierta: свободная запись, без сетки/раундов, без соревновательного рейтинга и турнирных очков. Упоминание турнирного штрафа для него ошибочно и вводит игроков в заблуждение.

Финансовые условия отмены (24 часа, полная оплата при поздней отмене, возможный возврат при найденной замене) для Padel Clinic нужны — такие же, как у Americano/King of Court, поскольку корты бронируются и оплачиваются клубу так же, как для соревновательных индивидуальных турниров.

## Связь с MASTER.md

Не затрагивает инварианты `specs/MASTER.md` — изменение не касается статусов регистрации (`RegistrationStatus`) или флоу парной регистрации, только текст информационного попапа после регистрации (чисто отображение, без изменения бизнес-логики отмены/оплаты — она и сегодня не автоматизирована, оплата при поздней отмене фиксируется организатором вручную, как и для остальных форматов).

## Требования

### Функциональные

- В `showRegistrationConfirmModal(tournamentType)` (дублирована в `tournament-details.js` и `dashboard.js`) добавить отдельную ветку для `tournamentType === 'PADEL_CLINIC'`:
  - Подзаголовок и 4 пункта «важно знать» — финансовые условия отмены (24ч / полная оплата / возврат при замене) и просьба приехать заранее, **без** пункта про −10 очков.
  - Заголовок блока «важно знать» — тот же текст, что и у индивидуального турнира (`regConfirm.individual.rulesTitle`), переиспользуется без дублирования ключа (текст идентичен для всех форматов с финансовыми условиями).
  - Остальные типы (`AMERICANO`, `KING_OF_COURT`) — поведение не меняется, попадают в прежнюю ветку «индивидуальный турнир» (5 пунктов, включая штраф).
  - `CANCHA_ABIERTA` — поведение не меняется.
- Новые i18n-ключи `regConfirm.clinic.subtitle`, `regConfirm.clinic.rule1..rule4` в `static/js/i18n/messages-{ru,es,en}.js` — тексты RU/ES даны заказчиком дословно (см. клиентский запрос), EN — перевод в стиле существующих ключей `regConfirm.*`.
- Визуально — переиспользовать существующую разметку/CSS-классы индивидуального блока (`reg-confirm-info-box`, `reg-confirm-info-box__title`, `reg-confirm-rules`), новых стилей не добавлять.

### Нефункциональные

- i18n: 4 новых строковых ключа × 3 языка (ru/es/en), остальные (`regConfirm.title`, `regConfirm.btn.ok`, `regConfirm.individual.rulesTitle`) переиспользуются как есть.
- Безопасность: новой точки входа пользовательских данных нет, тексты статические.

## Вне скоупа

- Email-подтверждение регистрации (`templates/email/tournament-confirmation.html`) — текст уже общий для всех типов («можно отменить за 24 часа»), без упоминания штрафа; изменений не требует (проверено).
- 5-часовое email-напоминание (`templates/email/individual-tournament-reminder.html`, содержит «−10 puntos») — **не отправляется** для `PADEL_CLINIC`: `IndividualTournamentReminderScheduler` фильтрует только `AMERICANO`/`KING_OF_COURT`/`CANCHA_ABIERTA` (явное решение вне скоупа в LFPT-0456). Штраф из письма для Padel Clinic сегодня не виден ни при каком сценарии; добавление 5-часового напоминания для Padel Clinic в этой задаче не запрошено и не делается.
- Любая бэкенд-логика автоматического удержания оплаты или начисления штрафа — в проекте нет платёжного шлюза и автоматического списания (см. `CLAUDE.md`, `payments_db` фиксируется вручную организатором); это не меняется.
- Парная/командная регистрация — вне скоупа (своя логика сообщений, не этот попап).

## Критерии приёмки

- [ ] Индивидуальная регистрация на Padel Clinic со статусом `CONFIRMED` со страницы турнира (`/torneo/{id}`) — после успеха показывается попап с подзаголовком «Вы успешно записались на тренировку + игру» и 4 пунктами (24ч отмена, полная оплата при поздней отмене, возврат при замене, приезжайте заранее), **без** пункта про −10 очков.
- [ ] Та же регистрация с дашборда (`/players/dashboard`) — то же окно.
- [ ] Регистрация на Americano/King of Court со статусом `CONFIRMED` — попап не изменился (5 пунктов, включая штраф −10 очков).
- [ ] Регистрация на Cancha Abierta — попап не изменился (короткая версия без финансовых условий).
- [ ] Тексты корректно переключаются между RU/ES/EN согласно языку сайта (RU/ES — дословно по клиентскому запросу, EN — эквивалентный перевод).
- [ ] `./mvnw compile -DskipTests` и `./mvnw verify` проходят успешно (фронтенд-задача, но сборка не должна быть сломана).
- [ ] `python3 .github/bin/docs-drift.py` — без новых расхождений (изменение не затрагивает эндпоинты/схему/enum).

## Edge cases

- Регистрация на Padel Clinic со статусом `WAITLIST` (лист ожидания) — попап `showRegistrationConfirmModal` не вызывается (вызывается только при `status === 'CONFIRMED'`, уже так в текущем коде) — не меняется.
- `window.tournament?.tipo` / `tournament?.tipo` равен `undefined` (не должно происходить в норме) — код уже и сегодня в этом случае попадает в ветку «индивидуальный турнир» по умолчанию; поведение не меняется.
