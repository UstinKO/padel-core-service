# LFPT-1480: Автоперевод в редакторе Telegram

Зависимость: сервер #1479. Организатор пишет один исходник на удобном языке (RU/ES/EN), кнопка подготовки получает переводы. Язык интерфейса не определяет язык адресатов: используется профиль игрока. Перед сохранением предпросмотра видны ES/RU/EN, их можно исправить. Ошибки сервиса не разрешают отправку исходника всем. Пустая доступная аудитория не требует внешнего перевода.

Исходник изменён — переводы очищаются, нужен новый запрос; устаревший ответ игнорируется. Изменение перевода или аудитории сбрасывает сохранённый предпросмотр/UUID, но сохраняет исходник и правки. При неизменном исходнике готовые три версии повторно не переводятся. Подтверждение и история показывают реальный сохранённый текст/язык адресатов. Старые кампании с единым текстом отображаются без выдуманного языка. Проба и retry используют серверный снимок. Нет автоповтора отправки при потере ответа.

Сохраняются существующие права, группы/категории/поиск, окно подтверждения, клавиатура, оранжевый стиль и RU/ES/EN на 320/390/1440. Проверка настоящим Chromium со Spring и отдельной QA PostgreSQL, внешний переводчик и Telegram подменены; источники RU/ES, языки профилей ES/RU/EN, ошибка перевода, устаревание, редактирование, подтверждение/история/повтор/отписка. Full verify, docs-drift, relay. Production и реальных сообщений нет.

Браузерная приёмка 27.11.2026: все четыре сценария TelegramMessagePreviewBrowserTest прошли. Новый сценарий проверил RU/ES исходники, смешанные профили ES/RU/EN, исправление испанской версии без повторного перевода, реальный серверный снимок, три разные доставки через подменённый транспорт и историю; также отказ сервиса и запоздавший ответ. Проверены 1440/390/320, доступность отправки на всех трёх языках интерфейса. Ручная правка переводов раскрывается отдельно. Прежние группы/исключения, проба/повтор/неопределённый ответ и восстановление входа сохранились. Настоящий OpenAI без ключа не вызывался.
