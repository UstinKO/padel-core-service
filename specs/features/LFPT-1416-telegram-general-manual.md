# LFPT-1416: Общий Telegram с ручными рассылками и независимым пилотом чеков

## Основание
Владелец согласовал подготовку подключения всех игроков с ручным запуском рассылок. Проверка рабочего окружения выявила включённые автоматические запросы и общий пилот, используемый также чеками. Подготовка не включает изменение production, деплой или отправку сообщений.

## Поведение
- При `telegram.players.pilot-enabled=false` активный обычный игрок может подключить профиль персональной ссылкой. Username не удостоверяет связь; /stop, WhatsApp и явное повторное подключение сохраняются.
- Для ручного режима `telegram.players.automatic-enabled=false`; ежедневная сводка выключена отдельно. Общий флаг расписаний не выключается, так как обслуживает другие процессы.
- Приём чеков ограничивается дополнительным независимым пилотом `telegram.players.receipts.pilot-enabled=true`. Нужны оба положительных ID: `pilot-player-id` и `pilot-tournament-id`. Пустой ID закрывает соответствующую область. Общие ограничения Telegram применяются дополнительно.
- Новые переменные `TELEGRAM_PLAYERS_RECEIPTS_PILOT_PLAYER_ID` и `TELEGRAM_PLAYERS_RECEIPTS_PILOT_TOURNAMENT_ID` имеют совместимый fallback к прежним переменным общего пилота в application.yml. Пустое явно заданное новое значение не снимает ограничение. `TELEGRAM_PLAYERS_RECEIPTS_PILOT_ENABLED` по умолчанию true независимо от общего пилота.
- Ограничение проверяется перед выбором события, показом кнопок, приёмом файла, прикреплением и блокировкой актуальной регистрации. Чтение и ручная проверка существующих чеков сохраняют прежние права; файл не подтверждает оплату.
- Редактор и очередь ручных сообщений уже реализованы в PR #1391/#1393/#1397/#1399; этот backend-PR их не дублирует. Включение флага рассылки без явного подтверждения кампании ничего не отправляет.

## Порядок будущего выпуска
1. Выпустить эту независимую защиту, сохранив общий пилот и существующие ID. Проверить совпадение области чеков до/после.
2. Подготовить остальные связанные PR на актуальном master и повторить CI/приёмку.
3. При отдельном поручении на рабочий запуск: зафиксировать независимые ID чеков, выключить автоматические запросы и ежедневную сводку, проверить значения, затем снять общий пилот.
4. Редактор ручных сообщений включить отдельно после выпуска стека; проверить пробу себе и выбранным подключённым получателям. Тексты и список подтверждает организатор.
5. Откат доступа — вернуть общий пилот, выключить флаг кампаний, оставить независимый пилот чеков включённым; данные регистраций/платежей и связи не удалять. Откат версии допустим только после возврата общего пилота, иначе старая версия снова расширит приём файлов.

Технический Telegram/алерты не выключаются. При включённом общем новом боте старый планировщик исключает его игроков из личных напоминаний. Подключение нового бота не переносит старую связь автоматически.

## Проверки
Отдельная синтетическая БД, подменённый Telegram: совместимость конфигурации, пустые ID, независимая область чеков при общем подключении, прямое прикрепление/старый цикл, активность/гости, отсутствие автоматических запросов и старых личных напоминаний. Никаких данных реальных игроков или секретов в репозитории.
