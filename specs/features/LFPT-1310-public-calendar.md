# LFPT-1310: Публичный календарь — сервер

## Статус
in-progress

## Источник
Задача #1310 и исходный запрос в `specs/requests/LFPT-1310-public-calendar.md`. В чате согласованы сервер → интерфейс → стенд и размещение только в `/torneos`.

## Связь с MASTER
Используются существующие события, правила публичности, вместимости, регистрации и статусы заявок. Вход не нужен для общего расписания; личный слой доступен только текущему игроку. Главная и административное проведение не меняются.

## Требования
- GET `/api/public/calendar?month=YYYY-MM`: полный диапазон сетки Пн–Вс, включая соседние даты, без усечения пагинацией. Дата события — его локальная дата начала; завершение после полуночи не переносит начало на другой день.
- GET `/api/public/calendar/catalog`: безопасные данные всего публичного каталога для существующего карточного режима. Общие фильтры и словари те же, что в календаре.
- Фильтры clubId/organizerId/format/gender/level. Категория C7 включает явно перечисленный C7 в диапазоне, C3 поддерживается; SUMA/TODOS совпадают точно. Не фильтровать скрыто по профилю. Существующий серверный каталог получает то же правило диапазонов.
- Единые общие форматы и фильтрация уровней переиспользуются административными вычислениями без изменения их HTTP-значений.
- Активные публичные события кроме BORRADOR; SOLO_POR_ENLACE и неактивные не раскрываются в данных и вариантах фильтров. Заполненное, закрытое, завершённое или отменённое публичное событие сохраняет статус, как в общем публичном каталоге.
- DTO содержит только безопасные поля расписания: ID, локальную дату/время/зону, формат, категорию, клуб, название организации, актуальную доступность и ссылку на существующую публичную страницу. Нет оплат, контактов участников, служебных комментариев и имени служебного аккаунта вместо организации.
- Доступность использует существующие числа основного состава и вместимости, порог последних мест 70% из действующих карточек и существующую открытость записи. Логика регистрации не меняется.
- GET `/api/players/me/calendar`: минимальные статусы собственных активных заявок только на публичные события; оба участника пары, резерв и неполные заявки учитываются отдельно от общей доступности. Отменённые/истёкшие и неактивные строки не являются действующей записью. Идентификатор игрока берётся из сессии, не из параметров. Личный ответ — no-store; общие ответы не содержат личных отметок.
- Справочники клубов/организаций выводятся из публичного источника до пользовательских фильтров, без раскрытия скрытых мероприятий.
- Изменение события или заявки видно при следующем GET, без отдельной копии расписания. Ошибки чтения не превращаются в пустой список.

## Вне объёма
Главная, новая схема регистрации, оплаты/отмена, новые типы событий, миграция БД, изменение административного интерфейса и выпуск без отдельного поручения.

## Критерии
- [x] Период на 4/5/6 недель, соседние даты, границы года; полный результат и стабильный порядок.
- [x] Черновики, скрытые, неактивные не видны ни в данных, ни в справочниках; закрытые и заполненные публичные видны.
- [x] Общая фильтрация диапазонов/C3/SUMA/TODOS и всех форматов; смена даты не создаёт дубль.
- [x] Основной участник, партнёр, резерв, одиночная заявка, отмена, чужой игрок и выход из аккаунта.
- [x] Безопасный DTO, авторизация, no-store, ошибки параметров и БД.
- [x] Полный verify на отдельной PostgreSQL; связанные регрессии календаря и каталога.
