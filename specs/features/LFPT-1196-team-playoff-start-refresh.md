# LFPT-1196: Fix завершение квалификации Team Playoff — показывать кнопку старта после сохранения результата

## Статус

in-progress

## Источник

[Issue #1196](https://github.com/UstinKO/padel-core-service/issues/1196), M04A приёмки #1045; владелец утвердил исправление 18.11.2026. Техническая постановка без отдельного клиентского запроса.

## Контекст / зачем

После AJAX-сохранения последней квалификации таблица обновляется, но серверный блок старта плей-офф остаётся прежним. Повторное открытие показывает кнопку. Нужно обновлять этот блок в текущей странице.

## Связь с MASTER.md

Условия допуска общей сетки и ранних матчей, состав, посев, результаты и права сохраняются. Видимость определяется действующим серверным Thymeleaf-условием, новые клиентские бизнес-правила не вводятся.

## Требования

### Функциональные

- Выделить всегда присутствующий контейнер двух существующих серверных блоков старта.
- После успешного сохранения результата квалификации загрузить свежий HTML управления без кеша и заменить только содержимое контейнера. Не навигировать и не терять другие поля страницы.
- При отказе сохранения блок не обновляется; неуспешное чтение сохраняет последнее подтверждённое состояние. Ответ старого запроса не заменяет более новый блок.

### Нефункциональные

Нет новых строк продукта, переводов и дизайна. Прежние формы, CSRF, confirm и условия сервера сохраняются. Проверка — реальным браузером на отдельном синтетическом контуре.

## Вне скоупа

Backend/API, ранние правила 9/16, изменение счёта/посева, редизайн или React-переключение, миграции и production-деплой.

## Изменения в системе

### API

Используется действующий GET управления. Новых маршрутов и полей нет.

### БД

Изменений нет.

### UI

`admin/americano/tournament-playoff.html`: контейнер `playoffStartSection` и его обновление после успешного AJAX-сохранения. Страница целиком не перезагружается.

### Документация

Документируется обновление блока в `.agents/PROJECT.md`; результат браузерного повтора M04A — в отчёте #1045 как действие агента.

## Критерии приёмки

- [ ] При незавершённой квалификации восьми пар общая кнопка отсутствует.
- [ ] Отказ сохранения не показывает кнопку и не меняет результат.
- [ ] После последнего успешного результата кнопка появляется в той же странице; тест не вызывает page.reload/goto для её появления.
- [ ] Настоящее нажатие старта создаёт четыре QF с восемью различными командами без TBD.
- [ ] Другие поля и текущие серверные confirm/CSRF сохраняются; ранние предложения не меняются.
- [ ] Реальный браузер, сборка/verify и документальные проверки проходят.

## Edge cases

Неуспешное сохранение/чтение, устаревший ответ загрузки HTML, истёкшая сессия без нужного фрагмента, ранее начатая сетка и уже завершённая квалификация.
