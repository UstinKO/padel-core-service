# LFPT-0547: Feature клубная учётная запись — скрыть блок «Администраторы» на главной панели (фронтенд)

## Статус
approved

## Источник
GitHub issue [#547](https://github.com/UstinKO/padel-core-service/issues/547) — техническая постановка от архитектора (прямой вход, `specs/requests/` не нужен). Telegram-сообщение (для reply): 5114.

Зависит от [#566](https://github.com/UstinKO/padel-core-service/issues/566) (бэкенд: флаг `isClubAdmin` в модели `AdminController.adminPanel()`, спека `specs/features/LFPT-0566-club-admin-dashboard-is-club-admin-flag.md`) — блокирует технически, этой задаче нужен атрибут модели из бэкенд-задачи. Реализуется в этом же прогоне, ветка — от бэк-ветки `feature/LFPT-0566` (PR [#594](https://github.com/UstinKO/padel-core-service/pull/594)).

## Контекст / зачем
После входа клубная учётная запись (`ROLE_CLUB_ADMIN`) на главной админ-панели (`GET /admin`, `admin/panel.html`) видит карточку статистики «Администраторы» с количеством администраторов **всей платформы** 1-Padel (`totalOwners`). Эта информация клубу не нужна и вводит в заблуждение — клуб не управляет и не должен видеть состав администраторов других клубов/платформы.

## Связь с MASTER.md
Не меняет инвариантов. `ROLE_CLUB_ADMIN` и принцип изоляции доступа по клубу уже описаны в `specs/MASTER.md` (раздел «Роли пользователей», LFPT-375/LFPT-376) — эта задача расширяет тот же принцип на видимость карточки статистики главной панели.

## Требования

### Функциональные
1. В шаблоне `src/main/resources/templates/admin/panel.html` скрыть `stat-card` с карточкой «Администраторы» (строки 52-60: `th:text="#{admin.panel.stat.admins}"` / `th:text="${totalOwners}"`) для `isClubAdmin == true`, добавив атрибут `th:unless="${isClubAdmin}"` на `<div class="stat-card">`, оборачивающий эту карточку.
2. Атрибут модели `isClubAdmin` уже передаётся контроллером (бэкенд-задача #566, PR #594, влита в эту ветку) — дополнительных изменений в `AdminController` не требуется.
3. Для всех остальных ролей (`SUPER_ADMIN`/`ORGANIZER`/`ADMIN`, т.е. `isClubAdmin == false`) карточка рендерится как раньше, без изменений разметки внутри неё.

### Нефункциональные
- i18n: новых пользовательских строк нет — существующий ключ `admin.panel.stat.admins` не меняется, условие рендера технического уровня (`th:unless`), не связано с локализацией.
- Безопасность: новой точки входа данных от пользователя нет — `isClubAdmin` берётся из атрибута модели, вычисленного на сервере из `@AuthenticationPrincipal Owner`.
- Производительность: не добавляет запросов — чисто условие рендера в уже существующем шаблоне.

## Вне скоупа
- Любые изменения `AdminController.adminPanel()` — сделаны в #566.
- Фильтрация значения `totalOwners` по клубу — карточка скрывается целиком, значение не используется для `CLUB_ADMIN`, его точность для этой роли не имеет значения.
- Другие карточки статистики главной панели (`totalPlayers`, `totalTournaments`, `totalWaitlist`) — не трогаются, уже обработаны в #546.

## Изменения в системе

### API
Нет. Чисто серверный Thymeleaf-рендеринг `GET /admin`.

### БД
Нет новой миграции.

### UI
`admin/panel.html` — одна карточка статистики («Администраторы») получает `th:unless="${isClubAdmin}"` на оборачивающий `<div class="stat-card">`. Остальная разметка страницы не меняется.

## Критерии приёмки
- [ ] `GET /admin` для `CLUB_ADMIN` — карточка «Администраторы» не рендерится (её нет в HTML-ответе: ни заголовка `#{admin.panel.stat.admins}`, ни значения `totalOwners` в этом блоке).
- [ ] `GET /admin` для `OWNER`(`ADMIN`)/`SUPER_ADMIN`/`ORGANIZER` — карточка «Администраторы» рендерится как раньше, со значением `totalOwners` (regression).
- [ ] Остальные карточки статистики («Total jugadores», «Torneos activos», «Lista de espera» и далее) рендерятся без изменений для всех ролей.
- [ ] `./mvnw verify` зелёный.

## Edge cases
- `CLUB_ADMIN` с `clubId == null` — `isClubAdmin` всё равно `true` (см. #566, зависит только от `role`), карточка скрыта так же, как для `CLUB_ADMIN` с привязанным клубом.
- Сетка статистики (`admin-stats-grid`, CSS grid/flex) — скрытие одной карточки через `th:unless` убирает элемент из DOM полностью (не `display: none`), остальные карточки переукладываются сеткой — ожидаемое поведение, не требует отдельной CSS-правки (аналогичный паттерн уже используется в этом же шаблоне для других условных блоков).
