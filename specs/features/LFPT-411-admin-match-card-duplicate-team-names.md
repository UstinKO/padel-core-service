# LFPT-411: Убрать дублирование названий команд в шапке карточки матча квалификации Team Playoff (админка)

## Статус
approved

## Источник
[GitHub issue #411](https://github.com/UstinKO/padel-core-service/issues/411) — клиентский запрос через Telegram (тема "AI Разработка", отправитель customer, переслано от Evgeny_754), оформлен как `specs/requests/LFPT-411-admin-match-card-duplicate-team-names.md`.

Telegram-сообщение (для reply): 4599

## Контекст / зачем
На странице управления Team Playoff в админке (`/tournaments/team-playoff/admin/{id}`, раздел "Квалификация") карточка матча квалификации показывает названия команд дважды: один раз — в серой шапке карточки в формате `Команда 1 vs Команда 2`, второй раз — сразу под ней, где те же названия уже показаны отдельно слева и справа с полем ввода счёта между ними. Для администратора, читающего карточку с телефона во время турнира, это лишняя, повторяющаяся информация, которая делает карточку выше и заставляет читать одно и то же два раза. Задача — оставить в шапке только номер корта, названия команд оставить только в основной части карточки.

Скриншот (сообщение в Telegram, переслано от Evgeny_754) подтверждает: карточка "Корт 1" на странице квалификации Team Playoff, шапка содержит `Martin Fiori / German Agustin vs Danila Gorbanev / Nikita Gorbanev`, та же пара имён повторяется ниже слева (`№5 Martin Fiori` / `German Agustin`) и справа (`№10 Danila Gorbanev` / `Nikita Gorbanev`).

## Связь с MASTER.md
Чисто техническая правка вёрстки существующей страницы, бизнес-инварианты, роли и статусы регистрации не затрагивает. `specs/MASTER.md` не меняется.

## Анализ (что реально происходит)

- Затронутая страница — `admin/americano/tournament-playoff.html`, раздел квалификации (`th:each="match : ${round.matches}" ... th:id="'qmatch-' + ${match.id}"`, строки 498-513).
- Шапка карточки (`.match-header`, строка 53: `display:flex;justify-content:space-between`) сейчас состоит из двух `<span>`:
  1. Строки 504-510 — `#{admin.playoff.label.court}` ("Корт"/"Cancha"/"Court" по локали) + номер корта + кнопка смены корта (`toggleCourtEdit`). Это единственное, что должно остаться.
  2. Строка 512 — `<span style="font-size:.75rem;color:#94a3b8" th:text="${match.note}">Equipo A vs B</span>` — дублирующая строка с названиями команд. `match.note` заполняется в `TeamPlayoffService` как `t1.getDisplayName() + " vs " + t2.getDisplayName()` (например, строки 1394, 1413, 1594, 1795) специально для этого поля — на других экранах (публичная страница, доска раундов плей-офф) это же поле используется иначе и не трогается.
  3. Ниже, в `.match-body` (строки 519-... и 567-...), названия команд уже показаны отдельно: `team-left` (`match.team1Number` + `match.team1Player1Name`/`team1Player2Name`) и `team-right` (аналогично для team2) — вот эта часть и есть та самая "основная часть карточки", которую нужно оставить как есть.
- Строка **512** — единственное место дублирования. Убрать нужно ровно этот `<span>`, не трогая соседний `<span>` с номером корта (строки 504-510) и не трогая `.match-body` (строки 519+).
- Проверено, что та же карточка (`qmatch`) на этой же странице больше нигде не переиспользует `match.note` в шапке — второе появление `match.note` на странице (строка 633, `round.note`) относится к заголовку раунда плей-офф (`SEMI_FINAL` и т.п.), это другое поле другой сущности (`AmericanoRound`, не `AmericanoMatch`) и визуально не дублирует названия команд — не трогается.
- Соседние карточки на той же странице для сравнения (не требуют изменений, дублирования нет):
  - Карточки плей-офф-сетки (`pmatch`, строки 637-651) — шапка показывает только "Корт N" + `match.playoffStage` (`SEMI_FINAL`), без названий команд — уже без дублирования.
  - Карточки Americano (`admin/americano/tournament.html`, строка 307) и Team Americano (`admin/americano/tournament-double.html`, строка 213-216) — тоже используют `match.note`/`match.matchNumber` в шапке, но их визуальная структура ("R1"/"R2" вкладки, статус, переведённый через `#{...}`) не совпадает со скриншотом клиента (там — непереведённый `IN_PROGRESS` и вкладки "Раунд N", что специфично именно для квалификации Team Playoff, строки 480-484 и 493). Эти шаблоны вне скоупа этой задачи (см. "Вне скоупа").

## Требования

### Функциональные
1. В шапке карточки матча квалификации на `admin/americano/tournament-playoff.html` (`qmatch`, строка 512) убрать `<span>` с `th:text="${match.note}"` целиком.
2. Шапка карточки после изменения содержит только: `#{admin.playoff.label.court}` + номер корта + кнопку смены корта (то, что уже на строках 504-510) — без изменений в этой части.
3. Основная часть карточки (`.match-body`: команда слева — счёт/форма ввода — команда справа) не меняется вообще — ни разметка, ни данные.
4. Поле `match.note` в backend (`TeamPlayoffService`) не меняется — оно используется и для других целей (например, дублирующего текста в другом месте UI, если такое найдётся при переносе кода), удаляется только его вывод в этой конкретной шапке.

### Нефункциональные
- i18n: не требуется — новых пользовательских строк не добавляется, только удаление вывода уже существующего поля.
- Безопасность: не применимо.
- Производительность: не применимо.

## Вне скоупа
- `admin/americano/tournament.html` (Americano) и `admin/americano/tournament-double.html` (Team Americano) — используют похожий паттерн (`match.note`/`match.matchNumber` в шапке), но не показывают дублирование названий команд визуально как на скриншоте (Americano — только номер матча `#{matchNumber}`, без названий команд вообще; Team Americano — показывает `match.note`, но карточка/вкладки раундов там выглядят иначе, чем на скриншоте клиента, и клиент явно ссылается на квалификацию Team Playoff по формату статусов "IN_PROGRESS"/"Раунд N"). Если аналогичное дублирование там тоже нежелательно — отдельная задача.
- Публичные страницы турниров (`tournaments/team-playoff/view.html`, `tournaments/team-americano/view.html`) — запрос касается только админки, публичные страницы не трогаем (явное ограничение в клиентском запросе).
- Карточки плей-офф-сетки (`pmatch`) — дублирования нет, изменений не требуют.
- Раздел "Квалификация" таблицы (не карточки, отдельная адаптированная под мобильные таблица из LFPT-407) — не затрагивается.

## Критерии приёмки
- [ ] На странице `/tournaments/team-playoff/admin/{id}`, раздел "Квалификация", в шапке карточки каждого матча (`qmatch`) отображается только "Корт N" (+ кнопка смены корта) — строка с названиями команд (`Команда 1 vs Команда 2`) в шапке отсутствует.
- [ ] Основная часть карточки (команда слева — счёт/форма — команда справа, номера команд, вторые игроки пар, M1/M2-метки) визуально не изменилась по сравнению с состоянием до правки.
- [ ] Смена корта (`toggleCourtEdit`/`submitCourtChange`) и ввод/редактирование результата матча продолжают работать без регрессий (ручная проверка в браузере).
- [ ] `./mvnw compile -DskipTests` проходит без ошибок (чисто разметочная правка, но компиляция затрагиваемого модуля должна быть проверена).
- [ ] Карточки плей-офф-сетки (`pmatch`) и страница Americano/Team Americano не изменились (регрессионная проверка — до/после diff шаблонов, кроме затронутой строки).

## Edge cases
- Матч без второго игрока в паре (гостевая/одиночная пара, `team1Player2Name == null`) — не относится к этой правке: `team-sub` в `.match-body` и так уже условно скрывается (`th:if`), в шапке никогда не показывался отдельно.
- Матч в статусе "TBD" (команда ещё не определена, `team1Player1Name == null`) — на квалификации такого не бывает (обе команды известны с начала квалификации, TBD характерно только для карточек `pmatch`, которые не затрагиваются).
- Очень длинные имена игроков (двойные фамилии) — раньше могли переноситься в обеих строках (шапка + тело), после правки перенос остаётся только в теле карточки — это и есть цель задачи (компактность), не побочный эффект для документирования отдельно.
