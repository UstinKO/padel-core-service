# LFPT-0907: Feature frontend UI v2 — карточка мероприятия и страницы клубов

## Статус
done

## Источник
[GitHub issue #907](https://github.com/UstinKO/padel-core-service/issues/907), спецификация напрямую из issue.

## Контекст / зачем
Главная и каталог уже работают на React под `/preview/**`. Следующий шаг — карточка мероприятия, список клубов и карточка клуба в визуальном языке UI 0.7, с реальными данными и сохранением действующих ссылок.

## Связь с MASTER.md
Правила участия, резерва, пар, оплаты и подсчёта мест не меняются. Сервер определяет формат, фазу и доступные действия. UI не раскрывает контакты участников. `SOLO_POR_ENLACE` доступен по прямой ссылке, но не появляется в списках.

## Проверка существующей реализации
- `GET /api/public/tournaments/{id}` возвращает типизированные данные мероприятия, клуб, цену, вместимость PLAYERS/PAIRS, резерв, описание, canonical `websiteUrl` и публичные имена участников.
- `GET /api/public/clubs` и `/{id}` возвращают публичные сведения активных клубов; каталог поддерживает `clubId` и серверную пагинацию.
- В `PublicTournamentDto` отсутствуют сведения об организаторе, вариант парного формата, фаза проведения, live-ссылка и список доступных действий. Одного `AMERICANO_TEAMS` недостаточно для различения round-robin и Team Playoff. Текущий `TournamentViewController` получает эти сведения отдельно из сервисов.
- `SpaForwardHandlerMapping` выполняет forward в неизменённый `/web/index.html`; серверной подстановки SEO/OG нет. ADR-0008 описывает её как отдельную серверную работу. Клиентские meta-теги не заменяют серверный HTML для краулеров.
- Ошибки мобильной карточки имеют прежний JSON `{code}`; клиент обязан учитывать HTTP-статус и не ожидать только ProblemDetail.
- Закрытые #827/#898 сами по себе не покрывали все критерии #907. Дополнения реализованы отдельной backend-задачей #944.

## Требования

### Функциональные
- Добавить BrowserRouter-страницы `/preview/torneo/{id}`, `/preview/clubs`, `/preview/clubs/{id}`; карточки каталога ведут в новый preview, публичные ссылки шаринга остаются `/torneo/{id}` и `/clubs/{id}`.
- Использовать только публичные типизированные API и TanStack Query, отменять устаревшие GET через AbortSignal. Фикстуры находятся только в тестах.
- Карточка мероприятия: название, время/зона, формат и модальность, уровень, клуб/адрес, цена, вместимость, основной состав/резерв, описание/правила, дедлайн отмены. Персональные контакты участников не отображаются.
- Организатор, точный вариант парного формата, состояние проведения, действия и live-ссылка поступают из нового серверного контракта, без догадок по датам, типу и числу участников.
- Список клубов и карточка клуба используют реальный API; мероприятия клуба загружаются каталогом с `clubId`, пагинацией и исключением скрытых событий.
- Share использует серверный canonical URL, без `/preview`, hash и административных параметров. Поддержать копирование, WhatsApp/Telegram и локальную генерацию QR из этой ссылки. PNG-ссылку показывать только при явном серверном разрешении и существующем контракте.
- Для записи и live использовать разрешённые сервером ссылки на действующие страницы. Реализация записи и live-экранов остаётся в #909/#911.
- Не переносить фиктивного организатора, демонстрационные контакты, расчёты мест и локальные статусы из макета. Не отображать YouTube.
- Подготовить SEO-контракт для будущего переключения: canonical/title/description/OG формируются сервером. Закрытый preview сохраняет noindex, боевые маршруты не переключаются.

### Нефункциональные
- ES/RU/EN, Intl с America/Argentina/Buenos_Aires; повторно использовать существующие токены и компоненты.
- Клавиатура, видимый фокус, доступные заголовки и подписи, управление фокусом share-диалога, reduced motion; без overflow на 320/390/1440 px.
- Отдельные loading/empty/error/retry и not-found. Некорректный id не должен становиться запросом к API или приводить к белому экрану. Ошибки 404/503 поддерживаются и для прежнего JSON-контракта.
- Описание мероприятия выводится безопасно, без вставки неподтверждённого HTML. Внешние URL проверяются по протоколу и назначению.

## Изменения в системе

### Реализованная зависимость — backend #944
1. Добавить обратно совместимый публичный контракт деталей для веба: публичные сведения об организаторе, точный вариант формата, phase/state, серверные ссылки и разрешённые действия. Использовать существующие сервисы `TournamentViewController`, не переносить бизнес-логику в DTO или React.
2. Не менять прежнюю форму мобильного API и ошибок. Не сериализовать административный `TournamentDto` и контакты игроков.
3. Подготовить серверную выдачу SEO/OG по ADR-0008 и контракт будущего маршрута; preview остаётся закрытым/noindex, production allowlist пуст.
4. Покрыть различия round-robin/Team Playoff, not-started/live/finished/cancelled, скрытые события, права, приватность и мобильную совместимость интеграционными тестами. Не реализовывать snapshots/ranking/history целиком: это #903.
5. Backend #944 и frontend #907 — отдельные issue, ветки и PR.

## Критерии приёмки
- [x] Мероприятие, клубы и мероприятия клуба работают на реальном API, без fixture-импортов в production.
- [x] Различия форматов и фаз приходят с сервера; PLAYERS/PAIRS, заполненность и резерв отображаются без клиентского пересчёта.
- [x] Организатор и действия показаны только в разрешённом серверном объёме; контакты участников отсутствуют.

- [x] Canonical/share/QR используют публичный URL, даже при открытии из `/preview/**`.
- [x] Desktop/mobile, ES/RU/EN, deep link/refresh, клавиатура и share-диалог проверены Playwright.

## Edge cases
Неизвестный/слишком большой/нечисловой id, пустые клубы/участники/резерв, неактивный клуб, мероприятие по прямой ссылке, недоступная БД, отсутствующие необязательные поля, длинные имена, ошибка clipboard, отсутствие Web Share API, небезопасная внешняя ссылка. Повтор загрузки выполняет только GET.
