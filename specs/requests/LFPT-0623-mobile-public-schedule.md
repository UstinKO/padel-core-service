> Заполнено по мотивам сообщения заказчика в Telegram (`telegram_launch_message_id: 5202`), переслано от третьего лица. К сообщению был приложен архив с готовым патчем, "фиче-спекой" и описанием задачи — эти файлы не являются согласованной спекой проекта и не применяются как готовый код; используются только как справочный материал о том, какой функционал нужен заказчику.

## Что нужно сделать
Подключить мобильное приложение 1Padel.App к расписанию турниров сайта: приложению нужен способ без входа в систему получить список турниров и детали конкретного турнира (события, даты, клубы, цены, свободные места).

## Где это происходит
Новый серверный API (нет сегодня) — аналог того, что сейчас видно без входа на страницах `/` (список) и `/torneo/{id}` (детали), но в формате JSON для мобильного клиента.

## Зачем это нужно
Мобильное приложение — отдельный клиент сайта, которому нужно отображать то же расписание, что видно на сайте, без логина пользователя в приложении.

## Кто это увидит/использует
- [x] Игроки (через мобильное приложение, не через сайт)
- [ ] Организаторы/владельцы клубов
- [ ] Только я (суперадмин)

## Насколько срочно
Не указано явно заказчиком; формулировка подразумевает готовность приступить сейчас.

## Примеры / референсы
Приложенный заказчиком архив содержал пример реализации (`backend-schedule.patch`) — контроллер `/api/public/tournaments` (список) и `/api/public/tournaments/{id}` (детали), публичный DTO без контактов участников и без полей управления. Взято как иллюстрация желаемого контракта, не как готовый к слиянию код — реализация ниже написана и проверена самостоятельно по обычному процессу.

## Есть ли ограничения
Прямо указано заказчиком: использовать существующие правила видимости турниров, не раскрывать контакты участников и внутренние данные. Не трогать существующие защищённые операции `/api/tournaments/**`.
