# Запрос на доработку

> Клиентский запрос через Telegram (пересланное сообщение, `telegram_launch_message_id: 5384`, отправитель отмечен как customer). Разбит на бэкенд (#679) и фронтенд (#680) — `GIT_WORKFLOW.md` §1.4.

## Что нужно сделать

Улучшить поиск зарегистрированного партнёра при парной регистрации на турнир и добавить автоматические подсказки при ручном вводе данных партнёра.

### 1. Расширить основной поиск

Сейчас подсказка в поле поиска: «Имя, фамилия или email».

Заменить на:
- RU: «Имя, фамилия, телефон или Telegram»
- ES: «Nombre, apellido, teléfono o Telegram»
- EN: «First name, last name, phone or Telegram»

Поиск должен работать по имени, фамилии, номеру телефона и Telegram username. Email можно оставить дополнительным параметром поиска, но убрать из основной подсказки. Поиск — автоматически по мере ввода текста (уже работает).

### 2. Поиск по номеру телефона

Номер может быть сохранён с кодом `+54`, а пользователь вводит его в другом допустимом формате — нужна нормализация, чтобы такие записи сопоставлялись. При этом избегать ошибочного сопоставления разных номеров.

### 3. Поиск по Telegram

Если Telegram указан в профиле игрока — искать по нему: с символом `@` и без него, без учёта регистра. Telegram username не считать постоянным уникальным идентификатором игрока (его можно изменить).

### 4. Автоматические подсказки при ручном вводе

Основная часть доработки. Если пользователь проигнорировал основной поиск и выбрал «Или введите вручную», система должна продолжать искать существующих игроков:
- при вводе имени — находить и предлагать похожие записи;
- при вводе фамилии — повторно искать, даже если по имени совпадений не было (например, имя введено с ошибкой, но фамилия совпадает с существующим игроком);
- при вводе телефона — проверять совпадения с существующими записями;
- при вводе Telegram или email, если такие поля в форме есть — тоже проверять совпадения.

### 5. Отображение найденных игроков

При обнаружении совпадений — компактный список: «Возможно, ваш партнёр уже зарегистрирован», дальше — найденные игроки с возможностью выбора. Показывать имя и фамилию, уровень (если есть), другие разрешённые публичные данные, помогающие различить игроков. **Не раскрывать** полные номера телефонов, email и другие закрытые контактные данные. При выборе — использовать существующий ID, не создавать новую запись.

### 6. Если совпадений нет

Пользователь должен спокойно продолжить ручное добавление партнёра — без лишних подтверждений.

### 7. Интерфейс

Основной поиск — приоритетное действие:
- «Найти зарегистрированного партнёра», поле «Имя, фамилия, телефон или Telegram»;
- ниже — «Не нашли партнёра? Добавить вручную»;
- во время ручного заполнения подсказки показываются ненавязчиво, не блокируя ввод.

### 8. Технические требования

- По возможности переиспользовать существующий механизм поиска игроков.
- Не создавать новую независимую базу партнёров.
- Корректно обрабатывать частичные совпадения.
- Debounce при вводе.
- Защитить поиск от массового перебора контактных данных.
- Поддержать RU/ES/EN.
- Проверить мобильную версию.
- Не нарушать сценарии «Ищу партнёра» и «Добавлю партнёра позже».

## Критерии готовности (как сформулировал заказчик)

1. Основной поиск работает по имени.
2. Работает по фамилии.
3. Работает по телефону.
4. Работает по Telegram, если эти данные есть в профиле.
5. При ручном вводе имени появляются подходящие варианты.
6. При вводе фамилии поиск продолжает работать независимо от результата поиска по имени.
7. При вводе телефона обнаруживаются возможные совпадения.
8. Пользователь может выбрать существующего игрока без создания новой записи.
9. Если совпадений нет — можно добавить нового партнёра.
10. Поиск корректно работает на мобильных устройствах.

## Где это происходит

Страница турнира, модалка парной регистрации («Busco compañero» / режим `WITH_PARTNER`) — `tournament-details.html`, `/api/players/search`.

## Зачем это нужно

Уменьшить количество дублирующихся профилей игроков, которые создаются, когда партнёр уже зарегистрирован, но пользователь об этом не знает и вводит данные вручную.
