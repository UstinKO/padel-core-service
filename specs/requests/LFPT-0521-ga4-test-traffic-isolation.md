# Запрос на доработку

> Собрано из сообщения в Telegram-теме "AI Разработка" (пересылка от Evgeny_754, оформлено через кнопки Начать/Отправить, telegram_launch_message_id: 4937). Техническая часть общего запроса на аудит GA4 — изоляция тестового трафика от боевой аналитики (остальная часть запроса — `specs/requests/LFPT-0522-ga4-registration-events.md`).

## Что нужно сделать

Заказчик просит проверить, не отправляет ли локальная или тестовая версия сайта данные в рабочий GA4, и, если это так, устранить попадание тестовых посещений в боевую аналитику. Повод: в отчёте GA4 за 1–9 октября 475 сеансов, но среди них есть аномалии — 41 сеанс с источником `(not set)`, встречаются сеансы с источником `localhost:4200 / referral`.

Анализ кода подтвердил причину: Measurement ID GA4 (`G-X5G4N3ND26`) и ID Microsoft Clarity захардкожены как дефолт в базовом `application.yml` без переопределения для `dev`/`cloud`/`test`-профилей — то есть любой локальный запуск разработчика и любая автоматическая browser-проверка в облачном конвейере (`/develop-feature`) реально отправляет данные в боевой GA4/Clarity.

## Где это происходит

`src/main/resources/application.yml` (дефолт ID), `application-prod.yml` (нет явного ID для прод-профиля — сейчас прод держится только на дефолте из базового файла), `templates/fragments/analytics.html` (рендеринг тега).

## Зачем это нужно

Чтобы отчёты GA4 показывали только реальных посетителей сайта, а не разработку/тестирование.
