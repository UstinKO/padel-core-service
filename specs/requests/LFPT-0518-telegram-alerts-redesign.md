# Запрос на доработку

## Что нужно сделать
Переделать Telegram-уведомления об ошибках. Сейчас сообщение выглядит так:

```
🔴 PlayerDashboardController
Error registering for tournament
```

Это практически бесполезно — известно только, что «что-то где-то не получилось». Telegram должен отвечать хотя бы на вопросы: что делал пользователь, где сломалось и почему.

Например, вместо этого — полезнее получать:

```
🔴 Ошибка регистрации на турнир
Event: TOURNAMENT_REGISTRATION
Tournament ID: 184
User ID: 928
Endpoint: POST /api/tournaments/184/register
HTTP: 500
Error: Duplicate registration
Request ID: a82f31...
Time: 08/10/2026 15:00
```

И для восстановления пароля:

```
🔴 Ошибка восстановления пароля
Event: PASSWORD_RESET
Stage: RESET_LINK_OPEN
Endpoint: /reset-password
Result: Invalid or expired token
HTTP: 400
User ID: 928
Request ID: f37a...
```

Причём полезно разделить этапы:
- `PASSWORD_RESET_REQUEST` — человек запросил письмо.
- `PASSWORD_RESET_EMAIL_SENT` — письмо успешно отправлено.
- `PASSWORD_RESET_LINK_OPEN` — попытался открыть ссылку.
- `PASSWORD_RESET_TOKEN_INVALID` — token неправильный/просроченный.
- `PASSWORD_RESET_SUCCESS` — пароль успешно поменяли.

При этом сам token, пароль и полный reset-link в Telegram отправлять нельзя — это чувствительная информация. Можно показывать только состояние токена — valid / expired / already used / invalid.

Ещё одна вещь, которую нужно изменить: сейчас Telegram смешивает в одном канале:
- настоящие ошибки приложения;
- срабатывания `RateLimitFilter`;
- попытки подозрительной авторизации.

Нужно разделить на три уровня:
- 🔴 **Application Error** — реально сломалась функция сайта.
- 🟡 **Security Warning** — rate limit, подозрительные IP, блокировки.
- 🟠 **User/Validation Error** — пользователь ввёл неправильные данные, попытался зарегистрироваться второй раз и т. п.

Тогда по Telegram сразу понятно: если красное — надо разбираться, если жёлтое — защита кого-то отсеяла, а не сайт сломался.

## Где это происходит
Не конкретная страница — внутренний канал уведомлений об ошибках в Telegram, которым пользуется архитектор/владелец для диагностики (логирование → `TelegramLogAppender` → Telegram-бот). Конкретные примеры из текста — ошибка регистрации на турнир (`PlayerDashboardController`) и флоу восстановления пароля.

## Зачем это нужно
Красное сообщение в Telegram сейчас не даёт понять, что произошло и насколько это серьёзно — приходится лезть в код/логи вручную. Конкретно по восстановлению пароля — это высокий приоритет: игрок, который забыл пароль, фактически теряется для сайта и не может зарегистрироваться на турнир, что напрямую влияет на набор игроков.

## Есть ли ограничения
- Token, пароль и полный reset-link восстановления пароля — никогда не отправлять в Telegram в открытом виде. Только статус токена (valid/expired/already used/invalid).
- Не заменять существующий канал Telegram-алертов целиком — успешные этапы (письмо отправлено, пароль сменён) не должны превращаться в лишний шум уведомлений.
