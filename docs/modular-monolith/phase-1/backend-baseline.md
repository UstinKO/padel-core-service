# Исходная проверка backend и данных пилота

Задача [LFPT-1047](https://github.com/UstinKO/padel-core-service/issues/1047). Исходный `master`: `b7a44ac05ba51a8f42b35f297bc493f8fe64ec0d`. Модульная сборка и перенос движка ещё не выполняются.

## Проверяемый набор

Существующие восемь unit-тестов сохранены. Девятый фиксирует порядок первой пары при одинаковой стоимости: для входа 1,2,3,4 — (1,3),(2,4), для обратного — (4,2),(3,1), для всех трёх PriorityOrder. Это unit-only проверка, без новой UI-кнопки. TC01–TC07 покрыты unit-тестами; REMATCH_FIRST и STRENGTH_FIRST остаются действующими потребителями TeamPlayoffService, SEED_FIRST — unit-only.

Пять интеграционных проверок подготовки данных используют настоящий PostgreSQL, TeamPlayoffService, историю и транзакционные proxy. Проверяются идемпотентность seed, квалификация, финал, reset с сохранением аккаунтов, совместимость прежнего JSON, роль/CSRF, запрет чужого клуба, stale expectedTeam/conductVersion, совместный rollback сетки/истории и отсутствие after-commit уведомления при rollback. Отказ пересоздания откатывает также удалённые турниры и метаданные.

В интеграционном тесте заменена только входная проверка имени БД, чтобы тест выполнялся на стандартной отдельной CI-БД; запись/история/удаление настоящие. Проверки настоящих preview guard выполняются существующими boundary-тестами и отдельно при запуске preview-образа. Этот seam не является доказательством допустимости подключения production-БД.

Для zsh аргумент с `TeamPlayoff*Test` необходимо заключить в одинарные кавычки. Не задавать глобально `APP_SCHEDULING_ENABLED=false` при full verify: существующий unit-тест проверяет включение scheduling по умолчанию. Отключение планировщика в изолированном runtime обеспечивает профиль preview.

Новый seed/reset на старом артефакте не запускать: он не знает дополнительных pilot metadata. Это ограничение подготовки fixtures, описанное в runbook.

Локальные Maven/Python логи, снимок ID и screenshot сохранены вне публикуемых файлов; чувствительные runtime-файлы не включаются в PR. Отчёт не заявляет ручной турнирный прогон или деплой.
