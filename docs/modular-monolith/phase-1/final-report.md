## Повторение

Из отдельного checkout с собственным подготовленным preview и Chromium:

```sh
./mvnw --batch-mode --no-transfer-progress -DskipTests package
./mvnw -pl padel-tournament-engines -am test
python3 automation/ui-preview/check.py
python3 automation/ui-preview/playoff-pilot.py extended
python3 automation/ui-preview/playoff-pilot.py run --rehearse
```

`-DskipTests package` здесь не подменяет backend verify: он получен из #1050 и CI выше.
Node из Maven toolchain должен быть в PATH, `PLAYWRIGHT_MODULE_PATH` указывает на установленный `frontend/node_modules/@playwright/test/index.mjs`.
Не отключать rate limit: при повторных логинах выдерживать пополнение лимита AUTH. Не повторять мутацию после отказа вслепую.
Общий browser smoke меняет собственные шесть seed-мероприятий; `check.py` восстанавливает их при завершении.
Для повторного полного прогона сначала вернуть исходный общий seed в своём preview.

`extended` создаёт два дополнительных мероприятия через существующие формы/API, использует только 32 синтетических игроков пилота.
Они не входят в reset пяти базовых мероприятий и сохраняются до осознанной очистки собственного контура.
Команда не принимает `--reset`, `--record`, `--rehearse`; fixture не подменяет production-правила.
Основной runner не меняет принятые JSON-эталоны; `--record` по-прежнему пишет только кандидата в target.

Безопасные runtime-доказательства: `target/modular-pilot/{report,extended-report,jwt-smoke,rollback,module-rollback}.json`,
скриншоты там же и `target/release-rehearsal/report.json`. Чувствительный browser input находится только в игнорируемом runtime,
создаётся с правами 0600 и удаляется в `finally`; файл доступа и runtime не входят в PR.
Проверка старого reactor выполнена отдельным операторским сценарием поверх штатного release-механизма: последовательность, хеши и сравнения указаны выше.

## Ограничения и остаток

- #1067 — прежний текстовый статус команды после play-in; продвижение победителя проверено отдельно. Новых регрессий автоматический прогон не обнаружил.
- Первое создание дополнительного события упало из-за незаполненного асинхронного select в тестовой подготовке. Fixture явно задаёт синтетическую категорию C9; после исправления оба дополнительных сценария прошли. Продуктовый код не менялся.
- При повторном unit-прогоне активная ручная блокировка обнаружила зависимость старого теста от настоящего runtime checkout. Тест переведён на временный runtime; добавлена проверка, что ручная сессия останавливает CLI до Docker/login, и отказы несовместимых флагов. После исправления весь набор прошёл.
- На Mac Python: 102 теста, 101 успешно, 1 платформенный Linux-тест пропущен. docs-drift и agent-migration: 0 расхождений. JS syntax и diff проверены.
- Настоящие ручные M01–M09, технические HTTP/WS-пункты, наблюдение restart/rollback человеком пока не выполнены. Исходные M01/M02 от 13.11 остаются историческими результатами #1048.
- Финальное решение go/no-go и закрытие #1045 возможны после ручного журнала. Проверенные автоматические результаты не дают сами по себе разрешения переносить следующие доменные срезы.
