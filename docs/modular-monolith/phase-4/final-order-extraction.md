# Итоговые места дополнительных встреч: выделение вычисления

[LFPT-1376](https://github.com/UstinKO/padel-core-service/issues/1376) продолжает baseline #1375, включённый через PR #1379. Исходный код — master `2ff7a03d4f72932477a823d209ed5cef10d6d073`. Перенесено только вычисление RoundRobinRules.finalOrder. Следующий шаг — [application read-сценарий #1377](application-contract.md).

## Владение и границы

RoundRobinFinalOrderEngine в padel-tournament-engines — единственный владелец назначения итоговых мест. Входы: Standing(index, teamId, position) и Match(firstId, secondId, firstScore, secondScore, completed, placementStart); результат: Ranked(index, position). Индекс обозначает исходную строку, не номер команды или место. Records используют только JDK; имён, DTO, JPA и legacy enum в engines нет.

RoundRobinRules.finalOrder сохраняет Java API и RoundRobinStandingDto. RoundRobinFinalOrderMapper через MapStruct преобразует строки/матчи, а затем исходную команду по возвращённому индексу в DTO с прежними id/номером/именем. Статический Mappers.getMapper сохраняет вызовы прежнего package-private helper без Spring bean. Потребитель этого моста — действующая сборка ответа TeamAmericanoService; при дальнейшей миграции адаптер удаляется после ухода его callers. Application ещё не вызывает final-order.

Формула в bootstrap больше не дублируется. SETS/POINTS engines, их адаптеры, RoundRobinAdditionalMatches и TeamAmericanoService не меняются. POM, HTTP/JSON/HTML/WS, схема/Liquibase, начисление, propagation/isolation/readOnly/flush и история прежние. Guard требует 10 вычислительных классов и 24 вложенных типа; отрицательные пробы, ArchUnit и Java release 17 сохраняются. Разрешения application для конкретных типов трёх engines вводятся только в #1377.

## Сохранённое поведение

Завершённая встреча с placementStart назначает победителю указанный слот, проигравшему — следующий. Оставшиеся строки сохраняют круговой порядок; общие места сдвигаются по свободным слотам. Pending и встреча без места пропускаются, включая null-счёт. Круговые показатели и исходные объекты не меняются.

Characterization также фиксирует прежние некорректные внутренние входы: ничья выбирает вторую сторону, повтор назначения перезаписывает слот, пересечения не приобретают новую проверку; duplicate id, неизвестный id, отсутствующий счёт и место вне диапазона сохраняют прежний класс исключения. Это описание helper, а не новые допустимые пользовательские правила: валидация команд остаётся прежней. Пустой круг не обходит обработку дополнительных встреч.
