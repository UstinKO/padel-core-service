## Ответ и поведение

GET /tournaments/team-americano/api/{id}/ranking возвращает 13 корневых полей и 43 поля каждой строки ranking. Порядок массивов и null закреплены целиком; порядок ключей JSON-объекта не является условием сравнения. Стороны игроков доступны Java DTO и не попадают в JSON. setDifference и незаполненные регистрационные/плей-офф-поля остаются null, даже если hasPaid/attended/adminComment заполнены в entity.

POINTS сохраняет последовательные места при равенстве, включая ничью 16:16 и ненулевые matchesDrawn. SETS начинает с общих мест 1/1. Полный круг даёт finished=true ещё при статусе CERRADO; pending дополнительный раунд снова делает finished=false. Команда завершения меняет статус, а её DTO совпадает с предыдущим GET завершённых матчей. Дополнительный финал меняет finalRanking, сохраняя круговой ranking.

Покрыты пустое проведение с fallback POINTS/32/1, обе ветки до счёта/после круга/pending/сыгранного финала, гость/уровни/телефоны/стороны, частичный круг/null mode, места 4–5 и встреча без места. Исходная интеграционная регрессия дополнительно покрывает финал/бронзу, исправление и restore; исходные adapter/engine-тесты — равенства и мини-таблицу. Fixture-нормализация меняет только динамические ID и UUID email; значения/порядок/статистика не подгоняются.

JSON API требует авторизации: anonymous Accept JSON — 401, Accept HTML — 302 на login. Публичная MVC-страница доступна анонимно. Авторизованный игрок/чужой Owner читает JSON, но admin-страница проверяет ownerId: чужой CLUB_ADMIN той же площадки получает HTML redirect /error/403 либо JSON 403. Redirect /{id}/ranking сохраняет публичный адрес.

Отсутствующий турнир сейчас приводит к необработанному ResourceNotFoundException и HTTP 500; это подтверждено MockMvc/конечным jar. Родственные задачи уже есть: [#453](https://github.com/UstinKO/padel-core-service/issues/453) для ResourceNotFoundException, [#445](https://github.com/UstinKO/padel-core-service/issues/445) для публичной страницы. Дубль не создаётся, исправление в перенос не включается. Если canonical fix будет принят раньше #1377, этот эталон ошибки обновляется явно.

## Доказательства транзакций

Пассивный test-only observer временно добавляется в настоящие repository-proxy и снимается в finally; реализация сервиса/маппинга не подменяется. Внешний service/MockMvc GET выполняет repository-чтения с actual transaction/readOnly=true и одним EntityManager внутри каждого запроса. Сохранённые позиции намеренно равны 9, DTO возвращает 1/2. Hibernate entity insert/update/delete — 0; полные строки команд/раундов/матчей и число history-записей не меняются.

Во внешней write-транзакции настоящий initialize возвращает результат до commit; getRanking видит изменённую, ещё не закоммиченную статистику; finish использует тот же EntityManager, active=true/readOnly=false. После принудительного rollback нет турнира, команд/раундов и history. Это проверка текущего REQUIRED и атомарности, не тест многорепличной конкурентности.

Текущий ConductChange делает собственные flush/capture до и после команды. AUTO-flush при joined write-read не запрещается новым портом; GET без записей проверяется отдельно во внешнем read-only контексте. Новые REQUIRES_NEW/isolation/locks/commit в #1377 не допускаются.

## Воспроизведение

На отдельной PostgreSQL: полный корневой `./mvnw -B verify` с frontend. Для адресного прогона:

```sh
./mvnw -B -pl padel-bootstrap -am -Dskip.frontend=true -Dtest=RoundRobinRankingBaselineTest -Dsurefire.failIfNoSpecifiedTests=false test
```

Флаг адресного выбора действует только в этом запуске, Surefire/POM не меняются. Отсутствующий JSON-файл приводит к ошибке теста; фактические ответы в target помогают разбору и не обновляют эталон автоматически.

Browser-скрипты round-robin-sets.mjs и round-robin-query.mjs получают путь к временному mode-0600 JSON с origin/gatewayPassword/password/cases собственного preview; файл удаляется после прогона. Синтетические пары независимы от общих fixtures. Сначала выполняется жизненный цикл, затем read-контракт. Общие fixtures для отдельного pilot должны быть исходными; между независимыми наборами выдерживается штатный AUTH-интервал. Runtime и доступы не коммитятся.

Исходный parent-plan/specs фазы публикуются вместе с baseline: подготовленные ранее локальные материалы актуализированы фактическим анализом. Их наличие не означает реализацию #1376/#1377/#1378.
