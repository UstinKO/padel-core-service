## Браузер и данные

Исходные round-robin-sets.mjs/round-robin-query.mjs повторены без изменения ожиданий: POINTS с равенством/ничьими, SETS с мини-таблицей личных встреч, исправление круга и финала с возвратом, завершение, история, 24 представления. API/public/admin сохраняют прежние правила доступа и ошибку отсутствующего турнира 500 (#453).

Новый round-robin-acceptance.mjs на двух турнирах по шесть пар проверяет исходную/частичную/полную таблицу, финал 1–2, бронзу 3–4, другие места 5–6 и встречу без места. Pending отключает завершение. После исправления победителя финала настоящая форма истории восстанавливает выбранную версию; JSON результата полностью совпадает с состоянием до исправления. Круговая таблица остаётся 1…6, итоговая — 6…1. Дополнительные результаты не меняют круговую статистику.

Отдельные guest-фикстуры POINTS/SETS воспроизводят исходную Java-модель отсутствующего профиля партнёра: SQL подготавливает только собственные синтетические строки после штатной инициализации. Это проверка read-границы, не нового сценария регистрации. SIN_ESPECIFICAR и гость дают null-уровни, имя/телефон гостя сохраняются. Стороны LEFT/RIGHT и отсутствие стороны проверяются в HTML; в JSON скрытых Java-полей по-прежнему нет. Пустой неинициализированный турнир сохраняет fallback POINTS/32/1 и публичное сообщение без таблицы.

Всего — **72 представления** public/admin × RU/ES/EN × desktop/mobile: 24 исходных, 24 расширенных и 24 гостевых. Новый readonly-проход повторяет 48 представлений и сравнивает DOM с API, включая места/имена/статистику; POINTS дополнительно проверяет горизонтальное прокручивание на 390px. Снимки синтетического интерфейса сохранены локально в target/round-robin-acceptance; физическая проверка устройств не подменяется viewport.

Полные строки команд/раундов/матчей/истории/регистраций, турниров и связанных профилей семи приёмочных турниров сравниваются до и после GET. Завершённые круговые позиции совпадают с сохранёнными. В гостевых фикстурах намеренно сохранена позиция 9: DTO вычисляет 1/2 либо 1/1, строки БД остаются с 9. Schema fingerprint включает колонки/default/nullability, constraints, indexes и полный databasechangelog.

При отладке нового сценария устранено чтение тела XHR после навигации. Два плотных браузерных набора также достигли штатного GENERAL-бюджета 200/мин; runner теперь разделяет их паузой 60 секунд. Итоговый прогон прошёл без новых превышений; RateLimitFilter, его лимиты и исходные ожидания не менялись.

## Воспроизведение и CI

Перед Maven переменные DB_URL/DB_USERNAME/DB_PASSWORD указывают на отдельную собственную тестовую PostgreSQL. Для отдельного preview из рабочей копии:

```sh
./mvnw -B clean verify
python3 automation/ui-preview/preview.py init --port 18378
python3 automation/ui-preview/preview.py build
python3 automation/ui-preview/preview.py up
python3 automation/ui-preview/round-robin-acceptance.py run
python3 automation/ui-preview/round-robin-acceptance.py capture
python3 automation/ui-preview/preview.py stop
python3 automation/ui-preview/preview.py up
python3 automation/ui-preview/round-robin-acceptance.py compare
```

Runner проверяет environment=preview, имя БД, совпадение UUID control и состояние ручного сеанса. Каждый run создаёт новые собственные fixtures из синтетического seed, чужие данные не удаляются. Полные inputs/checkpoint/ошибочные HTML сохраняются только в игнорируемом runtime с mode 0600; секреты/доступы/сырые данные не публикуются. Временный browser-input удаляется в finally, внешние запросы браузера блокируются.

CI запускает тот же runner после общего/расширенного пилота с отдельным AUTH-интервалом, затем сверяет capture после stop/up. Этот полный stop/up с сохранённым volume отдельно повторён локально; все ответы, строки, история и схема совпали. В artifact включены только три безопасных JSON-отчёта; runtime/checkpoint/inputs не загружаются. Документация и автоматизация проверяются docs-drift/agent-migration и собственными тестами.

Отдельно проверены jar #1376 до application-переноса (`c96d4369d9cb36614ef29d70ee5e63005496156153deb4b08f1e337cf35e2ece`) и исходный baseline #1375 (`e5f078da3c6d6aeb84cc74ec53e74c8d59bc8ada23ce099c4bd1d15fa20c77b1`), затем возврат текущего jar. [Безопасная сводка](acceptance-qa-2026-11-25.json) содержит точные хеши, результаты и ограничения.

Новый ручной сеанс владельца, физические iPhone/Android/VoiceOver и многорепличная конкурентность не проводились. DevTools повторно не запускался: production-классы/настройки прежние, принятая проба #1377 остаётся действующей; полный runtime restart проверяется отдельно. Ограничения #1067 и обычного Expo Basic 401 сохраняются; QA-адаптер проверяет реальный API/отрисовку и не выдаётся за исправление транспорта.

Команды запуска/счёта/завершения, дополнительные встречи/валидация/начисление, ConductChange/history/after-commit остаются в legacy. Следующий этап требует отдельной декомпозиции write-сценариев по фактическому графу. Persistence/web/integrations и физическая PostgreSQL/Swarm не выделены; #1051 не объявляется разблокированной. Техническая приёмка read-среза не означает готовность всех семи модулей.
