# ADR-0001: границы модулей и инверсия зависимостей

Статус: **Принято** владельцем 13.11.2026 в обсуждении LFPT-1041: семь модулей и PlayoffMatchingEngine как пилот. Историческое имя файла сохранено; исходное ограничение пятью модулями снято.

## Контекст и принятые решения

В исходной идее пять модулей. Владелец разрешил большее число при обосновании. Приняты разделение API DTO/domain/entity и владение портами со стороны application. Application не зависит от persistence или API DTO; engines не зависит от application/framework. Spring в application разрешён по ADR-0004.

## Принятая структура

[Семь модулей](../target-architecture.md): api-contract, tournament-engines, application, persistence, web, integrations, bootstrap. Отдельный bootstrap — единственный main/исполняемый jar, integrations — сетевые и фоновые адаптеры. Domain/ports остаются внутри application, отдельный domain пока не требуется. Публичные границы и пакеты доменов контролируются проверками.

## Альтернативы

| Вариант | Компромисс |
|---|---|
| Исходные пять с web/bootstrap/integrations вместе | Меньше структуры, но модуль контроллеров имеет слишком широкую ответственность |
| Шесть с отдельным bootstrap | Отделён запуск, но нужно явно определить место сетевых/фоновых адаптеров |
| Принятые семь | Отдельные входы, внешние интеграции и сборка; больше POM, зато нет общего инфраструктурного модуля, зависящего от всех |
| Отдельный восьмой domain | Может потребоваться при доказанной необходимости; сейчас добавляет границу без согласованной пользы |
| Модули сразу по доменам | Рассмотреть позднее по графу; сейчас данные/сервисы сильно связаны |

Это проектный выбор, а не универсальное правило best practices. [Ports & Adapters](https://alistair.cockburn.us/hexagonal-architecture) описывает независимость поведения от внешних адаптеров, а не число Maven-проектов. Выделять все модули одним переносом не требуется.

## Последствия и согласование

Маппинг нужен на реальных границах; одинаковые копии всех классов заранее не создаём. Bootstrap импортирует адаптеры, обратная зависимость запрещена. Application/engines тестируются с подменёнными портами. Семь модулей подтверждены отдельно после предложения. В первой фазе вводятся bootstrap и engines с единственным root legacy src; остальные модули — последующими рабочими срезами. Подготовленные задачи: [фаза 1](../phase-1/README.md).
