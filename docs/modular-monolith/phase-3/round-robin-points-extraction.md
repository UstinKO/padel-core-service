# Круговые места POINTS в вычислительном модуле

[LFPT-1371](https://github.com/UstinKO/padel-core-service/issues/1371) продолжает [SETS #1350](round-robin-sets-extraction.md), включённую через PR #1352. Спецификация: [LFPT-1371](../../../specs/features/LFPT-1371-round-robin-points-standings-module.md).

## Граница и формула

RoundRobinPointsStandingsEngine принадлежит padel-tournament-engines и использует только JDK. Team содержит индекс исходной строки, id, номер, сумму очков, победы, набранные/пропущенные очки и поражения; Ranked — индекс и место. Компаратор общий для rank и прежнего RoundRobinRules.order: totalScore DESC, wins DESC, разница очков DESC, losses ASC, number ASC, id ASC.

POINTS сохраняет последовательные места 1/2/3 при спортивном равенстве. Полностью равные строки остаются стабильными. Индекс не участвует в сравнении и не сворачивает одинаковые ID. Поля boxed не нормализуются: разница вычисляется только после сравнения суммы и побед. Сохраняется прежняя Integer-арифметика, включая переполнение; новых бизнес-правил нет.

## Legacy-адаптер

RoundRobinPointsStandingsMapper генерируется MapStruct с ReportingPolicy.ERROR. Из entity передаются только скалярные поля, без вызова getPointDifference при маппинге. Контекст списка возвращает исходный экземпляр по индексу, не создаёт entity и не хранится в mapper.

Для статических RoundRobinStandings.rank и RoundRobinRules.order используется default mapper через Mappers.getMapper — такой же адресный переходный мост, как у SETS. Нового Spring bean нет, конструкторы сервисов не меняются. RETURN_DEFAULT только на входном преобразовании сохраняет прежнюю одиночную null-строку: сортировка не сравнивает её, результат ссылается на исходный null. Для нескольких строк требуемый null-критерий по-прежнему приводит к NullPointerException.

POINTS не читает matches. order(null) по-прежнему использует POINTS, rank(null mode) — SETS; сервисный fallback scoringMode сохраняется. SETS engine/mapper/фильтрация и остальные методы RoundRobinRules, в том числе apply/validateScore/finalOrder, не меняются. TeamAmericanoService, сохранение currentPosition, транзакции/history, API/JSON/WS/UI и схема/Liquibase прежние.

В engines девять вычислительных классов и 21 обязательный вложенный тип. Проверка конечного jar отклоняет отсутствие/дубликаты, неверный release и framework; семь динамических Python-тестов охватывают и новые типы. Enforcer и ArchUnit не ослаблены.

## Проверки

До замены на master 5b102574 выполнены 41 проверки: прежние RoundRobinRulesTest (4), RoundRobinStandingsTest (6), RoundRobinStandingsAdapterTest (14) и новый RoundRobinPointsStandingsAdapterTest (17). После выделения выполняется тот же набор без изменения ожиданий; автономный engine проверяется отдельно.

Браузерный round-robin-sets.mjs теперь проверяет POINTS с тремя парами по 46 очков: победы отличают первую из них, номер — две оставшиеся. Исправление/возврат счёта меняют/восстанавливают таблицу. SETS сохраняет исходный сценарий личных встреч. Обе ветки проходят дополнительный финал без изменения круговой статистики, завершение, историю, 24 страницы организатора/зрителя × RU/ES/EN × 1440/390 с refresh. Позиции сравниваются с PostgreSQL.

Полный clean verify с frontend — на отдельной PostgreSQL. Итоговый jar проверяется в собственном preview: общий smoke/Team Playoff, репетиция выпуска/отката, прежний jar и возврат на той же БД. Сравниваются обе таблицы с матчами, полные строки команд, пилотные snapshots и схема/Liquibase. DevTools проверяет два запуска минимального контекста, идентичность исходных entities и оба POINTS API; это не полноценный ручной запуск IDE/сервисного bean.

## Остаток и ограничения

Начисление/валидация, finalOrder/дополнительные встречи и сервисные сценарии остаются в bootstrap. Для application нужны собственные модели/порты и сохранение транзакций; перенос JPA-сервиса целиком не подходит. Мапперы остаются адресными мостами до подготовки application-границы и поздней #1051. Физическая БД не переносится.

Физические устройства, новый ручной PASS владельца и многорепличная конкурентность не проверяются этим срезом. Принятые ограничения #1067 и Expo preview Basic 401 сохраняются; QA-адаптер общего пилота проверяет настоящий API и отрисовку. Runtime и доступы не публикуются.
