# Перенос расписания Americano в engines

Задача [#1332](https://github.com/UstinKO/padel-core-service/issues/1332), родитель #1041, предшественник #1279 / PR #1281. [Спецификация](../../../specs/features/LFPT-1332-americano-schedule-module.md). Это следующий согласованный с владельцем срез после King of Court.

## Реализация

AmericanoScheduleEngine и AmericanoScheduleValidator вместе с двумя исходными Test перемещены из корневого src в существующий `padel-tournament-engines`. Все четыре файла сохранены байтово: package, Java API, MatchSlot, ScheduleReport, Random, DP/fallback, число попыток, bye и критерии качества расписания прежние. Движок вызывает валидатор, а валидатор использует MatchSlot: совместный перенос сохраняет однонаправленные зависимости Maven.

AmericanoService, репозитории, MapStruct, права, транзакции, история проведения и дополнительные очки остаются в bootstrap. Статические утилиты не получают Spring bean. POM, HTTP/JSON/WS, UI, переводы, БД и Liquibase не меняются. Reactor по-прежнему содержит четыре дочерних модуля и один boot jar; application/persistence/web/integrations не расширяются этим переносом, #1051 сохраняет поздний порядок.

В engines теперь четыре вычислительных класса и девять публичных вложенных типов. Проверка конечного jar требует все эти типы в одной обычной библиотеке, запрещает shadow-копии основных и любых вложенных классов в BOOT-INF/classes, проверяет Java 17 и отсутствие Spring/JPA. Семь существующих Python-тестов автоматически охватывают расширенный список обязательных типов.

ArchUnit разбирает базовый тип массива и разрешает примитивы. Разрешение на весь legacy-пакет не добавляется: независимые отрицательные примеры отклоняют прямую legacy-зависимость и двумерный массив legacy-классов, положительный пример разрешает int[][]. Production-классы библиотеки по-прежнему зависят только от JDK и собственного модуля.

## Проверки и воспроизведение

Автономный прогон: `./mvnw -pl padel-tournament-engines -am test`. В engines выполняются 46 тестов: 12 исходных engine, 8 validator, 13 King of Court, 9 Playoff и 4 ArchUnit. Spring и БД этому модулю не нужны. Сервисные сценарии Americano остаются в bootstrap и проверяются корневым `./mvnw clean verify` с frontend и отдельной PostgreSQL. Артефакт: `python3 .github/bin/check-engine-artifact.py`.

`tests/browser/modular-pilot/americano-engine.mjs` принимает путь к временному JSON с origin, gatewayPassword, password и tournamentId своего preview. Доступы хранятся только локально в файле mode 0600 и удаляются после прогона. Использованы восемь синтетических игроков собственного Preview 1; внешние запросы блокируются, аналитика отклонена.

Браузер запускает индивидуальный Americano через штатную форму: 8 игроков, 2 корта, FULL, 7 раундов, лимит 21. Проверяются 14 сохранённых матчей, однократное участие каждого игрока в раунде и все 28 уникальных партнёрств. Два результата 13:8 вводятся через UI; API подтверждает автоматическое завершение первого раунда, рейтинг содержит четыре результата 13 и четыре 8. Кнопка навигации открывает уже созданный второй раунд. Затем проверяются организатор/зритель, refresh, RU/ES/EN и ширины 1440/390 — 12 страниц, история проведения и отсутствие JavaScript errors.

Раунд завершается автоматически при сохранении последнего результата. Первая версия наблюдателя ошибочно отправляла повторный complete и получила 409; исправлен только тест. Следующий раунд при FULL уже создан заранее: кнопка переключает отображение, не генерирует новое расписание.

Отдельно собранный неизменённый master запускается на той же синтетической БД. До/после переключения и возврата сравниваются rounds, matches, ranking/simple и отпечаток колонок схемы/журнала Liquibase. Для рейтинга сравниваются все поля DTO по playerId и отдельно проверяется порядок действующих критериев. Порядок строк при полном равенстве критериев не фиксируется: исходный findByTournamentId не задаёт дополнительный порядок, что проявилось при переключении jar. Нового правила разрешения равенства этот перенос не вводит. Общий smoke/репетиция: `python3 automation/ui-preview/playoff-pilot.py smoke --rehearse` с дополнительным сравнением состояния Americano.

## Результат 24.11.2026

Итоговые числа, хеши неизменённых файлов и проверенных jar приведены в [безопасной сводке](americano-qa-2026-11-24.json). Локальный jar собирается до коммита из рабочей копии master `e00e8014d045fdf6009364978e38835207b5c58d` с переносом классов; этот SHA обозначает основу рабочей копии, а не будущий коммит PR. CI опубликованного коммита проверяется отдельно.

Корневой `clean verify` с frontend: **1363 теста**, 0 failures/errors, 4 штатных browser-пропуска (RegistrationSourceBrowserTest, ParticipationBrowserTest и два PlayerTelegramBrowserTest). Engines — 46 тестов без пропусков. Python: 27 GitHub (включая 7 engine guard), 48 relay, 5 worker (1 Linux-only пропуск), 12 preview, 22 release. Три artifact-guard, docs-drift и agent-migration прошли.

Итоговый jar SHA-256 `554cebe9547920f43dc46b604119db652f57b63c9134d994f832d31c04c78ff3`; неизменённый master — `84782ae2c5d81ed01d9574131d37505ee293c88843fad3ad9d3b37fe339de9a6`. На этом итоговом jar повторно прошёл браузер Americano. Прежний jar и возврат сохранили все сравниваемые поля расписания, счёта и рейтинга, а также отпечаток схемы/Liquibase. Общий legacy/API/React/Expo/session/CSRF/роли/участие/JWT smoke и репетиция выпуска/отката прошли; состояние Americano сохранилось. JWT login/me/events — 200, anonymous me — 401. Репетиция сохранила пять snapshots, проверила старый lazy chunk, HTTP-сбои chunk/readiness и восстановление журнала.

Физические телефоны, новый ручной PASS владельца и новое измерение concurrent не заявляются. Ограничения принятых предыдущих фаз сохраняются. Runtime, доступы и полные HTTP/state JSON остаются локально.
