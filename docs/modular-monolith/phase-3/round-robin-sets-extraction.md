# Расчёт мест кругового SETS в engines

[Issue #1350](https://github.com/UstinKO/padel-core-service/issues/1350), родитель #1041, предшественник #1343 / PR #1347. [Спецификация](../../../specs/features/LFPT-1350-round-robin-set-standings-module.md).

## Граница вычисления

Новый RoundRobinSetStandingsEngine вычисляет только SETS и мини-таблицу личных встреч. Он использует JDK и собственные record, не импортирует entity/DTO/legacy enum, JPA, Spring, Jackson или репозитории. Критерии прежние: победы → общая разница геймов → победы внутри равной группы → разница внутри группы. Номер команды и id задают порядок строк, не отдельное спортивное место; полное равенство сохраняет места 1/1/3.

| Тип engines | Данные |
|---|---|
| Team | Индекс исходной строки, id, номер команды, победы и общая разница геймов |
| Match | Id двух команд и два счёта; адаптер уже отобрал завершённые круговые встречи |
| Ranked | Индекс исходной строки и вычисленное место |
| private Meetings | Победы/разница мини-таблицы, без инфраструктуры |

RoundRobinStandings.rank/Ranked остаются статическим legacy API. Ветка POINTS сохраняется; она не читает матчи и сохраняет последовательные места. RoundRobinRules не меняется: начисление, валидация, POINTS-компаратор и финальные места дополнительных встреч остаются прежними.

SETS-адаптер через RoundRobinSetStandingsMapper преобразует минимальные поля в record, вызывает engine и возвращает **те же экземпляры AmericanoTeam** по индексу исходной строки. MapStruct генерирует оба преобразования; связывание результата с entity — адресный lookup списка, не создание новой entity и не загрузка из БД. Это сохраняет последующие currentPosition/saveAll в TeamAmericanoService и не вводит нового поведения для одинаковых id: прежний SETS-отказ остаётся, POINTS допускает разные строки с одним id как прежде.

Default-маппер создаётся Mappers.getMapper для сохранения существующего static API; Spring bean и конструкторы сервисов не добавляются. Маппер не хранит контекст списка между вызовами. Его потребитель — RoundRobinStandings/TeamAmericanoService; временный JPA-маппинг компилируется в bootstrap до поздней #1051, затем принадлежит адаптеру хранения после подготовки application-границы. HTTP/JSON/UI, права, транзакции, история, JPA и Liquibase не меняются.

Default-фабрика отдельно проверена в настоящем Spring Boot DevTools: probe, адаптер и TeamAmericanoService загружены RestartClassLoader, SETS сохраняет исходные entity и места, POINTS работает по прежнему пути. После Restarter.restart() проверки повторены. Это минимальный probe-контекст без БД и сервисного bean; полноценные сервисные сценарии проверяются на boot jar.

Адаптер сохраняет порядок фильтров: isCompleted, затем phase==null и оба счёта заданы. Pending-встреча без round не разыменовывается; при пустом составе матчи не читаются. null mode в этом Java API по-прежнему выбирает SETS; действующий сервисный fallback отсутствующего scoringMode→POINTS остаётся в RoundRobinRules.mode.

## Доказательства до и после

До реализации на исходном RoundRobinStandings прошли 20 проверок: 6 прежних и 14 новых RoundRobinStandingsAdapterTest. Затем те же файлы с теми же ожиданиями прошли на адаптере. Проверяются две/три/четыре равные команды, личные встречи только внутри равной группы, placement/pending/неполный счёт, полные равенства, порядок по номеру/id, исходные ссылки и поля, пустой состав, null mode и отсутствие чтения матчей в POINTS.

12 новых автономных engine-тестов проверяют вычисления по нейтральным данным, включая общие места/пропуски после группы, мини-таблицу, неизменность входов и перенос индекса строки. В engines теперь 115 тестов без Spring/БД. ArchUnit не ослаблялся; artifact guard требует восемь вычислительных классов и девятнадцать вложенных типов, запрещает shadow-копии и framework, проверяет Java 17.

| Команда | Проверка |
|---|---|
| `./mvnw -pl padel-bootstrap -am -Dskip.frontend=true -Dtest=RoundRobinStandingsTest,RoundRobinStandingsAdapterTest -Dsurefire.failIfNoSpecifiedTests=false test` | Проверки legacy API до и после; флаг отсутствующего выбранного теста относится только к этому запуску, Surefire не ослаблялся в POM |
| `./mvnw -pl padel-tournament-engines -am test` | Автономные unit/ArchUnit |
| `./mvnw clean verify` | Всё приложение с frontend на отдельной PostgreSQL, включая RoundRobinIntegration/Elo и прежний Team Playoff |
| `python3 .github/bin/check-engine-artifact.py` | Конечный jar и все выделенные типы |

## Runtime

`tests/browser/modular-pilot/round-robin-sets.mjs` принимает путь к локальному JSON своего preview (origin, gatewayPassword, password и два сценария). Файл mode 0600 удаляется после прогона. Используются отдельные синтетические игроки и турниры, general fixtures не изменяются; внешние запросы заблокированы, аналитика отклонена.

В штатной форме запущены SETS и POINTS: четыре постоянные пары, два корта, три раунда, шесть круговых встреч. Результаты введены через UI. SETS проверяет исходные общие места, равные общие показатели двух команд и победителя личной встречи; исправление счёта меняет лидера, возврат восстанавливает таблицу. POINTS сохраняет прежний порядок. Дополнительный финал в обоих режимах меняет итоговые места и сохраняет все поля круговой статистики. Проверены завершение, история, 24 страницы организатора/зрителя 1440/390 × RU/ES/EN с refresh, без JavaScript errors. Сохранённые в PostgreSQL позиции совпадают с API.

После автоматического reload наблюдатель проверяет сохранённые значения формы/API, не пытается читать уже выгруженное браузером тело ответа. Полноценное восстановление истории Round Robin дополнительно покрыто существующим RoundRobinIntegrationTest; браузерный сценарий этой задачи проверяет страницу истории и исправление/возврат счёта.

Общий `playoff-pilot.py run --rehearse` и `extended` проверяют прежний Team Playoff, legacy/React/Expo/session/CSRF/JWT и репетицию выпуска/отката. Прежний jar/возврат на той же собственной БД сравнивают пять пилотных snapshots и обе круговые таблицы с дополнительными встречами, а также схему/журнал Liquibase.

## Остаток миграции

POINTS, начисление/валидация и дополнительные встречи остаются в RoundRobinRules; сервисные сценарии и хранение — в bootstrap. Следующие application-срезы требуют доменных моделей/портов и сохранения транзакций. #1051 остаётся поздним этапом хранения; физическая БД не переносится.
