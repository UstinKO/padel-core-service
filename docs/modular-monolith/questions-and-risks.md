# Согласованные решения, открытые вопросы и риски

Состояние на 13.11.2026, LFPT-1041. Ответ владельца принят как основание следующих решений; технические гипотезы и результаты проверок не подменяются согласием.

## Согласовано владельцем

| Решение | Практическое следствие |
|---|---|
| Приняты семь модулей | contract, engines, application, persistence, web, integrations, bootstrap; вводятся поэтапно |
| API DTO / domain / JPA entity разделяем | Разные владельцы типов; MapStruct на границах; без заранее созданных копий всех классов |
| Практичный Spring в application; ACID в приоритете | `@Service`/`@Transactional` разрешены; JPA/JDBC/Web и адаптеры запрещены; транзакции сохраняем и проверяем |
| OpenAPI JSON → Java API DTO | Канонический контракт и параметры в Git; generated Java в target, без ручного редактирования и коммита |
| Generated-классы могут быть не record | Узкое исключение CODE_STYLE только для генерации; рукописные модели под прежним правилом |
| Микросервисы сейчас не проектируем | Только Java-вызовы; возможность будущего выделения кратко описываем в ADR, без HTTP/брокера/распределённой инфраструктуры |
| Пилот PlayoffMatchingEngine подтверждён | История/потребители проверены; переносить вычисление и подключение, без соседнего рефакторинга |
| Отдельные исходная и итоговая e2e, скрипты и ручные нажатия | #1048 — исходный прогон; #1045 — повтор после #1050; дефекты исправить до расширения |
| Работа приложения сохраняется после каждой задачи | Каждый PR самостоятельно собирается/запускается/проверяется, не требует будущего PR для исправления |
| Хранение переносим отдельной поздней #1051 либо в согласованное окно Swarm | Пилот не меняет пути миграций/подключение; физическая PostgreSQL отдельно из #1040 при необходимости |

## Что осталось проверить или уточнить технически

| Вопрос | Как решается | Блокирует ли фазу 1 |
|---|---|---|
| Исходная полная регрессия и реальные browser-fixtures | #1047 и #1048, [детальный анализ](phase-1/code-analysis.md) | Блокирует reactor до успешного исходного отчёта |
| Реализация безопасного промежуточного reactor | #1049: bootstrap использует единственное root legacy src; необходимые runtime-пути меняются в том же PR | Блокирует перенос движка до рабочей сборки/доставки |
| Генератор, OAS и параметры | Отдельная будущая проба Java17/Jackson3/Jakarta/MapStruct | Нет, API codegen вне первой фазы |
| Готовность портов и графа данных для persistence | Поздняя #1051, зависимости последующих фаз дополняются | Нет |
| Окно #1051: конец миграции или Swarm | Выбрать по готовности портов и #1040, отдельные репетиции/откат | Нет; физическая PostgreSQL отдельной задачей при необходимости |

Семь модулей, направление генерации, Spring, record-исключение, пилот и отдельная задача хранения больше не являются открытыми вопросами. Первая фаза готова к последовательной реализации с #1047; все прогоны/дефекты фиксируются честно.

## Риски: проявление, предотвращение и доказательство

| Риск | Как проявится | Предотвращение / критерий |
|---|---|---|
| Новые имена вместо границ | Application импортирует entity, API DTO или адаптер | Проверки импортов, порт принадлежит application; запрещённый пример действительно падает |
| Цикл legacy ↔ новый модуль | Перенесённый класс тянет старый сервис/enum | Полный граф потребителей; адаптер остаётся в legacy и зависит от application; меньший совместимый срез |
| Нарушение ACID | Основная запись сохранилась без истории/очков/outbox | Одна транзакционная граница; принудительная ошибка и полный rollback; конкурентные сценарии по существующим гарантиям |
| Потеря Spring proxy/AOP | Аннотация есть, но вызов не перехвачен; after-commit не исполнился | Интеграция через настоящий bean/proxy, проверка propagation/isolation/rollback и побочных эффектов |
| JPA-семантика изменилась | Lazy-loading, потеря dirty checking/flush/lock, N+1 | Тесты затронутых чтений/записей и запросов; данные не переводятся в detached-модели без явного сохранения |
| Повтор Liquibase | Изменился логический путь файла | Путь в classpath сохранён; обновление тестовой схемы предыдущего выпуска и повторный старт не исполняют старые изменения |
| Generated DTO меняет контракт | Null/absent, enum, дата, деньги, validation расходятся | Проверка JSON до/после, API-контрактов и реальных клиентов; фиксированные генератор/параметры |
| Двойной обработчик | Два bean вызывают запись/уведомление | Один активный путь записи; не сравнивать старую/новую реализацию двойным выполнением I/O |
| Потеря контроля доступа | Новая точка входа обходит проверку клуба | Отрицательные сценарии на сервере, не только скрытая кнопка |
| Ошибка packaging | Выбран library jar, пропали static/templates, frontend собирается несколько раз | Один main/repackage; явный артефакт; image/archive и реальный browser smoke |
| Регрессия существующих клиентов | Нужен одновременный релиз React/Expo | Каждый backend-этап обратно совместим; отдельная frontend-задача при реальной необходимости |
| Временный мост бессрочен | Исключение не имеет задачи удаления | Реестр: класс/потребитель/владелец/issue удаления; очистка вслед за переключением |
| Смешали перенос кода и БД | Непонятно, какой шаг вызвал отказ; откат приложения требует восстановления данных | Независимые репетиции/артефакты, поздний перенос БД, сохранение схемы и явные шаги общего окна |
| Пропущена исходная ошибка пилота | Старое поведение ошибочно признано эталоном | Исходный e2e до переноса; несоответствие MASTER фиксируется отдельным дефектом, не консервируется молча |
| Редко менялся — принят за стабильный | Неиспользуемый/сломанный путь выбран пилотом | История — фильтр; реальные потребители, тесты и ручной проход — доказательства |
| Частичный перенос сломал приложение | Требуется следующий PR для запуска/исправления | Условия plan.md для каждого PR; подготовка → переключение → удаление, каждый шаг рабочий |

Главные проверки пилота описаны в [матрице TC01–TC25](phase-1/test-cases.md). Новых бизнес-правил не вводим. Первые измерения — фактическое время сборки, результаты регрессии, зависимости и оставшиеся мосты; сроки и ускорение без замеров не обещаем.
