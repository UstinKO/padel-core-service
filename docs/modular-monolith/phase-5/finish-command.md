# Завершение кругового турнира в application

[LFPT-1405](https://github.com/UstinKO/padel-core-service/issues/1405) продолжает [сохранение позиций #1404](position-command.md), включённое через PR #1409. Исходный master — `cf540dce7863832c3f7e52f6616eb876650868c4`. Следующий шаг фазы — независимая приёмка #1406.

`RoundRobinFinishCommand.finish(Long)` загружает через `RoundRobinFinishPort` идентификатор и признак отмены турнира. Для действующего события команда читает максимум номера раунда и число завершённых раундов по всем фазам. Затем она проверяет наличие кругового раунда и при его наличии проверяет список команд, сохраняя прежний порядок даже при недостаточном числе завершённых раундов. При отказе `RoundRobinFinishIncomplete` несёт исходную разность MAX и count. Нулевой запасной MAX и отрицательное значение разности проверяются отдельно.

После допуска команда последовательно вызывает `RoundRobinPositionCommand.update`, запись `FINALIZADO` через порт и `RoundRobinRankingQuery.ranking`. Query формирует прежний результат внутри write-транзакции. Итоговые места с дополнительными встречами и сохранённые круговые позиции остаются отдельными значениями.

`LegacyRoundRobinFinishAdapter` использует прежние repository-вызовы. MapStruct материализует `RoundRobinFinishEvent`. Для записи адаптер получает ссылку на уже загруженный турнир в том же EntityManager, меняет его состояние и передаёт тот же managed-объект в прежний `save`. Интеграционный тест проверяет identity и состояние объекта в момент сохранения.

`TeamAmericanoService.finishTournament` сохраняет обе аннотации, перевод application-ошибок в прежние `ResourceNotFoundException` и `InvalidStateException` и маппинг результата в прежний DTO внутри внешней транзакции. В bootstrap остаются права и MVC redirect/flash, ConductChange с блокировкой турнира и проверкой версии/ключа, история, восстановление и отправка уведомления после commit. Повтор с новым ключом сохраняет прежнее поведение. Счёт и автозавершение продолжают вызывать совместимый делегат позиций. Адаптеры и MapStruct остаются в bootstrap до поздней границы хранения #1051.

Данные, типы и порядок вызовов описаны в [контракте](command-contract.md). QA сопоставляет исходные [W01–W18](test-cases.md), результаты браузера и два JAR в [машинном отчёте](finish-command-qa-2026-11-25.json).

## Проверки реализации

Полный `./mvnw -B clean verify` с frontend и отдельной PostgreSQL прошёл 1650 тестов с пятью штатными пропусками. Исходные 28 write-проверок сохранены. Три добавленные проверки покрывают отсутствие турнира, запасной MAX и перевод ошибки чтения рейтинга. Исходные 12 read-проверок и 11 полных JSON совпадают побайтно.

Проверки подключения реальных Spring beans подтвердили один write EntityManager для finish, портов, записи позиций и чтения рейтинга. Отказы в positions, save турнира, query и истории откатили реальные SQL-записи без отправки уведомления. Тесты повторов и stale/replay сохранили HTTP/flash и эффекты истории. Конкурентная проверка на PostgreSQL подтвердила, что второй вызов ждёт удерживаемую первым блокировку, а затем получает отказ из-за устаревшей версии. Оба соединения принадлежат одному процессу. Приёмка двух реплик остаётся #1214.

Артефактные проверки и ArchUnit прошли с Java release 17 и runtime 21. В application guard входят 35 обязательных классов и 11 разрешённых типов engines. Из 980 production-классов 969 совпадают с JAR #1404, добавлено восемь, изменено три. Классы engines/api-contract совпадают побайтно. SHA-256 текущего JAR — `fb33e65c82bf71c882de7f8981f70f51a051b474da64ef0b6c17df20365802aa`. SHA-256 принятого JAR #1404 — `4ec17d7e4f325dfa512121a5af917e89913ecbfdf4b978d9c577e203cbc35f81`. Текущий артефакт собран до итогового коммита. 121 тест Python-автоматики прошёл с одним штатным пропуском. Проверки docs-drift и agent-migration завершились без расхождений.

DevTools дважды запустил минимальный контекст с общей загрузкой finish/position/query, портов, legacy-адаптеров, мапперов и engines. В этом контексте реальные Spring-прокси и мапперы работали с тестовыми repositories и transaction manager. Настоящий SQL, identity и откат проверены отдельно на PostgreSQL. Без include для application проба обнаружила расхождение загрузчиков. Настройки DevTools сохранены.

Браузер проверил 72 представления круговой матрицы и ещё 48 после restart. В SETS и POINTS прошли завершение, дополнительные встречи, гостевые команды и восстановление истории. Общий пилот проверил session/CSRF/JWT/права, двух WS-зрителей и плей-офф на 8, 9 и 16 пар. Репетиция выпуска прошла с восстановлением после сбоев chunk и readiness.

Restart и переход на принятый JAR #1404 с возвратом на новый сохранили ответы семи круговых и пяти пилотных сценариев. Для семи круговых сценариев дополнительно сопоставлены полные связанные строки, история и schema/Liquibase. Stop/up сохранил круговые контрольные данные. GET сохранил поведение чтения. В последнем контейнере аудит не нашёл ошибок quota, шаблонов и парсинга.

Ограничения #445, #453 и #1067 и Expo Basic 401 учтены в отчёте. Физические устройства, VoiceOver, новый ручной сеанс и две production-реплики остаются за пределами этого прогона.
