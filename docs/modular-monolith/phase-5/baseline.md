## Что закреплено до переноса

| Граница | Проверяемый результат |
|---|---|
| Standalone positions | Пустой/несуществующий Tournament не требует новой проверки; POINTS fallback/null mode, исходные объекты и порядок saveAll; нет новой истории/уведомлений |
| SETS | Личные встречи только COMPLETED круга, PLACEMENT исключён; полностью равные пары делят места 1,1,3 |
| Finish | Отмена до счётчиков; MAX номера и count COMPLETED всех фаз; initialized short-circuit; pending PLACEMENT/дыры номеров сохраняют исходный отказ |
| Круг / итог | currentPosition сохраняет круговое место; finalRanking отдельно учитывает финал; прочие бизнес-поля команд не меняются |
| Proxy / ACID | Один реальный write EntityManager на пересечении repositories/query; nested read query видит свои записи, standalone и внешняя write-транзакция работают как раньше |
| Отказы | После реального flush позиций, состояния, перед query и на границе history INSERT весь контекст откатывается; полные строки вместе с timestamps прежние |
| Commit / транспорт | Public invalidation наблюдается через отдельное JDBC-соединение уже после commit; два FINISH в одной внешней транзакции дают одну отправку, до commit отправки нет |
| Key / version | Известный ключ — текущий сервисный 409/replayed; stale — прежний отказ; MVC finish сохраняет 302 с error-flash и соответствующим заголовком |
| Повтор | Без ключа/без изменения snapshot нет новой истории; новый ключ владельца создаёт очередной FINISH |
| RESULT caller | Последний результат обновляет позиции; исправление уже завершённого раунда не получает нового вызова записи позиций — GET вычисляет актуальные, явный update/finish сохраняет их |
| Restore | Поздние версии сохраняются, регистрации не меняются, восстановленное проведение вновь завершается; общая платформа restore остаётся прежней |
| Конкуренция | Два независимых контекста одного процесса: первый удерживает FOR UPDATE, второй реально ждёт по pg_blocking_pids и после release отклоняется по stale version |
| HTTP | Все три POST счёта и MVC finish: свой организатор, чужой CLUB_ADMIN той же площадки, PLAYER/anonymous, CSRF; прежние form/JSON/redirect/flash-ответы |

Контролируемый WriteProbe вводится в тестовом наблюдателе существующих proxy/на JdbcClient.sql. Записи и rollback — настоящие PostgreSQL; отказ диска/сети БД не имитировался. Тестовый класс не имеет @Transactional: fixtures фиксируются отдельно, результат читается после завершения сценария. Транспорт брокера подменён безопасным наблюдателем, внешних реальных уведомлений нет.

Успешная запись позиции штатно меняет updated_at. Сравнение остальных полей исключает только current_position/updated_at; rollback сравнивает полные строки без исключения timestamps. Fixtures не предполагают, что первая сторона матча — пара №1: счёт задаётся по фактическим ID команд. Очистка удаляет только собственные связанные строки, включая автоматически созданную маркетинговую регистрацию.
