# Проверки командной границы

Это план baseline и последующих повторов, а не отчёт об успешном прогоне. Исходный код — `02200f09eeac5cb5eff15f7608889f3b9ee4e051`. В первой задаче фиксируются реальные ожидания, порядок I/O и безопасные fixtures; реализации не подменяют их новыми ожидаемыми значениями.

| ID | Действие | Что сравнить до/после переноса |
|---|---|---|
| W01 | Standalone updateTeamPositions: POINTS, пустые teams/нет Tournament | Прежний fallback/пустой результат и порядок чтений; только позиции нужных команд; отсутствие новой ConductChange/history/notification от этого входа |
| W02 | SETS: равенство по общим показателям, мини-таблица, полное равенство | Сохранённые 1,1,3 и прежний порядок строк; никакой новой сортировки несортированного repository-входа |
| W03 | Завершить круг с final/bronze/другими местами и встречей без места | currentPosition остаётся круговым, finalRanking учитывает PLACEMENT; round statistics не меняются |
| W04 | Finish несуществующего, CANCELADO, неинициализированного и незавершённого турнира | Исходные исключения/HTTP/redirect/flash; отсутствие частичных позиций/статуса/истории и after-commit отправки |
| W05 | Несколько типов раундов, pending PLACEMENT, дыры номеров | Текущие MAX(roundNumber), count COMPLETED всех фаз и short-circuit isInitialized; не подменять max на count/готовность ranking |
| W06 | Успешный finish из реального facade/proxy | Один существующий write-контекст/EntityManager; правильные позиции, FINALIZADO, полный прежний DTO query до commit; после clear/new transaction данные сохранены |
| W07 | Ошибка после начала применения позиций | Полный rollback всех частичных записей; нет FINISH/RESULT и public invalidation после rollback |
| W08 | Ошибка при сохранении Tournament или последующем query/маппинге | Позиции, статус и история откатились вместе; нет раннего commit |
| W09 | Ошибка сохранения снимка истории после команды | Игровые изменения не остаются без истории; после независимого чтения состояние исходное |
| W10 | Известный Idempotency-Key; stale expectedConductVersion | Текущие 409/исключение, X-Conduct-Replayed/X-Conduct-Stale и отсутствие повторной записи; прежний порядок lock/version/команды |
| W11 | Повтор finish без ключа и с новым ключом | Точная исходная зависимость числа history-строк от snapshot/key; уведомления только после commit и объединение в рамках транзакции |
| W12 | Последний результат круга; исправление результата завершённого раунда | Существующий tryAutoCompleteRound вызывает запись позиций только в прежних случаях; статистика apply/revert и legacy stale positions не «исправляются» новым GET/вызовом |
| W13 | Finish → preview истории → реальное restore → продолжение | Новая версия restore, поздние версии не удалены, регистрации/оплаты и snapshot-исключения сохранены |
| W14 | Все действующие POST счёта и MVC finish своим/чужим организатором, PLAYER/anonymous, без CSRF | Прежние роль/ownerId, статусы/redirect/ошибки; не уравнивать разные старые HTTP-контракты |
| W15 | Public/admin/карточка, RU/ES/EN, 1440/390, reload | Прежние круговые/итоговые места и поля, guest/null/сторона; исходная read-матрица и её ожидания сохранены |
| W16 | Restart и прежний принятый jar → возврат после новых write-операций | Полные связанные строки команд/раундов/матчей/истории/профилей и регистраций, schema/Liquibase и ответы совпали; никаких пользовательских БД |
| W17 | Итоговый jar, negative guards, реальные command/query proxy и DevTools | Одна application library/без копий, Java 17, точный engine allowlist; JPA/JDBC/legacy не протекают в application, команды реально внедрены |
| W18 | Два finish-вызова через ConductChange в независимых write-контекстах и устаревшая версия одного турнира | Существующий FOR UPDATE/проверка версии сериализуют наблюдаемый сценарий; нет второго успешного изменения по устаревшей версии; это не приёмка двух production-реплик #1214 |

W07–W09 проверяются на настоящей отдельной PostgreSQL с контролируемым отказом на конкретной границе. Fake-порт unit-теста полезен для сценария, но не доказывает ACID/flush/after-commit. Тестовые фикстуры фиксируются вне проверяемой транзакции; результат читается после её завершения в новом контексте. Тестовый @Transactional, скрывающий commit/rollback реального сценария, не заменяет проверку.

Исходные 12 read-baseline тестов/11 JSON и автоматизация фазы 4 остаются прежними. Дополнительно повторяются общий пилот, ранний плей-офф 9/16, session/CSRF/JWT/WS и репетиция выпуска. Прямыми потребителями кругового ranking не объявляются React/Expo; их действующая соседняя регрессия сохраняется. #445/#453/#1067, Expo Basic 401 и неповторённые ручные/физические проверки отмечаются по факту, без новых ложных PASS.

Измеренный повтор #1404 — [реализация и QA](position-command.md). Прежние 28 write-ожиданий сохранены с наблюдением фактических command/port proxy внутри RESULT/FINISH. Дополнительно проверены standalone write, identity исходных managed-объектов, ровно три SELECT без профилей, изменение только позиции/updated_at и полный rollback после частичного реального flush. В [повторе #1405](finish-command.md) тот же набор проверяет реальную finish-команду, её порт, identity турнира при save и порядок position → save → query. [Итоговая приёмка #1406](acceptance.md) связывает все W01–W18 с независимым прогоном на принятом master, браузером и дополнительной HTTP-пробой.
