# Ручные действия и границы приёмки клубного среза

В рамках LFPT-1201 новый ручной сеанс владельца не проводился и не запрашивался. Владелец поручил продолжение после мержа #1238; это разрешение на приёмочную работу, а не отметка ручного выполнения сценариев.

| Источник | Факт |
|---|---|
| Владелец, первая фаза | 20.11 принял совокупную приёмку #1045 с ограничениями: «принимаем, повторять не будем». [Исходное решение](../phase-1/followup-2026-11-20.md) сохраняется; новый повтор не требуется |
| Владелец, текущая фаза | Включил backend PR #1234/#1238 и поручил продолжение. Нового ручного PASS для клубов не заявляется |
| Агент | Подготовил собственные worktree/БД/preview, собрал jar принятого master, запустил отдельный HTTP/browser/restart/rollback прогон и общий smoke |
| Автоматизация | Chromium на desktop/mobile в RU/ES/EN, реальные ответы API и независимый baseline до обоих переносов; результаты приведены в [acceptance.md](acceptance.md) |

Исходный ручной стенд, его блокировка и пять сохранённых случаев #1045 остаются без изменений. Мутирующий общий smoke использует отдельные пять турниров нового собственного preview. Техническое выполнение браузера агентом не переименовывается в ручные действия владельца.

Сохраняются ранее принятые ограничения: concurrent без измеренного перекрытия; обычный Expo в защищённом preview получает Basic 401, реальный API 200 и расписание проверяются через ограниченный same-origin QA-адаптер; прежний текстовый #1067 не исправляется этой задачей. Эмуляция Chromium 390 px не означает проверку физического телефона или VoiceOver. У UI каталога нет отдельной ссылки из текста площадки прямо на клуб: проверяется фактический переход каталог → карточка события → ссылка клуба и самостоятельный фильтр клуба, без добавления новой навигации.

Бизнес-правила, production UI, роли, миграции и конфигурация защиты в этой приёмке не меняются. Обнаруженная продуктовая регрессия требует отдельной issue по соответствующему слою. Ошибка селектора наблюдателя при подготовке прогона исправляется в приёмочной автоматизации и не объявляется дефектом продукта.
