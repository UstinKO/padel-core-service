# Независимая приёмка клубного среза — LFPT-1201

Источник — [issue #1201](https://github.com/UstinKO/padel-core-service/issues/1201). Backend-переносы включены через #1234 и #1238. Приёмка выполняется отдельным прогоном на jar принятого master; прежние отчёты backend-задач и PASS движка не засчитываются как новое выполнение.

[Baseline и воспроизведение](baseline.md), [ручные действия и ограничения](manual.md). Данные владельца и исходный ручной стенд первой фазы не используются. Подготовка, команды и браузер выполняются агентом, не владельцем.

## Объём

| Проверка | Способ |
|---|---|
| HTTP/JSON/headers | Реальные запросы двух GET в RU/ES/EN, отдельный baseline до обоих переносов на тех же данных |
| Порядок и активность | Полный порядок ID сопоставляется с SQL nombre/id; неактивные отсутствуют в списке и дают 404 |
| Nullable и приватность | Шесть nullable полей реального клуба; девять wire-полей; публичный текст с `<&>`; контактный маркер отсутствует в JSON/DOM |
| Браузер | Chromium 1440/390 × RU/ES/EN, список/карточка/refresh/canonical, фильтр и каталог → событие → клуб, unknown/inactive и настоящий пустой список |
| Перезапуск и возврат | Перезапуск своей JVM, прежний jar, штатный rollback; весь клубный набор и пять live snapshots, схема/Liquibase |
| Границы | Корневой verify, artifact-guards трёх библиотек, детерминизм Club, прежняя OpenAPI-проба |
| Клиенты | Отдельные frontend check/E2E и общий legacy/API/React/Expo/session/CSRF/роли/JWT smoke конечного jar |

Клубный срез технически готов к продолжению поэтапной миграции. Следующий срез требует своей спецификации и проверки зависимостей; persistence/Liquibase #1051 остаётся поздней задачей. Приёмка не выделяет остальные модули и не меняет физическую БД или Swarm. Публикация/CI/ручной мерж PR учитываются отдельно. Новый ручной PASS владельца не заявляется; [принятые ограничения](manual.md) сохраняются.
