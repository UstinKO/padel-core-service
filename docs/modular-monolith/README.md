# Многомодульный монолит: анализ и план перехода

Задача: [LFPT-1041](https://github.com/UstinKO/padel-core-service/issues/1041). Дата: 13.11.2026. Статус: **семь модулей и пилот PlayoffMatchingEngine приняты владельцем**; подробный анализ выполнен для первой фазы, пул задач создан, подготовка завершена и публикуется отдельным PR; реализация не начата.

Цель — облегчить сопровождение через Maven-модули и гексагональные границы; количество не ограничено пятью. Сохраняются один процесс приложения, один выпускаемый Spring Boot jar и существующая PostgreSQL. Разделение на технические модули дополняется доменными пакетами внутри них.

**Обязательное требование владельца:** каждая завершённая задача оставляет приложение целиком работоспособным. Нельзя планировать промежуточный merge с обещанием восстановить сборку, запуск, API или пользовательский сценарий следующей задачей. Обязательные условия каждого этапа описаны в [плане](plan.md#условия-приёмки-каждой-реализационной-задачи).

Исходное предложение: API DTO из OpenAPI JSON, турнирные движки, БД и миграции, сервисный слой, контроллеры и эндпоинты. Главная поправка — сервисный модуль владеет портами хранения; модуль БД зависит от этих портов, а не наоборот. API DTO не становятся общей доменной моделью.

Связанные направления: [исторический микросервисный план](../microservices-migration-plan.md), [React ADR](../frontend-react/adr/README.md), [анализ Swarm #1040](https://github.com/UstinKO/padel-core-service/issues/1040). По решению владельца текущая цель — многомодульный монолит; микросервисный план остаётся материалом возможного будущего, внутренние HTTP-вызовы не создаются. Переход на модули не требует предварительного включения Swarm.

Документы обновляются с каждой принятой реализационной задачей: состояние этапа, фактические зависимости, результаты проверок и оставшиеся временные мосты. Предложенный граф нельзя описывать как уже реализованный. Spring в application и исключение record для generated-классов приняты; выделение хранения отложено. Сформирован пул первой фазы; отдельная поздняя задача хранения — #1051. Исходный и последующий e2e-прогоны пока не выполнялись.

Проверка первичного комплекта 13.11.2026: `docs-drift` и `check-agent-migration` — 0 расхождений, 48 тестов Telegram relay — успешно; локальные Markdown-ссылки и пробелы проверены. Дополнительно выполнен Maven unit-прогон PlayoffMatchingEngineTest: 8 тестов успешно, без frontend/БД. Приложение/браузер, full verify и integration не запускались; они запланированы в первой фазе.

Проверки подготовки первой фазы: 8 engine unit-тестов и 89 Python-тестов автоматики — успешно; docs-drift/agent-migration — 0 расхождений. Подробности и границы доказательств — [отчёт анализа](phase-1/code-analysis.md).
