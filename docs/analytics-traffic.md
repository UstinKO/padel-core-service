# Разделение аудитории аналитики

Серверная модель HTML содержит обезличенный analyticsTraffic.group (visitor, internal, test) и analyticsTraffic.reason. Данные только для измерения; роли и доступы не меняются. Служебные роли определяются по OwnerRole, тестовый статус — по testTournament. Имена и видимость событий не используются. King of Court использует родительское мероприятие, а не числовое совпадение kingId.

Обработчик AnalyticsTrafficConfig не выполняет SQL, не меняет REST-ответы и не создаёт новые события. Стенды продолжают работать без боевого Measurement ID по умолчанию. Подключение к общему тегу и инструкция GA4 выполняются отдельно в LFPT-1359. Историческую аудиторию до включения признаков достоверно очистить нельзя.

## Общий тег и тестовый браузер

После подключения LFPT-1359 общий тег передаёт traffic_group и traffic_reason до первого config/page_view, глобально для последующих событий. traffic_type=internal у служебных и тестовых событий; у visitor — external. Неопределённый или отсутствующий контекст — unclassified/missing_context, он не включается в visitor. Consent Mode и события записи сохраняют свою семантику. Аналитика не добавляется в страницы админки, где её раньше не было: это разделение аудитории, а не журнал всех действий администратора.

Для проверки под обычным игроком открыть в используемом браузере `https://1-padel.com/?analytics_test=on`. В текущем origin сохраняется только время окончания режима, без идентификатора; срок 48 часов. Посещения помечаются test/manual_test. Для выключения открыть `https://1-padel.com/?analytics_test=off`. Выключение не превращает служебный аккаунт или тестовое мероприятие во внешнюю аудиторию. При закрытом localStorage пометка действует только на текущую страницу со ссылкой on; сохранение не гарантируется. Параметр не передаётся в page_location/page_path; эти служебные ссылки не отправлять игрокам и не включать в рекламу. Новый браузер/инкогнито требует собственной пометки. Само посещение настоящего тестового мероприятия не помечает остальные страницы этого посетителя как тестовые.

Для полноценной ручной проверки под тестовым игроком режим on включать до прохождения входа и записи. Посещения обычным аккаунтом без пометки на настоящих мероприятиях невозможно надёжно распознать как тест. Отдельного списка email/телефонов или IP нет.

## Начало чистого периода и метод отчёта

Настройки GA4 сами по себе не означают начала чистого периода. После выпуска обеих частей проверить в Realtime реальные visitor/internal/test и события начала/завершения записи; отметить точный момент, затем начать период с первых полных суток Buenos Aires. Для предварительного среза собрать 7 полных дней, для месячного медиакита — 30. Обработка новых определений в стандартных отчётах может занять 24–48 часов. До проверки выпуска конкретная дата старта не утверждается.

Сравнения фильтруют события: один GA-пользователь может иметь события нескольких типов, поэтому число пользователей в трёх сравнениях нельзя складывать или вычитать из All Users как три непересекающиеся группы людей. Для аудитории без служебных/тестовых посещений сохранён пользовательский сегмент «Внешние пользователи без тестов и служебных визитов»: включает traffic_group=visitor across all sessions, исключает traffic_group matches ^(internal|test)$ across all sessions, режим исключения из сегмента permanently. Это обратимое определение сегмента, не удаление исходных событий. Использовать его в Explore за выбранный чистый период. [Сохранённые сегменты](https://analytics.google.com/analytics/web/?authuser=2#/a410604858p557242151/admin/segment). visitor — внешние события, а не доказательство уникального физического человека. Не использовать отсутствие значения как visitor и не пересчитывать исторические 794 пользователя предположением.

Подтверждение отправки настоящему GA4 остаётся обязательной проверкой после деплоя. Браузерные регрессионные тесты используют отрендеренный настоящий Thymeleaf и блокируют внешние запросы; тестовый Measurement ID G-TEST000000 не отправляет данные в production.

Официальная справка: [событийные параметры и задержка 24–48 часов](https://support.google.com/analytics/answer/14239696?hl=en), [область параметров gtag](https://developers.google.com/tag-platform/gtagjs/reference/parameters).
