# Карта экранов 1-Padel 0.5

Дата: 26 октября 2026. Здесь разделены готовые интерактивные макеты пользовательской части и историческая инвентаризация исходного сайта. Все новые экраны используют локальные демоданные; они не являются подключённой production-версией.

Текущий объём по комментариям Сергея сохранён: вся пользовательская часть, состояния и взаимодействия. API и закрытый контур подключает Сергей параллельно. Административная часть остаётся отдельным этапом. Согласованный объём — [DELIVERY-SCOPE.md](DELIVERY-SCOPE.md), точные прямые примеры — [STATES.md](STATES.md).

## Фактические маршруты версии 0.5

Адреса внутри демо начинаются с `/#/`. Параметр `event` сохраняет выбранное мероприятие в пути аккаунта. Для просмотра без настоящего входа используйте `/#/preview/<id>` из `/#/review`: он устанавливает нужную демосессию.

| Маршрут | Экран / поведение |
|---|---|
| `/home` | Главная гостя или игрока |
| `/events`, `/schedule` | Каталог с фильтрами; второй адрес — alias |
| `/event/:id` | Общая страница формата и состояния мероприятия |
| `/book/:id` | Условия, запись/резерв, три способа записи пары, подтверждения и ошибки |

| `/complete-profile` | Дополнение контактов после Google/email |
| `/verify-email` | Совместимость старых ссылок: переход к регистрации или продолжению записи, без кода |
| `/forgot-password`, `/reset-password` | Запрос восстановления, новый пароль и недействительная ссылка |
| `/oauth-error` | Вход через Google не завершён; возврат к тому же событию |

| `/profile` | Профиль, редактирование, выход |
| `/partners/:id` | Поиск, предложения и добавление партнёра позже |
| `/partner-invitation` | Входящее предложение пары, принятие/отказ/истечение |
| `/waitlist-offer` | Перевод в основу, подтверждение участия/отказ/изменившийся статус |
| `/live`, `/live/king` | Проведение King of Court для игрока/зрителя |
| `/live/americano` | Индивидуальный Американо: все раунды, рейтинг и история |
| `/live/pairs` | Постоянные пары: квалификация и плей-офф |
| `/clubs`, `/clubs/:id` | Клубы и связанные мероприятия |
| `/league`, `/ranking` | Будущие функции с явной заглушкой «В разработке» |

| `/legal/terms`, `/legal/privacy`, `/legal/cookies` | Юридические тексты из проекта |
| `/status/:kind` | Сессия, отсутствие доступа, сеть, лимит запросов, сервис |
| `/review`, `/preview/:id` | Служебная проверка и воспроизводимые прямые сценарии |
| Любой неизвестный адрес | Страница не найдена |

Карточки мероприятий: `king`, `americano`, `pairs`, `training`, `open`, а также `women`, `mixed` и сохранённый `live`-пример. У проведения формат ограничен `king`, `americano`, `pairs`; общий экран регистрации не смешивается с сеткой и рейтингом.

Русская версия служит согласованию. Полная ES-локализация ещё не выполнена; «Язык общения» в профиле — предпочтение для связи, не переключатель перевода интерфейса. Локальные расписания и рейтинги демонстрационные, существующие серверные алгоритмы остаются источником данных.

## Восемь входящих и редирект-сценариев

Эти адреса могут находиться в уже отправленных письмах, QR и сообщениях. Сохранять их должен сервер/интеграционный слой: hash-маршруты макета сами по себе не заменяют реальные токены, callback и редиректы.

| ID | Существующий вход | Новый экран и интеграционная граница |
|---|---|---|
| F-a | `/players/confirmar-email?codigo=…` | Устаревший серверный маршрут; в новой регистрации email подтверждается сервером автоматически, отдельного экрана нет |
| F-b | `/double-registration/complete?token=…` | Завершение приглашения партнёра; сопоставить с профилем/парным сценарием, сохранить серверное сообщение |
| F-c | `/double-registration/accept-pair?token=…` | Макет `/partner-invitation`; принятие требует отдельного действия пользователя |
| F-d | `/recuperar-password?token=…` | Макеты запроса и нового пароля; реальная проверка токена/смена пароля не выполняются |
| F-e | `/torneo/{id}/king-of-court` | Направить к правильному live-турниру: ID события и `kingId` могут отличаться |
| F-f | `/oauth2/authorization/google` → `/login/oauth2/code/google` | Сохранить серверный OAuth, выбранное событие и отдельный app-callback; Google в макете локальный |
| F-g | `POST /logout` | Подключить серверный выход с CSRF и очищение клиентского состояния; демо очищает только localStorage |
| F-h | Ошибка `POST /tournaments/americano/{id}/preview-rounds` | Административный сценарий вне этой поставки; не повторять инициализацию при ошибке |

## Перед интеграцией и запуском

1. Проверить все прямые примеры и переходы на телефоне и компьютере; сохранить утверждённый общий стиль.
2. Сопоставить демонстрационные типы с фактическими ответами API. Сервер отвечает за вместимость, очередь, права, оплату, сроки и подсчёт.
3. Сохранить разные правила индивидуальных турниров и постоянных пар; не переносить индивидуальный штраф −10 на парный турнир.
4. Закончить испанскую локализацию, сверить юридические тексты и данные клубов, подключить существующие входящие ссылки.
5. Сергей разворачивает отдельный контур с ограничением по одному-двум IP. Публичный концепт не считается закрытым окружением.
6. Старую версию сохранить до тестирования всего функционала и отдельного переключения с возможностью возврата. Административные экраны остаются следующим этапом.

Техническая интеграция описана в [INTEGRATION.md](INTEGRATION.md); исходники, материалы и документация передаются без ключей, `.openai`, `.git` и `node_modules`.
