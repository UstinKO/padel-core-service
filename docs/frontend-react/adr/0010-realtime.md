# ADR-0010. Realtime: один STOMP-клиент, событие = сигнал перечитать состояние; Americano — поллинг

- **Статус:** Предложено
- **Дата:** 2026-09-28
- **Связано:** [api.md §5](../contract/api.md#5-websocket), [0006](0006-frontend-stack.md)

## Контекст

WebSocket (`/ws`, SockJS + STOMP, in-memory simple broker) используется двумя форматами: King of Court (`/topic/tournament/{kingId}`, 5 типов событий) и Team Playoff (`/topic/team-playoff/{tournamentId}`, 6 типов). Канал только сервер → клиент, мутации — REST. Americano и Team Americano обновляются перезагрузкой страницы. Клиенты — `sockjs-client@1` и `stompjs@2.3.3` (не поддерживается) с CDN. Полезная нагрузка событий — разные Java-объекты, у Team Playoff — `Object`.

## Решение

1. **Сервер не меняется:** тот же `/ws`, те же топики и типы событий. SockJS оставляем (есть клиенты за прокси без нативного WebSocket, #284).
2. **Один STOMP-клиент на приложение** (`@stomp/stompjs` + `sockjs-client`), с автопереподключением и индикатором «нет связи». Экран подписывается хуком `useTopic(topic, onEvent)`.
3. **Событие — это сигнал, а не данные.** Клиент по событию инвалидирует соответствующий запрос TanStack Query (`state` турнира) и перечитывает его через REST. Полезную нагрузку события можно использовать для мгновенной подсветки, но источником правды остаётся REST-ответ. Так не нужно типизировать каждое событие и нельзя «разъехаться» с состоянием после пропущенного события или переподключения.
4. **После переподключения** — всегда перечитать состояние (события за время обрыва потеряны).
5. **Americano / Team Americano — поллинг** состояния на публичных страницах (каждые 15–30 с, пока вкладка видима). На пультах — перечитывание после собственных действий. WebSocket для них — отдельной задачей, если поллинга окажется мало.

## Отвергнутые альтернативы

| Вариант | Почему нет |
|---|---|
| **Server-Sent Events вместо STOMP** | Проще, но меняет сервер и ломает два работающих live-экрана, пока их Thymeleaf-версии ещё живы |
| **Полное состояние в каждом событии** | Сервер должен знать, что нужно каждому экрану; дублирует REST; сложнее типизировать |
| **Сразу WebSocket для Americano** | Новая серверная работа, не нужная для переезда; поллинг закрывает потребность |

## Последствия

- Нагрузка поллинга: при нынешнем трафике (~0,2 req/s) несущественна; при росте — перевести на WebSocket.
- Брокер in-memory ограничивает одним инстансом — согласуется с решением 2026-09-06.
