# ADR-0008. Публичные SEO-страницы: последними; SPA + серверная подстановка meta/OG

- **Статус:** Предложено — **вернуться и подтвердить перед Фазой 5**
- **Дата:** 2026-09-28
- **Связано:** [0003](0003-serve-spa-from-spring-boot.md), [0004](0004-api-only-boundary-openapi.md), [cross-cutting.md §8](../contract/cross-cutting.md#8-seo-и-шаринг)

## Контекст

Ссылка на турнир (`/torneo/{id}`) — главный канал продвижения: её шлют в WhatsApp-группы, Telegram, письма, печатают QR. Превью в мессенджере (название турнира, формат, уровень, картинка) строится из OG-тегов, а **краулеры мессенджеров не исполняют JavaScript**. Чистое SPA отдаст им одинаковый `index.html` для всех турниров — все превью станут одинаковыми. Поисковая индексация (`/`, `/torneos`, `/torneo/{id}`) важна меньше, но тоже есть.

Сейчас OG-теги динамические только на `/torneo/{id}`; `og:image` указывает на несуществующий файл (F-12).

## Решение

1. **Публичные индексируемые страницы переводятся последними** (Фаза 5): P-01 лендинг, P-04 список турниров, P-05 карточка турнира, P-06/P-07 клубы, P-08 рейтинг, P-09 legal. До этого они остаются на Thymeleaf — и продолжают работать как сейчас.
2. **Когда переводим — SPA + серверная подстановка `<head>`.** Для маршрутов из списка «SEO-маршрутов» Spring отдаёт тот же `index.html`, но с подставленными `<title>`, `description`, `og:*`, `twitter:*`, `canonical` для конкретной сущности (одним небольшим шаблоном-обёрткой над `index.html`). Тело страницы по-прежнему рисует React. Это единственное место, где бэкенд «знает» о содержимом фронтовой страницы, — и только meta-теги, не данные приложения (ADR-0004).
3. При выносе фронта в отдельный сервис (ADR-0003) эта подстановка переезжает в edge (nginx `sub_filter` с запросом к API, Cloudflare Worker) или в небольшой prerender — решается тогда.
4. Независимо от React — починить F-12 (картинка превью, favicon) и сделать `og:image` абсолютным URL. Это можно сделать сразу, на текущих шаблонах.

## Отвергнутые альтернативы

| Вариант | Почему нет |
|---|---|
| **Оставить публичные страницы на Thymeleaf навсегда** | Две технологии UI навсегда; публичная часть не получит общий дизайн и компоненты. Остаётся запасным вариантом, если подстановка meta окажется сложнее ожидаемого |
| **SSR-фреймворк (Next.js) только для публичной части** | Node-сервер в проде ради нескольких страниц (ADR-0001) |
| **Pre-rendering на сборке** | Турниры создаются каждый день — статическая пререндеренная страница устаревает сразу |
| **Prerender-сервис по User-Agent** (rendertron и т.п.) | Ещё один процесс/сервис; «разные ответы ботам и людям» хрупко |
| **Ничего не делать** | Все превью ссылок на турниры одинаковые — прямой удар по продвижению |

## Что проверить перед Фазой 5 (открытые вопросы)

- Какие страницы реально приходят из поиска (Cloudflare Analytics / логи), а какие — только по ссылкам из мессенджеров.
- Нужна ли `sitemap.xml` (сейчас нет).
- Решение `.claude/DESIGN.md` §10 по продающему лендингу (редизайн `index.html` или отдельный URL) — влияет на P-01.
