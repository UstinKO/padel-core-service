# ADR-0009. Локализация: строки веба — во фронт, строки писем и сервера — на бэкенде

- **Статус:** Предложено
- **Дата:** 2026-09-28
- **Связано:** [cross-cutting.md §3](../contract/cross-cutting.md#3-локализация), `docs/i18n/README.md`, issue #396

## Контекст

Интерфейс на трёх языках (es по умолчанию, ru, en), язык — по `Accept-Language`, без переключателя. Строки в двух местах: `i18n/messages_{es,ru,en}.properties` (1 395 ключей) и `static/js/i18n/messages-{es,ru,en}.js` (250 ключей для JS). Анализ использования ключей `.properties`:

| Кто использует | Ключей |
|---|---|
| только веб-шаблоны | 1 084 |
| только шаблоны писем | 103 |
| только Java (`MessageSource`: темы писем, пара ошибок админки) | 13 |
| никто | 195 |

Пересечений нет. Сообщения об ошибках API в основном захардкожены по-испански в Java (#396).

## Решение

1. **Строки веб-интерфейса переезжают во фронтенд** — `frontend/src/i18n/{es,ru,en}/*.json` (разбиты по разделам: `common`, `public`, `player`, `admin`, `formats`), react-i18next. Переезжают **вместе со своим экраном**: ключи экрана копируются в JSON при его переводе и удаляются из `.properties`/`messages-*.js` при удалении legacy-страницы (Фаза 6). Имена ключей сохраняем — так проще сверять.
2. **Строки писем и серверные строки остаются** в `.properties` на бэкенде. После Фазы 6 там останутся ~116 ключей.
3. **API не отдаёт готовый текст для UI.** Ошибки — стабильный `code` (ADR-0011), текст — из словаря фронта по коду. `detail` в ответе (на языке `Accept-Language`) — только запасной вариант для непредусмотренных ошибок. Это же чинит #396 для всего, что переведено.
4. **Язык:** SPA определяет язык по браузеру, даёт переключатель (запоминается локально), шлёт `Accept-Language` в каждом запросе к API. `preferredLocale` игрока (язык писем) остаётся отдельной настройкой профиля, как сейчас; при первом входе можно предложить синхронизировать.
5. **Enum-подписи** (типы турниров, уровни, статусы) — во фронтовых словарях по значению enum; `GET /api/admin/reference-data` отдаёт только значения. (Сейчас подписи частично в `.properties`, частично в Java-enum.)
6. **Проверка полноты в CI**: ключи во всех трёх языках совпадают, неиспользуемых нет — скрипт в `npm test`.
7. 195 неиспользуемых ключей не переносятся.

## Отвергнутые альтернативы

| Вариант | Почему нет |
|---|---|
| **Отдавать словари с бэкенда** (`GET /api/i18n/{lang}` из `.properties`) | Фронт остаётся зависим от файлов бэкенда — мешает выносу в отдельный сервис; ключи фронта и писем снова в одной куче |
| **Генерировать JSON из `.properties` на сборке** | Сборка фронта читает файлы бэкенда — та же связь, только скрытая |
| **Перенести всё сразу в Фазе 0** | Два источника правды для каждого ещё не переведённого экрана: правка текста на Thymeleaf-странице потребует править и JSON |
| **Локализованные тексты ошибок с сервера** | Каждый новый язык/формулировка — деплой бэкенда; мобильным нужны коды в любом случае |

## Последствия

- В переходный период строка экрана живёт в двух местах только между переводом экрана и удалением его legacy-версии — это допустимо, legacy не редактируем.
- Формат плейсхолдеров меняется с `{0}` на именованные `{{name}}` — конвертировать при переносе ключа.
- Переводчику/редактору текстов — один формат (JSON) для всего веба.
