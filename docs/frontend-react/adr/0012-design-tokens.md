# ADR-0012. Дизайн: токены как CSS-переменные; значения as-is до утверждения `.agents/DESIGN.md`

- **Статус:** Предложено
- **Дата:** 2026-09-28
- **Связано:** [0006](0006-frontend-stack.md), `.agents/DESIGN.md`, `docs/design-tokens-as-is.md`, `docs/screen-archetypes.md`

## Контекст

Идут два процесса. **Редизайн** (`.agents/DESIGN.md` v0.1): направление «тёплый корт в сумерках», токены и спеки компонентов разделов 4–5 **заморожены до готового логотипа**. **Переезд на React** не должен ждать логотипа и не должен означать «перерисовать всё дважды». Июльский `docs/frontend-migration-plan.md` принял подход «дизайн as-is при переносе»; `docs/design-tokens-as-is.md` уже свёл текущие цвета/шрифты/отступы из 14 CSS-файлов.

## Решение

1. **Все визуальные значения во фронте — только через CSS-переменные** (`--color-*`, `--space-*`, `--radius-*`, `--font-*`, `--shadow-*`) в одном файле токенов. В компонентах — никаких hex/px-констант (то же правило, что `DESIGN.md` вводит для шаблонов).
2. **Имена токенов — по `.agents/DESIGN.md` §4** (структура не зависит от логотипа), **значения — пока as-is** из `docs/design-tokens-as-is.md`. Переведённые экраны выглядят как сейчас — пользователи не замечают переезда.
3. **Когда `DESIGN.md` утверждён** — меняются значения в файле токенов, и все React-экраны перекрашиваются одним PR. Компоненты по спекам `DESIGN.md` §5 обновляются по мере необходимости.
4. Light-тема сейчас; dark — когда `DESIGN.md` утвердит палитру (токены это позволяют без переделки компонентов).
5. Структурные пункты `DESIGN.md` §3 (единый layout, одна система иконок, без мёртвого CSS) реализуются **в React сразу**, а не в Thymeleaf — чтобы не делать эту работу дважды.

## Отвергнутые альтернативы

| Вариант | Почему нет |
|---|---|
| Ждать утверждения `DESIGN.md`, потом переезжать | Блокирует переезд на неопределённый срок (логотип) |
| Переезжать сразу в новом дизайне | Смешивает две большие перемены в одном PR; не видно, что сломалось — логика или вид; решение по палитре не принято |
| Сначала редизайн Thymeleaf, потом React | Двойная работа по каждому экрану |

## Последствия

- В переходный период React-экраны визуально совпадают со старыми — меньше вопросов у организаторов.
- Редизайн после переезда — это в основном PR в файл токенов + доработка компонентов, а не переписывание экранов.
- Шрифт/иконки: выбор иконочной системы нужен уже в Фазе 0 (для каркаса) — взять ту, что предлагает `DESIGN.md`, даже если остальное заморожено.
