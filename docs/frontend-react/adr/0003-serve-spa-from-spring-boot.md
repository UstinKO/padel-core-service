# ADR-0003. SPA собирается внутрь jar и отдаётся Spring Boot с того же домена и тех же URL

- **Статус:** Предложено
- **Дата:** 2026-09-28
- **Связано:** [0002](0002-frontend-folder-not-maven-module.md), [0005](0005-auth-session-same-origin.md), [0007](0007-incremental-migration.md)

## Контекст

Сейчас: один контейнер `padel-app` (Spring Boot), перед ним Nginx на хосте (`/api/`, `/ws`, `/players/`, `/` → `:8080`), Cloudflare для `1-padel.com`. Деплой — push в `master` → сборка → рестарт контейнера → health-check → автооткат. Пользователь хочет пока **всё оставить в монолите**, но так, чтобы фронт потом можно было вынести в свой сервис.

Во время переезда старые (Thymeleaf) и новые (React) страницы живут одновременно, и **URL страниц менять нельзя**: они разосланы в письмах, Telegram, сохранены в закладках и QR-кодах на кортах ([cross-cutting.md §5](../contract/cross-cutting.md#5-входящие-ссылки-которые-нельзя-сломать)).

## Решение

1. **Сборка.** `frontend-maven-plugin` в фазе `generate-resources` выполняет `npm ci` + `npm run build`; результат (`frontend/dist`) копируется в `target/classes/static/app/`. Итог — тот же один jar.
2. **Статика SPA** — под отдельным префиксом `/app/` (`vite.config base: '/app/'`), чтобы не пересекаться со старыми `/js/**`, `/css/**`, `/images/**`. Файлы с хешем в имени кэшируются навсегда (`Cache-Control: immutable`), `index.html` — `no-cache`.
3. **Маршрутизация «экран за экраном».** SPA обслуживает **те же URL**, что и старые страницы. В бэкенде один класс `SpaRoutesConfig` со списком переведённых маршрутов (в `application.yml`, `app.spa.routes`): для них Spring отдаёт `/app/index.html`, а старый view-контроллер для этого пути удаляется (или переводится на запасной путь, ADR-0007). Всё, что не в списке, по-прежнему рендерит Thymeleaf. Переход между старой и новой страницей — обычная полная загрузка, это нормально.
4. **Базовые URL** в бэкенде: ссылки на *страницы* (письма, Telegram, редирект после Google) строятся от нового свойства `app.frontend-url`, ссылки на *серверные действия* (`/players/confirmar-email`, `/double-registration/complete`) — от `app.base-url`. Пока same-origin — одинаковые значения.
5. **Локальная разработка:** `npm run dev` (Vite, `:5173`) проксирует `/api`, `/ws`, `/login`, `/logout`, `/oauth2` и все ещё не переведённые пути на `:8080`. CORS для этого не нужен.

## Путь выноса в отдельный сервис (когда понадобится)

Никаких изменений кода фронта или API. Меняется только сборка и маршрутизация:

1. Убрать из `pom.xml` вызов сборки фронта, удалить `SpaRoutesConfig`.
2. `frontend/Dockerfile`: nginx со статикой `dist/` и SPA-фоллбэком (`try_files $uri /index.html`).
3. Хостовый Nginx: `location /api/`, `/ws`, `/login`, `/logout`, `/oauth2/`, `/login/oauth2/`, серверные действия из писем → бэкенд; всё остальное → контейнер фронта. **Домен тот же** — cookie сессии и CSRF продолжают работать, CORS не нужен (ADR-0005).
4. Отдельный workflow деплоя фронта (статике не нужен рестарт бэкенда).

Если когда-нибудь фронт уедет на **другой** домен — это уже смена модели аутентификации (токены вместо cookie) и отдельный ADR.

## Отвергнутые альтернативы

| Вариант | Почему нет |
|---|---|
| **Сразу отдельный контейнер nginx для фронта** | Честнее по архитектуре, но сейчас это второй деплой, ещё один контейнер на маленьком VPS и маршрутизация «какой путь уже переведён» в хостовом Nginx (правится по SSH вне git). Пользователь явно хочет пока всё в монолите |
| **SPA под префиксом `/app/*` для страниц** (новые URL) | Ломает все ссылки из писем/QR или требует редиректов на каждый переведённый экран; два адреса у одной страницы путают пользователей и аналитику |
| **Раздавать SPA с CDN (Cloudflare Pages и т.п.)** | Другой origin → cookie-сессия перестаёт работать без переделки аутентификации; `epadel.org` не за Cloudflare |

## Последствия

- Деплой остаётся одним: jar со статикой. Откат — тот же механизм `app.jar.backup`.
- Каждый перевод экрана затрагивает и фронт, и одну строку в `app.spa.routes` — это и есть «переключатель»: откат экрана = убрать строку и вернуть контроллер.
- Health-check деплоя дополнить проверкой, что `/app/index.html` отдаётся (иначе можно выкатить jar без фронта).
- Бэкенд знает о фронте ровно две вещи: список маршрутов SPA и `app.frontend-url`. Обе удаляются при выносе.
