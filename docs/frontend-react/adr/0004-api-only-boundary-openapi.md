# ADR-0004. Граница фронт↔бэк — только HTTP API и WebSocket; OpenAPI — контракт, TS-типы генерируются

- **Статус:** Предложено
- **Дата:** 2026-09-28
- **Связано:** [0002](0002-frontend-folder-not-maven-module.md), [0003](0003-serve-spa-from-spring-boot.md), [0011](0011-api-conventions.md)

## Контекст

Сейчас данные для страницы приходят тремя способами одновременно: атрибуты модели Thymeleaf, JSON, вшитый сервером прямо в страницу (`tournamentsJson`, `rankingJson`, `historicalJson`… — через `th:inline="javascript"`), и `fetch` к API. Фронт и бэк связаны на уровне имён переменных модели.

Из 108 JSON-эндпоинтов 37 возвращают `ResponseEntity<?>` или `Map<String,Object>` — их форма нигде не описана, кроме кода. `springdoc-openapi` не подключён (хотя `/swagger-ui/**` открыт в `SecurityConfig`).

## Решение

1. **Фронтенд получает данные только через HTTP API (`/api/**`) и WebSocket (`/ws`).** Никаких данных, вставленных сервером в `index.html`, никаких атрибутов модели, никаких cookie с данными (кроме сессии/CSRF/согласия на cookie). Единственное исключение — meta/OG-теги публичных страниц (ADR-0008), и они для краулеров, а не для приложения.
2. **Контракт — OpenAPI**, генерируемый из кода бэкенда (`springdoc-openapi`, `/v3/api-docs`). Каждый эндпоинт, которым пользуется SPA, — с типизированными DTO для запроса и ответа (MapStruct, как требует CLAUDE.md), без `?` и `Map`.
3. **TS-типы и клиент генерируются** из OpenAPI (`openapi-typescript` → типы; тонкий `fetch`-клиент поверх них). Сгенерированный файл коммитится во `frontend/src/api/generated/`, чтобы дифф API был виден в PR.
4. **Проверка расхождений в CI**: `pr-check.yml` поднимает приложение (он и так поднимает Spring-контекст с Postgres для тестов), выгружает `/v3/api-docs`, перегенерирует типы и падает, если они отличаются от закоммиченных. Изменил DTO и не обновил фронт — PR красный.
5. Бэкенд **не знает** фронтовых маршрутов, кроме списка SPA-маршрутов и `app.frontend-url` (ADR-0003).

## Отвергнутые альтернативы

| Вариант | Почему нет |
|---|---|
| **Рукописные TS-типы** | Разъезжаются с бэкендом молча; при 100+ эндпоинтах и одном разработчике это гарантированные баги в рантайме |
| **Contract-first (сначала пишем OpenAPI YAML, из него генерируем Java)** | Правильно для нескольких команд; для одного разработчика с готовым кодом — двойная работа и переписывание существующих контроллеров под генератор |
| **GraphQL / tRPC** | Новый слой и новая модель мышления поверх Spring MVC ради одного клиента; мобильным REST привычнее |
| **Оставить `window.__DATA__`, вшитый в `index.html`** | Быстрее первая отрисовка, но возвращает связь «бэкенд рендерит фронт» и ломает вынос в отдельный сервис |

## Последствия

- Подключить `springdoc-openapi-starter-webmvc-ui`; Swagger UI в проде — только `SUPER_ADMIN` (или выключен), `/v3/api-docs` — доступен сборке.
- Перевод каждого экрана начинается с API: DTO + эндпоинты + тесты на бэкенде, затем экран. Это и есть основной объём работы (см. [api.md §2](../contract/api.md#2-недостающие-эндпоинты-что-построить)).
- OpenAPI-документ бесплатно становится документацией для мобильных приложений.
- `docs/endpoints/*.md` со временем устаревают — источником правды становится `/v3/api-docs`.
