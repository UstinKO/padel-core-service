# ADR-0001. Переводим веб-интерфейс с Thymeleaf на React SPA

- **Статус:** Предложено
- **Дата:** 2026-09-28
- **Связано:** [0002](0002-frontend-folder-not-maven-module.md), [0007](0007-incremental-migration.md), решение 2026-09-06 «остаёмся на монолите» (память проекта), `.claude/DESIGN.md`

## Контекст

Весь UI — 60 Thymeleaf-шаблонов (~21,5 тыс. строк), 27 JS-файлов (~8 тыс. строк), 14 CSS-файлов (~12,4 тыс. строк), 28 контроллеров, отдающих HTML. Цифры и детали — в [контракте](../contract/README.md).

Что болит на практике:

1. **Живые пульты турниров — уже не «страницы», а приложения, написанные внутри шаблонов.** `admin/americano/tournament.html` — 655 строк inline JS, `tournament-playoff.html` — 616, `admin/tournaments/details.html` — 248; всего ~2 800 строк JS внутри HTML. Состояние живёт в DOM, каждое действие — либо полный перезагруз страницы через form POST + flash, либо ручная перерисовка кусков DOM. Правки в этих файлах — самые частые и самые рискованные (LFPT-407, 411, 415 — всё на одном шаблоне за один день; дубли PR #414/#417 появились именно там).
2. **Одни и те же действия реализованы дважды** — form POST во view-контроллере и JSON в `*/api/*` (результаты Team Playoff, инициализация Americano). Бизнес-правила расползаются по двум путям.
3. **Мобильные приложения** (iOS/Android) уже в планах, и решено делать их API в этом же монолите. Мобильным нужен полный JSON API — тот же, который нужен вебу, если веб перестанет получать данные из модели Thymeleaf.
4. **Редизайн** (`.claude/DESIGN.md`) требует общей системы компонентов; сейчас `<head>`/шапка скопированы в ~10 шаблонов, навбаров три разных, три системы иконок.
5. **Безопасность**: из-за inline-скриптов в CSP вынужденно стоит `script-src 'unsafe-inline'`.

## Решение

Переводим **веб-интерфейс** (кроме писем и внутреннего `test/tournaments`, см. ADR-0007) на React SPA, которое получает данные только через HTTP API монолита. Бэкенд остаётся одним Spring Boot-монолитом.

Цели, по которым будем судить, что переход удался:

- пульты турниров не перезагружают страницу на каждое действие и не теряют введённое при обрыве сети;
- каждое действие пользователя реализовано на сервере **один раз** — в API, которым пользуются и веб, и будущие мобильные приложения;
- новый экран собирается из общих компонентов и дизайн-токенов, а не копированием разметки;
- `script-src` без `'unsafe-inline'`;
- фронтенд можно вынести в отдельный сервис без правок кода (ADR-0003).

Не-цели: переписать бэкенд, делить монолит, SSR-фреймворк (Next.js и т.п.), менять бизнес-логику под видом переезда.

## Отвергнутые альтернативы

| Вариант | Почему нет |
|---|---|
| **Остаться на Thymeleaf, навести порядок** (layout-фрагменты, вынести JS в модули) | Решает п.4 частично, но не решает п.1–3: пульты так и останутся ручной работой с DOM, а API для мобильных всё равно придётся писать отдельно — то есть двойная работа |
| **Thymeleaf + HTMX / Alpine.js** | Хорошо для форм и списков, плохо для пультов с богатым клиентским состоянием (очередь матчей, swap команд, черновики счёта, realtime). И не даёт JSON API для мобильных — HTMX отдаёт HTML-фрагменты |
| **Next.js / Remix (SSR)** | Нужен Node-сервер в проде (ещё один процесс на VPS 2 vCPU / 3,8 GB), ещё один деплой. SSR нужен только нескольким публичным страницам ради превью ссылок — это решается дешевле (ADR-0008) |
| **Vue / Svelte** | Технически равноценны. React выбран за экосистему (TanStack Query, react-i18next, тестирование), за то, что Claude Code и агенты конвейера лучше всего пишут на нём, и за переиспользование навыков в React Native, если мобильные приложения пойдут этим путём |
| **Переписать всё сразу («big bang»)** | Один разработчик + живые турниры каждую неделю: нельзя заморозить UI на месяцы. См. ADR-0007 |

## Последствия

**Плюсы:** один API на веб и мобильные; пульты — нормальные приложения с состоянием; общая дизайн-система; строже CSP; фронт тестируется отдельно (Vitest) и end-to-end (Playwright — уже используется Tester-агентом в облаке).

**Минусы и цена:**
- Долгий переходный период с двумя технологиями UI (ADR-0007) — дублирование шапок/стилей, пока не переедет всё.
- Большая работа на бэкенде: ≈33 позиции нового API и приведение 37 нетипизированных эндпоинтов к DTO ([api.md](../contract/api.md)). Это **основная** часть работы, не React.
- Node.js появляется в сборке (локально, в CI, в Docker-сборке, в облачной среде конвейера).
- Публичные страницы требуют отдельного решения для превью ссылок (ADR-0008).
- Первая загрузка SPA тяжелее серверной страницы — важно для мобильного интернета в Аргентине; нужен бюджет размера бандла (ADR-0006).
