# ADR-0011. Соглашения API для SPA

- **Статус:** Предложено
- **Дата:** 2026-09-28
- **Связано:** [0004](0004-api-only-boundary-openapi.md), [0009](0009-i18n-split.md), [api.md §4](../contract/api.md#4-соглашения-целевые-и-что-сейчас)

## Контекст

Сейчас: ошибки в трёх форматах (`{success:false,message}`, `{error}`, строка), 11 мест отвечают `200` с `success:false`, тексты ошибок захардкожены по-испански, 37 эндпоинтов без типов, JSON-эндпоинты разбросаны вне `/api/` (`/tournaments/*/api/**`, `/admin/**`, `/players/tournaments/**`, `/recuperar-password/*`), публичного read-only API почти нет — публичные страницы берут данные из модели. Всё это — одновременно и для будущих мобильных клиентов.

## Решение

1. **Ошибки — `ProblemDetail` (RFC 9457)**, встроенный в Spring 6: `{type, title, status, detail, instance, code, errors?}`. `code` — стабильный машинный код (`TOURNAMENT_FULL`, `CONTACT_REQUIRED`, `ROUND_ALREADY_STARTED`…), по нему фронт показывает текст (ADR-0009); `errors` — ошибки полей формы `[{field, code}]`. Один `@RestControllerAdvice` для `/api/**`.
2. **HTTP-статусы значат то, что значат:** `400/422` валидация, `401` не вошёл, `403` нет прав, `404` не найдено, `409` конфликт состояния (раунд уже начат, мест нет), `429` лимит. Никогда `200` с признаком ошибки в теле.
3. **Всё новое — под `/api/`**, разделение по потребителю:
   - `/api/public/**` — анонимно, только чтение, без персональных данных, можно кэшировать (`Cache-Control: max-age` на 10–60 с);
   - `/api/players/me/**` — текущий игрок;
   - `/api/admin/**` — админ-роли, клубная изоляция `CLUB_ADMIN` проверяется в сервисе, а не только в контроллере;
   - доменные `/api/tournaments/{id}/…`, `/api/king-of-court/**` и т.п. — действия.
   JSON-эндпоинты вне `/api/` переносятся под `/api/` **вместе со своим экраном**; старый путь живёт, пока жив legacy-экран.
4. **Эндпоинты первой отрисовки** («всё, что нужно экрану» одним запросом: `GET /api/admin/tournaments/{id}`, `GET /api/public/tournaments/{id}`) — допустимы и предпочтительны для тяжёлых экранов. Действия остаются гранулярными.
5. **Только DTO** (MapStruct) в запросах и ответах, никаких JPA-сущностей (сейчас `initialize` KoC отдаёт сущность) и `Map`.
6. **Даты/время** — ISO-8601, дата и время турнира — локальные для места проведения (`LocalDate`/`LocalTime`, как в модели), моменты времени (создано, дедлайн) — с зоной (`OffsetDateTime`). Деньги — число + код валюты.
7. **Списки** — пагинация `?page=&size=` для заведомо растущих (игроки, история), без пагинации для ограниченных (раунды турнира).
8. **Версию в URL не вводим**, пока единственный клиент деплоится вместе с бэкендом. Правило на будущее: когда выйдет мобильное приложение со своими релизами, ломающие изменения публичных эндпоинтов делаются новыми путями/полями, а не правкой старых.
9. **Переходный период для ошибок:** существующие эндпоинты, которые вызывает ещё живой Thymeleaf-JS, меняют формат ответа **только вместе с переводом своего экрана** — чтобы не сломать старый JS.

## Отвергнутые альтернативы

| Вариант | Почему нет |
|---|---|
| Оставить `{success, message}` | Не стандарт, путает статусы, текст вместо кода — нельзя локализовать на клиенте |
| `/api/v1/...` сразу | Версия, которую не с чем сравнивать; добавить префикс позже дешевле, чем тащить его без нужды |
| Переписать все 108 эндпоинтов разом | Сломает ещё живые Thymeleaf-страницы, которые их вызывают |

## Последствия

- В Фазе 0 — `@RestControllerAdvice` с `ProblemDetail`, entry point `401`, фикс `RateLimitFilter` для `/api/**`.
- Каталог кодов ошибок — единый enum на бэкенде + ключи `errors.<CODE>` во фронтовых словарях; CI проверяет, что для каждого кода есть перевод.
