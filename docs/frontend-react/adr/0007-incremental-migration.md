# ADR-0007. Переезд по экранам (strangler fig); что не переносим

- **Статус:** Предложено
- **Дата:** 2026-09-28
- **Связано:** [0003](0003-serve-spa-from-spring-boot.md), [план](../plan.md), [screens.md](../contract/screens.md)

## Контекст

40 экранов разной сложности и риска: от статичных юридических страниц до пульта Team Playoff, которым организатор управляет живым турниром. Турниры идут каждую неделю, разработчик один. Заморозить UI на время переписывания нельзя, откатывать — быстро.

## Решение

1. **Экран — единица переезда.** Один экран (или тесная группа, например «клубы: список/форма/детали») = одна фиче-спека `LFPT-XXX` по обычному SDD-процессу, один PR, один деплой. Спека опирается на раздел экрана в [screens.md](../contract/screens.md) как на чек-лист приёмки.
2. **Порядок — от безопасного к рискованному** (подробно в [плане](../plan.md)): каркас без видимых изменений → пилот на простом админском CRUD (клубы) → остальная админка → live-пульты (Team Playoff последним) → кабинет игрока и вход → публичные SEO-страницы → уборка.
3. **Старое и новое живут рядом** на одном домене и одних URL (ADR-0003). Переход между ними — полная перезагрузка страницы; общая сессия.
4. **Откат экрана** = убрать маршрут из `app.spa.routes` и вернуть контроллер. Поэтому **Thymeleaf-шаблон и контроллер переведённого экрана не удаляются сразу**: они переезжают на запасной путь `/legacy/<исходный путь>` (доступен только тем же ролям) и живут до Фазы 6 уборки, но не меньше **двух реальных турниров** для live-экранов и двух недель — для остальных.
5. **Live-экраны переключаются только между турнирами**, не в день турнира. Во время первого турнира на новом пульте у организатора есть ссылка на `/legacy/...` как запасной вариант.
6. **Каждое действие реализуется на сервере один раз.** Если у экрана действие сейчас есть и в form POST, и в JSON (Team Playoff, Americano) — после перевода form POST-версия удаляется вместе с legacy-страницей, а не поддерживается параллельно навсегда.
7. **Переезд — не место для новых фич и редизайна логики.** Поведение экрана переносится как есть (включая тексты), найденные баги чинятся отдельными issue ([findings.md](../contract/findings.md)). Визуальный стиль — по ADR-0012.

### Что НЕ переносим

| Что | Почему |
|---|---|
| **Письма** (`templates/email/*`, 12 шт.) | Почтовые клиенты не исполняют JS; письма — серверный HTML с inline-стилями. Остаются на Thymeleaf навсегда |
| **`test/tournaments`** (T-01, 3 159 строк, JDBC) | Внутренний dev-инструмент SUPER_ADMIN; остаётся Thymeleaf-страницей до удаления |
| **Мёртвые маршруты** (#330, #335, F-01, F-02) | Удаляются, а не переносятся |
| **`/waitlist/confirm`** (P-10) | До решения по F-06 |
| **Экспорт в Excel** (A-19) | Это скачивание файла, SPA просто даёт ссылку |

## Отвергнутые альтернативы

| Вариант | Почему нет |
|---|---|
| Big bang (переписать всё в ветке и переключить разом) | Месяцы без релизов UI; огромный непроверяемый PR; невозможен частичный откат |
| Новый UI под `/app/*` параллельно старому, переключение пользователей флагом | Два адреса у каждой страницы, ссылки из писем ведут в старое; поддерживать обе версии каждого экрана до конца переезда |
| Переносить по слоям (сначала все API, потом все экраны) | Долго нет видимого результата и проверки, что API действительно подходит экрану |

## Последствия

- Переходный период — месяцы, с двумя технологиями UI. Общие элементы (шапка, стили) временно существуют в двух версиях; визуально старые и новые страницы могут отличаться — это принимаем.
- Нужен трекинг прогресса: колонка «Фаза» в `screens.md` + метка/milestone в GitHub.
- `/legacy/**` — временная поверхность атаки и путаница; снимается в Фазе 6 обязательно.
