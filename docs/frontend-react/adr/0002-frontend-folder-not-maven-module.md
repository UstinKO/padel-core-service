# ADR-0002. Фронтенд — самостоятельный npm-проект в `frontend/`; Maven multi-module не делаем

- **Статус:** Предложено
- **Дата:** 2026-09-28
- **Связано:** [0003](0003-serve-spa-from-spring-boot.md), [0004](0004-api-only-boundary-openapi.md)

## Контекст

Нужно разместить React-код так, чтобы (1) сейчас всё собиралось и деплоилось одним jar, как сегодня, и (2) потом фронтенд можно было безболезненно унести в отдельный сервис или репозиторий.

Бэкенд сейчас — один Maven-модуль в корне (`pom.xml` + `src/`). От этих путей зависят `Dockerfile` (`COPY src ./src`), `.github/workflows/deploy.yml` и `pr-check.yml`, облачная среда конвейера, пути в `.claude/**` и документации, открытые PR.

## Решение

```
padel-core-service/
├── pom.xml          ← без изменений структуры: Spring Boot-приложение
├── src/             ← бэкенд + templates/email (+ Thymeleaf-страницы до конца переезда)
└── frontend/        ← самостоятельный npm-проект (package.json, свой README, свой .env)
```

- `frontend/` **не является Maven-модулем**. Это обычный npm-проект, который собирается и запускается сам по себе (`npm ci && npm run build`, `npm run dev`), без Java.
- Корневой `pom.xml` только **вызывает** его сборку через `frontend-maven-plugin` и кладёт результат в jar (ADR-0003). Плагин сам скачивает нужную версию Node — на машинах сборки не нужен предустановленный Node.
- Бэкенд не переезжает в `backend/`. Разделение на Maven-модули — отдельная будущая задача, когда (и если) начнём делить **сам бэкенд** на модули; тогда же фронт уже будет самостоятельным и не помешает.
- Фронтенд ничего не импортирует из `src/` (ни файлов, ни путей). Единственная связь — HTTP-контракт (ADR-0004).

## Отвергнутые альтернативы

| Вариант | Почему нет |
|---|---|
| **Maven multi-module** (родительский pom + `backend/` + `frontend/`) | Даёт тот же результат ценой переноса всего бэкенда: правки Dockerfile, двух workflow, облачной среды, `.claude/**`, путей в документации и конфликты с открытыми PR. Отложено до разделения бэкенда на модули (решение пользователя 2026-09-28) |
| **Отдельный репозиторий для фронта сразу** | Два репозитория, два CI, согласование версий API между ними — лишняя координация для одного разработчика, пока фронт и бэк деплоятся вместе. Когда понадобится — `git subtree split --prefix=frontend` сохраняет историю |
| **React-код внутри `src/main/resources/static`** | Смешивает исходники фронта с ресурсами бэкенда, требует бандлер внутри Maven-структуры, не выносится без переделки |

## Последствия

- Вынос фронта в отдельный репозиторий = `git subtree split --prefix=frontend` + удалить вызов сборки из `pom.xml`.
- В CI и в Docker-сборке появляется шаг `npm ci` + сборка (через Maven-плагин — без отдельной настройки Node), время сборки вырастет на 1–2 минуты. Кэшировать `~/.m2` и `frontend/node_modules`/npm-кэш.
- `Dockerfile` (builder-стадия сейчас копирует только `pom.xml` и `src`) должен копировать и `frontend/`.
- `.gitignore`: `frontend/node_modules/`, `frontend/dist/`.
- Облачная среда конвейера (`/develop-feature` в роутине) должна уметь собрать фронт — проверить в Фазе 0 (Playwright там уже есть, значит Node, скорее всего, тоже).
- Агентам (`.claude/agents/developer.md`, `tester.md`) нужны правила для фронтенд-кода — обновить в Фазе 0.
