# Контракт текущего фронтенда

Полная инвентаризация того, что сейчас делает Thymeleaf-интерфейс, — чтобы при переводе на React **ничего не потерять**: ни экран, ни поле, ни действие, ни ссылку из письма, ни проверку прав.

Снято с кода **2026-09-28**, ветка `master`, коммит `eeee06c`. Факты извлечены скриптами (разбор `controller/**`, `templates/**`, `static/js/**`), выводы и целевой API — ручной анализ.

## Как пользоваться при переводе экрана

1. Найти экран в [screens.md](screens.md) по URL или шаблону.
2. Пройти по его разделу как по чек-листу приёмки: **каждое** поле из «Данные в модели» должно либо прийти из API, либо быть сознательно выброшено (записать почему в спеке); **каждое** действие из «Формы» и «Подключённый JS» — работать.
3. Проверить экран в [findings.md](findings.md) и в таблице прав [api.md §3](api.md#3-расхождения-в-правах-доступа-проверить-до-перевода-экрана).
4. Если экран — цель входящей ссылки ([cross-cutting.md §5](cross-cutting.md#5-входящие-ссылки-которые-нельзя-сломать)), проверить, что старый URL открывает новую страницу.
5. После перевода — отметить экран в сводной таблице `screens.md` (колонка «Фаза» → `✅ React, PR #…`).

## Легенда

- **ID экрана:** `P` — публичная страница, `L` — публичная live-страница формата, `U` — кабинет игрока, `A` — админка, `T` — внутренний инструмент. `F-a…F-h` — редирект-флоу без своей страницы. `F-00…F-13` — находки.
- **NEW** в «Целевом API» — эндпоинта ещё нет.
- **Доступ «админ-роли»** = `SUPER_ADMIN`, `ORGANIZER`, `ADMIN`, `CLUB_ADMIN` (роль `OWNER` в коде упоминается, но не существует — F-09).
- **Фаза** — см. [plan.md](../plan.md).

## Как обновить

`screens.md` и таблица существующих эндпоинтов в `api.md` (§1) генерируются скриптами из [tools/](tools/):

```bash
bash docs/frontend-react/contract/tools/run.sh   # из корня репозитория
```

- `ctrl.py` — разбирает контроллеры (маршруты, параметры, атрибуты модели, flash, редиректы, `@PreAuthorize`);
- `tpl.py` — разбирает шаблоны (формы и поля, fetch, скрипты, `th:inline`, фрагменты, OG-теги, i18n);
- `gen_screens.py` — собирает `screens.md`; **ручные части** — словарь `JS` (что вызывает каждый JS-файл) и список `SCREENS` (назначение, целевой API, фаза) в начале файла: при изменениях править там, а не в `screens.md`;
- `gen_api.py` — таблица существующих эндпоинтов; результат вклеивается в `api.md` §1 вручную (остальные разделы `api.md` — ручные).

Скрипты — эвристика на регулярках, не парсер Java: после перегенерации пролистать дифф глазами.
