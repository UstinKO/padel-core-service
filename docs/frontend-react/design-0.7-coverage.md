# Покрытие пользовательской части дизайном заказчика 0.7

> **Источник:** архив `1Padel-User-Interface-0.7` (заказчик, 2026-10-27), лежит в `docs/frontend-react/1Padel-User-Interface-0.7/`. Демо: <https://one-padel-play-concept.evgeny-1800.chatgpt.site/#/home>, каталог состояний: `/#/review` (99 сценариев × ES/RU/EN).
> **Сверено с кодом** 2026-10-28 (`master` 4ac0b49): `contract/screens.md`, шаблоны `templates/**`, `static/js/**`, enum'ы `model/enums/**`.
> **Что это:** React 18 + TS + Vite, hash-роутинг, все данные — локальные фикстуры (`src/data/*`), операции — заглушка `src/services/registration.ts`. Стиль «Play Concept»: Manrope, светлый тёплый фон, глубокий зелёный, лаймовый акцент. Админки нет.

## 1. Итог

- **Пользовательская часть покрыта почти полностью**: все публичные экраны (P-01…P-12), кабинет и профиль (U-01, U-02), зрительские страницы всех live-форматов (L-01…L-06), модалки записи/отмены/пар/профиля, системные экраны, cookie-баннер, переключатель языка.
- **Все 5 наших типов турниров в дизайне есть** (таблица §3). Новых *форматов турнира* в 0.7 нет. Новые *разделы* — «Лига 1-Padel» и «Общий рейтинг» — в дизайне уже показаны экраном «В разработке».
- **Не покрыто:** вся админка (A-01…A-19), несколько наших функций (§5).
- **Дизайн предполагает изменения бэкенда** (§6): без них часть экранов показать честно нельзя.

**Правило «В разработке»** (решение пользователя 2026-10-28): раздел или формат, которого нет на сервере, показывается экраном «В разработке» (компонент дизайна уже есть: короткое объяснение + переход к доступному разделу, без даты и без запросов к несуществующему API). Сейчас это **Лига** и, если так решим, **общий рейтинг**. Тип турнира, неизвестный фронту, показывается так же, а не падает.

## 6. Изменения бэкенда, которых требует дизайн

Из `docs/INTEGRATION.md`, `REGISTRATION-INTEGRATION.md`, `PAIR-AUDIT.md` архива — каждое пункт сверить с кодом и оформить отдельной backend-задачей перед экраном:

1. **Новая модель резерва** («Revised reserve contract», решение владельца 2026-10-27): готовые пары имеют приоритет над неполными, авто-перевод в основу → `CONFIRMED` + `participationStatus=PENDING`, подтверждение / отказ игрока без дедлайна, отказ сразу продвигает очередь; `register-solo` не должен отказывать при полном турнире.
2. **Телефон обязателен**, Telegram — по желанию (сейчас достаточно одного из двух, `hasValidContact()`).
3. **Регистрация**: структурные ошибки по полям (422 + `fieldErrors`), 429 в JSON с реальным `Retry-After`, `RateLimitFilter` не штрафует GET формы и обычные ошибки валидации.
4. **Пары**: отказ от предложения, просмотр предложения до принятия, изменение `shareContacts` после заявки, проверка категории партнёра.
5. **Статус оплаты для игрока** — у игрока сейчас нет API (`Payment` видит только админ).
6. **Язык**: переключатель дизайна работает через `localStorage` — переделать на наш механизм (`?lang=` → cookie `CookieOverrideLocaleResolver` → `Accept-Language`); `preferredLocale` в профиле уже есть (в дизайне это «язык общения», не язык интерфейса).
7. Hash-роутинг демо не годится для боевого сайта: реальные URL (ADR-0003) + серверная подстановка OG (ADR-0008).
8. Push-уведомления — в дизайне упомянуты, на сервере нет; считать «в разработке».

## 7. Открытые вопросы

1. Стиль Play Concept из 0.7 заменяет наши варианты главной (Трансляция / Журнал / Стеклянный корт, `design-grid.md`)? Если да — токены в `.agents/DESIGN.md` берём из архива.
2. Общий рейтинг: в дизайне «В разработке», а у нас `/ranking` работает. Скрываем рабочую страницу или делаем её в новом стиле?
3. Функции из §5 (YouTube, PNG-сетка, QR, резерв/«не пришла» в плей-офф) — дорисовать по стилю или убрать?
4. Изменения §6 (особенно резерв и обязательный телефон) — согласованы заказчиком как бизнес-правила? Тогда сначала MASTER.md и бэкенд-спеки, потом экраны.

> **2026-10-28:** заказчик ответил на вопросы 2–4 — см. [design-0.7-decisions.md](design-0.7-decisions.md) (рейтинг «В разработке»; YouTube убираем, PNG и QR оставляем; резерв и обязательный телефон согласованы с уточнениями).


## LFPT-0911: пользовательские live-экраны UI v2

Реализованы отдельные preview views KoC, индивидуального Americano и Team Playoff: раунды/корты, серверные рейтинги, история/участник, очередь и bracket, share/QR/PNG, ES/RU/EN и табло. Один STOMP-клиент слушает безопасный public topic #903; события объединяются в refetch, reconnect/focus/visibility перечитывают snapshot, polling 20 с и Retry-After ограничивают запросы. Временные ошибки сохраняют последний снимок со stale; 403/404/409 убирают его.

[Маршруты, детали реализации, бюджеты и проверки](../../frontend/README.md#lfpt-0911-пользовательские-live-экраны-ui-v2). Production URL и SUPER_ADMIN-защита preview сохранены; отдельный контур #904 и физические устройства не входят в этот результат.
