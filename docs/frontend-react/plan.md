# План перехода на React — по фазам

> **Статус:** v2 (2026-10-26), Phase 0 в работе с 2026-11-05. План перестроен под
> [ADR-0013](adr/0013-redesign-and-react-together.md), контракт доставки принят в
> [ADR-0014](adr/0014-spa-delivery-routes.md); чек-листы экранов — в [контракте](contract/README.md).
> **Ресурсы:** один разработчик + Claude Code и SDD-конвейер `/develop-feature`. Дедлайнов нет, турниры — каждую неделю.
> **Оценки** — S / M / L / XL (как в `docs/microservices-migration-plan.md`), не в днях. Риск — отдельно.

## Принципы (кратко)

- Одна фаза даёт ценность сама по себе и может стать последней — сайт при этом полностью рабочий.
- **Экран переводится один раз — сразу на React и в согласованном новом дизайне** (ADR-0013). Thymeleaf-страницы не перерисовываются.
- Цикл экрана: спека (чек-лист `screens.md` + макет из дизайна) → React на `/preview/<путь>` → проверка → демо и согласование с заказчиком → переключение боевого URL (`app.spa.routes`) → старая страница на `/legacy/...`, потом удаление.
- Экран = одна фиче-спека `LFPT-XXX` = один PR = один деплой (ADR-0007).
- Сначала API экрана (DTO, эндпоинты, тесты), потом React-экран (ADR-0004).
- Откат экрана — убрать маршрут из `app.spa.routes`; legacy-версия живёт на `/legacy/...` до Фазы 6 (ADR-0003, ADR-0007).
- Live-экраны переключаются только между турнирами.
- Баги из [findings.md](contract/findings.md) — отдельными issue, не внутри переезда.

## Фаза «Демо». Закрытые React-страницы для акцепта (M)

Несколько экранов из сетки заказчика — сразу на React, в новом дизайне, на `/preview/...`. Данные — реальный API, где он есть; иначе фикстуры с пометкой «демо». Это первые боевые экраны, не прототип: после акцепта дорабатываются и переключаются.

**Готово, когда:** заказчик провёл демо и письменно принял дизайн. До этого ни один боевой URL не переключается.

## Фаза 1. Пилот — клубы (M)

Экраны A-13, A-14, A-15. Выбраны потому что: простой CRUD, только админы, нет SEO и realtime, API почти есть (`/api/clubs`), но требует правки прав для `CLUB_ADMIN` ([api.md §3](contract/api.md#3-расхождения-в-правах-доступа-проверить-до-перевода-экрана)) — то есть пилот проверит весь путь: права → DTO → OpenAPI → типы → экран → тесты → деплой → откат.

**Готово, когда:** клубы в проде на React ≥ 2 недель без регрессий; хотя бы один из трёх экранов сделан конвейером `/develop-feature` от спеки до PR; откат через `app.spa.routes` проверен на стейдже/локально; по итогам пилота обновлены правила в `CODE_REVIEW.md` и, если нужно, ADR.

## Фаза 2. Админка (XL)

Порядок: A-18 telegram-pipeline (разминка) → A-16/A-17 игроки → A-01 панель → A-02 список турниров → A-03 форма турнира (заодно #384 — даты в ISO) → A-06 платежи → A-05 сетка → **A-04 детали турнира** (самый большой экран, 1 856 строк; вход во все пульты) → A-19 экспорт (только ссылка).

**Готово, когда:** вся админка, кроме пультов форматов, на React; JSON-эндпоинты под `/admin/**` перенесены под `/api/admin/**`.

## Фаза 3. Live-форматы (XL, высокий риск)

Порядок по готовности API и риску:
1. **King of Court** A-07 + L-01 — API и WebSocket уже есть, не хватает `reset`/`start`.
2. **Americano** A-08, A-09 + L-02, L-03 — API почти весь есть; предпросмотр перестаёт быть «ответом на POST».
3. **Team Americano** A-10, A-11 + L-04 — перенос `/tournaments/team-americano/api/**` под `/api/`; попутно закрываются #334, #329.
4. **Team Playoff** A-12 + L-06 — **последним**: самый сложный и самый используемый прямо сейчас пульт (очередь матчей, swap, две колонки квалификации, WebSocket, экспорт сетки).

Правила фазы:
- админские страницы форматов закрываются ролями (#391) сразу при переводе;
- публичные табло требуют публичного read-only API ([api.md §2.2](contract/api.md#22-публичное-чтение-фаза-35));
- черновики счёта не теряются при обрыве сети (сейчас `localStorage` по matchId);
- переключение — между турнирами; на первом турнире организатор знает про `/legacy/...`;
- по каждому формату — Playwright-сценарий «провести мини-турнир от инициализации до финиша».

**Готово, когда:** каждый формат прошёл ≥ 2 реальных турнира на React без отката.

## Фаза 4. Игрок (L)

## LFPT-0911: пользовательские live-экраны UI v2

Реализованы отдельные preview views KoC, индивидуального Americano и Team Playoff: раунды/корты, серверные рейтинги, история/участник, очередь и bracket, share/QR/PNG, ES/RU/EN и табло. Один STOMP-клиент слушает безопасный public topic #903; события объединяются в refetch, reconnect/focus/visibility перечитывают snapshot, polling 20 с и Retry-After ограничивают запросы. Временные ошибки сохраняют последний снимок со stale; 403/404/409 убирают его.

[Маршруты, детали реализации, бюджеты и проверки](../../frontend/README.md#lfpt-0911-пользовательские-live-экраны-ui-v2). Production URL и SUPER_ADMIN-защита preview сохранены; отдельный контур #904 и физические устройства не входят в этот результат.
