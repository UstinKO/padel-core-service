# Контакт организатора мероприятия

`GET /admin/api/organizer-contact/countries` возвращает ISO-страны, локализованные подписи, международные коды и национальные примеры. AR предлагается первой. `POST /admin/api/organizer-contact/preview` принимает `{eventId?, name, phone, country}` и возвращает `{valid, contact, message}` без записи; необходимы служебная роль и CSRF, при eventId — право управления этим мероприятием. Ответ не кешируется. Предпросмотр не подтверждает наличие WhatsApp.

`contact`: name, phone (E.164), country, displayPhone, whatsappUrl, needsReview, errorCode. Только успешный результат содержит URL `https://wa.me/<digits>`. Поддерживаются числовой телефон, национальный ввод выбранной страны, `https://wa.me/<digits>` и `https://api.whatsapp.com/send?phone=<digits>`; текст сообщения из вставленной ссылки не сохраняется. При необходимости будущий текст добавляется отдельным URL-параметром `text` с кодированием.

Создание/редактирование через `TournamentDto`: organizerName, organizerPhone, organizerCountry. Явно пустой organizerPhone — ошибка, старый contactoOrganizador не служит обходом. Для старых клиентов при отсутствующем organizerPhone проверяется legacy-поле. Сервис независимо повторяет ту же проверку.

Старое поле сохраняется для совместимости в каноническом числовом формате после явного сохранения формы. Первоначальное значение сохраняется сервером в organizerContactOriginal и недоступно для перезаписи клиентом. Чтение старых контактов не запускает миграцию: телефон или имя с одним явным международным номером разбираются без записи; неоднозначный текст получает needsReview, пустой URL и видимую причину в интерфейсе.

Номера пользователей, права доступа, правила допуска и SUMA не изменяются. Публичные ссылки используют только контакт данного мероприятия; фиксированного номера платформы нет.

## Диагностика исходного сбоя

26.11.2026: на публичной странице №196 имя из legacy-поля попадало в путь wa.me вместе с телефоном. Реальный переход перенаправлен на `api.whatsapp.com/resolve/?deeplink=…&not_found=1`, страница WhatsApp показывает «404. Этой страницы не существует». Прямой канонический адрес с тем же номером открыл страницу чата с соответствующим международным номером. Это сбой формирования ссылки до открытия чата, а не отказ сайта при сохранении. Фактический HTTP-статус ответа не снимался; 404 подтверждён текстом страницы WhatsApp. Отправка сообщения не выполнялась.

В админском шаблоне дополнительно обнаружено добавление фиксированного номера платформы перед контактом события. Новая общая политика исключает обе причины. Проверка выполнена в настольном браузере; открытие приложения на физических iPhone/Android остаётся ручной проверкой перед выпуском.

Интерфейс: `organizer-contact.js` отправляет предпросмотр с CSRF и защищает от устаревших ответов. `organizer-contact.css` размещает поля в одну колонку на узких экранах. Сохранение не зависит от доступности JS-предпросмотра: серверная валидация обязательна. Публичная и административная страницы используют `TournamentDto.organizerContact`; неправильный URL не отображается.

Дополнительная проверка того же конечного URL ошибки подтвердила HTTP 404 (26.11.2026).
