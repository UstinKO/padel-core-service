# Универсальный экспорт результатов

Старая техническая выгрузка `/admin/export` также ограничена SUPER_ADMIN: прежний допуск OWNER закрыт, чтобы не оставался альтернативный путь к тем же результатам и контактам.

Только `ROLE_SUPER_ADMIN`, дополнительно к общей защите административных URL. Организатор и принадлежность клуба не ограничивают главного администратора. `GET /admin/tournaments/{id}/results-export/preview` возвращает предварительность, число уникальных профилей/матчей и коды предупреждений без персональных данных. `POST /admin/tournaments/{id}/results-export` с CSRF формирует `format=XLSX` (по умолчанию) или `CSV` (ZIP). `contacts=true` требует `acknowledged=true`; другие роли запрещены при любом ID и наборе параметров.

Файл — только в памяти, `Cache-Control: no-store`, `nosniff`, безопасное имя attachment с ID, final/provisional и contacts. Никакой автоматической передачи партнёру. После успешного формирования записывается `tournament_result_exports`: actor, UTC-время, ID мероприятия, формат, контактный режим и числа строк. Это журнал формирования, не доказательство получения файла браузером. Отказ записи журнала не выдаёт файл. Спортивные таблицы не изменяются.

## Схема 1

Excel содержит три листа; ZIP — три одноимённых CSV с UTF-8 BOM, запятыми, CRLF и RFC4180-кавычками. Названия листов и машинных колонок одинаковы на всех языках. Интерфейс локализуется отдельно.

- `Tournament`: метаданные события, организация из organization_name (без подстановки личного email), число строк участников и отдельное число уникальных профилей (включая резерв/отмены, различаемые статусом), FINAL/PROVISIONAL, время снимка, режим, коды предупреждений.
- `Participants`: один профиль — одна строка; текстовый гость без профиля сохраняется отдельной строкой с пустым player_id и предупреждением, без выдуманного идентификатора; имя/фамилия как сохранены, связи team_ids/team_numbers/partner_ids, достигнутая стадия, final_place отдельно от current_place, статус заявки, спортивные показатели и standing_unit (POINTS/GAMES), чтобы не смешивать очки и геймы. `phone` существует только в расширенном файле. Невалидный телефон, например Telegram username, не выгружается как телефон.
- `Matches`: source + match_id образуют идентификатор; у King match_id — ID корта конкретного раунда, result_id — запись сохранённого счёта. Указаны фактические составы, стадия/раунд/корт, score_unit (POINTS/GAMES/SETS), отдельно сетовый результат, победитель, исходный статус и явно сохранённый технический признак. winner_reference_type=PLAYER_IDS для игровых движков; LEGACY_ID сохраняет старый идентификатор победителя без предположения, что это профиль. Списки ID разделяются `;`, порядок сторон сохраняется. Ничья или незавершённый матч не получает победителя по предположению.

Используются существующие расчёты рейтинга, сохранённый итоговый порядок Americano и круговые дополнительные встречи. В плей-офф полное распределение мест не придумывается: финалисты получают 1/2, другие — достигнутый этап. Игровые очки отделены от автоматического бонуса корта и ручных изменений. Снимок — readOnly REPEATABLE_READ; текущий King выбирается active DESC,id DESC, архивные JSON-версии не добавляются.

Неполное проведение King остаётся предварительным, даже если статус родительского события устарел. Пустые значения остаются пустыми, нулевой счёт — числом 0. XLSX использует текстовые ячейки для пользовательских строк. В CSV текстовые значения с опасным префиксом получают `'`; импортёр учитывает это защитное экранирование, в том числе у телефонного `+`.

Предупреждения: PROVISIONAL, NO_MATCHES, NO_STANDINGS, MISSING_PLACEMENTS, LEGACY_GUEST_WITHOUT_PROFILE, MISSING_LINEUP, INVALID_PHONE_EXCLUDED, CONTACTS_INCLUDED. Они не выводят контакты. Для мероприятия без матчей экспортируются метаданные и регистрации с явным предупреждением.

Проверки: ResultExportIntegrationTest (PostgreSQL, все форматы/роли и режимы), ResultFilesTest (типизация, формулы, CSV). Учебный XLSX создаётся интеграционным тестом в target/results-export-qa. Удалённые мероприятия возвращают стандартное not found; деактивация не препятствует чтению сохранённых результатов.
