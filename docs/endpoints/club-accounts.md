# Клубные аккаунты и назначенные площадки

Все операции `/admin/club-accounts` доступны только SUPER_ADMIN, с действующей сессией. POST требует CSRF.

| Метод | URL | Действие |
|---|---|---|
| GET | `/admin/club-accounts` | Список существующих CLUB_ADMIN для назначения площадок |
| GET | `/admin/club-accounts/{id}` | Аккаунт, доступные клубы и выбранные назначения |
| POST | `/admin/club-accounts/{id}/clubs` | Заменить назначения набором `clubIds`; пустой набор снимает назначения |

`ClubAccountService` проверяет роль действующего пользователя, тип целевого аккаунта и существование клубов. Нельзя изменить роль/пароль/авторство турниров. Для новой записи требуется назначенная активная площадка. Прежние одиночные привязки сохраняются; открытая сессия перечитывает назначения из БД. Шаблоны этих новых страниц поставляет зависимый frontend PR #1188; до него навигация на страницы не добавляется.

CLUB_ADMIN управляет только своими мероприятиями (ownerId), даже если другие организаторы проводят события на той же площадке. Проверка `TournamentAccessService` распространяется на проведение и производные ресурсы. Административные списки, игроки, история регистраций, оплаты и сводка ограничены своими событиями. SUPER_ADMIN сохраняет все площадки и мероприятия, ADMIN/ORGANIZER — прежние полномочия.

HTML-отказ использует действующий обработчик (перенаправление на `/error/403` либо публичную карточку события), JSON — HTTP 403 без административных данных. Публичный просмотр турниров не меняется.
