# Календарь административных мероприятий

`GET /api/admin/events/calendar` — служебные роли, не PLAYER и не аноним. Параметры: `month=YYYY-MM`, `clubId`, `format` (AdminEventFormat), `gender`, `level`, `status` (действующие enum).

Ответ `no-store`: month, today (Buenos Aires), periodCount до фильтров, events, clubs. Событие: id, date/time локальные, timeZone, nullable endDate/endTime, clubId/clubName, format, gender, level, status, active. Нет регистраций, контактов и оплат. Не передавать даты через часовой пояс устройства. Все пересекающие месяц доступные события включены, включая продолжение с предыдущего дня/месяца. Исключительный конец ровно в полночь не создаёт дополнительный день.

SUPER_ADMIN/ADMIN видят все записи; остальные действующие управляющие роли — собственные мероприятия. Клубная площадка сама по себе не даёт доступа к чужим событиям. Варианты клубов берутся из доступных событий и соответствующих прав. Отменённые скрыты по умолчанию, `status=CANCELADO` возвращает их явно. Черновики и завершённые доступны по тем же правам. Удалённые строки отсутствуют. Некорректный month — 400, сбой не заменяется пустым результатом. API не принимает ограничение дат списка.

## Интерфейс

`/admin/tournaments?view=calendar&month=YYYY-MM&day=YYYY-MM-DD` — обычный защищённый раздел. Совместимые фильтры clubId/format/gender/level/status/organizerId/lang сохраняются в URL; from/to удаляются при входе в календарь. Ссылка возврата из карточки принимает только same-origin `/admin/tournaments?view=calendar`. Браузерный возврат обновляет данные. На компьютере ячейка показывает все записи дня; высота недели определяется содержимым без вложенной прокрутки. На телефоне — количество и полный список выбранного дня. В записи время/категория, формат, клуб, организация; открытая регистрация без отдельной строки, остальные статусы с текстовой меткой. Название организации редактируется в сворачиваемом блоке календаря. RU/ES/EN и существующее оранжевое оформление. Ошибка загрузки имеет повтор и не маскируется пустым месяцем.

Логика дат: `node --test tests/admin-event-calendar.test.mjs`. Браузерная приёмка выполняется на отдельной базе, без заполнения рабочего аккаунта клуба.

Проверено 22.11.2026 на отдельной среде: общий Java-прогон 1178 тестов (0 ошибок, 2 прежних пропуска), 3 проверки локализации UI, 9 тестов дат Node и 48 relay. Ручная браузерная приёмка: 1440×1000, 390×844 и 320×740; RU/ES/EN; клуб с двумя площадками, главный администратор, организатор, пустой клуб; фильтры при смене месяца/вида/возврате браузера; перенос учебного события через форму и возврат после сохранения; явная отмена; отключение сервера и повтор загрузки. Горизонтального переполнения нет. Месяц/день сохраняются также в существующем механизме возврата списка, без хранения авторизации или данных событий в браузере. Рабочий сайт не затрагивался.

## Организации

Календарь принимает organizerId, событие содержит organizer {id, name}, ответ — organizers только по доступным мероприятиям до фильтров. Название берётся из Owner.organizationName, не из клуба/редактора. Новая nullable колонка v1.86 не заполняет старые данные автоматически. GET /api/admin/organizers/organizations — accountId и accounts {id, accountName, organizationName} доступных для переименования аккаунтов; PUT /api/admin/organizers/{id}/organization — {name}, до 120 символов, пробелы по краям удаляются, пустое значение очищает поле. SUPER_ADMIN редактирует любой аккаунт, остальные служебные роли — только свой, CSRF обязателен. В ответах нет контактов.
