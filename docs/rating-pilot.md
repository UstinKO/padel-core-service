# Закрытый пилот рейтинга Elo

Статус: кандидат для тестовой версии, без разрешения на выпуск. Спецификации: [доступ](../specs/features/LFPT-1083-rating-pilot-access.md), [автоматический пересчёт](../specs/features/LFPT-1086-rating-pilot-refresh.md).

`app.rating.pilot.enabled` по умолчанию выключен. `player-ids` содержит основные ID выбранных игроков; подтверждённые aliases дают связанным аккаунтам ту же строку. Список ограничивает доступ к новому кабинету и таблице, а расчёт включает всех игроков. Гость и посторонний игрок сохраняют прежние страницы, включая ресурсы. Рейтинг проверяет доверенную сессию перед чтением результатов; query/cookie с ID не переключают участника. Ответы персонализированных страниц помечены private/no-store.

## Источник

`snapshot` — внешний проверенный JSON (snapshot/startStep/aliases), без персональных данных в репозитории. Без auto-refresh показывается этот фиксированный срез.

При `app.rating.pilot.auto-refresh=true` нужен `app.rating.pilot.history`: внешний JSON с history, liveAfter, managedEvents, excludedEvents. При запуске полное воспроизведение истории сверяется с исходным срезом. Матчи читаются при открытии страницы в read-only транзакции REPEATABLE_READ и пересчитываются хронологически в памяти. Отдельного фонового задания, записи очков в старую таблицу рейтинга и push в открытый браузер нет. Обновление страницы показывает новые значения.

Старый турнир S-ID включается в managedEvents только после полной сверки с БД: состав, результаты, категория, дата, титулы. Его результаты заменяются целиком, включая сброс/отмену. Остальная старая история не подменяется несверенными данными. Новые события выбираются строго после liveAfter; событие на этой дате или задним числом требует сверки и включения в управляемую историю. Срез даты должен включать все проверенные результаты этого дня. excludedEvents используется для исключения искусственных локальных сценариев и не может пересекаться с подтверждённой историей.

Пересчёт не зависит от текущего уровня в карточке игрока. Архивная категория управляемого турнира сохраняется. Для нового события используется категория самого турнира. Правки архивных источников вносятся в подтверждённую историю и новый согласованный срез; они не заменяются текущими данными сайта автоматически.

## Проверка и откат

1. На отдельной локальной БД сравнить все строки базового рейтинга с исходным срезом.
2. Создать помеченные тестовые турниры и сохранить результаты штатными средствами. Проверить кабинеты, историю по турнирам и повторное чтение без дублей.
3. Исправить старый счёт, проверить последующую историю, вернуть счёт и сравнить все строки. Отдельно проверить турнир, уже перенесённый в управляемую историю.
4. Проверить неучастника и выход из аккаунта. Исключить искусственные результаты и повторно сверить базовый рейтинг.
5. Выключение auto-refresh возвращает фиксированный срез; выключение pilot.enabled возвращает прежний интерфейс всем. Конфигурация читается при запуске. На боевом сервере эти переключения требуют отдельного разрешения.

Обычный профиль не включает preview: не создаёт тестовые карточки, таблицу поправок или фикстуры. Настройка изоляции БД, почты и остальных интеграций для браузерной проверки обязательна вне приложения. Производственные данные не используются для тестовых записей.
