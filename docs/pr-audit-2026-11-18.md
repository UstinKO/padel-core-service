## Доказательство интеграции Elo

GitHub подтверждает #1100 как merged PR для коммита `3cb3e146`. Этот коммит содержит 45 изменённых файлов, включая все шесть исходных спецификаций. Сравнение дерева последнего PR цепочки (`39c2e826`, #1097) с интеграцией:

- 30 из 38 файлов объединённого исходного объёма совпадают побайтно.
- Все Elo Java-классы и тесты цепочки совпадают, кроме `PilotEloRanking`: интеграция добавляет `allows` и использует его при прежней проверке доступа.
- Ranking template, фрагмент Elo, CSS и оба JS-файла совпадают.
- Все 55 исходных ключей `elo.*` совпадают по значениям в ES/RU/EN; остальные изменения properties относятся к актуальному master.
- Изменения dashboard добавляют актуальные participation-элементы; Elo-вставки сохраняются. Документационные различия не содержат отдельной невключённой реализации.
- Текущий master развивает этот код через #1156, #1166, #1167. `git cherry` не считает исходные коммиты эквивалентными: это следствие составного переноса, не доказательство отсутствия кода.

Поэтому закрываются устаревшие PR, а исходные issues — как выполненные, со ссылкой на #1100. Ветки и уникальная работа оставшихся PR сохраняются; мерж продуктовых PR и деплой этим аудитом не выполняются.

## Организационные ошибки

На исходном срезе 12 из 13 PR не имели меток/Milestone. Две source issues пилота (#1083/#1086) тоже были без Milestone. Метаданные выравниваются по source issue; обычные PR не превращаются в автономные добавлением `pipeline:*`.

В #1121 написано `Depends-On: #1118`, но #1118 — issue. Backend PR — #1122, его head совпадает с base фронта. Стек #1030 → #1031 → #1035 → #1084 → #1088 → #1097 имел feature-base и draft: оркестратор, выбирающий только готовые PR в master, сам такую цепочку не закрывает.

## Что меняется в правилах

[PR_MANAGEMENT.md](../.agents/PR_MANAGEMENT.md) — единая проверка перед началом работы и непосредственно перед публикацией. Она ищет работу по issue, ветке, маркерам, diff и фактическому коду master; предусматривает продолжение PR, составные интеграции, корректные зависимости и служебную архивацию. В workflow устраняются проверка только последних 100 заголовков и трактовка возраста claim как достаточного доказательства остановки.

Это изменение документации. Исполняемые engine/select/archive workflow не изменяются; атомарное предотвращение гонок и API-сбоев требует отдельной задачи с тестами. Выполненные проверки этой документации и текущий CI отражаются в PR LFPT-1174.
