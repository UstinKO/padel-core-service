# padel-core-service — правила работы Codex

Общение, постановки задач, коммиты и PR — на русском. Идентификаторы сохраняют язык домена.

## Перед работой

- Прочитай [мастер-спецификацию](specs/MASTER.md) и соответствующую фиче-спеку. Не придумывай бизнес-правила; неразрешённые бизнес-вопросы передавай пользователю.
- Техническая карта: [.agents/PROJECT.md](.agents/PROJECT.md). Документация по областям: [docs/Home.md](docs/Home.md). При расхождении описания реализации с кодом проверь код и обнови документ; изменение бизнес-инварианта согласуй отдельно.
- Обязательны [.agents/GIT_WORKFLOW.md](.agents/GIT_WORKFLOW.md), [.agents/CODE_REVIEW.md](.agents/CODE_REVIEW.md) и [.agents/CODE_STYLE.md](.agents/CODE_STYLE.md). Перед изменением UI прочитай `.agents/DESIGN.md`, если он доступен локально, и актуальные решения в `docs/frontend-react/`.
- Сначала проверь `git status`. Сохраняй чужие незакоммиченные изменения. Не переключай и не удаляй чужие worktree, не исправляй соседний код вне задачи.

## Разработка

- Источник задачи — GitHub issue `LFPT-XXXX`. Новая фича начинается со спецификации `specs/features/`, согласованной с MASTER. Фронт и бэк — отдельные задачи и PR; порядок зависимостей сохраняется.
- Java source/release **17**, хотя CI и Docker используют 21. DTO — типизированные, маппинг — MapStruct, бизнес-логика — в сервисах, вычисления по возможности отдельно от I/O. Полные требования — в CODE_STYLE.
- Новые пользовательские строки сразу переводятся на ES/RU/EN. Документация меняется вместе с кодом. Миграции Liquibase добавляются новыми файлами.
- Для `mobile-app/` проверяй `pnpm test` и `pnpm typecheck`, после изменений исходников пересобирай `pnpm build:site` и включай результат `src/main/resources/static/app/`.

## Проверка

- Бэкенд: `./mvnw verify`; интеграционным тестам нужен отдельный PostgreSQL. Не используй боевую БД и не пересоздавай существующие пользовательские базы.
- Документация: `python3 .github/bin/docs-drift.py`.
- Конвейер: `python3 -m unittest discover -s automation/telegram-relay -p 'test_*.py'` и `python3 .github/bin/check-agent-migration.py`.
- UI проверяй реальным браузером через доступные инструменты или Playwright. Не считай чтение шаблона доказательством работы. Если проверка недоступна, явно укажи это в отчёте.
- Не останавливай чужие процессы. Останавливай только запущенные тобой экземпляры по сохранённому PID.

## Полномочия и конвейер

- Обычная сессия: без push и PR, пока пользователь явно их не поручил. Сам запрос на анализ или исправление не включает автономный выпуск.
- Явный запуск `$develop-feature` или задание доверенного Telegram-воркера включает SDD-конвейер: Analyst → Developer → Tester → Architect. Полный протокол — [.agents/workflows/develop-feature.md](.agents/workflows/develop-feature.md), роли — [.agents/roles/](.agents/roles/).
- В конвейере сохраняй `Pipeline-Task`, `Depends-On`, `Closes` и метки `pipeline:*`. `pipeline:ready` разрешена только после проверок последнего коммита и финального ревью: она запускает существующий автомерж и деплой.
- Навыки проекта находятся в `.agents/skills/`: `$new-feature` готовит постановку и спецификацию, `$develop-feature` проводит полный цикл. Файлы ролей — инструкции, а не автоматически зарегистрированные подагенты. Если делегирование недоступно, последовательно выполняй роли сам с отдельными отчётами.

## Приватность и среда

- `.env*`, локальные настройки, `.agents/SECURITY.md`, `.agents/THREATS.md`, `docs/infrastructure-security.md`, `docs/telegram-ai-pipeline.md` и runtime-состояние не публикуются. Не выводи токены, доступы и приватные адреса в логи или публичные документы.
- `.claude/worktrees/` и `.claude/settings.local.json` — сохранённые локальные артефакты старой среды. Не переноси их обычным переименованием: worktree зарегистрированы в Git.
- Не переноси разрешения из Claude `settings.json` в Codex. Используй фактические права текущей среды; не обходи sandbox и запросы разрешений.
- Устаревшие команды сохранены в `.agents/archive/` для истории. Они не заменяют MASTER и действующие навыки.
